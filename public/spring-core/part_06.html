What is a Bean?
📖 Definition

A Bean is a Java object whose lifecycle, dependencies, and configuration are managed by the Spring IoC Container.

❌ Normal Java Object
Student s = new Student();
// Developer creates & manages
✅ Spring Bean
ApplicationContext ac =
  new ClassPathXmlApplicationContext("config.xml");
Student s = ac.getBean("student");
// Spring creates & manages → this is a Bean!
What is Bean Life Cycle?
📖 Definition

Bean Life Cycle describes: (1) when the bean is created, (2) how dependencies are injected, (3) what actions are performed after creation (init), (4) when the bean is destroyed. The complete lifecycle is managed by the Spring Container.

Bean Life Cycle Flow
Spring Container Starts
▼
Bean Object Created  (new Person())
▼
Dependency Injection  (setter / constructor)
▼
Init Method Executed  (init-method / @PostConstruct)
▼
Bean Ready For Use
▼
Business Logic Executes  (your methods called)
▼
Container Closed  (c.close())
▼
Destroy Method Executed  (destroy-method / @PreDestroy)
▼
Bean Removed from Container

Bean Life Cycle — XML & Annotation Implementation
PART 2
Method 1 — XML Configuration Lifecycle
📄 Person.java — POJO with Init & Destroy Methods
package com.init_destroy;

public class Person {

    public void initimethod() {
        System.out.println("Init method executed after bean creation");
    }

    public void sing() {
        System.out.println("Person is singing");  // business logic
    }

    public void destroy_method() {
        System.out.println("Destroy method executed");
    }
}
📄 config2.xml — Bean with init-method & destroy-method
<bean
    id="person"
    class="com.init_destroy.Person"
    init-method="initimethod"       <!-- called after bean creation -->
    destroy-method="destroy_method"  <!-- called when container closes -->
>
</bean>
⚠️ Common Mistake

❌ Wrong: destroy-method="initimethod"   (same as init — copy-paste error!)
✅ Correct: destroy-method="destroy_method"

📄 Driver.java — Use ConfigurableApplicationContext to call close()
package com.init_destroy;

import org.springframework.context.ConfigurableApplicationContext;
import org.springframework.context.support.ClassPathXmlApplicationContext;

public class Driver {
    public static void main(String[] args) {

        // ConfigurableApplicationContext needed to call close()
        ConfigurableApplicationContext c =
            new ClassPathXmlApplicationContext("config2.xml");

        Person p = (Person) c.getBean("person");

        p.sing();   // business method

        c.close();  // triggers destroy_method()
    }
}
📤 Output
Init method executed after bean creation
Person is singing
Destroy method executed
💡 Why ConfigurableApplicationContext?

ApplicationContext does NOT have a close() method. ConfigurableApplicationContext extends it and provides close() and registerShutdownHook() — needed to trigger the destroy method.

Method 2 — Annotation-Based Lifecycle
@Component
public class Person {

    @PostConstruct              // replaces init-method in XML
    public void init() {
        System.out.println("Init Method — @PostConstruct");
    }

    @PreDestroy                 // replaces destroy-method in XML
    public void destroy() {
        System.out.println("Destroy Method — @PreDestroy");
    }
}
Method 3 — Interface-Based Lifecycle
InterfaceMethod to OverrideWhen Called
InitializingBeanafterPropertiesSet()After dependencies are injected (init phase)
DisposableBeandestroy()When container is closed (destroy phase)

Interview Questions
🎤 Q1. What is a Bean?

A Bean is a Java object whose lifecycle is managed by the Spring IoC Container — including creation, dependency injection, initialization, and destruction.

🎤 Q2. What is Bean Life Cycle?

Bean Life Cycle is the complete process: Container Starts → Bean Created → DI → Init Method → Bean Used → Container Closed → Destroy Method → Bean Removed.

🎤 Q3. How many ways to implement Bean Life Cycle?

3 ways: (1) XML — init-method & destroy-method attributes  |  (2) Annotations — @PostConstruct & @PreDestroy  |  (3) Interfaces — InitializingBean & DisposableBean

🎤 Q4. Why use ConfigurableApplicationContext instead of ApplicationContext?

ApplicationContext does not have close() method. ConfigurableApplicationContext provides close() which is needed to trigger the destroy method of the bean.

🧠 Final Memory Tricks

Lifecycle order: Create → DI → Init → Use → Destroy

👉 "CD I UD" — "Container Delivers Ice, Use Deliberately!"

Init runs: right after bean creation   |   Destroy runs: when c.close() is called

XML: init-method / destroy-method   |   Annotation: @PostConstruct / @PreDestroy
