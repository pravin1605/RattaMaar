Spring Framework
Spring Core Annotations
PART 1
@Component01

Without @Component, Spring doesn't know which class to create as a bean. You'd need a manual <bean> entry in XML for every class — 100 classes = 100 entries. @Component solves this.

📖 DefinitionMarks a class as a Spring-managed bean. Spring automatically detects it during component scanning, creates its object, and stores it in the IoC Container.
XML Equivalent
<bean id="student"
      class="com.ty.Student"/>
Annotation Approach
@Component
public class Student {
  public void study() {
    System.out.println("Studying");
  }
}
@Configuration02

In XML we have <beans>...</beans> as the starting point. When using annotations, Spring still needs a starting point — that is @Configuration.

📖 DefinitionMarks a class as a Spring configuration class. It acts as the replacement for the XML <beans> file and contains bean definitions.
XML Equivalent
<beans>
  ...
</beans>
Annotation Approach
@Configuration
public class Configure {
  // bean definitions here
}
💡 Real Life Analogy

Like a College Principal Office — every instruction starts from there. Spring starts from the Configuration Class.

@ComponentScan03

Classes can be in different packages (com.ty.student, com.ty.employee). Spring doesn't know where to look. @ComponentScan tells Spring which package to search.

📖 DefinitionTells Spring where to search for @Component, @Service, @Repository, @Controller classes and automatically create their beans.
XML Equivalent
<context:component-scan
  base-package="com.ty"/>
Annotation Approach
@Configuration
@ComponentScan("com.ty")
public class Configure {
}
@Value04

Without Spring, you manually call setters to assign values. With @Value, Spring directly injects values into fields — no manual assignment needed.

📖 DefinitionUsed to inject default/hardcoded values into variables, constructors, and setter methods automatically by Spring.
XML Equivalent
<property name="id"
          value="101"/>
<property name="name"
          value="Pravin"/>
Annotation Approach
@Component
public class Student {
  @Value("101")
  private int id;
  @Value("Pravin")
  private String name;
}
📤 Output
101 Pravin

Annotations — DI & Scope
PART 2
@Autowired05

When one class depends on another (e.g. Student needs Laptop), you'd manually create and pass the object. With 100 dependencies this becomes unmanageable. @Autowired lets Spring handle it automatically.

📖 DefinitionUsed for automatic dependency injection. Spring automatically finds the required bean and injects it — no manual object creation needed.
XML Equivalent
<bean id="laptop"
  class="com.ty.Laptop"/>
<bean id="student"
  class="com.ty.Student">
  <property name="laptop"
    ref="laptop"/>
</bean>
Annotation Approach
@Component
public class Student {
  @Autowired
  Laptop laptop;

  public void study() {
    laptop.coding();
  }
}
⚙️ Internally Spring Does

Laptop l = new Laptop(); then student.laptop = l; — automatically!

@Qualifier06

If two beans of same type exist (e.g. OracleDB and MySQLDB), Spring gets confused which one to inject → throws NoUniqueBeanDefinitionException. @Qualifier specifies exactly which bean.

📖 DefinitionUsed with @Autowired to specify exactly which bean should be injected when multiple beans of the same type exist.
XML Equivalent
<property name="db"
          ref="mysql"/>
Annotation Approach
@Component("mysql")
class MySQLDB {}

@Component("oracle")
class OracleDB {}

@Autowired
@Qualifier("mysql")
MySQLDB db; // MySQLDB injected
@Primary07

When many beans of same type exist, instead of writing @Qualifier everywhere, mark one bean as the default choice using @Primary.

📖 DefinitionTells Spring to choose this bean by default when multiple beans of the same type exist, without needing @Qualifier.
XML Equivalent
<bean id="mysql"
  class="com.ty.MySQLDB"
  primary="true"/>
Annotation Approach
@Component
@Primary
public class MySQLDB {
}
// Spring auto-picks MySQLDB
💡 @Primary vs @Qualifier

@Primary = default bean for everyone.  |  @Qualifier = pick specific bean at injection point. If both used, @Qualifier wins.

@Scope08

By default Spring creates only one object (singleton). Sometimes you need a new object every time. @Scope controls this behaviour.

📖 DefinitionDefines the lifecycle and visibility of a bean inside the Spring Container. Two main scopes: singleton and prototype.
Singleton (Default)
@Component
@Scope("singleton")
public class Student {}
// getBean() → same object
// Student@123
// Student@123
Prototype
@Component
@Scope("prototype")
public class Student {}
// getBean() → new object each time
// Student@123
// Student@456
ScopeObject CountWhen to Use
singletonOnly 1 per containerShared stateless beans (services, DAOs)
prototypeNew object every timeStateful beans (user sessions, carts)

@Bean09

If a class belongs to a third-party library, you cannot modify it to add @Component. In such cases, use @Bean inside a @Configuration class to manually register it.

📖 DefinitionUsed to manually create and register a bean inside the Spring Container from a @Configuration class. Useful for third-party classes.
XML Equivalent
<bean id="engine"
  class="com.ty.Engine"/>
Annotation Approach
@Configuration
public class Configure {
  @Bean
  public Engine getEngine() {
    return new Engine(); // manual
  }
}
💡 @Bean vs @Component

@Component = Spring auto-creates (you own the class).  |  @Bean = you manually create (third-party class you can't modify).

@Lazy10

By default Spring creates ALL singleton beans at startup — even if you never use some of them. This wastes memory. @Lazy delays creation until the bean is actually requested.

📖 DefinitionDelays bean creation until the bean is actually requested using getBean(). Saves memory on startup.
XML Equivalent
<bean id="student"
  class="com.ty.Student"
  lazy-init="true"/>
Annotation Approach
@Component
@Lazy
public class Student {
  public Student() {
    System.out.println("Created");
  }
}
// Object created only after getBean()
@PostConstruct11

After bean creation and DI, you may want to open a DB connection, load config files, etc. @PostConstruct runs a method automatically right after the bean is ready.

📖 DefinitionExecutes a method immediately after bean creation and dependency injection. Equivalent to init-method in XML.
XML Equivalent
<bean id="student"
  init-method="init"/>
Annotation Approach
@Component
public class Student {
  @PostConstruct
  public void init() {
    System.out.println("Bean Initialized");
  }
}
📤 Output
Bean Initialized
@PreDestroy12

Before a bean is destroyed, you may need to close DB connections, release memory, or save logs. @PreDestroy runs a method just before the bean is removed.

📖 DefinitionExecutes a method just before bean destruction (when Spring Container is closed). Equivalent to destroy-method in XML.
XML Equivalent
<bean id="student"
  destroy-method="destroy"/>
Annotation Approach
@Component
public class Student {
  @PreDestroy
  public void destroy() {
    System.out.println("Bean Destroyed");
  }
}
📤 Output (when c.close() called)
Bean Destroyed

Annotations — Layers & Extras
PART 4
@Service13
📖 DefinitionSpecialization of @Component for Service Layer classes. Contains business logic.
@Service
public class StudentService {
  public void addStudent() {
    System.out.println("Student Added");
  }
}

Used for: Business Logic

@Repository14
📖 DefinitionSpecialization of @Component for DAO Layer. Handles database operations.
@Repository
public class StudentDao {
  public void save() {
    System.out.println("Saved to DB");
  }
}

Used for: Database Access

@Controller15
📖 DefinitionSpecialization of @Component for Web Layer. Handles HTTP requests in Spring MVC.
@Controller
public class StudentController {
  // handles web requests
}

Used for: Web/MVC Layer

🏗️ Spring Application Layers
@Controller → @Service → @Repository → Database

All three are specializations of @Component. They work the same way but communicate the role/layer of the class.

@RequestMapping16

When a user visits http://localhost:8080/home, Spring needs to know which method handles it. @RequestMapping maps URLs to methods.

📖 DefinitionMaps a URL path to a specific method in a controller class.
@Controller
public class HomeController {
  @RequestMapping("/home")
  public String home() {
    return "home.jsp";
  }
}
@PropertySource17
📖 DefinitionLoads external properties files so values can be injected using @Value. Avoids hardcoding.
app.properties
student.name=Pravin
@Configuration
@PropertySource("app.properties")
public class Configure {}

// Then use:
@Value("${student.name}")
String name;
@DependsOn18
📖 DefinitionSpecifies bean creation order. Ensures one bean is created before another.
@Component
public class Database {
  // Created FIRST
}

@Component
@DependsOn("database")
public class Student {
  // Created AFTER Database
}

Use when: Student bean needs Database bean to exist first.
