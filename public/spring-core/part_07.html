1📌 What is an Annotation?
😊 Easy idea: An annotation is a sticky label on your class. The label (@Component) tells Spring “treat this class like this”.
📖 Definition: An annotation is a special instruction written using @ that tells Spring how a class, method, field or other element should be treated.
✅ ANNOTATION WAY
@Component
public class Student {
}
📄 OLD XML WAY
<bean id="student"
      class="com.ty.Student"/>

⬇

PART 1 — Spring Core AnnotationsCreate beans · find them · fill values
2🧩 @Component ★ MOST IMPORTANT
😊 Easy idea: Think of a school register. If a student’s name is written in it, the school knows that student exists. @Component writes your class’s name in Spring’s register.
📖 Definition: @Component marks a class as a Spring-managed Bean. Spring detects it during component scanning, creates its object, and stores that object in the IoC Container.
✅ JAVA EXAMPLE
@Component
public class Student {
    public void study() {
        System.out.println("Studying");
    }
}
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"/>
📌 Must know:
  • You never write new Student() — Spring creates it for you (this is IoC: Inversion of Control).
  • Default bean name = class name with small first letter → student. Custom name: @Component("stu").
  • Works only if @ComponentScan covers that package.
  • Parent of @Service, @Repository, @Controller (called stereotype annotations).
  • Spring needs a usable constructor (no-arg, or one constructor it can fill).
@Component on class
⬇
Spring scans the package
⬇
Object is created
⬇
Stored as Bean in IoC Container
⚠ Common mistake: Class is in a package that is not scanned → Spring never creates it → NoSuchBeanDefinitionException.
🧠 Memory trick: @Component is used to mark a class as a Spring-managed Bean. Spring detects it during component scanning, creates its object, and stores it in the IoC Container.
🎤 Say in interview: “COMPONENT = “Make me a BEAN””
3⚙️ @Configuration ★ MOST IMPORTANT
😊 Easy idea: The control room of a factory. All the main switches and settings are kept in one room — Spring looks here first to know how to set everything up.
📖 Definition: @Configuration marks a class as a Spring configuration class. It is the starting point of configuration and can contain Bean definitions (@Bean methods).
✅ JAVA EXAMPLE
@Configuration
@ComponentScan("com.ty")
public class Configure {

    @Bean
    public Laptop laptop() {
        return new Laptop();
    }
}
📄 XML EQUIVALENT
<beans>
   <!-- the whole
   applicationContext.xml -->
</beans>
📌 Must know:
  • Replaces the whole XML file: Configure.java = applicationContext.xml.
  • The class itself also becomes a bean (it is meta-annotated with @Component).
  • Spring wraps it in a proxy (CGLIB) so @Bean methods return the same singleton even if called many times.
  • Loaded with new AnnotationConfigApplicationContext(Configure.class).
⚠ Common mistake: Forgetting to pass the config class to the context → nothing is configured.
🧠 Memory trick: @Configuration marks a class as a Spring configuration class. It is the starting point of configuration and holds bean definitions.
🎤 Say in interview: “CONFIGURATION = Control room”
4🔍 @ComponentScan ★ MOST IMPORTANT
😊 Easy idea: A security guard with a search area. You tell him “search only this building (package)”. He walks through, finds every class with a Spring tag, and reports to Spring.
📖 Definition: @ComponentScan tells Spring where to search for @Component, @Service, @Repository and @Controller classes.
✅ JAVA EXAMPLE
@Configuration
@ComponentScan("com.ty")
public class Configure {
}

// many packages:
// @ComponentScan({"com.a","com.b"})
📄 XML EQUIVALENT
<context:component-scan
    base-package="com.ty"/>
📌 Must know:
  • Scans the given package and all its sub-packages.
  • No package given → scans the package of the config class.
  • Spring Boot: @SpringBootApplication already includes it.
  • Alternative: basePackageClasses = Student.class (type-safe).
⚠ Common mistake: Bean placed outside the scanned package is silently ignored.
🧠 Memory trick: @ComponentScan tells Spring in which packages to look for @Component, @Service, @Repository and @Controller classes.
🎤 Say in interview: “COMPONENT = WHAT to create · SCAN = WHERE to search”
5💬 @Value ★ MOST IMPORTANT
😊 Easy idea: Filling a form field. You write “name = Pravin” and Spring puts that value into the variable.
📖 Definition: @Value is used to inject values into variables, constructors or setter methods.
✅ JAVA EXAMPLE
@Component
public class Student {
    @Value("101")
    private int id;

    @Value("Pravin")
    private String name;
}
// Output: 101 Pravin
📄 XML EQUIVALENT
<property name="id"
          value="101"/>
<property name="name"
          value="Pravin"/>
📌 Must know:
  • 4 styles: literal @Value("101") · placeholder @Value("${student.name}") · default @Value("${student.name:Guest}") · SpEL @Value("#{2*5}").
  • Spring auto-converts the text to int, double, boolean.
  • Hard-coded value = for demo. Real projects read from a .properties file (see @PropertySource).
  • Works on field, setter and constructor parameter.
⚠ Common mistake: Using ${...} but forgetting @PropertySource → value not found.
🧠 Memory trick: @Value is used to inject values, either hard-coded or from a properties file, into fields, constructors or setters.
🎤 Say in interview: “VALUE = Fill the variable”

PART 2 — Dependency Injection & ScopeConnect beans · pick the right one · decide how many
6🔌 @Autowired ★ MOST IMPORTANT
😊 Easy idea: You are hungry and a waiter brings food to your table automatically. You do not go to the kitchen. Same here: Student needs a Laptop, Spring brings the Laptop.
📖 Definition: @Autowired is used for automatic dependency injection. Spring finds the required Bean and injects it.
✅ JAVA EXAMPLE
@Component
public class Student {

    @Autowired
    Laptop laptop;   // no "new Laptop()"

    public void study() {
        laptop.coding();
    }
}
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"
      autowire="byType"/>
<!-- or manually -->
<property name="laptop"
          ref="laptop"/>
📌 Must know:
  • 3 places: field, setter, constructor. Constructor injection is best (final fields, easy testing).
  • Single constructor → @Autowired is optional (Spring 4.3+).
  • Matches by type first. Many matches → @Primary / @Qualifier / variable name.
  • required=true by default (missing bean = error). @Autowired(required=false) allows null.
  • Both classes must be Beans, otherwise nothing to inject.
⚠ Common mistake: Two beans of same type, no @Qualifier/@Primary → NoUniqueBeanDefinitionException.
🧠 Memory trick: @Autowired is used for automatic dependency injection. Spring finds the required Bean and injects it automatically.
🎤 Say in interview: “AUTOWIRED = “Bring it to me””
7👆 @Qualifier ★ MOST IMPORTANT
😊 Easy idea: In a shop you point and say “I want THAT one”. When two beans look the same, @Qualifier points to the exact one.
📖 Definition: @Qualifier selects the exact Bean when more than one Bean of the same type exists.
✅ JAVA EXAMPLE
@Component("mysql")
class MySQLDB implements DB { }

@Component("oracle")
class OracleDB implements DB { }

@Autowired
@Qualifier("mysql")
DB db;   // MySQLDB injected
📄 XML EQUIVALENT
<property name="db"
          ref="mysql"/>
<!-- ref = exact bean id -->
📌 Must know:
  • Problem: MySQLDB and OracleDB both fit → Spring confused. Solution: give names, pick one.
  • Name given in @Component("mysql") must match @Qualifier("mysql").
  • Used at the injection point (field/parameter).
  • Also works on parameters: Student(@Qualifier("oracle") DB db).
⚠ Common mistake: Typing a name that doesn’t exist → NoSuchBeanDefinitionException.
🧠 Memory trick: @Qualifier is used with @Autowired to choose a specific Bean by name when multiple beans of the same type exist.
🎤 Say in interview: “QUALIFIER = Qualify = Choose exact one”
8🥇 @Primary
😊 Easy idea: Your phone has a default payment method. If you don’t choose, the default is used. @Primary = default bean.
📖 Definition: @Primary tells Spring: “If multiple Beans are available, choose this Bean by default.”
✅ JAVA EXAMPLE
@Component
@Primary
public class MySQLDB implements DB { }

@Component
public class OracleDB implements DB { }

@Autowired
DB db;   // MySQLDB (default)
📄 XML EQUIVALENT
<bean id="mysql"
      class="com.ty.MySQLDB"
      primary="true"/>
📌 Must know:
  • Placed on the Bean class (or @Bean method).
  • If both are used, @Qualifier wins.
  • Only one @Primary per type, else error.
@Primary@Qualifier
Default beanSpecific bean
On Bean classAt injection point
“Choose me by default”“Choose THIS exact one”
WeakerStronger (wins)
⚠ Common mistake: Putting @Primary on two beans of the same type.
🧠 Memory trick: @Primary defines the default Bean when multiple Beans are available, while @Qualifier selects a specific Bean at the injection point.
🎤 Say in interview: “PRIMARY = Priority = Default”
9🥤 @Scope
😊 Easy idea: Singleton = one water cooler for the whole office (everyone shares). Prototype = a fresh paper cup every time you ask.
📖 Definition: @Scope controls how many objects Spring creates for a Bean and its lifecycle/visibility in the container.
✅ JAVA EXAMPLE
@Component
@Scope("singleton")     // default
public class Student { }

@Component
@Scope("prototype")
public class Teacher { }

// singleton : Student@123, Student@123
// prototype : Teacher@123, Teacher@456
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"
      scope="singleton"/>
<bean id="teacher"
      class="com.ty.Teacher"
      scope="prototype"/>
📌 Must know:
  • singleton (default): 1 object per container, created at startup.
  • prototype: new object on every getBean(), created only when asked.
  • Web scopes: request, session, application.
  • Singleton = shared → keep it stateless (no user-specific data).
ScopeObjectsCreatedUse
singletonOneStartupServices, DAOs
prototypeManyOn requestStateful beans
⚠ Common mistake: Spring does not call @PreDestroy on prototype beans.
🧠 Memory trick: Singleton gives one shared object per Spring container; prototype creates a new object every time it is requested.
🎤 Say in interview: “SINGLE-ton = SINGLE object · PROTO = new copy”

10🛠️ @Bean ★ MOST IMPORTANT
😊 Easy idea: @Component = Spring cooks from your recipe. @Bean = you cook and hand the ready dish to Spring. Needed when the recipe belongs to someone else (library class).
📖 Definition: @Bean is used to manually create and register a Bean in the Spring Container. Useful for third-party classes you cannot modify.
✅ JAVA EXAMPLE
@Configuration
public class Configure {

    @Bean
    public Engine getEngine() {
        return new Engine();
    }
}
📄 XML EQUIVALENT
<bean id="getEngine"
      class="com.ty.Engine"/>
📌 Must know:
  • Written on a method inside a @Configuration class.
  • Bean name = method name (getEngine). Custom: @Bean("engine").
  • Return value = the bean. You control how it is built.
  • Real uses: DataSource, RestTemplate, PasswordEncoder.
@Component@Bean
On classOn method
Auto-detectedExplicit
Your own classesAny class
Spring makes objectYou write new
⚠ Common mistake: Using @Bean in a normal class without @Configuration (works “lite” but not proxied).
🧠 Memory trick: @Component is used when Spring can detect the class automatically, whereas @Bean explicitly registers an object, especially for third-party classes.
🎤 Say in interview: “@Bean = Build it Because I can’t edit the class”
11😴 @Lazy ★ MOST IMPORTANT
😊 Easy idea: Cooking Maggi only when you are hungry, not in advance. The bean is created only when someone asks for it.
📖 Definition: @Lazy delays Bean creation until the Bean is actually requested. Normally singleton beans are created at startup.
✅ JAVA EXAMPLE
@Component
@Lazy
public class Student {
    public Student() {
        System.out.println("Created");
    }
}
// "Created" prints only at first getBean()
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"
      lazy-init="true"/>
📌 Must know:
  • Pros: faster startup, less memory.
  • Con: errors appear late (at first use, not at startup).
  • Can be on a class, @Bean method, or injection point.
  • No effect on prototype (already lazy).
⚠ Common mistake: Expecting @Lazy to hide a broken bean — it only delays the crash.
🧠 Memory trick: @Lazy delays bean creation until it is actually needed instead of creating it at startup.
🎤 Say in interview: “LAZY = Later”
12🏁 @PostConstruct ★ MOST IMPORTANT
😊 Easy idea: A footballer’s warm-up after reaching the ground and before the match. The bean is built, everything is injected, then it warms up.
📖 Definition: @PostConstruct runs a method after the Bean has been created and dependency injection is completed.
✅ JAVA EXAMPLE
@Component
public class Student {

    @Autowired
    Laptop laptop;

    @PostConstruct
    public void init() {
        System.out.println("Bean Initialized");
    }
}
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"
      init-method="init"/>
📌 Must know:
  • Use for: load cache, open connection, check injected values.
  • Why not the constructor? Inside constructor, @Autowired fields are still null.
  • Method must be void with no parameters.
  • Import jakarta.annotation.PostConstruct (Spring 6/Boot 3), older: javax.annotation.
⚠ Common mistake: Putting heavy logic that needs injected beans inside the constructor.
🧠 Memory trick: @PostConstruct runs after bean creation and dependency injection, so the bean is ready for use.
🎤 Say in interview: “POST = After → READY / START”
13🧹 @PreDestroy ★ MOST IMPORTANT
😊 Easy idea: Cleaning the room before leaving. Before the bean dies, it closes files and connections.
📖 Definition: @PreDestroy executes a method just before a Bean is destroyed, when the Spring Container is closed.
✅ JAVA EXAMPLE
@Component
public class Student {

    @PreDestroy
    public void destroy() {
        System.out.println("Bean Destroyed");
    }
}
ctx.close();   // triggers @PreDestroy
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"
      destroy-method="destroy"/>
📌 Must know:
  • Use for: close DB connection, files, threads.
  • Runs only when the container is closed: ctx.close() or registerShutdownHook().
  • Not called for prototype beans.
⚠ Common mistake: Program just ends without closing context → @PreDestroy never runs.
🧠 Memory trick: @PreDestroy runs before the bean is destroyed, when the container is closed, to release resources.
🎤 Say in interview: “PRE-DESTROY = Before death → STOP / CLEANUP”

PART 4 — Spring Layers & Extra AnnotationsController → Service → Repository · URLs · files · order
14🧠 @Service
😊 Easy idea: The chef in a restaurant. He takes the order and applies the rules — cooking = business logic.
📖 Definition: @Service is a specialization of @Component used for the Service Layer. It generally contains business logic.
✅ JAVA EXAMPLE
@Service
public class StudentService {

    @Autowired
    StudentDao dao;

    public void addStudent() {
        dao.save();
    }
}
📄 XML EQUIVALENT
<bean id="studentService"
      class="com.ty.StudentService"/>
📌 Must know:
  • Works exactly like @Component; the gain is clarity of layer.
  • Put rules, calculations, validations and @Transactional here.
  • Calls the Repository (DAO).
⚠ Common mistake: Writing SQL directly in Service instead of Repository.
🧠 Memory trick: @Service marks the business logic layer and is a specialization of @Component.
🎤 Say in interview: “SERVICE = Serve the logic”
15🗄️ @Repository
😊 Easy idea: The store room (godown). Only he talks to the database — saves and fetches data.
📖 Definition: @Repository is a specialization of @Component used for the DAO/Data Access Layer. It handles database operations.
✅ JAVA EXAMPLE
@Repository
public class StudentDao {
    public void save() {
        System.out.println("Saved to DB");
    }
}
📄 XML EQUIVALENT
<bean id="studentDao"
      class="com.ty.StudentDao"/>
📌 Must know:
  • Extra power: Spring converts DB-specific exceptions (SQLException) to DataAccessException.
  • Only DB code here, no business rules.
⚠ Common mistake: Mixing business logic into the DAO class.
🧠 Memory trick: @Repository marks the data access layer and handles database operations.
🎤 Say in interview: “REPOSITORY = REPO = storage (DB)”
16🛎️ @Controller
😊 Easy idea: The waiter/reception. Takes the customer’s (browser’s) request and passes it inside.
📖 Definition: @Controller is a specialization of @Component used for the Web/MVC Layer. It handles HTTP requests in Spring MVC.
✅ JAVA EXAMPLE
@Controller
public class StudentController {

    @Autowired

    // handles web requests

📄 XML EQUIVALENT
<bean id="studentController"
      class="com.ty.StudentController"/>
📌 Must know:
  • Returns a view name (e.g. "home.jsp").
  • For JSON/REST use @RestController = @Controller + @ResponseBody.
  • Calls the Service, never the DB directly.

17🪧 @RequestMapping
😊 Easy idea: A signboard: “/home this way → home() room”. It links a URL to a method.
📖 Definition: @RequestMapping maps a URL path to a controller method.
✅ JAVA EXAMPLE
@Controller
public class HomeController {

    @RequestMapping("/home")
    public String home() {
        return "home.jsp";
    }
}   // request /home → home()
📄 XML EQUIVALENT
<mvc:view-controller
    path="/home"
    view-name="home"/>
<!-- or SimpleUrlHandlerMapping -->
📌 Must know:
  • Attributes: value/path, method, params, consumes, produces.
  • On class = common prefix; on method = rest of the path.
  • Shortcuts: @GetMapping @PostMapping @PutMapping @DeleteMapping.
⚠ Common mistake: Same URL + same HTTP method mapped twice → ambiguous mapping error.
🧠 Memory trick: @RequestMapping maps an incoming URL to a controller method.
🎤 Say in interview: “MAPPING = Map URL → method”
18📒 @PropertySource
😊 Easy idea: A phonebook / settings file. Instead of writing values inside code, keep them in a file and let Spring read them.
📖 Definition: @PropertySource loads an external .properties file so its values can be injected using @Value.
✅ JAVA EXAMPLE
// app.properties
student.name=Pravin

@Configuration
@PropertySource("app.properties")
public class Configure { }

@Value("${student.name}")
String name;
📄 XML EQUIVALENT
<context:property-placeholder
   location="classpath:app.properties"/>
📌 Must know:
  • Flow: .properties → @PropertySource → @Value → Java variable.
  • Use classpath: for files in resources.
  • Change values without touching code.
  • Spring Boot auto-loads application.properties.
⚠ Common mistake: Wrong file path → FileNotFoundException at startup.
🧠 Memory trick: @PropertySource loads an external properties file whose values we inject with @Value.
🎤 Say in interview: “PROPERTY = Properties file”
19🏗️ @DependsOn
😊 Easy idea: You must build the foundation before the house. Database must be ready before Student.
📖 Definition: @DependsOn specifies Bean creation order — the named Bean is created first.
✅ JAVA EXAMPLE
@Component
public class Database { }

@Component
@DependsOn("database")
public class Student { }
// Database → created FIRST
// Student  → created AFTER
📄 XML EQUIVALENT
<bean id="student"
      class="com.ty.Student"
      depends-on="database"/>
📌 Must know:
  • Use when one bean needs another ready but has no direct reference.
  • Value is the bean name (database).
  • Destruction happens in reverse order.
⚠ Common mistake: Giving class name instead of bean name ("Database").
🧠 Memory trick: @DependsOn controls the order in which beans are created.
🎤 Say in interview: “DEPENDS ON = Depends on that first”

🔗 ALL ANNOTATIONS TOGETHEROne story to remember everything
🏫 Story — Student Management App: Spring opens the @Configuration control room → @ComponentScan searches the packages → it finds @Controller, @Service, @Repository, @Component → creates them as beans (@Scope decides how many) → @PropertySource loads the file → @Value fills values → @Autowired connects beans (@Qualifier/@Primary pick the right one) → @Bean adds library objects → @DependsOn fixes order, @Lazy delays some → @PostConstruct runs → app works, @RequestMapping routes URLs → on close, @PreDestroy cleans up.
▶ FULL WORKING EXAMPLE
// app.properties  →  student.name=Pravin
@Configuration
@ComponentScan("com.ty")
@PropertySource("classpath:app.properties")
public class Configure {
    @Bean @Primary
    public DB mysql() { return new MySQLDB(); }
}

@Repository
public class StudentDao {
    public void save() { System.out.println("Saved to DB"); }
}

@Service
public class StudentService {
    @Autowired StudentDao dao;
    public void add() { dao.save(); }
}

@Component @Scope("singleton") @Lazy
public class Student {
    @Value("${student.name}") String name;
    @Autowired StudentService service;
    @Autowired @Qualifier("mysql") DB db;
    @PostConstruct public void init() { System.out.println("Ready: " + name); }
    @PreDestroy   public void clean() { System.out.println("Cleanup"); }
}

// Main
var ctx = new AnnotationConfigApplicationContext(Configure.class);
Student s = ctx.getBean(Student.class);   // lazy bean created now
s.service.add();
ctx.close();                              // @PreDestroy runs

❓ What is @Component?
@Component is used to mark a class as a Spring-managed Bean. Spring detects it during component scanning, creates its object, and stores it in the IoC Container.
❓ What is @Autowired?
@Autowired is used for automatic dependency injection. Spring finds the required Bean and injects it automatically.
❓ @Primary vs @Qualifier?
@Primary defines the default Bean when multiple Beans are available, while @Qualifier selects a specific Bean at the injection point. If both exist, @Qualifier wins.
❓ @Component vs @Bean?
@Component is used when Spring can automatically detect the class, whereas @Bean explicitly registers an object, especially for third-party classes that we cannot modify.
❓ @PostConstruct vs @PreDestroy?
@PostConstruct runs after Bean creation and dependency injection, while @PreDestroy runs before the Bean is destroyed.
❓ Explain Controller → Service → Repository.
@Controller handles web requests, @Service contains business logic, and @Repository handles database operations.
❓ Singleton vs Prototype?
Singleton gives one shared object per container; prototype creates a new object on every request and Spring does not call @PreDestroy on it.
❓ Why @PostConstruct instead of constructor?
Injected dependencies are not available inside the constructor, but they are ready in @PostConstruct.
❓ Annotation vs XML configuration?
Annotations are short and sit beside the code; XML is centralised and changeable without recompiling, and works for classes we cannot edit.
❓ What are stereotype annotations?
@Component and its specializations @Service, @Repository and @Controller — they register the class as a bean and describe its layer.
