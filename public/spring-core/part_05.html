What is Dependency Injection?
📖 Definition

Dependency Injection (DI) is the main feature provided by the Spring IoC Container. It is a design pattern in which Spring creates the required objects and injects them into other objects at runtime, instead of the developer creating objects manually using new keyword.

🔧 Spring Takes Responsibility For:
Creating Objects Managing Lifecycle Injecting Dependencies Destroying Objects
Without DI vs With DI
❌ Without DI — Tight Coupling
class Engine {}

class Car {
    Engine e = new Engine();
    // Car creates Engine itself
    // Tightly coupled!
}

Car is directly dependent on Engine. If Engine changes → Car breaks.

✅ With DI — Loose Coupling
class Engine {}

class Car {
    Engine e;
    public void setEngine(Engine e) {
        this.e = e;
        // Spring injects Engine!
    }
}

Car doesn't create Engine. Spring injects it → Loose Coupling.

Why Dependency Injection?
🏢 Problem Example — Company & Employee
class Employee {}

class Company {
    Employee emp = new Employee(); // Tight coupling!
}

If Employee changes to Manager → Company class must also be modified.

❌ Problems Without DI

Tight Coupling — Changes in one class break another  |  Difficult Testing — Can't replace object with dummy  |  Difficult Maintenance — Large projects become unmanageable

✅ Loose Coupling ✅ Better Maintainability ✅ Easy Testing ✅ Reusability ✅ Better Code Quality

IoC = "Spring will manage objects" → the idea
DI = "Spring will inject objects into your class" → the action
👉 DI is how IoC is achieved in Spring.

Setter Dependency Injection (SDI)
PART 2
Types of Dependency Injection
1. Setter DI (SDI)

Spring injects values using setter methods. Object created first, then values set.

XML Tag: <property>

2. Constructor DI (CDI)

Spring injects values through constructor. Object created with values at the same time.

XML Tag: <constructor-arg>

Setter DI — Student Class (POJO)
package com.ty;

public class Student {

    private int sid;
    private String sname;
    private String sage;

    // Getters and Setters
    public int getSid()              { return sid; }
    public void setSid(int sid)     { this.sid = sid; }

    public String getSname()         { return sname; }
    public void setSname(String s)   { this.sname = s; }

    public String getSage()          { return sage; }
    public void setSage(String s)    { this.sage = s; }
}
Setter DI — XML Configuration (myconfig.xml)
<bean id="student1" class="com.ty.Student">

    <property name="sid"   value="101"/>   <!-- calls setSid(101) -->
    <property name="sname" value="Pravin"/> <!-- calls setSname("Pravin") -->
    <property name="sage"  value="22"/>    <!-- calls setSage("22") -->

</bean>
Setter DI — Driver Class
public class DriverStudent {
    public static void main(String[] args) {

        ApplicationContext ac =
            new ClassPathXmlApplicationContext("myconfig.xml");

        Student s = (Student) ac.getBean("student1");

        System.out.println(s.getSid() + " " + s.getSname() + " " + s.getSage());
    }
}
📤 Output
101 Pravin 22
How Setter DI Works Internally
⚙️ Spring Internally Does This
Student s = new Student();  // Step 1: Object created
s.setSid(101);             // Step 2: setSid() called
s.setSname("Pravin");     // Step 3: setSname() called
s.setSage("22");          // Step 4: setSage() called
Important Attributes of <property>
AttributeUsed ForExample
nameVariable / property name in the class<property name="sid"/>
valuePrimitive values and Strings<property name="sid" value="101"/>
refObject injection (reference to another bean)<property name="emp" ref="emp1"/>
🧠 SDI Memory Trick

Setter DI → Setter Methods → <property> tag → Object created first, values set after.

👉 Use SDI for optional fields (email, phone, address).

Constructor DI + Comparison + Interview
PART 3
Constructor DI — Person Class
package com.Variable;

public class Person {

    int id;
    String name;
    double sal;

    // Spring calls this constructor to inject values
    public Person(int id, String name, double sal) {
        this.id   = id;
        this.name = name;
        this.sal  = sal;
    }
}
Constructor DI — XML Configuration (config.xml)
<!-- Bean 1 -->
<bean id="person" class="com.Variable.Person">
    <constructor-arg value="101"/>      <!-- id -->
    <constructor-arg value="Pravin"/>   <!-- name -->
    <constructor-arg value="45000"/>   <!-- sal -->
</bean>

<!-- Bean 2 -->
<bean id="person2" class="com.Variable.Person">
    <constructor-arg value="102"/>
    <constructor-arg value="Rahul"/>
    <constructor-arg value="55000"/>
</bean>
Constructor DI — Driver Class + Output
ApplicationContext ac =
    new ClassPathXmlApplicationContext("config.xml");

Person p1 = (Person) ac.getBean("person");
System.out.println(p1.id + " " + p1.name + " " + p1.sal);

Person p2 = (Person) ac.getBean("person2");
System.out.println(p2.id + " " + p2.name + " " + p2.sal);
📤 Output
101 Pravin 45000.0
102 Rahul 55000.0
How Constructor DI Works Internally
⚙️ Spring Internally Does This
// Object created AND values injected in ONE step:
Person p = new Person(101, "Pravin", 45000);
// No setter methods needed!

Interview Questions
🎤 Q1. What is Dependency Injection?

DI is a design pattern in which the Spring Container creates objects and injects dependencies into them instead of allowing classes to create dependencies themselves. It promotes loose coupling.

🎤 Q2. What are the types of DI?

1. Setter DI — uses setter methods, <property> tag, for optional values.
2. Constructor DI — uses constructor, <constructor-arg> tag, for mandatory values.

🎤 Q3. Which DI is recommended?

Constructor DI is generally recommended because: dependencies are mandatory, object is fully initialized at creation, better immutability, and easier testing. Setter DI is used for optional dependencies.

🎤 Q4. Difference between IoC and DI?

IoC is the principle — control of object creation transferred from developer to Spring.
DI is the implementation — Spring injects required objects into your class.
DI is the most common way IoC is achieved in Spring. IoC is the "what", DI is the "how".

🧠 Final Memory Tricks

SDI → Setter → <property> → Set after creation → Optional values

CDI → Constructor → <constructor-arg> → Create with values → Mandatory values

IoC vs DI: IoC = "IT Dept manages" (idea)  |  DI = "IT Dept delivers laptop to your desk" (action)
