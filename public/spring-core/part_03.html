Types of IoC Container
PART 1
What is an IoC Container?
📖 Definition

An IoC Container is the core component of Spring Framework responsible for creating objects (Beans), configuring them, managing their lifecycle, managing dependencies, and providing objects whenever required.

⚠️ Without IoC Container

Developers would have to manually create and manage all objects — increasing complexity, errors, and maintenance effort.

Two Types of IoC Containers
1. BeanFactory

Core Container

Most basic version of Spring IoC Container. Provides fundamental bean management.

2. ApplicationContext

J2EE Container

Advanced version of BeanFactory. Adds enterprise-level features on top.

1. BeanFactory — Core Container
📖 Definition

BeanFactory is the most basic version of Spring IoC Container. It provides a mechanism to instantiate, configure, manage lifecycle, and retrieve objects.

Interface: org.springframework.beans.factory.BeanFactory

⚡ Key Behaviour — Lazy Initialization

Beans are created only when requested, not at container startup.

Resource resource = new ClassPathResource("beans.xml");
BeanFactory factory = new XmlBeanFactory(resource);

// Bean is created ONLY at this line:
Student s = (Student) factory.getBean("student");
Features of BeanFactory
#FeatureDescription
1Bean CreationCreates Java objects (Beans) from configuration
2Bean ConfigurationReads configuration and sets properties on objects
3Dependency ManagementManages dependencies between beans
4Lifecycle ManagementHandles Creation → Initialization → Usage → Destruction
5Memory EfficientCreates beans only when needed (Lazy)
Configuration Support
📄 XML Configuration (Traditional Approach)
<bean id="student" class="com.ty.Student"/>
<!-- Spring reads XML and creates the object -->
Limitations of BeanFactory
❌ BeanFactory Does NOT Provide

Event Handling  |  Internationalization (i18n)  |  Automatic Bean Post Processing  |  Advanced Resource Loading

Because of these limitations, BeanFactory is rarely used directly in modern Spring applications.

2. ApplicationContext — J2EE Container
📖 Definition

ApplicationContext is an advanced version of BeanFactory. It supports all BeanFactory features plus many enterprise-level features.

Interface: org.springframework.context.ApplicationContext

Relationship: public interface ApplicationContext extends BeanFactory

→ ApplicationContext IS-A BeanFactory. It inherits all BeanFactory capabilities.

⚡ Key Behaviour — Eager Initialization

All Singleton beans are created at container startup, not on demand.

// At this line itself — ALL beans are created:
ApplicationContext context =
    new ClassPathXmlApplicationContext("beans.xml");

// Student Bean → Created
// Employee Bean → Created
// Department Bean → Created

Student s = context.getBean("student", Student.class);
Why ApplicationContext Was Introduced?
⚠️ BeanFactory Was Not Enough For

Event management  |  Annotation support  |  Resource loading  |  Internationalization  |  Better bean processing

Features of ApplicationContext
#FeatureDetails
1Bean ManagementCreates and manages all beans (inherits from BeanFactory)
2Event HandlingContext Started / Closed / Custom Events
3Internationalization (i18n)Supports English, Hindi, Japanese, French etc.
4Annotation Support@Component @Service @Repository @Controller @Configuration
5Resource LoadingXML Files, Properties Files, URLs, Classpath Resources
6Auto Bean ProcessingSupports BeanPostProcessor automatically
Two Ways to Provide Configuration to IoC Container
1. XML Configuration — Old Approach
<bean id="student"
      class="com.ty.Student"/>
<!-- Spring reads XML → creates object -->

✅ Advantages

Centralized config  |  Easy to understand

❌ Disadvantages

Large XML files  |  Difficult maintenance  |  More boilerplate

2. Annotation Configuration — Modern
@Component
public class Student {}
// Spring auto-detects → creates bean

Common Annotations

@Component @Service @Repository @Controller @Configuration @Bean

✅ Advantages

Less config  |  Cleaner code  |  Faster dev  |  Easy maintenance

🧠 BeanFactory vs ApplicationContext — One Line

BeanFactory = Basic container, Lazy loading, No enterprise features, XML only.
ApplicationContext = Advanced container, Eager loading, Full enterprise features, XML + Annotations.

IoC Container Hierarchy — Very Important for Interviews
BeanFactory   (Interface — Root IoC Container)
▼ extends
ApplicationContext   (Interface — Extends BeanFactory)
▼ extends
ConfigurableApplicationContext   (Interface — Adds lifecycle methods)
▼ extends
AbstractApplicationContext   (Abstract Class — Partial implementation)
▼ extends
ClassPathXmlApplicationContext   (Concrete Class — Actual implementation)
Understanding Each Level
LevelTypePurpose / Key Methods
BeanFactory Interface Root IoC interface. Provides: Bean Creation, Retrieval, Lifecycle, Dependency Management. Key method: getBean()
ApplicationContext Interface Extends BeanFactory. Adds: Events, i18n, Annotations, Resource Loading. IS-A BeanFactory.
ConfigurableApplicationContext Interface Extends ApplicationContext. Adds lifecycle control methods: refresh() close() start() stop() registerShutdownHook()
AbstractApplicationContext Abstract Class Partial implementation. Reduces code duplication. Developers don't use it directly.
ClassPathXmlApplicationContext Concrete Class ✅ Actual class used by developers. Loads XML from classpath → Creates → Stores → Manages → Provides Beans.
🔄 Visual Flow — How It Works
beans.xml → ClassPathXmlApplicationContext → AbstractApplicationContext → ConfigurableApplicationContext → ApplicationContext → BeanFactory → Creates & Manages Beans ✅

Final Interview Answer
🎤 Expected Interview Answer

Spring provides two types of IoC Containers: BeanFactory and ApplicationContext. Both are interfaces. BeanFactory is the basic IoC container that provides bean creation, configuration, dependency management, and lifecycle management using lazy initialization. ApplicationContext extends BeanFactory and provides advanced enterprise features such as event handling, internationalization, annotation support, resource loading, and automatic bean processing using eager initialization. Configuration can be provided via XML or Annotations. Internally, the hierarchy is BeanFactory → ApplicationContext → ConfigurableApplicationContext → AbstractApplicationContext → ClassPathXmlApplicationContext, where ClassPathXmlApplicationContext is the concrete implementation commonly used to load XML configuration and create Spring beans.
