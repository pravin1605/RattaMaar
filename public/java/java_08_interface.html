Java - 08 Interface

Interface

  • An interface is a blueprint of a class. it tells a class what to do, but not how to do it
  • Interface is a collection of abstract methods and static, final variables that is used to achieve abstraction and multiple inheritence in Java

syntax

modifier interface InterfaceName { }

★ Where can we create interface ?

  • inside .Java File
    after compilation we get .class file with the name same as interface name.

★ Why Interface is used ?

① To achieve abstraction

② To support multiple inheritance

③ To define common behaviour for different classes

④ To achieve loose coupling

★ Members of interface

① Abstract Method (implicitly public and abstract)

② Variables in interface are implicitly public, static and Final

③ Default Methods introduced in Java 8

④ Static methods introduced in Java 8

⑤ Private Non-static method (Java 9 onwards)

⑥ private static method

public interface Demo_of_Interface { #==== Before Java 8 ==== // Variables is an interface are by default: // public, static and Final int x = 10 // Methods in an interface are by default: // public and abstract void m1(); #==== Java 8 Features ==== // Default method introduced in Java 8 // Uses 'default' keyword // Access modifier is public // Non-static (belongs to object) // can have method body default void m2() { //default implementation } // static method introduced in Java 8 // Belong to interface, not to implementing class object // Must be called using interface Name static void m3() { //static method implementation } #==== Java 9 Features ==== // private non-static method introduced in Java 9 // used to share common code inside interface // can be called only inside this interface private void m4() { // private helper method } // private static method introduced in Java 9 // used for code reusability inside interface // cannot be accessed outside the interface private static void m5() { // private static helper method } }

★ Not Allowed inside interface

① Instance variable [non static variables]

② constructors

③ Instance initializer blocks [non static blocks]

② Inside interface we cannot have constructor and initializer except single line static initializer

★ can We inherit interface

Yes, using implements keyword

interface parent { } class child implements parent { }

Multiple inheritance in Java

  • one child having more than one parent at same level
  • We can not achieve multiple inheritance using classes alone
  • When we want to achieve multiple inheritance we should make use of interface.

① Multiple inheritance using classes (Not allowed)

Because of Diamond problem
① Two parent classes may have same method
② child gets confused which one to call
③ constructor chaining becomes ambiguous

public class parent-1 { } Public class parent-2 { } class child extends parent-1, parent-2 //CTE { } //one class can extends only one class

② Class First extends class and implements interface

Diagram: Parent-1 (class) and Parent-2 (Interface); the child box has an "extends" arrow to Parent-1 and a dashed "implements" arrow to Parent-2.

Public class parent-1 { } Public interface parent-2 { } class child extends parent-1 implements parent-2 { //one class First extends, and then implements }

③ Class implements Multiple interface

  • one class can implements n number of interface.

Diagram: Parent-1 (interface) and Parent-2 (interface); child (class) has an "implements" arrow to each.

public interface parent-1 { } public interface parent-2 { } public class implements Parent-1, Parent-2 { }

④ Interface Extends Multiple Interface

Diagram: Parent-1 and Parent-2 (Interface); child (Interface) has an "extends" arrow to each.

public interface parent-1 { } public interface parent-2 { } interface child extends parent-1, Parent-2 { // one Interface can extends n number of interface }
  • Java does not support multiple inheritance using classes because of the Diamond problem, where ambiguity occurs in method and constructor inheritance. constructor chaining becomes impossible when multiple parent classes exist.
  • Java solve this problem using interface. Interface do not have constructor because they cannot create objects and they do not contain instance variable to initialize
    since interface only declare abstract method and constants there is no ambiguity. therefore multiple inheritance is achieved using interface.

⑤ Class + Interface Method conflict

class extends a parent class and implements an interface
Both have same method name.

class Parent-1 { Public void m1() { S.O.P.l("Parent-1 method"); } } Interface parent-2 { void m1(); } Public class child extends Parent-1 implements parent-2 { } Public class Driver { Public static void main(string[] args) { child c = new child(); c.m1(); S.O.P.l(c instanceof Parent-1) S.O.P.l(c instanceof Parent-2) S.O.P.l(c instanceof child) } } O/P Parent-1 method
only the first output line is written; the instanceof lines have no output written

In the above example

  • The child class extends parent-1
  • The child class implements parent-2

First the child class inherits from parent-1. parent-1 already has complete (concrete) method m1()
then child implements parent-2, which has an abstract method m1()
Normally when we implement an interface, we must provide implementation for its abstract methods
But here, we don't need to write m1() again in child

Why ?
Because
① The m1() method already inherited from parent-1 has the same method name and signature
② that inherited method automatically works as the implementation for the interface method

So
• No error
• No need to override again
• parent-1 m1() method will execute.

⑥ Default Method Ambiguity (Must Override)

Public interface parent-1 { default void m1() { S.O.P.l("parent-1 method"); } } Public interface parent-2 { default void m1() { S.O.P.l("Parent-2 method"); } } class childs implements parent-1, Parent-2 { Public void m1() { Parent-1.super.m1(); Parent-2.super.m1(); S.O.P.l("child method") } } Public class Driver { Public static void main(string[] args) { Parent-1 p = new child(); verify: class is named childs above P.m1() } }

In the above example
IF a child class has more than one parent interface, and both interface contain default methods with the same name, the child class must provide it's own implementation otherwise we get a compile-time error due to ambiguity

To access specific parent interface method, we can use

InterfaceName.super.methodName();

This can be used only inside the child class

⑦ static Methods in interface (Not inherited)

Public interface parent-1 { Public static void m1() { S.O.P.l("parent-1 static method"); } } Public interface parent-2 { Public static void m1() { S.O.P.l("Parent-2 static method"); } } class child implements parent-1, Parent-2 { } Public class Driver { Public static void main(string[] args) { Parent-1 p = new child(); p.m1(); //CTE (static method Not inherited) } }

★ We already know about static are not inherited
Because
① The main reason we have interface to achieve multiple inheritance
② IF we have more than one parent interface and if both the parent interfaces are having static methods, it may lead to ambigus state
③ IF it was default method we can avoid ambigious state using method overriding
But static method we can not override. so IF the static methods are inherited from interface to class again it leads to ambigus state
To avoid this Java developers did not allow static method to inherit from interface to class

★ what are inherited from interface to class

① static variable ② abstract method ③ default method

★ what are Not inherited from interface to class

① public static method ② private static method ③ private Non-static method

★ We already know about private methods are not inherited because they are accessible only within the class or within that interface.
