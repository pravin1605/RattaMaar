Java - 10 String

Strings

A string in Java is an immutable object that represent a sequence of characters and is implemented using the java.lang.string class

★ Properties

① Immutable - once string created, its value cannot be changed

② string is a class - string is built in class in Java.lang

③ Final class - The string class declared as Final, so it cannot be inherited

④ object based - every string in Java is an object

⑤ Thread safe

⑥ Immediate child of object class - The string class directly extends the object class

String Literal

  • In Java string literal is a group of character which is enclosed with " "
  • string literals in Java are stored using objects

There are 3 built in classes to store string literal
① java.lang.string
② java.lang.stringBuilder
③ java.lang.stringBuffer

① java.lang.string

  • string is a built in class which is present in Java.lang package
  • string class is declared as Final which means it can not be inherited
  • string class is immediate child class for object class

Case-I

string s = "abc"

Diagram: s holds 0x1 → String object 0x1 inside the string constant pool (SCP, in the Heap area). Inside it: arr = 0x2 → char[] object 0x2 holding 'a' 'b' 'c' (index 0, 1, 2), plus Method.

★ string constant pool (scp)
↳ scp is a special memory area inside the Heap area in Java where string literal objects are stored to avoid duplicate object and to improve memory efficiency

Case-II

string s1 = "abc" string s2 = "abc"

Diagram: both s1 and s2 hold 0x1, pointing to the same String object 0x1 (arr = 0x2) in the string constant pool.

Case-I explanation

① "abc" is a string literal
② Java checks the string constant pool (scp) too see if "abc" already exists
③ since this is the First time, "abc" is Not present
④ Java creates one object "abc" inside the scp
⑤ the reference variable s points to that object.

Case-II explanation

① "abc" is already present in the string constant pool
② Java does not create a new object
③ the reference variable s2 points to the same object that s1 is pointing to

★ string pool

IF the same literals appears again, no new object is created.
Java reuses the existing object to save memory
This process is called string pool

★ Note

  • string constant pool area is also present inside heap area
  • string object internally uses char array to store the group of character
  • after Java 9 version they started using byte[] array instead of character array to consume less memory space
  • since byte use only one byte - 8 bits and char uses 2 bytes - 16 bits

Comparison

① equals(string str)

  • is a method of the string class used to compare the data (values) of two string
  • It returns true if both string have the same sequence of characters
  • It returns False if the contents are different
  • It is case-sensitive
string s1 = "abc" string s2 = "abc" S.O.P.l(s1.equals(s2)); //true

② equalsIgnoreCase(string str)

  • is a method of the string class used to compare the contents of two strings without considering case (uppercase or lowercase)
  • Return true if both string have the same character ignoring case
  • Return False if the contents are different
string1.equalsIgnoreCase(string 2); string s1 = "abc" string s2 = "ABC" S.O.P.l(s1.equalsIgnoreCase(s2)); //True

③ compareTo(string str)

  • is a method of string class used to compare two strings lexicographically (dictionary order).
  • Return 0 → if both strings are equals
  • Return +ve value → IF the 1st string is greater than 2nd
  • Return -ve value → IF the 1st string is smaller than 2nd
  • It is case-sensitive
string1.compareTo(string 2); string s1 = "apple" string s2 = "banana" S.O.P.l(s1.compareTo(s2)); //-1 • a in "apple" → ASCII 97 • b in "banana" → ASCII 98 97-98 = -1

s1 == s2 → 0  |  s1 < s2 → Negative  |  s1 > s2 → Positive

④ compareToIgnoreCase(string str)

  • is a method of the string class used to compare two strings lexicographically without considering case (uppercase or lowercase)
string1.compareToIgnoreCase(string 2) string s1 = "apple" string s2 = "BANANA" S.O.P.l(s1.compareToIgnoreCase(s2)); //-1

Java.lang.stringBuffer

  • stringBuffer is a built in class present in Java.lang
  • string Buffer is mutable sequence of character
  • A stringBuffer is same like a string but can be modified without creating any de-referenced objects
  • stringBuffer class is Final and cannot be inherited
  • stringBuffer class is also immediate child class of object class
  • stringBuffer objects can be created only by using New operator
stringBuffer sb = "abc" //CTE stringBuffer sb = new stringBuffer()

IMP constructors

① stringBuffer() - creates a stringBuffer object with capacity 16
② stringBuffer(string s) - Creates a stringBuffer object with capacity 16+stringLength
③ stringBuffer(int capacity) - creates a stringBuffer object with given capacity

★ append() Method

append() is a method of stringBuffer class used to add (concatenate) data at the end of the existing string

  • It modify the same object
  • It return the same stringBuffer object for chaining

stringBufferObject.append(value);

  • In the above example we created a stringBuffer object which internally creates an array of capacity 16
  • IF we try to append more than 16 character into that stringBuffer, it internally creates a new array with the bigger capacity using the following formula

Formula for new capacity

New capacity = (old capacity * 2) + 2

  • after creating the new array entire data from the old array will be copied into the new array in the corresponding indexes
  • after copying the data into new array the old array will be dereferenced and the new array address will be stored inside the stringBuffer object

Note

  • concatenation operation by using + operator is not possible in string Buffer
  • Any modification to stringBuffer can be done only by using methods of stringBuffer class
  • the only way to concatenate stringBuffer is by using append() present in string Buffer class
  • append method is overloaded in such a way that it accept all datatypes as formal argument
Public class Democomparing { Public static void main(string[] args) { stringBuffer sb1 = new stringBuffer("abcd"); //20 stringBuffer sb2 = new stringBuffer("abcd"); //20 S.O.P.l(sb1) } both have same data but different address S.O.P.l(sb2) //It compare address S.O.P.l(sb1 == sb2) //False //equals is not overridden, so compare address S.O.P.l(sb1.equals(sb2)); //converting stringBuffer into a string to compare string s1 = sb1.toString() string s2 = sb2.toString() S.O.P.l(s1.equals(s2)); //or we can directly compare S.O.P.l(sb1.toString().equals(sb2.toString())); } }
