Non-static Part

① Non-static Variables

[properties or fields or data member or attribute]

  • A variable created inside the class body without using static keyword is known as non-static variable
  • Whenever an object of a class is created (and stored) using the New keyword, a separate copy of the non-static variable is created and stored in memory for that object.
  • Becoz each object has its own copy, changes made to a non-static variable through one object do not affect the same variable in another object

characteristics

① they represent the data member of a real world object

② Memory is allocated inside the object

③ We cannot use the non static variables without object of the class

④ Non static variables will be allocated once in every object

⑤ Non static variables are initialized with default values during the object creation

⑥ We can use non-static variable only with the help of reference of an object

⑦ cannot be accessed from static context directly
  A static method must use an object to access non-static

② Non-static Method

  • A method which is created without using static keyword and belongs to object is known as non-static method
  • Non static represent action or behaviors of an object
  • Inside non static method we can access data member of an object and perform operation on the data (data member = Non-static variable)

characteristics

① Non static method is allocated inside the object

② We cannot call or use a non static method without creating an object

③ The only way to access non-static method is by using object reference

④ Non static method will get memory allocation inside every object created of that class

⑤ The body of the non static method is called as non static context

⑥ Non-static methods can access static members Directly

why

  • static members belong to the class
  • Non-static methods run inside an object, but they still know the class
  • so Java allows direct access to static members from non-static methods
class Demo { static int count = 10; //static variable static void showCount() //static method { System.out.println("static method = " + count); } void display() //Non-static method { System.out.println("Non-static method = " + count); showCount(); //access static members } public static void main(String[] args) { Demo d = new Demo(); d.display(); } } output Non-static method = 10 static method = 10

⑦ Inside non-static context we can access Non-static members without using object address verify: "Non-" written above "static"

public class mobile { string brand; int Ram; public void display details() { System.out.println(brand); System.out.println(RAM); } }

Constructor chaining

  • one constructor calling another constructor is known as constructor chaining

Why

  • To avoid code duplication
  • To Use initialization logic.
Constructor Chaining
Same class → using this()
parent class → using super()

Rules

① this () can be used inside the constructor body

② this() should be first statement inside constructor body

③ Recursive call to this() Not allowed

Public class student { int id; string name; Float cgpa; double Fees; public void Display() { S.O.P.l(id) S.O.P.l(name) S.O.P.l(cgpa) S.O.P.l(fees) } student(int id, string name, Float cgpa, double Fees) { this(id, name, cgpa); //calls constructor below this.Fees = Fees; } student(int id, string name, Float cgpa) { this(id, name) //calls constructor below this.cgpa = cgpa } student(int id, string name) { this(id) //calls constructor below this.name = name } student(int id) { this.id = id } }

(In the notes, arrows show each this(...) call jumping down to the next constructor, and after it finishes, control returns to the line after the call, back up the chain.)

Non-static initializer

A single or multi line instruction which gets executed during object creation

characteristics

① Non-static initializer get executed automatically during the object creation

② Non-static initializer get executed once for every object created

Note

IF there are more than one non-static initializer they get executed in a top to bottom order during object creation

Public class Demo { int x = 1000; //single line non-static initializer { x = 25; } Demo() { System.out.println("executing constructor"); } public static void main(String[] args) { Demo d1 = new Demo(); System.out.println(d1.x) } } O/P executing constructor 25
  • We can use display statements inside a constructor, becoz a constructor can contain any valid Java statement
  • However it is not recommended, since the main purpose of a constructor is to initialize object data, not to display it
  • Display logic should be placed in separate method.
class Test { { System.out.println("Non-static initializer") } Test() { System.out.println("constructor"); } public static void main(String[] args) { Test t1 = new Test(); Test t2 = new Test(); } } O/P Non-static initializer constructor Non-static initializer constructor

When we are creating the object what will be the Flow of execution

1st - New operator will allocate block of memory

2nd - And calls the constructor

3rd - constructor will load all the non-static member

4th - After loading first non-static initializer will get executed from top to bottom order

5th - and then constructor body will get executed

6th - AND then new operator will return the address

Class Loading

  • class loading is the process of loading a .class File from hard disk into the JRE memory (method area) inside the RAM
  • Class Loading
    • Loading → .class File → Method Area
    • Linking
      • Verification → checks bytecode for correctness and security
      • preparation → Allocates memory for static variables; Assigns default values
      • Resolution → converts symbolic reference into direct reference
    • Initialization → static variables initialized; static blocks executed.

Memory Partitions

  • JRE divides memory into different areas, and each area has a specific responsibility

① Static pool area
static pool area is the memory area used to store all static members of a class

② Method area
Method area is the memory area where the complete class structure and bytecode are stored

③ Stack Area
stack area is the memory area where method execution takes place

④ Heap area
Heap area is the memory area where all objects and instance variables are stored.

  • static variables belongs to the class, not to individual object. only one copy of a static variable is created in memory when the class is loaded

  • As a result updated value becomes visible to all other objects of the same class
