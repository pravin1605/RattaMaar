Encapsulation

  • The process of wrapping properties and behaviours of an object together is called as encapsulation
  • encapsulation specifies us that make the data member as private to provide security to data

Advantage

① Data hiding
Data hiding is the process of restricting the direct access to the properties of the object and providing controlled and restricted access to the properties of the object
We can provide the controlled access using getter and setter method

② Verification
Verification is the process of checking whether the input value given to a class variable is correct and acceptable before it is stored in the object

③ Validation
Validation is the process of ensuring that the data stored inside an object follows all required rules and remains logically correct throughout the program execution

getter Method

  • Method which is used to fetch the data which is having private access modifier is called as getter method

Syntax

  • Access modifier will be public always
  • return type should be same as the variable data type
  • and the name of the method follows some naming conventions
    • IF the variable name is id, method name will be getId();
  • getter methods are also called as accessors

Setter Method

  • Method which is used to modify the data which is having private access modifier is called as setter method
  • setter methods are also called as modifiers

syntax

① Access modifier will be public always

② return type will be void

③ And name of the method follow some naming convention
  If the variable name is id, method name will be setId(formal arg);
  Formal arg data type should be same as type of variable.

Has-A

Has-a relationship is an association betn two classes, where one class contain an object of another class as a data member

Simple words

  • one object uses another object
  • No inheritance involved.

Why Has-A Relationship is Needed ?

① To reuse functionality

② To model real-world relationship

③ To reduce tight coupling

④ To achieve modular design

How can we achieve Has-A betn two classes?

  • Inside one class create a non-static variable of other class type (which can store other class object address)
  • The object in which we are storing the reference of other object is called as depending object or container object.
  • The object whose reference is stored in depending object class as dependent object or containment object.

  • Inheritance in Java is a mechanism in which one class acquires all the properties and behaviours of a other class

child class | sub class | derived class

A class which acquires or inherits properties and behaviours from the other class is called as derived class or child class or sub class

parent class or super class | base class

A class from where a subclass inherits the feature. It is also called a base class or a parent class

Object loading with inheritance

  • whenever we create object of child class, the child class constructor will call the parent class constructor using super() to load non-static member of the parent class into the child class object.
  • so whenever you create an instance of the child, the constructor of child as well as constructor of parent gets executed.

Super()

  • super() is used to achieve constructor chaining betn parent and child class.
  • super() is a statement which is used to call the immediate parent class constructor
  • super() calls the parent class constructor and parent class constructor will load and initialize the parent non-static member into child class object.

characteristics

① super() can be written only inside the constructor body

② super() should be the First instruction inside the constructor body.

③ only one super() can be used inside one constructor

④ this() and super() can not be used in the same constructor

Public class parent { int x; parent() { S.O.P.l("creating instance of Parent."); } } Public class child extends parent { int y; child() { super(); //compiler will add implicitly even if u Don't write S.O.P.l("creating instance of child"); } } Public class Driver { public static void main(string[] args) { child c = new child(); } } O/P creating instance of parent creating instance of child

Note

compiler will add super() implicitly if and only if parent constructor is No-argument constructor

  • A child having more than one parent at same level is known as multiple inheritance

Diamond problem

the ambiguity in multiple inheritance, which arises when a super class member is being accessed from a child class

  • IF we don't have any member in both the parent classes still the problem of Diamond arises
    Because every class contain default constructor and child class will get super() by the compiler after the compilation
    so the super() inside the child class will get confused to call which parent class constructor.
    that is why multiple inheritance is not possible in Java using classes alone
class parent_1 { parent_1() //constructor { } } class parent_2 { parent_2() //constructor { } } class child { child() { super() //ambigious State } }

  • hybrid inheritance include multiple inheritance, Hence we can not achieve hybrid inheritance with the help of class.

Non-Primitive Type Casting

★ Non-Primitive Type Casting

  • The process of converting one non primitive Data type into other non-primitive Data type is called as derived type casting or non-primitive type casting
    OR
  • Non-primitive type casting is the process of converting the type of reference from one non-primitive type into other non-primitive type

When non-primitive typecasting can be achieved?
We can achieve non-primitive type casting if and only if there Is-A relationship betn the classes

Note

We can also convert from one parent to other parent type if both the parents are having common child. (multiple inheritance)

Types

① upcasting (implicitly and explicitly)
② Down casting (explicitly)

① UPCASTING

  • The process of converting sub class type reference to super class type reference is called as upcasting
class Parent { } class Child extends Parent { } public class Derived { public static void main(String[] args) { Parent p = new Child(); // upcasting } } ← create object of Child class, give reference variable of Parent class.

How to achieve upcasting?

① Implicitly can be done automatically by the compiler

Parent p = new Child();

② explicitly can be done by the programmer using typecast operator

Parent p = (Parent) new Child();

Important Note

After upcasting we can not use the member of child class with upcasted reference variable

Purpose

① Generalisation ② Runtime polymorphism

class Parent { void show() { System.out.println("Parent method"); } } class Child extends Parent { void display() { System.out.println("Child method"); } } public class Driver { public static void main(String[] args) { Parent p = new Child(); // upcasting p.show(); // p.display(); → CTE → Not allowed } }

Downcasting

  • the process of converting reference type from Parent type to child type is known as downcasting.
  • Downcasting can only be done by explicitly by programmer
  • We can perform downcasting explicitly by using typecast operator

syntax

(TargetType) obj_ref;

Purpose of Downcasting

  • In an upcasted scenario if I want to access member of child, downcasting is necessary
  • Without downcasting we cannot access member of child
class Parent { void show() { System.out.println("Parent method"); } } class Child extends Parent { void display() { System.out.println("Child method"); } } public class Driver { public static void main(String[] args) { Parent p = new Child(); // upcasting Child c = (Child) p; // Downcasting c.display(); } }

ClassCast Exception

  • It is an exception which might occur while downcasting
  • When we try to downcast a reference to a subclass type, but the object doesn't contain instance of that subclass then we get classcast exception
class Parent { } class Child extends Parent { } public class Driver { public static void main(String[] args) { Parent p = new Parent(); // parent object Child c = (Child) p; // Runtime error: ClassCastException } }

why error: object created Parent, Trying to convert it into Child

Instance of operator

  • It is used to check whether the object contains the instance [object] of particular class or not
  • IF the object contains instance of the particular class then it return true
  • IF the object doesn't contain instance of the particular class then it returns False

syntax

obj_ref instanceof ClassName

How to Avoid classCast Exception

  • Use instanceof
public class Driver { public static void main(String[] args) { Parent p = new Parent(); if (p instanceof Child) { Child c = (Child) p; } else { System.out.println("Downcasting Not possible"); } } }

★ Method overriding

  • The process of providing new implementation to the Parent class method in the child class known as method overriding
  • Method overriding allows a same method name and parameters but different class

Rules to achieve method overriding

① create a method in subclass whose declaration should be same as in parent class

② Access modifier of overriding method [child class] should be either same or higher than visibility of overriden method [parent class]

③ Inheritance is mandatory

④ Method must Not be static

⑤ Method must Not be final

⑥ Method must Not be private

⑦ Runtime polymorphism required

@override annotation

  • It is used to compare method declaration of sub class with method declaration of super class by the compiler
  • IF there is no matching declaration found by the compiler it gives compile time error
  • we can override only non-static method

Example-01

Public class GrandParent { Public void m1() //Method to be overridden { S.O.P.l("GrandParent method"); } } Public class parent extends Grandparent { @override Public void m1() //overriding Grandparent's m1 { S.O.P.l("parent method"); } } Public child extends parent { @override Public void m1() //overriding Parent's m1() { S.O.P.l("executing child m1"); } } Public class Driver { Public static void main(string[] args) { Grandparent gp1 = new Grandparent(); gp1.m1() Grandparent gp2 = new Grandparent(); verify: output suggests new Parent() gp2.m1(); Grandparent gp3 = new child(); gp3.m1(); } } O/P GrandParent method Parent method executing child m1

Example-02

Public class WhatsAPP_1 { Public void sendMessage() { S.O.P.l("V-1"); } Public void calls() { S.O.P.l("C-1"); } } Public class whatsAPP_2 extends whatsAPP-1 { Public void sendMessage() { super.sendMessage() S.O.P.l("V-2"); } Public void calls() { super.calls() S.O.P.l("C-2"); } } Public class whatsAPP_3 extends whatsAPP-2 { Public void sendMessage { super.sendMessage() S.O.P.l("V-3"); } Public void calls() { super.calls() S.O.P.l("C-3"); } } Public class Driver { Public static void main(string[] args) { WhatsAPP_1 obj = new whatsAPP_3 //upcasting obj.sendMessage(); obj.calls(); } } O/P V1 V2 V3 C1 C2 C3

This code shows method overriding using multilevel inheritance. Even though the reference is of WhatsApp-1, the methods of WhatsApp-3 run at runtime using super.

  • It is Not overriding
  • Methods call depends on reference, Not object type

Polymorphism

  • polymorphism means "one name, many forms" where the same method behaves differently based on the object.
  • the ability of an object to exhibit multiple behaviours with same name is known as polymorphism

★ Types of polymorphism

① compile time polymorphism | static binding

② runtime polymorphism | dynamic binding

① compile Time polymorphism

(static binding | early binding)

  • the process of binding method call statement with method defintion during compile time by the compiler by looking at formal argument and actual argument is known as compile time polymorphism

Ex ① Method overloading ② constructor overloading ③ Method shadowing ④ variable shadowing

② Runtime polymorphism

(dynamic method dispatch or dynamic binding | late binding | Non-static binding)

  • The process of binding method call statement with method definition during run time by the JVM based on the object created is known as runtime polymorphism
  • since the binding is done during the execution it is called late binding
  • once the binding is done during compile time by the compiler, later it can be changed by the JVM during runtime so it is also called as runtime binding

Ex ① Method overriding

Concrete class

  • A concrete class is a normal class that has a complete implementation and can be used to create objects
  • It is Not abstract
  • All methods must have method bodies
  • we can create objects using New
  • It can extend an abstract class or implement an interface (but must implement all methods)

syntax

Class className { // Variables // concrete methods }

Concrete Method

  • A concrete method is a method that has a body (implementation)
  • It contains method logic
  • can be inside ① concrete class ② Abstract class

syntax

returnType methodName(parameters) { // method body (logic) }
Class student { int id void display() { S.O.P.l('concrete method') } }

student is a concrete class which contain concrete method.

Abstraction

  • The process of Hiding the implementation and providing the functionality to the user is known as abstraction

How can we achieve abstraction

  • using abstract methods

Abstract component

A component which is not full or incomplete can be considered as abstract component ① abstract class ② interface

Abstract method

  • A method which doesn't have implementation [incomplete] and prefixed with abstract keyword is known as abstract method

syntax

modifier abstract return-type method name(formal-arg); public abstract void add(int x, int y)

Note

① We cannot execute abstract method
② We can create abstract methods inside abstract class or interface

Abstract class

  • A class which is declared by using abstract keyword is called as abstract class

syntax

public abstract class Demo { //abstract method //concrete method }

Characteristics

① It can have both abstract and concrete methods

② For abstract class we can not create the object

③ If a class has at least one abstract method, the class must be abstract

④ child class must implement all abstract methods

⑤ can have constructors

⑥ can have instance and static variable

⑦ supports inheritance

⑧ cannot be final Because final classes cannot be inherited

Note

① It is not mandatory to create abstract method inside abstract class.

② We can make non-static method as abstract but we cannot make static method as abstract

Can we inherit abstract class ?

Yes
When we inherit abstract class the abstract method also gets inherited so the subclass is also having one abstract method.
since the child class is concrete class it cannot have abstract method so we get compile time error

Public abstract class Demo //abstract class { //abstract method Public abstract void m1(); } Public class Demo-2 extends Demo //CTE { }

In this case we can do any one of the following things ① make subclass as abstract ② we can override inherited abstract method

① We can make subclass as abstract

Public abstract class Demo-2 extends Demo { }

② We can override inherited abstract method, means we can provide implementation to the inherited abstract method

Public class Demo-2 extends Demo { @override Public void m1() { S.O.P.l("Implementation of abstract method"); } }

steps to achieve abstraction using abstract class

① create an abstract class with abstract method

② provide implementation to the abstract methods by creating a child class by method overriding

③ create the object of child class and store it in a variable of type parent. (upcasting)

④ using upcasted variable call the abstract method

★ During compile time method call statement will be bound with abstract method present in parent class i.e (abstract class) [compile time binding]

★ During run time method call statement will be rebound with child class method definition based on the object created [run time binding]

Final keyword

  • It is a non access modifier which is available in the form of keyword in Java
  • It can be used in the declaration of ① Variable ② Method ③ class

Final variable

when a variable is declared using Final we can not re-initialize it's value

Public class Demo { Final int x = 10 Public static void main(string[] args) { Demo obj = new Demo(); // obj.x = 12 → CTE } }

Final method

When a method is declared using Final keyword it can not be overridden by it's child classes

class parent { Public Final void m1() { S.O.P.l("parent m1"); } } class child extends parent { Public void m1() → //CTE //can not be override { S.O.P.l("parent m1"); } }

Final class

When a class is declared using Final it can not be inherited to other classes.
Which means Final class can not have child class

Final class parent { } class child extends parent → //CTE { }
