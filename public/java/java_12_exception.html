Termination

  • Termination is the process of stopping a program after the main() method finishes execution normally or when it stop due to an error

Types of termination

① Normal termination   ② Forced termination   ③ Abrupt termination

① Normal termination

  • when entire program executes successfully till the last instruction then we say it is normal termination
Public class Normal_termination { Public static void main(string[] args) { S.O.P.l("main started") S.O.P.l("main ended") } } O/P main started main ended

② Forced Termination

  • Forced termination means stopping a Java program manually before it finishes executing all statements when system.exit(0)
  • The JVM stop running the program immediately
  • All currently running threads are terminated
  • Remaining statements after system.exit() are ignored
  • control returns to the operating system

so the program ends instantly

Public class Forced-termination { Public static void main(string[] args) { S.O.P.l("main started") system.exit(0); S.O.P.l("main end") } } O/P main started

③ Abrupt Termination

  • Abrupt termination means suddenly stopping the normal flow of program execution before reaching the expected end of a block or statement

Exception

  • It is an unexpected event or a problem that occur during the execution of a program and disturbs the normal flow of the program.
  • when an exception occurs program execution will be abruptly terminated from the line where exception occurred [if not handled]

  • Program will be abruptly terminated only if exception is not handled when it occured

What exactly happens when an exception occur in Java?

Public class Demo { Public static void main(string[] args) { S.O.P.l("main started"); S.O.P.l(10/0); → JVM creates ArithmeticException object (0x1) S.O.P.l("main ended"); } }
  • When an exception occurs, one object of appropriate exception type will be created
  • That object contains instance of Throwable class
  • That object contains the details of exception, like line number at which the the exception occurred the method name and the class name and it also contains the reason for the exception
  • This process is called as raising an exception
  • once the exception is raised or occured JVM will check if the exception is handle or not
  • IF exception is handled program execution will be continued
  • IF the exception is not handled program execution will be abruptly stopped from the line where exception occured and default exception handler will call printstackTrace() method
  • what ever exception message we are seeing on the console is just because of the printstackTrace()

Exception handling

In Java exception are handled by using try-catch block

syntax

try { //instruction which may give exception } catch(Exception-name Variable) { //handler }
  • We use try block block to write the instruction which may cause exception
  • catch block is used to handle the exception if occured
  • IF any exception occurs in any line inside try block, control will directly go to catch block without executing further instructions inside try block.
  • IF the catch block is able to handle the exception occurred catch block will get executed without abrupt termination
  • IF no exception occurs in try block, try block will be completely executed and catch block will never get executed

Note

  • We can use n number of catch blocks along with one try block
try { } catch(Exception_name variable_name) { } catch(Exception_name variable_name) { }
  • IF 2 or more catch blocks are defined and exception occurred control will go to the First catch block which can handle the occurred Exception
Public class Demo { Public static void main(string[] args) { S.O.P.l("main started ") try { S.O.P.l("try started "); S.O.P.l(10/0); // ArithmeticException S.O.P.l("Hello"); ✗ S.O.P.l("try ended"); ✗ } catch(ArithmeticException exp) { S.O.P.l("catch started") S.O.P.l("exception handled"); S.O.P.l("catch ended") } S.O.P.l("main ended"); } } O/P main started try started catch started exception handled catch ended main ended

Try-catch Finally

syntax-01

try { //Instruction which many give exception } catch(Exception-name variable) { //handler code } finally { //always execute; }
  • IF exception occurs in try block
    • First catch block will be executed if that catch block is able to handle occurred exception and then finally will be executed
    • IF the catch block is not able to handle code or the exception occured even though it is not handled finally block will get executed.
  • IF exception doesn't occurs in try block
    • catch block will never executed
    • only finally will be executed

syntax-02

try { //Instruction which may give exception } finally { //always executes }

We can use finally along with try block without using catch block.

Exception object propagation

  • when an exception occurs in a method body the JVM looks For the handler code in the same method body
  • IF the handler code is not Found in the same method body the execution object propagates to caller method searching For the handler
  • IF the handler is Found in the caller method the JVM execute the handler code and continues program execution from caller method this process continues until the handler is Found somewhere in the entire stack
  • IF the handler is not present in the stack the JVM unwinds the stack and stops execution this known as stack unwinding
  • after unwinding the stack default exception handler calls the printstackTrace() this method printstackTrace() prints all data releated to exception

Definition

The moment of exception object from the current method to its caller when exception occurred and not handled is known as exception object propogation

Public class Driver { Public static void main(string[] args) { S.O.P.l("main start ") m1(); S.O.P.l("main end "). } Public static void m1() { S.O.P.l("m1 start") m2(); S.O.P.l("m1 end") } Public static void m2() { S.O.P.l("m2 start") m3() S.O.P.l("m2 end") } Public static void m3() { S.O.P.l("m3 start") S.O.P.l(10/0); //ArithmeticException S.O.P.l("m3 end") } } O/P main start m1 start m2 start m3 start Exception -

Diagram: the stack holds main, m1(), m2() and m3() frames (m3 on top, "m3 started (10/0)"). The JVM creates an ArithmeticException object (0x1) and searches for a handler in m3, then m2, then m1, then main; with none found, the JVM calls the Default Exception handler, which calls printStackTrace().

Types of Exception

  • checked Exception
  • unchecked Exception

① Unchecked exception

  • unchecked exception are the exceptions which are not identified by the compiler
  • All the subclasses to the RuntimeExceptions class are unchecked exception

② Checked Exception

  • The exceptions which are identified by the compiler during compilation are checked exceptions
  • IF compiler identifies any checked exceptions we get compile time error
  • until we write the handler code this CTE will not be gone
  • All exception classes except RuntimeException hierarchy comes under checked exception
  • they are identified during compile time, but occurs during runtime only
Public class Demo { Public static void main(string[] args) { system.out.println("main start") File F = new File("c:\basic"); //this instruction may throw IOException //since it throw IOException which is checked exception //we get CTE //we must and should handle this using try-catch block F.createNewFile() //CTE S.O.P.l("main end") } }

After writing handler code

Public class Demo { Public static void main(string[] args) { File F = new file("c\basic"); try { F.createNewFile(); } catch(IOException e) { } } }

Note

  • Always Exception occurs during runtime only
  • checked Exception are not propogated automatically to the caller method
  • only unchecked exception are propogated automatically

Throws

  • Throws is a declaration keyword used in the method declaration or constructor declaration
  • It is used to propogate the exception object from called method to caller method
  • It specifies that the checked exception may occur in the current method body is not handled it must be handled in the caller method
Public class Driver { Public static void main(string[] args) throws IOException { S.O.P.l("main start") m1() S.O.P.l("main end") } Public static void m1() throws IOException { S.O.P.l("m1 start") m2() S.O.P.l("m1 end") } Public static void m2() throws IOException { S.O.P.l("m2 start") m3() S.O.P.l("m2 end") } Public static void m3() throws IOException { S.O.P.l("m3 start") File f = new File("c:\basic") F.createNewFile(); S.O.P.l("m3 end") } }

Custom Exception

  • It is also called user defined exception
  • Exception which are created by the programmer is known as user defined exception
  • In Java we can create user defined exception objects by using throw keyword

Throw

  • Throw is a keyword which is used to create and rise custom exception object.
  • Throw keyword can be used only inside blocks
  • By using throw keyword we can throw checked exception, unchecked exception and custom exception

syntax

throw ThrowableType object;

example

throw new ArithmeticException

Steps to create custom exception

  • create a class and inherit any class which is throwable type
  • create the object of that class and use throw keyword to throw the object
  • to display the reason for exception if not handled we can create a parameterized constructor which accepts String message inside the custom exception class and using super() we can call pass this message to throwable class
  • using throw keyword we can throw only throwable type objects
Public class IneligibleToVote extends RuntimeException { Public IneligibleToVote(string msg) { super(msg) } } Public class Driver { Public static void main(string[] args) throws IneligibleToVote { Scanner sc = new scanner(system.in) S.O.P.l("enter your age "); int age = sc.nextInt() IF(age <= 18) verify: 18 is eligible in the chapter 03 voting example { throw new IneligibleToVote("you are not eligible") } else { S.O.P.l("eligible for voting") } } }

Imp Point.

1) The Exception and throwable classes are partially checked and partially unchecked, even though compiler will consider them as checked exception only

2) IF we are creating custom exception class by inheriting checked exception or Partially checked exception, the custom exception also will be considered as checked exception by the compiler.

3) IF we trying to throw the custom exception which is considered as checked exception we have to either handle it or propogate it by using throws keyword. it works same like checked exception
