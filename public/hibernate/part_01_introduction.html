📘 1. Introduction to Hibernate

Hibernate is a framework that provides an abstraction layer.

That means: Programmer does not need to worry about internal implementation details.

🔹 Hibernate internally handles:
  • Establishing database connection
  • Writing SQL queries
  • Performing CRUD operations
  • Managing transactions
  • Mapping Java objects with database tables
  • Auto DDL operations (CREATE, ALTER, DROP)

👉 So developer can focus mainly on business logic.

Hibernate is a Java ORM framework that provides an abstraction layer over JDBC. It internally handles DB connections, SQL generation, CRUD operations, transactions, and Java-to-table mapping — allowing developers to focus only on business logic.
📘 2. Simple Definition of Hibernate

Hibernate is a Java framework used to develop: Persistence Logic

🔹 What is Persistence Logic?

Persistence means: Storing data permanently for long-term use.

Example:

  • Saving employee details
  • Saving banking records
  • Saving student information

Data is stored inside database for future use.

🔹 Another Simple Definition — Hibernate is an:
Open Source

Source code freely available. No license fees. Can use, modify, improve.

Lightweight

Less memory. Less resources. Easy to integrate. Not heavy like enterprise servers.

Non-Invasive

Classes loosely coupled with Hibernate API. No need to extend/implement Hibernate classes.

ORM Framework

Object Relational Mapping. Maps Java objects to DB tables automatically.

Hibernate is an Open Source, Lightweight, Non-Invasive ORM Framework for Java. Open Source = free to use/modify. Lightweight = low resource usage. Non-Invasive = POJO classes, no forced inheritance. ORM = maps Java classes to DB tables.
📘 3. ORM — Object Relational Mapping (Core Concept)

ORM means: Object Relational Mapping

Hibernate maps:

Java Side (Object) Database Side (Relational)
Class Table
Object (instance) Row (record)
Variable (field) Column
Data Type (int, String) SQL Type (INT, VARCHAR)
🔹 Example — ORM in Action

Java Object:

Student s = new Student(); s.setId(1); s.setName("Pravin");

Database Table (auto-mapped):

idname
1Pravin

👉 Hibernate automatically maps both. No manual SQL INSERT needed.

ORM (Object Relational Mapping) is the core concept of Hibernate. It maps Java Class → DB Table, Object → Row, Variable → Column. Hibernate automatically generates the SQL INSERT/SELECT/UPDATE/DELETE based on the Java object state — developer never writes SQL manually.
📘 4. Non-Invasive Nature of Hibernate

Non-invasive means: Hibernate classes are loosely coupled with Hibernate API.

That means:

  • Our class does NOT need to implement Hibernate interfaces
  • Our class does NOT need to extend Hibernate classes

We can create normal Java classes (POJO classes).

Simple POJO — becomes Hibernate Entity:

public class Student { private int id; private String name; // getters and setters }

This simple class can become Hibernate entity class. No need to extend Hibernate class. That is called: Non-Invasive Nature

POJO = Plain Old Java Object
  • Simple Java class
  • No extends (no parent framework class)
  • No implements (no framework interface)
  • Has private fields
  • Has public getters/setters
  • Optional: no-arg constructor
Hibernate is non-invasive because entity classes are plain POJO classes — they don't need to extend HibernateEntity or implement any Hibernate interface. Hibernate uses annotations or XML to map the class to a table without polluting the class hierarchy.
📘 5. Who Invented Hibernate?

Hibernate was invented by: Gavin King in 2001.

He also invented:

  • JBoss Server
  • JPA (Java Persistence API)
📝 JPA vs Hibernate:
JPA (Java Persistence API) is a specification/standard defined by Java EE — it defines the rules and interfaces.
Hibernate is an implementation of JPA — it provides the actual working code behind the JPA interfaces.
👉 JPA = rules | Hibernate = implementation of those rules. Hibernate can also be used without JPA.

🔹 Flow Explanation:

Developer creates/saves Java object (e.g. Student object)

Session is the main interface to interact with Hibernate. Like Connection in JDBC. Used to save/get/delete objects.

Hibernate internally generates the correct SQL (INSERT/SELECT etc.) — developer never writes SQL.

Hibernate sits on top of JDBC. Developer uses Hibernate Session API → Hibernate generates SQL → passes to JDBC Driver → DB executes. Developer never writes SQL or manages connections manually.
📘 7. Functionalities Supported by Hibernate (9 Features)
🔹 1. Auto DDL Operations

DDL means: Data Definition Language. Commands: CREATE, ALTER, DROP

In JDBC — Manual:

create table employee( id int, name varchar(30) );

In Hibernate — Automatic:

// Just configure hbm2ddl.auto=create // Hibernate auto-creates table from class @Entity public class Employee { ... }

Hibernate automatically: create / drop / alter table internally.

Real-Life: Without Hibernate → Developer manually creates furniture. With Hibernate → Machine automatically creates furniture.

🔹 2. Auto Primary Key Generation

In JDBC — Manual ID:

insert into employee values(101, 'Pravin');

In Hibernate — Auto ID:

@GeneratedValue private int id;

Hibernate automatically generates: 1, 2, 3, 4 ... internally.

🔹 3. Database Independent

Hibernate supports: HQL (Hibernate Query Language) — database independent.

// HQL — works on all DBs from Employee

Works for: PostgreSQL, MySQL, Oracle. No need to change query.

// SQL — DB specific SELECT * FROM employee; // MySQL SELECT * FROM employee; // PostgreSQL // May differ for Oracle etc.
🔹 4. Exception Handling Not Mandatory

JDBC — Mandatory try-catch:

try { // DB code } catch(SQLException e) { e.printStackTrace(); }

Hibernate — Unchecked exceptions:

// No mandatory try-catch // Hibernate uses Runtime/Unchecked // exceptions → code is cleaner session.save(employee);

👉 Hibernate mainly uses unchecked exceptions → code becomes cleaner.

🔹 5. Hibernate Supports Cache Memory

Hibernate supports: Cache Memory. JDBC does not support caching directly.

What is Cache?

Cache stores frequently used data temporarily. So repeated database calls reduce.

  • faster execution
  • better performance
Real-Life Example:

Suppose you daily search same book in library. Instead of going library every time, you keep copy near you. That copy is: Cache

Hibernate has L1 Cache (Session level) and L2 Cache (SessionFactory level).

📘 7. Functionalities Supported by Hibernate (Continued)
🔹 6. Hibernate Supports ORM
JDBC works with:
  • Primitive values
  • Rows and columns
  • ResultSet → manual data extraction
  • Developer maps column → variable manually
Hibernate works with:
  • Java objects (POJOs)
  • No ResultSet iteration needed
  • Auto mapping: column → field
  • Get complete object back from DB
// JDBC way — manual mapping ResultSet rs = stmt.executeQuery("SELECT * FROM student"); Student s = new Student(); s.setId(rs.getInt(1)); s.setName(rs.getString(2)); // Hibernate way — auto mapping Student s = session.get(Student.class, 1); // complete object — auto mapped!
🔹 7. Hibernate Supports Inheritance, Associations, Collections
Inheritance

Hibernate maps Java inheritance hierarchy to DB tables automatically. Strategies: SINGLE_TABLE, TABLE_PER_CLASS, JOINED.

Associations (Relationships)
  • @OneToOne
  • @OneToMany
  • @ManyToOne
  • @ManyToMany

One student → Many courses
One customer → Many orders

Collections

Hibernate supports mapping Java collections (List, Set, Map) to DB tables automatically.

E.g. List of phone numbers mapped to a separate table.

🔹 8. Hibernate Supports HQL (Hibernate Query Language)

Hibernate has its own query language: HQL (Hibernate Query Language)

It is: database independent + object oriented

// HQL — object oriented from Employee where salary > 50000 // Uses class name, not table name // Uses field name, not column name
// SQL — table/column names SELECT * FROM employee WHERE sal > 50000

HQL: Employee = Java class name
SQL: employee = table name
👉 HQL is closer to Java thinking.

🔹 9. Hibernate Supports Annotations

Apart from XML configuration, Hibernate supports annotations.

@Entity // marks class as Hibernate entity (maps to DB table) @Table(name="employee") // specifies exact table name in DB public class Employee { @Id // marks this field as primary key @GeneratedValue // auto-generates ID value (1, 2, 3...) private int id; @Column(name="emp_name") // maps field to specific column name private String name; }

Annotations reduce XML configuration. Code and mapping in same file → easier to read and maintain.

Hibernate supports 9 key features: Auto DDL, Auto PK generation, DB independence via HQL, unchecked exceptions, L1/L2 cache, ORM, Inheritance/Associations/Collections, HQL, and Annotations. These make it far more powerful and developer-friendly than raw JDBC.

🔹 Architecture Components:
Configuration
Reads hibernate.cfg.xml or annotations. Contains DB URL, username, password, dialect, entity classes.
SessionFactory
Created ONCE from Configuration. Heavy object. Thread-safe. Used to create Session objects. Like DataSource/ConnectionPool in JDBC.
Session
Main interface to interact with DB. Created per request (not thread-safe). Provides save(), get(), update(), delete(), createQuery(). Like Connection in JDBC.
Transaction
Wraps DB operations. Begin → commit/rollback. Like setAutoCommit(false) + commit() in JDBC.
HQL / SQL
Hibernate generates SQL from HQL or uses native SQL. Sent to DB via JDBC Driver.
JDBC Driver
Hibernate uses JDBC internally. Developer never interacts with JDBC directly in Hibernate.
Hibernate Architecture: Configuration → SessionFactory (once) → Session (per request) → Transaction → HQL/SQL → JDBC → DB. SessionFactory = heavy, created once. Session = lightweight, created per operation. Transaction wraps DB changes.
