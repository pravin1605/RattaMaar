📘 1. What is ORM?

ORM stands for: Object Relational Mapping

ORM is a technique used to automatically map Java Objects with Relational Database Tables.

In simple words: ORM acts as a bridge between Java Applications and Relational Databases.

🔹 Standard Definition
Object Relational Mapping (ORM) is the automated and transparent persistence of objects in a Java application into relational database tables using metadata that describes the mapping between objects and database tables.
Java applications work with:
  • Classes
  • Objects
  • Fields / Variables
  • Collections
  • References
Relational databases work with:
  • Tables
  • Rows (records)
  • Columns
  • Multiple rows
  • Relationships (FK)

👉 ORM automatically converts Java Objects into Database Records and Database Records into Java Objects.

ORM (Object Relational Mapping) is a technique used to automatically map Java Objects with Relational Database Tables. It acts as a bridge between Java applications and databases, reducing JDBC complexity and enabling transparent persistence.
📘 2. Why ORM Came Into Picture?

Before ORM, developers used JDBC. While working with JDBC, developers had to:

❌ Problems with JDBC (Before ORM):
  • Write SQL queries manually
  • Handle ResultSet manually
  • Convert rows into objects manually
  • Manage database-specific code

This increased:

  • Development time
  • Code complexity
  • Maintenance cost

👉 To solve these problems ORM was introduced.

Without ORM — Manual JDBC:
Connection con = DriverManager.getConnection(...); PreparedStatement ps = con.prepareStatement(...); ResultSet rs = ps.executeQuery(); // Then manually convert: Student s = new Student(); s.setId(rs.getInt("id")); s.setName(rs.getString("name")); // Lots of manual work!

With ORM (Hibernate):

session.save(student); // That's it! Hibernate handles everything.
ORM came as a solution to JDBC's problems: manual SQL writing, manual ResultSet iteration, manual object mapping, and DB-specific code. ORM automates all of this — developer just works with Java objects.

📘 4. ORM Mapping Example
Java Class:
public class Student { private int id; private String name; }
Database Table — STUDENT:
IDNAME
101Pravin
Student Class → Student Table | id field → ID Column | name field → NAME Column

👉 ORM automatically maps: Student Class → Student Table | id → ID Column | name → NAME Column

ORM maps Java class to DB table, instance variable to column, and object to row. When you call session.save(student), ORM generates INSERT INTO STUDENT(ID, NAME) VALUES(101,'Pravin') automatically.
📘 5. Reversible Transformation

ORM performs two-way conversion.

Java Object ↔ Database Table

This process is called: Reversible Transformation

Object → Table (Insert Operation)
session.save(student);

Java Student object → Hibernate generates INSERT SQL → row inserted into STUDENT table.

Table → Object (Fetch Operation)
Student s = session.get( Student.class, 101);

Hibernate reads row from STUDENT table → creates Student object with id=101, name="Pravin" → returns it.

ORM supports Reversible Transformation: Object→Table (save/insert) and Table→Object (fetch/select). session.save() converts Java object to DB row. session.get() converts DB row back to Java object — completely automatic, no manual SQL or ResultSet handling.
📘 6. Without ORM vs With ORM
❌ Without ORM (JDBC) — Manual Work
Connection con = DriverManager.getConnection(...); PreparedStatement ps = con.prepareStatement( "SELECT * FROM student WHERE id=?"); ps.setInt(1, 101); ResultSet rs = ps.executeQuery(); // Manual conversion: Student s = new Student(); s.setId(rs.getInt("id")); s.setName(rs.getString("name")); rs.close(); ps.close(); con.close();
  • Developer writes SQL manually
  • Manual ResultSet iteration
  • Manual object creation
  • Manual resource closing
  • DB-specific code
VS
✅ With ORM (Hibernate) — Auto
// Just one line — fetch by ID: Student s = session.get( Student.class, 101); // Just one line — save object: session.save(student);

Hibernate internally:

  • Generates SQL automatically
  • Opens DB Connection
  • Executes Query
  • Maps Result to Object
  • Stores / Returns Data
  • Closes resources

All automatically!

Without ORM: developers write Connection, PreparedStatement, ResultSet, manual object mapping, manual close — lots of boilerplate. With ORM: session.save(obj) or session.get(Class, id) — one line handles everything internally. This is the power of ORM.

📘 8. Why ORM is Needed? (5 Reasons)
1. Reduces JDBC Code
No need to write lengthy JDBC code. One line replaces 10+ lines.
2. Eliminates Manual Mapping
Objects are mapped automatically — no manual ResultSet column extraction.
3. Database Independence
Same code works with PostgreSQL, MySQL, Oracle — just change dialect in config.
4. Better Maintainability
Less code means easier maintenance. Change in one place updates everywhere.
5. Supports OOP
Works directly with Java Objects — keeps codebase truly object-oriented.
ORM is needed to: reduce JDBC boilerplate code, eliminate manual object-row mapping, achieve DB independence, improve maintainability, and keep code object-oriented. These 5 reasons drove the adoption of ORM frameworks like Hibernate.
📘 9. Transparent Persistence

One of the most important features of ORM is: Transparent Persistence

Meaning: Developer does not need to know how data is stored internally.

ORM framework handles everything automatically.

📝 Transparent = Hidden from Developer
When you call session.save(student) → you don't see the SQL, you don't see the connection opening, you don't see the transaction — Hibernate does it all transparently behind the scenes. Developer only works with Java objects.
Transparent Persistence means developer does not need to know how data is internally stored in DB. ORM handles SQL generation, connection management, and data persistence transparently — developer only interacts with Java objects.
📘 10. Metadata in ORM

ORM uses Metadata to perform mapping.

🔹 What is Metadata?

Metadata means: Data about Data

Metadata tells ORM:

  • Which class maps to which table
  • Which variable maps to which column
  • What is primary key
  • What are relationships
🔹 Two ways to provide Metadata:
  • Annotations → modern, in Java class
  • XML file → old way (hbm.xml)
🔹 Example — Metadata via Annotations:
@Entity @Table(name="student") public class Student { @Id private int id; private String name; }

Here:

@Entity
Tells ORM: Student Class → Database Table
@Table(name="student")
Table name in DB is "student"
@Id
id field is the primary key column
ORM uses Metadata (data about data) to perform mapping. Metadata tells ORM which class maps to which table, which field maps to which column, and what is the primary key. In Hibernate, metadata is provided via Annotations (@Entity, @Table, @Id) or XML files.
📘 11. ORM Frameworks in Java

A Persistent Framework is an ORM service that stores and retrieves objects from a relational database.

📝 JPA vs Hibernate:
JPA = Java Persistence API = Specification / Interface (defines rules — what to do)
Hibernate = Implementation of JPA (defines how to do it)
👉 JPA is the standard. Hibernate implements JPA + provides extra features beyond JPA.

Hibernate's ORM flow: Create Java Object → pass to Hibernate Session → ORM reads metadata (@Entity, @Table, @Id) → generates SQL → sends via JDBC Driver → PostgreSQL stores/retrieves data. Developer only creates the Java object and calls session.save() or session.get().
