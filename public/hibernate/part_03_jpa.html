📘 1. What is JPA?
🔹 Definition

JPA (Java Persistence API) is a Java Specification that provides a standard set of rules and APIs for performing persistence operations and ORM (Object Relational Mapping) in Java applications.

🔹 Simple Definition

JPA defines HOW Java objects should be stored and retrieved from a relational database, but it does NOT provide implementation.

🔹 Important Point — What JPA IS and IS NOT:
❌ JPA is NOT:
  • ❌ Not a Framework
  • ❌ Not an ORM Tool
  • ❌ Not an Implementation
  • ❌ Does not write SQL
  • ❌ Does not connect to DB
✅ JPA IS:
  • ✅ A Specification
  • ✅ A Collection of Interfaces
  • ✅ A Collection of Classes
  • ✅ A Collection of Annotations
  • ✅ A Set of Rules
🔹 Real-Life Example
Government = JPA (Rules only)

Government creates traffic rules. Government only defines rules. It does NOT enforce them directly.

JPA = Rules (Specification)

Police = Hibernate (Implementation)

Police officers implement the traffic rules on the ground. They do the actual work.

Hibernate = Implementation

JPA (Java Persistence API) is a specification — not a framework or implementation. It defines rules and standard interfaces for ORM in Java. Hibernate is the most popular implementation of JPA. JPA = rules; Hibernate = implementation of those rules.
📘 2. Why JPA was Introduced?
❌ Before JPA (Problem):
  • Different ORM frameworks had different APIs
  • Hibernate had its own API
  • TopLink had its own API
  • OpenJPA had its own API
  • Developers had to learn different APIs for each framework
  • Code written for Hibernate → couldn't switch to TopLink easily
✅ After JPA (Solution):
  • Java introduced JPA as a standard specification
  • Now every ORM framework follows the same standard
  • Developer writes code using JPA interfaces
  • Can switch ORM (Hibernate → EclipseLink) without code change
  • One standard → many implementations
🔹 Popular JPA Implementations:

Most companies use: JPA + Hibernate

JPA was introduced because different ORM frameworks had different APIs — developers had to learn each separately. JPA standardized the interfaces so any JPA implementation (Hibernate, EclipseLink, OpenJPA) can be used with the same code.

📘 4. Persistence Class
🔹 Definition

Persistence is a utility class used to bootstrap the JPA application and create an EntityManagerFactory object.

Type
Class (not interface)
Package
javax.persistence.Persistence
Constructor
Private — object creation not allowed
Method Type
Static Method (called on class, not object)
Key Method
createEntityManagerFactory(unitName)
🔹 Example:
EntityManagerFactory emf = Persistence.createEntityManagerFactory( "pravin"); // "pravin" = persistence-unit name // defined in META-INF/persistence.xml
🔹 Why Needed?
  • Without Persistence class → EntityManagerFactory cannot be created
  • JPA cannot read persistence.xml without it
  • It is the starting point of every JPA application
🔹 Important Points:
  • Reads: META-INF/persistence.xml
  • Loads database configuration (URL, user, password, dialect)
  • Creates EntityManagerFactory from config
  • Starting point of JPA application
🔹 What is persistence.xml?
<!-- META-INF/persistence.xml --> <persistence-unit name="pravin"> <properties> <property name="javax.persistence.jdbc.url" value="jdbc:postgresql://localhost:5433/mydb"/> <property name="javax.persistence.jdbc.user" value="postgres"/> <property name="javax.persistence.jdbc.password" value="root"/> <property name="hibernate.hbm2ddl.auto" value="create"/> </properties> </persistence-unit>

👉 "pravin" = persistence-unit name passed to createEntityManagerFactory("pravin")

Persistence is a utility class in javax.persistence with a private constructor — no object creation allowed. Its static method createEntityManagerFactory(unitName) reads persistence.xml and creates the EntityManagerFactory. It is the entry point of every JPA application.
📘 5. EntityManagerFactory
🔹 Definition

EntityManagerFactory is a factory interface used to create EntityManager objects.

Type
Interface (javax.persistence)
Implementation
Provided internally by Hibernate
Nature
Heavy Weight Object
Method Type
Non-static methods
Design Pattern
Factory Design Pattern
Key Methods
createEntityManager() | close()
🔹 Example:
EntityManagerFactory emf = Persistence.createEntityManagerFactory( "pravin");
🔹 Why Needed?
  • EntityManager cannot be created directly
  • EntityManagerFactory creates EntityManager objects
  • Like a factory that produces workers (EntityManagers)
🔹 Factory Design Pattern

EntityManagerFactory follows Factory Design Pattern because it creates EntityManager objects without exposing creation logic.

🔹 Important Points:
  • Created only once per application (expensive!)
  • Thread Safe — shared across threads
  • Heavy object — creating it is costly
  • Responsible for creating EntityManagers
  • Must be closed at application shutdown: emf.close()
EntityManagerFactory is a heavy-weight, thread-safe interface created once per application. It follows Factory Design Pattern to create EntityManager objects. Since creating it is expensive, it is shared and reused. Hibernate provides its implementation internally.

📘 6. EntityManager Most Important
🔹 Definition

EntityManager is the central interface of JPA used to perform CRUD operations and manage entity objects.

Type
Interface (javax.persistence)
Nature
Light Weight Object
Created By
emf.createEntityManager()
JDBC Equivalent
Connection object
🔹 Example:
EntityManager em = emf.createEntityManager();
🔹 Why Needed?

Actual database operations happen through EntityManager. Without EntityManager:

  • ❌ Insert impossible
  • ❌ Update impossible
  • ❌ Delete impossible
  • ❌ Fetch impossible
🔹 Important Points:
  • Most important JPA interface
  • Performs CRUD operations
  • Communicates with database
  • Manages entity lifecycle
  • Not thread-safe — create per request
  • Must close after use: em.close()
🔹 Important CRUD Methods of EntityManager:
persist(object) — INSERT
em.persist(obj);

Used to store (insert) an entity object into the database. Hibernate generates INSERT SQL internally.

find(class, primaryKey) — SELECT
em.find(Student.class, 101);

Used to find/search for object based on primary key. Returns the entity object or null if not found.

merge(object) — UPDATE
em.merge(obj);

Used to update the existing object in DB by merging the states of given entity object. Updates all changed fields.

remove(object) — DELETE
em.remove(obj);

Used to remove an entity object from the database. Hibernate generates DELETE SQL internally.

getTransaction() — TRANSACTION
em.getTransaction();

Creates and returns an object of EntityTransaction. Used to begin/commit/rollback transactions.

createQuery(String jpql) — QUERY
em.createQuery("from Student");

Accepts a JPQL query as input and creates a Query object for executing JPQL statements.

EntityManager is the most important JPA interface — the central point for all CRUD operations. persist() inserts, find() selects by PK, merge() updates, remove() deletes. It is lightweight, not thread-safe, must be created per request, and is the JPA equivalent of JDBC's Connection object.
📘 7. EntityTransaction
🔹 Definition

EntityTransaction is an interface used to manage transactions in JPA.

Type
Interface (javax.persistence)
Created By
em.getTransaction()
🔹 Example:
EntityTransaction et = em.getTransaction();
🔹 Why Needed?
  • Database consistency
  • Without transaction → data may become inconsistent
  • Maintains ACID properties
🔹 Transaction Flow:
et.begin()
↓
CRUD Operation
↓
et.commit()
or et.rollback() on error
🔹 Important Methods:
begin() — Start Transaction
et.begin();

Starts the transaction. All DB operations after this are part of the transaction.

commit() — Save Permanently
et.commit();

Saves all operations to DB permanently. Changes become visible to other users.

rollback() — Undo Changes
et.rollback();

Undoes all operations since begin(). Used when an error occurs — data returns to previous state.

🔹 Important Points:
  • Maintains ACID properties
  • Controls database transactions
  • Ensures data consistency
  • Supports rollback on failure
EntityTransaction manages database transactions in JPA. et.begin() starts the transaction, et.commit() saves changes permanently, et.rollback() undoes all changes on error. It maintains ACID properties — ensures data consistency even when errors occur.

📘 8. Query Interface
🔹 Definition

Query is an interface used to execute JPQL (Java Persistence Query Language) and Native SQL queries in JPA.

Type
Interface (javax.persistence)
Created By
em.createQuery(jpqlString)
🔹 Example:
Query q = em.createQuery("from Student"); // "from Student" = JPQL // "Student" = Java class name (not table)
🔹 Important Points:
  • Supports JPQL (object-oriented queries)
  • Supports Native SQL (raw SQL)
  • Used for complex retrieval
  • Database independent
  • Used when retrieving multiple records
🔹 Important Methods:
getResultList() — Multiple Records
q.getResultList();

Returns List of all matching entity objects. Used when SELECT returns multiple rows.

getSingleResult() — One Record
q.getSingleResult();

Returns single entity object. Throws exception if no result or multiple results found.

executeUpdate() — Update/Delete
q.executeUpdate();

Performs bulk update or delete using JPQL. Returns int (rows affected).

📝 JPQL vs SQL:
JPQL: from Student where sid > 100 — uses Java class/field names
SQL: SELECT * FROM student WHERE sid > 100 — uses table/column names
JPQL is translated to SQL by Hibernate automatically.
Query interface executes JPQL and Native SQL. getResultList() returns List of objects. getSingleResult() returns one object. executeUpdate() for bulk DML. JPQL uses Java class names (not table names) — making it object-oriented and database-independent.

  • JPA = Specification (not framework, not implementation)

JPA is a specification, not a framework. It standardizes ORM through interfaces: EntityManagerFactory (heavy, once), EntityManager (light, per request), EntityTransaction (begin/commit/rollback), Query (JPQL). Hibernate is JPA's most popular implementation.
