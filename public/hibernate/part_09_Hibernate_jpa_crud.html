1. Entity Class — Person.java

ORIGINAL CODE 
package com.ty;

import javax.persistence.Entity;
import javax.persistence.Id;

/*
 * @Entity
 * Marks this class as Hibernate Entity Class.
 * Hibernate maps this class with a database table.
 */
@Entity
public class Person {

    /*
     * @Id
     * Marks p_id as Primary Key.
     */
    @Id
    private int p_id;

    private String pName;
    private int pAge;

    // Default Constructor (Recommended)
    public Person() {

    }

    // Getter and Setter Methods

    public int getP_id() {
        return p_id;
    }

    public void setP_id(int p_id) {
        this.p_id = p_id;
    }

    public String getpName() {
        return pName;
    }

    public void setpName(String pName) {
        this.pName = pName;
    }

    public int getpAge() {
        return pAge;
    }

    public void setpAge(int pAge) {
        this.pAge = pAge;
    }
}
EXTRA — Explanation
  • @Entity tells Hibernate/JPA that this POJO maps to a database table. By default the table name = class name (Person), unless overridden with @Table(name="...").
  • @Id marks the primary key field. Every entity must have exactly one field annotated @Id.
  • A no-arg (default) constructor is mandatory for JPA — Hibernate uses reflection to instantiate entities, and it requires this constructor even if you never call it yourself.
  • Fields without explicit @Column are auto-mapped to columns with the same name as the field (pName → column pName). You can rename columns with @Column(name="p_name").
  • Because there's no @GeneratedValue on p_id, the ID is assigned manually by the application.

2. Insert — PersonDriver.java (persist())

ORIGINAL CODE 
package com.ty;

import javax.persistence.EntityManager;
import javax.persistence.EntityManagerFactory;
import javax.persistence.EntityTransaction;
import javax.persistence.Persistence;

public class PersonDriver {

    public static void main(String[] args) {

        // Create EntityManagerFactory
        EntityManagerFactory emf =
                Persistence.createEntityManagerFactory("pravin");

        // Create EntityManager
        EntityManager em = emf.createEntityManager();

        // Transaction Object
        EntityTransaction et = em.getTransaction();

        // Transient Object
        Person p = new Person();

        p.setP_id(1);
        p.setpName("Pravin");
        p.setpAge(21);

        et.begin();

        /*
         * persist()
         * Used to save object into database.
         */
        em.persist(p);

        et.commit();

        System.out.println(
            "Record Inserted Successfully"
        );
    }
}
INSERT persist() ↓ Record Created
EXTRA — Explanation
  • EntityManagerFactory is created once per persistence unit ("pravin").
  • EntityManager is the lightweight interface to the persistence context.
  • Before persist(), the Person object is in the Transient state.
  • After persist(), it becomes Persistent (Managed).
  • et.begin() / et.commit() wrap the write in a transaction.

3. Fetch by ID — FetchById.java (find())

ORIGINAL CODE 
package com.ty;

import javax.persistence.EntityManager;
import javax.persistence.EntityManagerFactory;
import javax.persistence.Persistence;

public class FetchById {

    public static void main(String[] args) {

        EntityManagerFactory emf =
                Persistence.createEntityManagerFactory("pravin");

        EntityManager em =
                emf.createEntityManager();

        /*
         * find()
         * Fetches record using Primary Key.
         */
        Person p =
                em.find(Person.class, 1);

        if (p != null) {

            System.out.println(
                "Id : " + p.getP_id()
            );

            System.out.println(
                "Name : " + p.getpName()
            );

            System.out.println(
                "Age : " + p.getpAge()
            );

        } else {

            System.out.println(
                "Record Not Found"
            );
        }
    }
}
FETCH BY ID find() ↓ Single Record
EXTRA — Explanation
  • em.find(Class, primaryKey) is the standard way to fetch by primary key.
  • It returns null if the record is not found.
  • find() checks the first-level cache before accessing the database.
  • A simple find() operation does not require a transaction.
  • The returned entity is in the Persistent state while managed by the EntityManager.

4. Update — UpdateById.java (Dirty Checking)

ORIGINAL CODE 
package com.ty;

import javax.persistence.EntityManager;
import javax.persistence.EntityManagerFactory;
import javax.persistence.EntityTransaction;
import javax.persistence.Persistence;

public class UpdateById {

    public static void main(String[] args) {

        EntityManagerFactory emf =
                Persistence.createEntityManagerFactory("pravin");

        EntityManager em =
                emf.createEntityManager();

        EntityTransaction et =
                em.getTransaction();

        /*
         * Fetch Existing Record
         */
        Person p =
                em.find(Person.class, 1);

        if (p != null) {

            p.setpName("Shravan");

            et.begin();

            /*
             * Dirty Checking
             * Hibernate automatically updates.
             */

            et.commit();

            System.out.println(
                "Record Updated"
            );
        }
    }
}
UPDATE find() ↓ Modify Object ↓ commit()
EXTRA — Explanation: Dirty Checking
  • There is no explicit em.update() or em.merge() call.
  • The object returned by find() is managed by Hibernate.
  • Hibernate maintains a snapshot of the entity state.
  • At flush/commit time Hibernate compares the current state with the original snapshot.
  • If a difference is found, Hibernate automatically generates an UPDATE statement.
  • Dirty checking works while the entity remains attached to the same EntityManager.

5. Fetch All — FetchAll.java (JPQL)

ORIGINAL CODE 
package com.ty;

import java.util.List;

import javax.persistence.EntityManager;
import javax.persistence.EntityManagerFactory;
import javax.persistence.Persistence;
import javax.persistence.Query;

public class FetchAll {

    public static void main(String[] args) {

        EntityManagerFactory emf =
                Persistence.createEntityManagerFactory("pravin");

        EntityManager em =
                emf.createEntityManager();

        /*
         * JPQL Query
         * p is alias
         */
        Query query =
                em.createQuery(
                    "select p from Person p"
                );

        List<Person> persons =
                query.getResultList();

        for (Person p : persons) {

            System.out.println(
                "----------------"
            );

            System.out.println(
                "Id : " + p.getP_id()
            );

            System.out.println(
                "Name : " + p.getpName()
            );

            System.out.println(
                "Age : " + p.getpAge()
            );
        }
    }
}
FETCH ALL createQuery() ↓ Multiple Records
EXTRA — Explanation: JPQL
  • JPQL queries entity objects and their fields rather than database table names.
  • Person refers to the entity class.
  • p is the alias for the entity.
  • getResultList() returns multiple records as a List.
  • JPQL is database-independent because Hibernate converts it into database-specific SQL.

6. Delete — DeleteById.java (remove())

ORIGINAL CODE 
package com.ty;

import javax.persistence.EntityManager;
import javax.persistence.EntityManagerFactory;
import javax.persistence.EntityTransaction;
import javax.persistence.Persistence;

public class DeleteById {

    public static void main(String[] args) {

        EntityManagerFactory emf =
                Persistence.createEntityManagerFactory("pravin");

        EntityManager em =
                emf.createEntityManager();

        EntityTransaction et =
                em.getTransaction();

        Person p =
                em.find(Person.class, 1);

        if (p != null) {

            et.begin();

            /*
             * remove()
             * Deletes record from database.
             */
            em.remove(p);

            et.commit();

            System.out.println(
                "Record Deleted"
            );
        }
    }
}
DELETE find() ↓ remove() ↓ commit()
EXTRA — Explanation
  • em.remove() operates on a managed entity.
  • This is why find() is called before remove().
  • After remove(), the entity moves to the Removed state.
  • The actual DELETE SQL is executed during flush/commit.

8. Comparison Table — All Operations

Operation Core Method Transaction Needed? Entity State SQL Generated
Insert persist() Yes Transient → Persistent INSERT
Fetch by ID find() No → Persistent SELECT
Fetch All createQuery() + JPQL No → Persistent SELECT
Update Setter + Dirty Checking Yes Persistent → Modified UPDATE
Delete remove() Yes Persistent → Removed DELETE
EXTRA — Entity Lifecycle States
  • Transient — plain Java object, not associated with an EntityManager.
  • Persistent (Managed) — associated with an open EntityManager and tracked by Hibernate.
  • Detached — previously persistent but no longer associated with the persistence context.
  • Removed — entity scheduled for deletion.

9. Interview Q&A

INTERVIEW PREP
Q1. What is Dirty Checking in Hibernate?
Hibernate compares a managed entity's current field values against the snapshot taken when it was loaded. If they differ at flush/commit time, Hibernate automatically issues an UPDATE — no explicit save call is needed.
Q2. Why does remove() require calling find() first?
remove() operates on managed entities. find() loads the object into the persistence context.
Q3. What's the difference between persist() and merge()?
persist() is used for new entities and makes them Persistent. merge() is used for Detached entities and copies their state to a managed instance.
Q4. Why is a default constructor mandatory in an @Entity class?
Hibernate instantiates entities using reflection, which requires a no-argument constructor.
Q5. Does JPQL query tables or entities?
JPQL queries entity objects and their fields rather than database tables and columns. Hibernate converts JPQL into native SQL.
Q6. What happens if you call commit() without begin()?
An IllegalStateException is thrown because a transaction must first be started.
Q7. Why doesn't find() need a transaction, but persist(), updates and remove() do?
Read operations do not modify database data, while write operations must be performed inside a transaction.
Q8. What is the role of EntityManagerFactory vs EntityManager?
EntityManagerFactory is a heavyweight factory for creating EntityManagers. EntityManager manages the persistence context and database operations for a unit of work.

10. Memory Tricks

CRUD → Methods: "Persist, Find, Dirty(update), Remove" — remember as "Please Find Dirty Records".
Entity states in order: Transient → Persistent → Detached → Removed — remember as "Two Pandas Danced Rapidly".
Transaction needed? Anything that writes — persist / update / remove — needs begin() + commit(). Think: "Write = Wrap in transaction."
Dirty Checking: No save call for updates — just "get it, change it, commit it." Hibernate quietly compares old vs new state at flush time.
