1. What is One-to-Many Mapping?

THEORY

A One-to-Many relationship means one record in a table is associated with multiple records in another table. In this example, one Company can have many Employees.

From the other direction, this same relationship is called Many-to-One — many Employees belong to one Company. One-to-Many and Many-to-One are two sides of the same relationship, just modeled from opposite entities.

Company │ ├── Employee 1 (Pravin) ├── Employee 2 (Mayuresh) └── Employee 3 (Rahul)

2. Key Annotations Used

THEORY
Annotation Used On Purpose
@Entity Employee, Company Marks the class as a Hibernate entity — a table is created with the same name.
@Id eid, cid Marks the primary key field of each entity.
@GeneratedValue(strategy = GenerationType.SEQUENCE) eid, cid Auto-generates the primary key using a database sequence, instead of relying on the table's own identity column.
@OneToMany employees field in Company Declares that one Company maps to a list of many Employees.
@JoinColumn(name = "company_id") employees field in Company Tells Hibernate to put the foreign key directly in the Employee table, avoiding a separate join table.

3. Why @JoinColumn Matters (Join Table vs Foreign Key)

EXTRA — Explanation
  • By default, a plain @OneToMany (with no @JoinColumn and no mappedBy) makes Hibernate create a separate join table — e.g. Company_Employee — with two foreign key columns, one pointing to Company and one to Employee. This is wasteful for a simple one-to-many relationship where each Employee only ever belongs to one Company.
  • Adding @JoinColumn(name = "company_id") tells Hibernate: "don't create a join table — instead, add a company_id foreign key column directly inside the Employee table." This is the simpler, more common real-world approach.
  • An alternative (not used here) is a bidirectional mapping: adding a @ManyToOne field for Company inside the Employee entity, and using mappedBy on the Company side. That approach lets you navigate from Employee back to its Company too — this code only supports navigating Company → Employees, not the reverse.
  • Because Company owns the @JoinColumn, Company is the "owning side" of this relationship even though logically the foreign key column physically lives in the Employee table.

5. Code — Employee, Company, Driver

5.1 Entity — Employee.java (com.DTO)

ORIGINAL CODE 
package com.DTO;

import javax.persistence.Entity;
import javax.persistence.GeneratedValue;
import javax.persistence.GenerationType;
import javax.persistence.Id;

/*
 * @Entity
 * Marks this class as an Entity.
 * Hibernate will create a table named Employee.
 */
@Entity
public class Employee {

	/*
	 * @Id
	 * Specifies the Primary Key of the table.
	 */
	@Id

	/*
	 * @GeneratedValue
	 * Automatically generates the primary key.
	 *
	 * GenerationType.SEQUENCE
	 * Uses a database sequence to generate unique IDs.
	 */
	@GeneratedValue(strategy = GenerationType.SEQUENCE)
	private int eid;

	// Employee Name
	private String ename;

	// Employee Salary
	private double esal;

	/*
	 * Default Constructor
	 *
	 * Hibernate requires a no-argument constructor
	 * to create objects internally.
	 */
	public Employee() {

	}

	// Getter for Employee ID
	public int getEid() {
		return eid;
	}

	// Setter for Employee ID
	public void setEid(int eid) {
		this.eid = eid;
	}

	// Getter for Employee Name
	public String getEname() {
		return ename;
	}

	// Setter for Employee Name
	public void setEname(String ename) {
		this.ename = ename;
	}

	// Getter for Employee Salary
	public double getEsal() {
		return esal;
	}

	// Setter for Employee Salary
	public void setEsal(double esal) {
		this.esal = esal;
	}

	/*
	 * toString()
	 *
	 * Prints Employee object in readable format.
	 */
	@Override
	public String toString() {
		return "Employee [eid=" + eid +
				", ename=" + ename +
				", esal=" + esal + "]";
	}

}

5.2 Entity — Company.java (com.DTO)

ORIGINAL CODE 
package com.DTO;

import java.util.List;

import javax.persistence.Entity;
import javax.persistence.GeneratedValue;
import javax.persistence.GenerationType;
import javax.persistence.Id;
import javax.persistence.JoinColumn;
import javax.persistence.OneToMany;

/*
 * @Entity
 * Marks this class as an Entity.
 * Hibernate creates a table named Company.
 */
@Entity
public class Company {

	/*
	 * @Id
	 * Primary Key of Company table.
	 */
	@Id

	/*
	 * Automatically generates Company ID.
	 */
	@GeneratedValue(strategy = GenerationType.SEQUENCE)
	private int cid;

	// Company Name
	private String cname;

	/*
	 * One Company can have Multiple Employees.
	 *
	 * @OneToMany
	 * Defines One-to-Many relationship.
	 *
	 * @JoinColumn
	 * Creates a Foreign Key (company_id)
	 * inside Employee table.
	 *
	 * Without @JoinColumn,
	 * Hibernate creates an unnecessary Join Table.
	 */
	@OneToMany
	@JoinColumn(name = "company_id")
	private List<Employee> employees;

	/*
	 * Default Constructor
	 * Required by Hibernate.
	 */
	public Company() {

	}

	// Getter for Company ID
	public int getCid() {
		return cid;
	}

	// Setter for Company ID
	public void setCid(int cid) {
		this.cid = cid;
	}

	// Getter for Company Name
	public String getCname() {
		return cname;
	}

	// Setter for Company Name
	public void setCname(String cname) {
		this.cname = cname;
	}

	// Getter for Employee List
	public List<Employee> getEmployees() {
		return employees;
	}

	// Setter for Employee List
	public void setEmployees(List<Employee> employees) {
		this.employees = employees;
	}

	/*
	 * toString()
	 * Prints Company object.
	 */
	@Override
	public String toString() {
		return "Company [cid=" + cid +
				", cname=" + cname + "]";
	}

}

7. One-to-Many vs Many-to-One vs One-to-One

Mapping Meaning Annotation Used Example (from these chapters)
One-to-One One record ↔ exactly one record @OneToOne Car ↔ Engine
One-to-Many One record → many records @OneToMany + @JoinColumn Company → Employees
Many-to-One Many records → one record (reverse view of One-to-Many) @ManyToOne Employees → Company (not implemented in this code, since Employee has no back-reference to Company)

8. Interview Q&A

INTERVIEW PREP
Q1. What does @OneToMany mean, and where is it used here?
It declares that one entity instance is associated with a collection of many instances of another entity. Here, it's placed on the List<Employee> employees field inside Company, meaning one Company has many Employees.
Q2. What does @JoinColumn(name = "company_id") do, and why is it needed?
It tells Hibernate to add a company_id foreign key column directly inside the Employee table, pointing back to the owning Company. Without it, Hibernate would default to creating a separate join table to represent the relationship, which is unnecessary overhead for this simple case.
Q3. What's the difference between GenerationType.SEQUENCE and GenerationType.IDENTITY?
SEQUENCE uses a database sequence object to pre-allocate unique IDs (supports batching, and the ID can be known before insert). IDENTITY relies on the table's own auto-increment column and only knows the ID after the row is actually inserted, which disables insert batching.
Q4. Is this a unidirectional or bidirectional mapping? How can you tell?
Unidirectional — Company holds a reference to its list of Employees, but Employee has no @ManyToOne Company field pointing back. You can navigate Company → Employees but not Employee → Company.
Q5. How would you make this relationship bidirectional?
Add a @ManyToOne field of type Company inside the Employee entity, and change the Company side to use @OneToMany(mappedBy = "company") instead of @JoinColumn, so the Employee side becomes the owning side of the foreign key.
Q6. Why might deleteCompanyWithEmployees() exist as a separate method from deleteCompany()?
Because there's no cascade attribute on @OneToMany in this entity, deleting a Company alone would not automatically delete its Employees. A separate method is likely needed to explicitly remove the Employees first (or the foreign key reference), then the Company — following the same manual two-step pattern seen in the Car/Engine example.
Q7. One-to-Many vs Many-to-One — are they two different relationships or the same one?
The same relationship, viewed from opposite sides. Company → Employees is One-to-Many; Employees → Company is Many-to-One. Only one side needs to be the "owning side" that holds the foreign key mapping.

9. Memory Tricks

@JoinColumn vs Join Table: "JoinColumn = FK lives in the child table (Employee)." No JoinColumn/mappedBy = Hibernate builds an extra middle table you probably didn't want.
One-to-Many ↔ Many-to-One: Same relationship, different lens. "Company sees many Employees (One-to-Many). Each Employee sees one Company (Many-to-One)."
SEQUENCE vs IDENTITY: SEQUENCE = "the database hands you a numbered ticket before you're served" (ID known pre-insert). IDENTITY = "you only get your number after checkout" (ID known post-insert).
