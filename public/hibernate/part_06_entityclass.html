📘 What is an Entity Class?

A Java class whose objects are stored permanently in a database table is called an Entity Class or Persistent Class.

🔹 Definition

An Entity Class is a Java class that represents a table in a database.

🔹 Example:
idnamecity
101PravinMumbai

Equivalent Entity Class:

@Entity public class Student { @Id private int id; private String name; private String city; }
📝 Note: These 6 rules for Entity Class is one of the most important Hibernate interview questions. Learn all 6 thoroughly.
Rule 1 Class Must Be Public
✅ Correct
public class Student { }
❌ Wrong
class Student { }// not public

Why? Hibernate internally creates and manages objects. If class is not public, Hibernate may not access it properly from other packages. Public access ensures Hibernate can instantiate and manage the class.

Rule 2 Variables Must Be Private
✅ Correct
private int id; private String name;
❌ Wrong
public int id; public String name;

Why? Hibernate follows Encapsulation. Benefits:

  • Data Security
  • Controlled Access (only via getters/setters)
  • Better Maintainability
Rule 3 Generate Getter and Setter Methods
public int getId() { return id; } public void setId(int id) { this.id = id; }

Why Needed? Hibernate uses getters and setters to:

  • Read data from object
  • Write data to object
  • Perform Column ↔ Field mapping

Without getters and setters: ❌ Hibernate may fail to access attributes properly.

Rule 4 Must Have No-Argument Constructor (Default Constructor)
✅ Correct — with only default constructor:
public Student() { // no-arg constructor }
✅ Correct — both constructors:
public Student() { // default — mandatory! } public Student(int id, String name) { this.id = id; this.name = name; }

Why Needed?

Hibernate creates objects internally using Java Reflection API. Internally Hibernate does:

// Hibernate internally does: Student s = new Student(); // Then sets values using setters

Therefore a no-argument constructor is mandatory.

⚠️ Important: If you define only a parameterized constructor, Java does NOT auto-generate a default constructor. You must explicitly write the no-arg constructor. If you define no constructor at all, Java auto-generates a default one.
Rule 5 Class Must Be Annotated with @Entity
✅ Correct
@Entity public class Student { }
❌ Wrong
// No @Entity public class Student { }
Package
jakarta.persistence.Entity
Type
Annotation (class-level)

Why Needed?

@Entity tells Hibernate:

This Java Class
↓ represents
Database Table

Without @Entity: ❌ Hibernate will not treat the class as a DB table. It remains a regular Java class.

📝 By default: Table name = Class name. To specify a different table name use @Table(name="custom_name").
Rule 6 Define Primary Key Using @Id
@Id private int id;
Package
jakarta.persistence.Id
Type
Annotation (field-level)
Required
Mandatory in every Entity class

Why Needed? Primary Key uniquely identifies each record in the table.

idname
101Pravin
102Amit

Here id uniquely identifies each row. Without @Id → Hibernate throws AnnotationException.

📝 Auto ID: Combine with @GeneratedValue → Hibernate auto-generates IDs (1, 2, 3...):
@Id @GeneratedValue private int id;

📘 Complete Entity Class Example — Student.java
import jakarta.persistence.Entity; import jakarta.persistence.Id; @Entity // Rule 5: marks class as Entity (maps to DB table) public class Student { // Rule 1: class must be public @Id // Rule 6: marks id as primary key private int id; // Rule 2: variable must be private private String name; // Rule 2: variable must be private private String city; // Rule 2: variable must be private // Rule 4: no-argument constructor — mandatory for Hibernate reflection public Student() { } // Parameterized constructor — optional but useful public Student(int id, String name, String city) { this.id = id; this.name = name; this.city = city; } // Rule 3: Getter and Setter methods public int getId() { return id; } public void setId(int id) { this.id = id; } public String getName() { return name; } public void setName(String name) { this.name = name; } public String getCity() { return city; } public void setCity(String city) { this.city = city; } }
📝 Import Note:
Use jakarta.persistence.Entity and jakarta.persistence.Id for Hibernate 6.x (Jakarta EE).
Older Hibernate 5.x uses javax.persistence.Entity and javax.persistence.Id.
Your project uses Hibernate 5.6.15 → use javax.persistence.*.

🎯 Interview Answer
✅ Q: What are the rules for creating an Entity Class in Hibernate?

An Entity Class must follow 6 rules:

  1. Be declared as public — Hibernate must be able to access the class from any package.
  2. Have private instance variables — follows Encapsulation for data security and controlled access.
  3. Provide getter and setter methods — Hibernate reads and writes field values through these methods for mapping.
  4. Contain a no-argument constructor — Hibernate uses Java Reflection API to create objects internally using new Student().
  5. Be annotated with @Entity — tells Hibernate that this class represents a database table.
  6. Have a primary key annotated with @Id — uniquely identifies each record. Without @Id, Hibernate throws an AnnotationException.

These rules allow Hibernate to properly create, manage, and persist objects into database tables automatically.
