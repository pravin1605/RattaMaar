1. What is a Stored Procedure?
Interview Definition

A Stored Procedure is a named block of SQL and PL/SQL statements that is saved permanently in the database. It is precompiled and stored in advance, making execution faster. It can accept parameters, perform DML operations, and may or may not return a value.

  • Once created, it is saved permanently in the Oracle database
  • It is precompiled — so execution is faster than normal SQL statements
  • Can accept parameters using IN, OUT, or IN OUT modes
  • Can perform tasks such as INSERT, UPDATE, DELETE, and SELECT
  • May or may not return a value
  • Reusable — once written, it can be executed multiple times without rewriting the code
Memory Trick

Procedure = Named + Stored + Precompiled PL/SQL Block

Like a saved function on your calculator — define once, use any number of times

2. Advantages of Stored Procedures
AdvantageExplanation
ReusableWrite the procedure once and use it in multiple programs without rewriting the code
Faster ExecutionPrecompiled in the database — runs faster than normal SQL statements each time
Improved SecurityUsers access data through the procedure, preventing unauthorized direct table access
Reduced Network TrafficEntire procedure runs on the DB server — only the call is sent over the network
Easy MaintenanceLogic is stored in one place — change the procedure and all callers benefit automatically
3. Parts of a Stored Procedure
Procedure Specification (Header)
  • Specifies the name of the procedure
  • Defines the parameters and their modes (IN / OUT / IN OUT)
  • Written before IS / AS keyword
Procedure Body
  • Contains the actual code to perform the required task
  • Written between BEGIN and END
  • Can include SQL statements, loops, conditions, cursors, and exception handling
4. Stored Procedure — Syntax
STORED PROCEDURE — GENERAL SYNTAX
CREATE [OR REPLACE] PROCEDURE procedure_name ( param1 mode datatype, -- mode = IN / OUT / IN OUT param2 mode datatype ) IS / AS -- Local variables, cursors, exceptions (optional) BEGIN -- SQL / PL/SQL statements to perform the task EXCEPTION WHEN OTHERS THEN -- Optional error handling code END [procedure_name]; /
KeywordMeaning
CREATE PROCEDURECreates a new procedure in the database
OR REPLACEOptional — replaces the existing procedure if it already exists
procedure_nameName given to the procedure by the developer
INPasses input value into the procedure (default mode)
OUTReturns output value from the procedure
IN OUTPasses value in and also returns a value back
IS / ASMarks the start of the procedure block — both work the same way
BEGIN … ENDMain executable section where SQL and PL/SQL statements are written
EXCEPTIONOptional — handles runtime errors inside the procedure
END [procedure_name]Marks the end of the procedure
Extra — How to Execute a Procedure

Syntax: EXEC procedure_name(actual_parameters);

Example: EXEC EMP_EMPNO(7369);  → passes 7369 as the EMPNO parameter

EXEC and EXECUTE both work the same way.

Extra — How to View a Procedure's Code

To display the source code of a stored procedure:

SELECT TEXT FROM USER_SOURCE WHERE NAME = 'PROCEDURE_NAME';

Replace PROCEDURE_NAME with the actual name in uppercase.

5. Parameter Modes — IN / OUT / IN OUT
IN Mode (Default)
  • Used to pass input values into the procedure
  • Default mode — if no mode is written, IN is assumed
  • Value cannot be changed inside the procedure
  • Read-only inside the procedure body

Example: P_EMPNO IN NUMBER

OUT Mode
  • Used to return a value from the procedure
  • Behaves like an uninitialized variable inside the procedure
  • Cannot be read inside the procedure — only assigned
  • Caller receives the value after the procedure runs

Example: A OUT NUMBER

IN OUT Mode
  • Used to pass a value in AND return a value back
  • Can be both read and modified inside the procedure
  • Caller passes a variable — same variable gets the result back

Example: A IN OUT NUMBER

ModeDirectionReadable Inside?Modifiable Inside?Default?
INCaller → ProcedureYesNo (read-only)Yes
OUTProcedure → CallerNoYes (write-only)No
IN OUTBoth directionsYesYesNo
Memory Trick

IN = Input only (read-only inside)  |  OUT = Output only (write-only inside)  |  IN OUT = Both read and write

Default mode is always IN — if you write no mode, Oracle assumes IN

6. Stored Procedure — Program Examples
Example 1 — IN Mode: Calculate Square of a Number (Procedure P2)
Task: Create a procedure that accepts a number as IN parameter and displays its square.
Logic: N is passed as IN — read inside, squared, and displayed. EXEC P2(6) → 6×6 = 36.
IN MODE — SQUARE OF A NUMBER
-- Step 1: Create the procedure CREATE OR REPLACE PROCEDURE P2(N IN NUMBER) AS RESULT NUMBER; BEGIN RESULT := N * N; -- Square the input DBMS_OUTPUT.PUT_LINE(RESULT); END; / -- Step 2: Execute the procedure EXEC P2(6);
Output: 36  → 6 × 6 = 36
Example 2 — OUT Mode: Return a Value from Procedure (Procedure P2)
Task: Create a procedure with an OUT parameter. Assign value 100 to it inside the procedure and display it from the caller.
Logic: A is OUT — assigned 100 inside. Caller passes variable X → X receives the value 100 after procedure runs.
OUT MODE — RETURN VALUE FROM PROCEDURE
-- Step 1: Create the procedure with OUT parameter CREATE OR REPLACE PROCEDURE P2(A OUT NUMBER) AS BEGIN A := 100; -- Assign value to OUT parameter END; / -- Step 2: Call the procedure using an anonymous block DECLARE X NUMBER; -- Variable to receive OUT value BEGIN P2(X); -- X receives the OUT value (100) DBMS_OUTPUT.PUT_LINE(X); END; /
Output: 100  → X receives value 100 from OUT parameter A
Example 3 — IN OUT Mode: Pass Value In and Get Result Back (Procedure P5)
Task: Create a procedure that takes a number IN OUT, squares it, and returns the result back through the same variable.
Logic: X = 10 passed in → A = 10 inside → A := A * A = 100 → X gets back 100 after call.
IN OUT MODE — SQUARE USING SAME VARIABLE
-- Step 1: Create the procedure with IN OUT parameter CREATE OR REPLACE PROCEDURE P5(A IN OUT NUMBER) AS BEGIN A := A * A; -- Read input (IN) and write result back (OUT) END; / -- Step 2: Call using an anonymous block DECLARE X NUMBER := 10; -- X = 10 passed in BEGIN P5(X); -- X becomes 10 × 10 = 100 DBMS_OUTPUT.PUT_LINE(X); END; /
Output: 100  → X was 10 going in, becomes 100 coming out
Example 4 — IN Mode: Fetch Employee Name and Salary by EMPNO
Task: Create a procedure that accepts EMPNO as IN parameter and displays the employee's name and salary. Handle NO_DATA_FOUND if EMPNO does not exist.
Logic: EXEC EMP_EMPNO(123) → EMPNO 123 does not exist → NO_DATA_FOUND exception handled.
IN MODE — FETCH EMPLOYEE BY EMPNO
-- Step 1: Create the procedure CREATE OR REPLACE PROCEDURE EMP_EMPNO(PEMPNO NUMBER) AS V_NAME VARCHAR2(20); V_SAL NUMBER; BEGIN -- Fetch employee details using the IN parameter SELECT ENAME, SAL INTO V_NAME, V_SAL FROM EMP WHERE EMPNO = PEMPNO; DBMS_OUTPUT.PUT_LINE(V_NAME || ' ' || V_SAL); EXCEPTION WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('DATA DOES NOT EXIST'); END; / -- Step 2: Execute the procedure EXEC EMP_EMPNO(7369); -- Valid EMPNO → displays SMITH 800 EXEC EMP_EMPNO(123); -- Invalid EMPNO → DATA DOES NOT EXIST
EXEC EMP_EMPNO(7369) → SMITH 800  |  EXEC EMP_EMPNO(123) → DATA DOES NOT EXIST
Example 5 — IN Mode: Fetch All Employees of a Department Using Cursor
Task: Create a procedure that accepts DEPTNO as IN parameter and displays all employees (name, job, department) of that department using an Explicit Cursor.
Logic: Cursor C1 uses P_DEPTNO as filter → OPEN → LOOP FETCH → display each row → CLOSE.
IN MODE — FETCH EMPLOYEES BY DEPARTMENT USING CURSOR
-- Step 1: Create the procedure CREATE OR REPLACE PROCEDURE DEPT_EMP(P_DEPTNO IN NUMBER) AS I EMP%ROWTYPE; CURSOR C1 IS SELECT * FROM EMP WHERE DEPTNO = P_DEPTNO; -- Filter using IN parameter BEGIN OPEN C1; LOOP FETCH C1 INTO I; EXIT WHEN C1%NOTFOUND; DBMS_OUTPUT.PUT_LINE( I.ENAME || ' ' || I.JOB || ' ' || I.DEPTNO ); END LOOP; CLOSE C1; END; / -- Step 2: Execute the procedure EXEC DEPT_EMP(10);
Output: CLARK MANAGER 10  → KING PRESIDENT 10  → MILLER CLERK 10
Example 6 — IN Mode: Insert a New Record into DEPT Table
Task: Create a procedure that accepts DEPTNO, DNAME, and LOCATION as IN parameters and inserts a new record into the DEPT table.
Logic: EXEC INSERT_RECORDS(50,'TRAINER','MUMBAI') → values passed in → inserted into DEPT table.
IN MODE — INSERT RECORD INTO DEPT TABLE
-- Step 1: Create the procedure CREATE OR REPLACE PROCEDURE INSERT_RECORDS ( P_DEPTNO DEPT.DEPTNO%TYPE, -- Anchored to DEPT.DEPTNO column P_DNAME DEPT.DNAME%TYPE, P_LOCATION DEPT.LOC%TYPE ) AS BEGIN -- Insert the new department record INSERT INTO DEPT(DEPTNO, DNAME, LOC) VALUES(P_DEPTNO, P_DNAME, P_LOCATION); DBMS_OUTPUT.PUT_LINE('RECORD INSERTED SUCCESSFULLY'); END; / -- Step 2: Execute the procedure EXEC INSERT_RECORDS(50, 'TRAINER', 'MUMBAI');
Output: RECORD INSERTED SUCCESSFULLY  → DEPTNO 50, TRAINER, MUMBAI added to DEPT table
7. How to View a Stored Procedure

To display the source code of any stored procedure saved in the database:

VIEW PROCEDURE SOURCE CODE
SELECT TEXT FROM USER_SOURCE WHERE NAME = 'PROCEDURE_NAME'; -- Replace with actual name in UPPERCASE
Extra — USER_SOURCE

USER_SOURCE is a data dictionary view in Oracle that stores the source code of all procedures, functions, packages, and triggers created by the current user. The NAME column must always be in UPPERCASE.

Common Mistakes with Stored Procedures

1. Writing ELSEIF instead of ELSIF inside procedure body → PLS-00103 error

2. Forgetting OR REPLACE → creates duplicate — old version remains if error occurs

3. OUT parameter used with EXEC directly → must use an anonymous block with a variable

4. IN parameter modified inside procedure → PLS-00363: expression cannot be used as assignment target

5. Procedure name in USER_SOURCE not in UPPERCASE → returns no rows

9. Frequently Asked Interview Questions
Q1. What is a stored procedure in PL/SQL?
A stored procedure is a named block of SQL and PL/SQL statements that is saved permanently in the database. It is precompiled, reusable, can accept parameters, and may or may not return a value.
Q2. What are the advantages of stored procedures?
1. Reusable — write once, use multiple times. 2. Faster execution — precompiled in the database. 3. Improved security — users access data through procedures, not directly. 4. Reduced network traffic — entire logic runs on the DB server. 5. Easy maintenance — logic stored in one place.
Q3. What are the three parameter modes in PL/SQL procedures?
1. IN — passes input values into the procedure. Read-only inside. Default mode. 2. OUT — returns output values from the procedure. Write-only inside. 3. IN OUT — both passes a value in and returns a result back through the same variable.
Q4. What is the difference between IN and OUT parameters?
IN parameters pass values from the caller into the procedure — they are read-only inside. OUT parameters return values from the procedure to the caller — they behave like uninitialized variables inside and can only be assigned, not read.
Q5. What is the default parameter mode in PL/SQL?
The default parameter mode in PL/SQL is IN. If no mode is specified, Oracle automatically treats the parameter as IN mode.
Q6. What is the difference between a Stored Procedure and an Anonymous Block? Extra
An Anonymous Block has no name, is not stored in the database, and cannot be reused. A Stored Procedure has a name, is stored permanently in the database, is precompiled, and can be called and reused multiple times.
Q7. How do you execute a stored procedure in Oracle? Extra
Using EXEC or EXECUTE command: EXEC procedure_name(parameters); For procedures with OUT or IN OUT parameters, an anonymous block with declared variables must be used to capture the returned values.
Q8. What is OR REPLACE in CREATE OR REPLACE PROCEDURE? Extra
OR REPLACE is an optional clause that overwrites the existing procedure if it already exists in the database. Without it, trying to create a procedure with the same name will throw an error if the procedure already exists.
Q9. What is the difference between IN OUT and OUT mode? Extra
OUT mode starts as an uninitialized variable — the caller's value is not passed in, only a result is returned. IN OUT mode both receives the caller's value AND returns a result through the same variable. Use IN OUT when the procedure needs to read and modify the caller's variable.
