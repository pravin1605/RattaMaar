1. What are Anchored Datatypes?
Interview Definition

Anchored Datatypes are special PL/SQL datatypes that automatically derive their datatype from a database table column or another variable, instead of manually specifying it. This makes the code more flexible, reliable, and easier to maintain.

They are also called Reference Datatypes in PL/SQL.

Without Anchored Datatype

V_NAME VARCHAR2(20);

If ENAME column changes to VARCHAR2(50), this code breaks — must be manually updated

With Anchored Datatype

V_NAME EMP.ENAME%TYPE;

Automatically uses whatever datatype ENAME has — no code change needed

Memory Trick

Anchored = Tied to the source. Like a boat anchored to the sea floor — wherever the floor changes, the boat stays connected.

2. Why Do We Need Anchored Datatypes?
Problem Without Anchored DatatypesSolution With Anchored Datatypes
Must manually check and update datatypes in code whenever DB column changesCode automatically picks up the new datatype — zero manual effort
Risk of datatype mismatch causing runtime errorsDatatype always matches the source — no mismatch possible
Code is less flexible and harder to maintainCode is flexible, reliable, and easy to maintain
3. Advantages of Anchored Datatypes
  • Automatically adopts column datatype, size, precision, and scale
  • Reduces maintenance effort — no need to update code when DB column changes
  • Prevents datatype mismatch errors at runtime
  • Improves code reliability and flexibility
  • Makes code self-documenting — clear which column a variable is linked to
4. Types of Anchored Datatypes
%TYPE

Anchors a variable to the datatype of a single table column or another variable

Example: V_NAME EMP.ENAME%TYPE;

%ROWTYPE

Anchors a record variable to the structure of an entire table row — holds all columns

Example: V_EMP EMP%ROWTYPE;

5. %TYPE — Definition and Syntax
Interview Definition

The %TYPE attribute allows a variable to inherit the datatype, length, precision, and scale of a table column or another variable. The variable automatically becomes the same type as the referenced source.

Syntax — Anchoring to a Table Column:

VARIABLE_NAME TABLE_NAME.COLUMN_NAME%TYPE;

Syntax — Anchoring to Another Variable:

VARIABLE_NAME OTHER_VARIABLE_NAME%TYPE;

Examples:

V_NAME EMP.ENAME%TYPE; -- inherits ENAME's datatype from EMP table
V_SAL EMP.SAL%TYPE; -- inherits SAL's datatype from EMP table
Extra — Anchoring to Another Variable

%TYPE can also anchor to another PL/SQL variable:

V_NAME VARCHAR2(30);
V_EMP_NAME V_NAME%TYPE; -- inherits same type as V_NAME

V_EMP_NAME automatically becomes VARCHAR2(30)

6. %TYPE — What It Inherits
Property InheritedExample
DatatypeENAME is VARCHAR2, so V_NAME becomes VARCHAR2
Length / SizeENAME is VARCHAR2(10), so V_NAME becomes VARCHAR2(10)
PrecisionSAL is NUMBER(7,2), so V_SAL gets precision 7
ScaleSAL is NUMBER(7,2), so V_SAL gets scale 2
Important — NOT Inherited

%TYPE does NOT inherit the NOT NULL constraint. Even if the column is NOT NULL, the PL/SQL variable declared with %TYPE can still hold NULL.

7. %ROWTYPE — Definition and Syntax
Interview Definition

The %ROWTYPE attribute creates a record variable that can store an entire row of a table. Instead of declaring separate variables for each column, one %ROWTYPE variable holds all column values of the row together.

Syntax:

VARIABLE_NAME TABLE_NAME%ROWTYPE;

Example:

V_EMP EMP%ROWTYPE;

V_EMP now contains all columns of EMP table: EMPNO, ENAME, JOB, MGR, HIREDATE, SAL, COMM, DEPTNO

Accessing Individual Columns — Syntax:

RECORD_VARIABLE.COLUMN_NAME
V_EMP.ENAME    -- access name
V_EMP.SAL     -- access salary
V_EMP.JOB     -- access job
8. %TYPE vs %ROWTYPE — Comparison
Feature%TYPE%ROWTYPE
Refers toOne column of a tableComplete row of a table (all columns)
StoresSingle valueMultiple values (one per column)
Used forIndividual fields / single column fetchEntire records / SELECT * fetch
MemoryMore efficient — only one valueUses more memory — holds all columns
Access syntaxDirect — V_NAMEDot notation — V_EMP.ENAME
ExampleV_SAL EMP.SAL%TYPE;V_EMP EMP%ROWTYPE;
Best used whenFetching one or few specific columnsFetching all columns of a row
Memory Trick

%TYPE = one TYPE (one column)  |  %ROWTYPE = entire ROW (all columns)

If column name appears → %TYPE  |  If only table name appears → %ROWTYPE

9. Side-by-Side Comparison — Declaration
Without %ROWTYPE — 3 separate variables
V_NAME EMP.ENAME%TYPE;
V_JOB EMP.JOB%TYPE;
V_SAL EMP.SAL%TYPE;

Need one variable per column — gets long quickly

With %ROWTYPE — 1 record variable
V_EMP EMP%ROWTYPE;

One variable holds all columns — cleaner and simpler

10. Practice Questions on EMP Table

All questions use %TYPE and %ROWTYPE with the standard EMP table.

Q1. Fetch the name and job of SCOTT (EMPNO 7788) using %TYPE
Logic

Declare V_NAME as EMP.ENAME%TYPE and V_JOB as EMP.JOB%TYPE

Use SELECT INTO to fetch ENAME and JOB where EMPNO = 7788

Display using DBMS_OUTPUT.PUT_LINE

Output: NAME: SCOTT   JOB: ANALYST
Q2. Fetch all details of KING (EMPNO 7839) using %ROWTYPE
Logic

Declare V_EMP as EMP%ROWTYPE

Use SELECT * INTO V_EMP where EMPNO = 7839

Access V_EMP.ENAME, V_EMP.SAL, V_EMP.JOB, V_EMP.DEPTNO individually

Output: NAME: KING   SAL: 5000   JOB: PRESIDENT   DEPTNO: 10
Q3. Fetch name and salary of the employee with the highest salary using %TYPE
Logic

Declare V_NAME as EMP.ENAME%TYPE and V_SAL as EMP.SAL%TYPE

Use SELECT ENAME, SAL INTO V_NAME, V_SAL FROM EMP WHERE SAL = (SELECT MAX(SAL) FROM EMP)

KING has salary 5000 — the subquery returns 5000, outer query fetches KING's row

Output: NAME: KING   SALARY: 5000
Q4. Fetch all details of SMITH (lowest salary) using %ROWTYPE
Logic

Declare V_EMP as EMP%ROWTYPE

Use SELECT * INTO V_EMP WHERE SAL = (SELECT MIN(SAL) FROM EMP)

SMITH has the lowest salary = 800 — his entire row is fetched

Output: NAME: SMITH   SAL: 800   JOB: CLERK   DEPTNO: 20
Q5. Fetch the name and department number of BLAKE (EMPNO 7698) using %TYPE
Logic

Declare V_NAME as EMP.ENAME%TYPE and V_DEPTNO as EMP.DEPTNO%TYPE

Use SELECT ENAME, DEPTNO INTO V_NAME, V_DEPTNO WHERE EMPNO = 7698

Output: NAME: BLAKE   DEPTNO: 30
Q6. Fetch name, job and salary of FORD (EMPNO 7902) using %ROWTYPE and display all three Extra
Logic

Declare V_EMP as EMP%ROWTYPE

SELECT * INTO V_EMP WHERE EMPNO = 7902

Display V_EMP.ENAME, V_EMP.JOB, V_EMP.SAL separately

Output: NAME: FORD   JOB: ANALYST   SALARY: 3000
Q7. Using %TYPE, fetch the name of the employee whose manager is KING (EMPNO 7839) and works in DEPTNO 10 Extra
Logic

Declare V_NAME as EMP.ENAME%TYPE

SELECT ENAME INTO V_NAME FROM EMP WHERE MGR = 7839 AND DEPTNO = 10

CLARK reports to KING (MGR=7839) and is in DEPTNO 10

Output: NAME: CLARK
Q8. Using %ROWTYPE, fetch the complete details of the employee with second highest salary Extra
Logic

Declare V_EMP as EMP%ROWTYPE

Use subquery with DENSE_RANK() OVER (ORDER BY SAL DESC) and filter WHERE RN = 2

SCOTT and FORD both have salary 3000 — DENSE_RANK gives them rank 2

This may raise TOO_MANY_ROWS — use ROWNUM = 1 to limit to one result

Output: NAME: SCOTT or FORD   SAL: 3000   JOB: ANALYST
11. Frequently Asked Interview Questions
Q1. What is an Anchored Datatype?
An Anchored Datatype is a datatype that automatically derives its datatype from a table column or another variable instead of being manually specified. Types: %TYPE and %ROWTYPE.
Q2. What are the types of Anchored Datatypes?
1. %TYPE — anchors to a single table column or variable.   2. %ROWTYPE — anchors to the entire row structure of a table.
Q3. What is %TYPE?
%TYPE is used to declare a variable with the same datatype, length, precision, and scale as a table column or another variable. Example: V_NAME EMP.ENAME%TYPE;
Q4. What is %ROWTYPE?
%ROWTYPE is used to create a record variable that can store an entire row of a table. All columns and their datatypes are inherited automatically. Example: V_EMP EMP%ROWTYPE;
Q5. What are the advantages of using %TYPE?
1. Automatic datatype and size matching with the DB column.   2. No manual updates needed when column type changes.   3. Prevents datatype mismatch errors.   4. Less maintenance effort.
Q6. What is the difference between %TYPE and %ROWTYPE?
%TYPE anchors to one column and stores a single value. %ROWTYPE anchors to an entire table row and stores all column values in one record variable. %TYPE uses less memory; %ROWTYPE is more convenient when fetching all columns.
Q7. How do you access individual columns from a %ROWTYPE variable? Extra
Using dot notation: RECORD_VARIABLE.COLUMN_NAME. Example: V_EMP.ENAME gives the name, V_EMP.SAL gives the salary from the V_EMP record.
Q8. Does %TYPE inherit the NOT NULL constraint from the column? Extra
No. %TYPE inherits only the datatype, length, precision, and scale — it does NOT inherit the NOT NULL constraint. A variable declared with %TYPE can still hold a NULL value even if the source column is NOT NULL.
Q9. Can %TYPE anchor to another PL/SQL variable (not just a table column)? Extra
Yes. %TYPE can anchor to another variable declared earlier in the same DECLARE section. Example: V_NAME VARCHAR2(30); V_EMP_NAME V_NAME%TYPE; — V_EMP_NAME automatically becomes VARCHAR2(30).
Q10. When should you use %TYPE vs %ROWTYPE? Extra
Use %TYPE when fetching specific columns — it is memory efficient. Use %ROWTYPE when fetching all columns of a row using SELECT * — it is more convenient and reduces the number of variable declarations needed.
