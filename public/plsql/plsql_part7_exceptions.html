1. What is an Exception?
Interview Definition

An Exception is a runtime error that occurs while a PL/SQL program is executing. PL/SQL provides a dedicated EXCEPTION section to handle these errors gracefully — preventing program crashes and allowing custom error messages or recovery actions.

  • Exceptions occur at runtime — not during compilation
  • Without exception handling, the program terminates abruptly with an Oracle error
  • The EXCEPTION section catches the error and allows the developer to handle it cleanly
  • After the EXCEPTION block runs, the program ends normally — no crash
Memory Trick

Exception = Runtime Error Safety Net — catches errors before they crash the program

Predefined = Oracle already named it  |  User-Defined = Developer creates their own

2. Types of Exceptions
1. Predefined Exceptions
  • Oracle has already defined 20 predefined exception names
  • Raised automatically when a matching error occurs
  • Developer just uses the name in the EXCEPTION block
  • Examples: NO_DATA_FOUND, TOO_MANY_ROWS, ZERO_DIVIDE
2. User-Defined Exceptions
  • Created by the developer for custom business rules
  • Must be declared, raised manually using RAISE, and handled
  • Three steps: DECLARE → RAISE → HANDLE
  • Examples: LOW_SAL, LOW_AGE, INVALID_MARKS
3. PL/SQL Block with Exception — Syntax
EXCEPTION HANDLING — GENERAL SYNTAX
DECLARE -- Variables, constants, cursors, user-defined exceptions BEGIN -- Executable statements (SQL + logic) EXCEPTION WHEN exception_name THEN -- Error handling code WHEN OTHERS THEN -- Catch-all for any unhandled exception (always placed last) END; /
Extra — WHEN OTHERS

WHEN OTHERS is a catch-all handler that handles any exception not covered by a specific WHEN clause. It must always be the LAST handler in the EXCEPTION block. Use it to avoid unexpected program crashes.

5. Predefined Exception — Program Examples
Exception 1 — NO_DATA_FOUND
Raised when: SELECT INTO returns zero rows.   Oracle Error: ORA-01403: NO DATA FOUND
Task: Fetch employee where EMPNO = 736. No such employee exists → NO_DATA_FOUND is raised.
NO_DATA_FOUND — EMPNO 736 DOES NOT EXIST
DECLARE V_NAME VARCHAR2(20); V_SAL NUMBER; BEGIN -- EMPNO 736 does not exist → raises NO_DATA_FOUND SELECT ENAME, SAL INTO V_NAME, V_SAL FROM EMP WHERE EMPNO = 736; DBMS_OUTPUT.PUT_LINE(V_NAME || ' ' || V_SAL); EXCEPTION WHEN NO_DATA_FOUND THEN DBMS_OUTPUT.PUT_LINE('RECORD NOT FOUND'); END; /
Output: RECORD NOT FOUND  → No employee with EMPNO 736
Exception 2 — TOO_MANY_ROWS
Raised when: SELECT INTO returns more than one row.   Oracle Error: ORA-01422
Task: SELECT INTO from EMP without a WHERE clause → all 14 rows returned → TOO_MANY_ROWS is raised.
TOO_MANY_ROWS — SELECT INTO WITHOUT WHERE
DECLARE V_NAME VARCHAR2(20); V_SAL NUMBER; BEGIN -- No WHERE clause → returns all 14 rows → raises TOO_MANY_ROWS SELECT ENAME, SAL INTO V_NAME, V_SAL FROM EMP; DBMS_OUTPUT.PUT_LINE(V_NAME || ' ' || V_SAL); EXCEPTION WHEN TOO_MANY_ROWS THEN DBMS_OUTPUT.PUT_LINE('CANNOT FETCH MULTIPLE RECORDS USING INTO CLAUSE'); END; /
Output: CANNOT FETCH MULTIPLE RECORDS USING INTO CLAUSE
Exception 3 — ZERO_DIVIDE
Raised when: A number is divided by zero.   Oracle Error: ORA-01476: divisor is equal to zero
Task: Divide V_NUM1 (10) by V_NUM2 (0) → ZERO_DIVIDE is raised.
ZERO_DIVIDE — DIVIDING BY ZERO
DECLARE V_NUM1 NUMBER := 10; V_NUM2 NUMBER := 0; -- divisor is zero BEGIN -- Dividing by 0 → raises ZERO_DIVIDE DBMS_OUTPUT.PUT_LINE(V_NUM1 / V_NUM2); EXCEPTION WHEN ZERO_DIVIDE THEN DBMS_OUTPUT.PUT_LINE('ERROR: CANNOT DIVIDE BY ZERO'); END; /
Output: ERROR: CANNOT DIVIDE BY ZERO
Exception 4 — INVALID_CURSOR
Raised when: FETCH or CLOSE is performed on a cursor that was never opened.   Oracle Error: ORA-01001
Task: FETCH from cursor C1 without calling OPEN C1 first → INVALID_CURSOR is raised.
INVALID_CURSOR — FETCH WITHOUT OPEN
DECLARE I EMP%ROWTYPE; CURSOR C1 IS SELECT * FROM EMP; BEGIN -- OPEN C1 is missing → FETCH on closed cursor → raises INVALID_CURSOR LOOP FETCH C1 INTO I; EXIT WHEN C1%NOTFOUND; DBMS_OUTPUT.PUT_LINE(I.ENAME || ' ' || I.SAL); END LOOP; CLOSE C1; EXCEPTION WHEN INVALID_CURSOR THEN DBMS_OUTPUT.PUT_LINE('ERROR: CURSOR WAS NOT OPENED. USE PROPER SYNTAX'); END; /
Output: ERROR: CURSOR WAS NOT OPENED. USE PROPER SYNTAX
Exception 5 — CURSOR_ALREADY_OPEN
Raised when: OPEN is called on a cursor that is already open.   Oracle Error: ORA-01001
Task: OPEN C1 is called inside the loop when it is already open → CURSOR_ALREADY_OPEN is raised on the second OPEN call.
CURSOR_ALREADY_OPEN — OPENING AN ALREADY OPEN CURSOR
DECLARE I EMP%ROWTYPE; CURSOR C1 IS SELECT * FROM EMP; BEGIN LOOP OPEN C1; -- First OPEN: OK FETCH C1 INTO I; EXIT WHEN C1%NOTFOUND; DBMS_OUTPUT.PUT_LINE(I.ENAME || ' ' || I.SAL); END LOOP; OPEN C1; -- Second OPEN: raises CURSOR_ALREADY_OPEN EXCEPTION WHEN CURSOR_ALREADY_OPEN THEN DBMS_OUTPUT.PUT_LINE('ERROR: CLOSE THE CURSOR BEFORE REOPENING IT'); END; /
Output: SMITH 800  → CURSOR_ALREADY_OPEN raised → ERROR: CLOSE THE CURSOR BEFORE REOPENING IT
Exception 6 — INVALID_NUMBER
Raised when: Oracle tries to convert a non-numeric string to a number inside a SQL statement.   Oracle Error: ORA-01722
Task: INSERT 'ABC' into EMPNO (NUMBER column) → INVALID_NUMBER is raised.
INVALID_NUMBER — INSERT NON-NUMERIC VALUE INTO NUMBER COLUMN
BEGIN -- 'ABC' cannot be converted to NUMBER → raises INVALID_NUMBER INSERT INTO EMP(EMPNO, ENAME) VALUES('ABC', 1111); EXCEPTION WHEN INVALID_NUMBER THEN DBMS_OUTPUT.PUT_LINE('ERROR: PLEASE INSERT VALID NUMERIC DATA'); END; /
Output: ERROR: PLEASE INSERT VALID NUMERIC DATA
Exception 7 — VALUE_ERROR
Raised when: A value assigned to a variable exceeds its defined precision, or a string-to-number conversion fails in PL/SQL.   Oracle Error: ORA-06502
Task: Assign 123456 to Z NUMBER(5) — max 5 digits allowed but 6 digits given → VALUE_ERROR is raised.
VALUE_ERROR — VALUE TOO LARGE FOR VARIABLE
DECLARE Z NUMBER(5); -- max 5 digits allowed BEGIN -- 123456 has 6 digits → exceeds NUMBER(5) → raises VALUE_ERROR Z := 123456; DBMS_OUTPUT.PUT_LINE(Z); EXCEPTION WHEN VALUE_ERROR THEN DBMS_OUTPUT.PUT_LINE('ERROR: VALUE EXCEEDS THE ALLOWED SIZE OF THE VARIABLE'); END; /
Output: ERROR: VALUE EXCEEDS THE ALLOWED SIZE OF THE VARIABLE
6. User-Defined Exceptions
Definition

User-Defined Exceptions are custom exceptions created by the developer to enforce business rules that Oracle does not handle automatically. The developer declares, raises manually using RAISE, and handles them just like predefined exceptions.

1
DECLARE
Define the exception in the DECLARE section using the EXCEPTION keyword.

Syntax: exception_name EXCEPTION;
2
RAISE
Manually raise the exception in the BEGIN section using the RAISE keyword when the condition is met.

Syntax: RAISE exception_name;
3
HANDLE
Handle the exception in the EXCEPTION section just like a predefined exception.

Syntax: WHEN exception_name THEN …
Memory Trick

D-R-H → DECLARE → RAISE → HANDLE  |  "Developers Raise Handles"

7. User-Defined Exception — Program Examples
Example 1 — LOW_SAL Exception (Single Exception)
Task: Check if salary is less than 5000. If yes, raise LOW_SAL user-defined exception.
Logic: V_SAL = 3000 → condition IF V_SAL < 5000 is TRUE → RAISE LOW_SAL → EXCEPTION block handles it.
USER-DEFINED EXCEPTION — LOW_SAL
DECLARE V_SAL NUMBER := 3000; LOW_SAL EXCEPTION; -- Step 1: Declare user-defined exception BEGIN -- Step 2: Check condition and RAISE exception if met IF V_SAL < 5000 THEN RAISE LOW_SAL; END IF; DBMS_OUTPUT.PUT_LINE('SALARY IS VALID'); EXCEPTION -- Step 3: Handle the exception WHEN LOW_SAL THEN DBMS_OUTPUT.PUT_LINE('SALARY MUST BE >= 5000'); END; /
Output: SALARY MUST BE >= 5000  → V_SAL = 3000 < 5000 → LOW_SAL raised
Example 2 — LOW_AGE Exception
Task: Check if age is less than 18. If yes, raise LOW_AGE exception.
Logic: V_AGE = 16 → IF V_AGE < 18 is TRUE → RAISE LOW_AGE → handled in EXCEPTION block.
USER-DEFINED EXCEPTION — LOW_AGE
DECLARE V_AGE NUMBER := 16; LOW_AGE EXCEPTION; -- Declare user-defined exception BEGIN IF V_AGE < 18 THEN RAISE LOW_AGE; -- Raise when condition met END IF; DBMS_OUTPUT.PUT_LINE('AGE IS VALID'); EXCEPTION WHEN LOW_AGE THEN DBMS_OUTPUT.PUT_LINE('AGE MUST BE 18 OR ABOVE'); END; /
Output: AGE MUST BE 18 OR ABOVE  → V_AGE = 16 < 18 → LOW_AGE raised
Example 3 — INVALID_MARKS Exception (Multiple Exceptions in One Block)
Task: Check marks — raise INVALID_MARKS if marks > 100. Two exceptions declared in one block. Since INVALID_MARKS fires first, the second check is never reached.
Logic: V_MARKS1 = 120 → > 100 → RAISE INVALID_MARKS → first WHEN handler executes → second WHEN is skipped.
MULTIPLE USER-DEFINED EXCEPTIONS — SINGLE BLOCK
DECLARE V_MARKS1 NUMBER := 120; V_MARKS2 NUMBER := 0; INVALID_MARKS EXCEPTION; -- Exception for marks > 100 INVALID_MARKS1 EXCEPTION; -- Exception for marks = 0 BEGIN IF V_MARKS1 > 100 THEN RAISE INVALID_MARKS; -- Fires first → second check skipped END IF; IF V_MARKS2 = 0 THEN RAISE INVALID_MARKS1; END IF; DBMS_OUTPUT.PUT_LINE('MARKS ARE VALID'); EXCEPTION WHEN INVALID_MARKS THEN DBMS_OUTPUT.PUT_LINE('MARKS SHOULD NOT EXCEED 100'); WHEN INVALID_MARKS1 THEN DBMS_OUTPUT.PUT_LINE('MARKS SHOULD NOT BE ZERO'); END; /
Output: MARKS SHOULD NOT EXCEED 100  → First exception fires, second check never reached
Example 4 — Multiple Exceptions Using Nested Blocks (Both Execute)
Task: Check both conditions — marks > 100 AND marks = 0 — and handle both exceptions independently.
Logic: Each condition is in its own inner BEGIN-EXCEPTION-END block. So even if first fires, second block still runs independently. V_MARKS1 = 0 → skips first, raises second.
NESTED BLOCKS — BOTH EXCEPTIONS HANDLED INDEPENDENTLY
DECLARE V_MARKS1 NUMBER := 0; INVALID_MARKS EXCEPTION; INVALID_MARKS1 EXCEPTION; BEGIN -- Inner block 1: check if marks exceed 100 BEGIN IF V_MARKS1 > 100 THEN RAISE INVALID_MARKS; END IF; EXCEPTION WHEN INVALID_MARKS THEN DBMS_OUTPUT.PUT_LINE('MARKS SHOULD NOT EXCEED 100'); END; -- Inner block 2: check if marks are zero BEGIN IF V_MARKS1 = 0 THEN RAISE INVALID_MARKS1; END IF; EXCEPTION WHEN INVALID_MARKS1 THEN DBMS_OUTPUT.PUT_LINE('MARKS SHOULD NOT BE ZERO'); END; END; /
Output: MARKS SHOULD NOT BE ZERO  → V_MARKS1 = 0 → only second block fires
Example 5 — Bank Withdrawal (Multiple Nested Exceptions)
Task: Validate three conditions — insufficient balance, invalid amount, underage user — using three separate nested blocks.
Logic: Each nested block checks one condition independently. WITHDRAW_AMOUNT (500) < ACCOUNT_BALANCE (1000) → withdrawal succeeds. V_AGE = 16 < 18 → AGE_EXCEPTION fires in third block.
BANK WITHDRAWAL — THREE NESTED EXCEPTION BLOCKS
DECLARE ACCOUNT_BALANCE NUMBER := 1000; WITHDRAW_AMOUNT NUMBER := 500; V_AGE NUMBER := 16; AGE_EXCEPTION EXCEPTION; INSUFFICIENT_BALANCE EXCEPTION; INVALID_AMOUNT EXCEPTION; BEGIN -- Block 1: Check if withdrawal exceeds balance BEGIN IF WITHDRAW_AMOUNT > ACCOUNT_BALANCE THEN RAISE INSUFFICIENT_BALANCE; END IF; DBMS_OUTPUT.PUT_LINE('WITHDRAWAL SUCCESSFUL'); EXCEPTION WHEN INSUFFICIENT_BALANCE THEN DBMS_OUTPUT.PUT_LINE('INSUFFICIENT BALANCE. AVAILABLE: ' || ACCOUNT_BALANCE); END; -- Block 2: Check if withdrawal amount is valid BEGIN IF WITHDRAW_AMOUNT <= 0 THEN RAISE INVALID_AMOUNT; END IF; EXCEPTION WHEN INVALID_AMOUNT THEN DBMS_OUTPUT.PUT_LINE('PLEASE ENTER A VALID WITHDRAWAL AMOUNT'); END; -- Block 3: Check if user is old enough BEGIN IF V_AGE < 18 THEN RAISE AGE_EXCEPTION; END IF; EXCEPTION WHEN AGE_EXCEPTION THEN DBMS_OUTPUT.PUT_LINE('YOU ARE NOT ELIGIBLE TO WITHDRAW'); END; END; /
Output: WITHDRAWAL SUCCESSFUL  → YOU ARE NOT ELIGIBLE TO WITHDRAW
8. Single Block vs Nested Block — Key Difference
FeatureSingle Exception BlockNested Exception Blocks
How many exceptions fire?Only the FIRST matching exception fires. All remaining checks are skipped.Each inner block handles its own exception independently. All blocks execute.
Use whenOnly one condition matters at a timeMultiple conditions must all be validated independently
ExampleMARKS > 100 fires → zero-check skippedMARKS > 100 fires in block 1, zero-check runs in block 2
Extra — Why Nested Blocks?

In a single EXCEPTION block, once the first exception is raised, execution jumps directly to the EXCEPTION section and the remaining BEGIN logic is skipped. Nested blocks allow each condition to be checked and handled separately — useful in real-world validations where multiple rules must all be enforced.

9. Frequently Asked Interview Questions
Q1. What is an exception in PL/SQL?
An exception is a runtime error that occurs while a PL/SQL program is executing. PL/SQL provides the EXCEPTION section to handle these errors gracefully — preventing crashes and allowing custom error messages.
Q2. What are the types of exceptions in PL/SQL?
1. Predefined Exceptions — Oracle has already defined 20 exception names for common errors (NO_DATA_FOUND, TOO_MANY_ROWS, ZERO_DIVIDE, etc.). 2. User-Defined Exceptions — created by the developer using DECLARE → RAISE → HANDLE.
Q3. What is NO_DATA_FOUND?
NO_DATA_FOUND is raised when a SELECT INTO statement returns zero rows. Oracle Error: ORA-01403. It is handled in the EXCEPTION block using WHEN NO_DATA_FOUND THEN.
Q4. What is the difference between INVALID_NUMBER and VALUE_ERROR?
INVALID_NUMBER is raised when a string-to-number conversion fails inside a SQL statement (e.g., INSERT with a non-numeric value in a NUMBER column). VALUE_ERROR is raised when a value is too large for a PL/SQL variable or when string-to-number conversion fails inside PL/SQL code (not SQL).
Q5. What are the steps to create a User-Defined Exception?
Step 1: DECLARE — define the exception name using the EXCEPTION keyword in the DECLARE section. Step 2: RAISE — use the RAISE keyword inside the BEGIN section when the condition is met. Step 3: HANDLE — use WHEN exception_name THEN in the EXCEPTION section.
Q6. What is WHEN OTHERS in PL/SQL exception handling? Extra
WHEN OTHERS is a catch-all exception handler that handles any exception not covered by a specific WHEN clause. It must always be the LAST handler in the EXCEPTION section. It is used to avoid unexpected program crashes from unhandled errors.
Q7. What is the difference between a single EXCEPTION block and nested blocks? Extra
In a single EXCEPTION block, only the first raised exception is handled — the rest of the BEGIN logic is skipped. In nested blocks, each inner block handles its own exception independently, allowing multiple validations to all execute even if one raises an exception.
Q8. What error does ZERO_DIVIDE raise? Extra
ZERO_DIVIDE raises ORA-01476: divisor is equal to zero. It occurs when a PL/SQL program attempts to divide a number by zero during execution.
Q9. What is the difference between INVALID_CURSOR and CURSOR_ALREADY_OPEN? Extra
INVALID_CURSOR is raised when you try to FETCH or CLOSE a cursor that was never opened. CURSOR_ALREADY_OPEN is raised when you try to OPEN a cursor that is already open. Both return ORA-01001.
