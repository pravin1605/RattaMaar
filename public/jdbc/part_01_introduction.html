📘 1. What is JDBC?

JDBC stands for Java Database Connectivity. It is an API (Application Programming Interface) provided by Java that allows Java programs to connect with databases, send SQL queries, and get results.

Using JDBC, Java can communicate with databases like:

  • PostgreSQL
  • MySQL
  • Oracle
  • SQL Server
  • SQLite
🔹 Real-Life Example:

You = Java Program 👨‍💻
Friend = Database 🗄️
Language difference exists ❌
👉 You need a translator → That translator is JDBC

JDBC is a Java API that provides a standard way for Java applications to interact with relational databases using SQL.
📘 2. Why JDBC is Used?

JDBC is used to:

  • Connect Java with database
  • Execute SQL queries (INSERT, UPDATE, DELETE, SELECT)
  • Fetch data from database
  • Store data into database
🔹 Real-Life Example — ATM Machine:

You insert card → Java program
Machine connects to bank server → JDBC
Fetches your balance → Database

👉 Without JDBC, Java cannot talk to database.

Without JDBC, Java has no standard mechanism to communicate with a database. JDBC acts as the bridge between the Java application layer and the database layer.
📘 3. Key Features / Properties of JDBC
🔹 1. Platform Independent

Works on any OS (Windows, Linux, Mac)

🔹 2. Database Independent

Can connect to MySQL, PostgreSQL, Oracle, SQL Server. Only driver changes, code remains almost same.

🔹 3. Simple API

Provides interfaces like: Connection, Statement, ResultSet

🔹 4. Supports SQL

DDL → CREATE, ALTER
DML → INSERT, UPDATE, DELETE
DQL → SELECT

🔹 5. Secure (PreparedStatement)

Prevents SQL Injection

🔹 6. Reusable

PreparedStatement can be executed multiple times

📘 4. What is Vendor in JDBC?

👉 Vendor = Database Company / Provider

Examples:

  • Oracle Corporation → Oracle DB
  • PostgreSQL Global Development Group → PostgreSQL
  • Microsoft → SQL Server
🔹 Real-Life Example:

JDBC = Universal charger 🔌
Vendor = Mobile company 📱
Each company needs a different pin (driver)

Vendor refers to the database company/provider. Each vendor provides their own JDBC driver. Only the driver changes per vendor; the JDBC API remains the same.

📘 5. What is JDBC Driver?

👉 A Driver is a software component that helps Java communicate with database.

🔹 Simple Definition:

JDBC Driver converts Java commands into database-understandable format.

🔹 Real-Life Example:

You speak English
Database understands SQL
👉 Driver = Translator 🧠

🔹 Flow:
Java
↓
JDBC API
↓
Driver (Translator)
↓
Database
A JDBC Driver is a software component that translates Java method calls into database-specific protocol calls, enabling communication between Java and the database.
📘 6. Types of JDBC Drivers (Important for Interview)
Type 1 JDBC-ODBC Bridge Driver
  • Old and removed in modern Java
  • Uses ODBC driver
  • ❌ Slow performance
Type 2 Native API Driver
  • Uses database-specific libraries
  • 👉 Example: Oracle native driver
  • Partially Java
Type 3 Network Protocol Driver
  • Uses middleware server
  • 👉 Less used today
  • Pure Java
★ Most ImportantType 4 Thin Driver
  • Pure Java driver
  • Directly connects to database
  • ✔ Fast ✔ Most used in real projects
  • 👉 Example: PostgreSQL Driver → org.postgresql.Driver
Type 4 (Thin Driver) is the most preferred in real projects because it is pure Java, platform-independent, and directly communicates with the database without any middleware.

JDBC — COMPLETE STUDY NOTES | Page 3 — Step 1: Load & Register Driver
✅ Step 1: Load & Register Driver (Deep Explanation)
🔹 Why do we load and register the driver?

👉 Purpose:

  • Java doesn't know how to talk to database directly
  • Driver acts as a bridge/translator between Java and DB

🧠 Flow: Java → JDBC API → Driver → Database

👉 Without driver: ❌ Java cannot understand DB-specific language

🔹 Two Ways to Load Driver

✔️ 1. Using Class.forName()

Class.forName("org.postgresql.Driver");

✔️ 2. Using Driver object

Driver d = new Driver(); DriverManager.registerDriver(d);

👉 Both do same thing → register driver with DriverManager

🔍 Deep Dive into Class.forName()
🔹 What is Class?

👉 Class is a built-in class in Java (java.lang package)

👉 Example: It holds information like:

  • Class name
  • Methods
  • Constructors
🔹 What is forName()?

👉 forName() is a static method of Class class

Syntax:

Class.forName("fully_qualified_class_name");
🔹 What happens internally?
Class.forName("org.postgresql.Driver");

👉 Step-by-step:

  1. JVM searches this class in classpath
  2. Loads it into memory
  3. Executes static block inside driver class
🔥 Important Point
Inside PostgreSQL driver:
static { DriverManager.registerDriver(new Driver()); }
👉 So automatically:
✔️ Driver gets registered
✔️ You don't need manual registration
🔹 What is inside "org.postgresql.Driver"?

👉 This is called Fully Qualified Class Name (FQCN)

Breakdown:

  • org → organization
  • postgresql → package
  • Driver → class

👉 It tells JVM: "Load this exact driver class"

🔹 What does driver do after loading?

👉 Driver:

  • Registers with DriverManager
  • Knows how to:
    • Open DB connection
    • Send SQL
    • Receive results
⚠️ Exception: When driver JAR is not added to classpath, it shows ClassNotFoundException. We need to propagate this exception (throws or try-catch).
Class.forName() dynamically loads the driver class into JVM memory at runtime. Its internal static block auto-registers the driver with DriverManager, making it ready to establish database connections.
JDBC — COMPLETE STUDY NOTES | Page 4 — Step 2: Create Connection
✅ Step 2: Create Connection
🔹 Meaning

👉 Establish a live connection (session) between Java application and the database so queries can be executed.

🔹 Syntax
Connection con = DriverManager.getConnection( "jdbc:postgresql://localhost:5432/mydb", "postgres", "password" );
🔍 URL Breakdown (Very Important)
jdbc:postgresql://localhost:5432/mydb

🧠 What each part means:

  • jdbc → tells Java we're using JDBC API
  • postgresql → which DB driver to use
  • localhost → DB server location (your machine)
  • 5432 → port where DB listens
  • mydb → specific database to connect
🔹 What is DriverManager?

👉 A JDBC class (java.sql package) that:

  • Maintains list of all registered drivers
  • Chooses the correct driver based on URL
  • Establishes connection between Java and DB

DriverManager = Manager who assigns right driver

🔹 What is getConnection()?

getConnection() is a static factory method of the DriverManager class that is used to establish a connection with a database and return a Connection object without exposing its implementation details.

🔹 Overloaded Methods of getConnection()

✔️ 1. Using URL + username + password

Connection con = DriverManager.getConnection(url, user, password);

✔️ 2. Using only URL (credentials inside URL)

Connection con = DriverManager.getConnection( "jdbc:postgresql://localhost:5432/mydb?user=postgres&password=root" );

✔️ 3. Using Properties object

Properties p = new Properties(); p.put("user", "postgres"); p.put("password", "root"); Connection con = DriverManager.getConnection(url, p);
🔹 What is Connection?

👉 An interface in java.sql package

Purpose:

  • Represents a session with database
  • Used to:
    • Create statements
    • Execute queries
    • Manage transactions

Common Methods:

con.prepareStatement(...) con.createStatement() con.setAutoCommit(false) con.close()
🔹 Why this line is used?
Connection con = DriverManager.getConnection(...);

👉 Without this:

  • ❌ No communication with DB
  • ❌ No query execution
  • ✔️ It is the entry point to database operations
🔴 Exceptions (Very Important)

✔️ 1. SQLException

👉 Main exception

❓ When occurs?

  • Wrong URL
  • Wrong username/password
  • DB not running
  • Network issue
DriverManager.getConnection() is a static factory method that scans registered drivers, matches the URL to the correct driver, and returns a Connection object representing an active session with the database.

✅ Step 3: Create Statement
🔹 Meaning

👉 Create an object that can send SQL queries from Java to the database.

👉 After connection, this is the tool used to communicate with DB.

✅ Statement (Only)
🔹 Meaning

👉 Used to send simple SQL queries from Java to the database.

🔹 Syntax
Statement stmt = con.createStatement();
🔹 Breakdown
  • Statement → Interface from java.sql
  • con.createStatement() → createStatement() is an instance method of the Connection interface used to create and return a Statement object for executing SQL queries.
  • Returns a Statement object
🔹 How it Works
  • SQL query is written directly (hardcoded)
  • Sent to database
  • Database compiles and executes every time
🔹 Example
Statement stmt = con.createStatement(); stmt.executeUpdate("INSERT INTO emp VALUES(101, 'Pravin', 30000)");
🔹 Execution Methods
executeQuery() → for SELECT
executeUpdate() → for INSERT, UPDATE, DELETE
execute() → for any SQL
🔹 Disadvantages
  • ❌ Prone to SQL Injection
  • ❌ Slower (no pre-compilation)
  • ❌ Not reusable
🔹 Exception
  • SQLException → if query is wrong / DB issue
con.createStatement() is an instance method of the Connection interface that creates a Statement object. Statement sends hardcoded SQL queries to the database but is prone to SQL Injection and slower due to no pre-compilation.
JDBC — COMPLETE STUDY NOTES | Page 6 — Step 4: Execute the Query
✅ Step 4: Execute the Query (PostgreSQL)
🔹 Meaning

👉 Send the SQL query to PostgreSQL and get result / perform operation.

🔹 Methods
🔸 1. executeQuery() (For SELECT)
ResultSet rs = stmt.executeQuery("SELECT * FROM emp");

🔍 Breakdown:

  • executeQuery() → method of Statement
  • Used only for SELECT
  • Returns a ResultSet
🔹 What is ResultSet?

👉 ResultSet is an interface (java.sql package)

🧠 Meaning:

  • Represents data returned from database in tabular form
  • Like a table cursor (points to rows one by one)
🔹 How it works
  • Initially pointer is before first row
  • You must move it using next()
🔹 Important Methods
while(rs.next()) { int id = rs.getInt("eid"); String name = rs.getString("ename"); double sal = rs.getDouble("esal"); }

🔍 Methods Explanation:

  • rs.next() → Moves cursor to next row. Returns true if row exists
  • getInt("column") → fetch integer column value
  • getString("column") → fetch string column value
  • getDouble("column") → fetch double column value
🔸 2. executeUpdate() (For INSERT, UPDATE, DELETE)
int rows = stmt.executeUpdate("INSERT INTO emp VALUES(1,'John',30000)");

🔍 Breakdown:

  • Returns number of rows affected
  • Insert → 1
  • Update → number of rows updated
🔸 3. execute() (For both)
boolean result = stmt.execute("SELECT * FROM emp");

🔍 Breakdown:

  • Returns boolean
  • true → ResultSet available
  • false → update count
🔴 Exception

✔️ SQLException

👉 Occurs when:

  • Wrong SQL syntax
  • Table/column not found
  • PostgreSQL server issue
executeQuery() is used for SELECT and returns a ResultSet. executeUpdate() is used for INSERT/UPDATE/DELETE and returns rows affected. execute() works for both and returns a boolean.

✅ Step 5: Close the Connection
🔹 Meaning

👉 Close all JDBC resources after execution to free memory and avoid resource leaks.

🔹 Syntax
rs.close(); stmt.close(); con.close();
🔍 Breakdown
  • ResultSet.close() → closes fetched data
  • Statement.close() → closes query object
  • Connection.close() → ends database session
🔹 Why this step is important
  • Prevents memory leaks
  • Frees database resources
  • Avoids connection overload
  • Improves performance
⚠️ Best Practice: Always close in reverse order of creation: ResultSet → Statement → Connection. Use try-with-resources in modern Java for automatic cleanup.
Not closing JDBC resources causes resource leaks and connection pool exhaustion. Closing order must be ResultSet → Statement → Connection. Use try-with-resources for automatic cleanup in modern Java.
📋 Quick Reference — JDBC Interfaces & Classes
DriverManager class

java.sql. Manages registered drivers. getConnection() picks correct driver from URL.

Connection interface

java.sql. Represents live DB session. Creates statements, manages transactions.

Statement interface

java.sql. Sends SQL to DB. Prone to SQL Injection. No pre-compilation.

ResultSet interface

java.sql. Holds SELECT results as tabular data. Cursor-based row iteration.

PreparedStatement interface

java.sql. Pre-compiled SQL. Prevents SQL Injection. Reusable. Preferred.

SQLException exception

Main checked exception. Thrown for DB errors, wrong URL, wrong credentials.
