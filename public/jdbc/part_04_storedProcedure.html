📘 1. What is PreparedStatement?

👉 PreparedStatement is an interface in the java.sql package that is used to execute parameterized SQL queries.

👉 It extends the Statement interface and adds the ability to use placeholders (?) in SQL queries instead of hardcoding values.

👉 The SQL query is pre-compiled by the database once and then executed multiple times with different parameter values — making it faster and more secure.

🔹 Real-Life Analogy
Statement (Old Way)

Like writing a new letter every time you want to send to someone — you rewrite the full letter each time with different names.

❌ Slow. ❌ Not secure.

PreparedStatement (Better Way)

Like having a template letter with blanks (_____) — you just fill in the blanks each time. Template is ready — only values change.

✅ Fast. ✅ Secure.

PreparedStatement is an interface in java.sql that extends Statement. It uses ? as placeholders for parameters, pre-compiles the SQL query, prevents SQL Injection, and is faster for repeated executions.
📘 2. Why PreparedStatement? (Problems with Statement)
❌ Problems with Statement:
  • SQL Injection Risk — user input is directly placed in SQL string → attacker can manipulate query
  • Slow — DB compiles the SQL query every single time execute() is called
  • Not Reusable — new compilation on every call
  • Hard to read — SQL with concatenated strings is messy
// Statement — UNSAFE String name = "Pravin"; stmt.execute( "insert into student values(1,'" + name + "',20)"); // If name = "'; DROP TABLE student;--" // → SQL Injection attack!
✅ Solutions with PreparedStatement:
  • SQL Injection Prevention — values set via setXxx() methods — treated as pure data, not SQL code
  • Faster — SQL pre-compiled once, executed many times with different values
  • Reusable — same PreparedStatement used with different parameter values
  • Cleaner code — ? placeholders make SQL readable
// PreparedStatement — SAFE PreparedStatement ps = con.prepareStatement( "insert into student values(?,?,?)"); ps.setInt(1, 1); ps.setString(2, "Pravin"); // Safe! ps.setInt(3, 20);
PreparedStatement solves two major problems of Statement: SQL Injection vulnerability and poor performance. It pre-compiles SQL once and treats all user input as data — never as SQL code — making it safe and fast.
📘 3. How to Create PreparedStatement
🔹 Syntax
PreparedStatement ps = connection.prepareStatement(String sql);
📖 Breakdown
PreparedStatement
Interface in java.sql package. Extends Statement. Reference variable type.
ps
Variable name — holds reference to PreparedStatement object returned by prepareStatement()
connection.prepareStatement(sql)
Non-static (instance) method of Connection interface. Sends SQL to DB for PRE-COMPILATION. Returns PreparedStatement object.
? (placeholder)
Question mark in SQL = placeholder for a parameter. Each ? is replaced by actual value using setXxx() methods.
🔹 What happens when prepareStatement() is called?
Java sends SQL with ? to DB
→
DB compiles/parses SQL
→
Compiled plan stored in DB
→
On execute() → just fill ? values

👉 DB does NOT re-compile on every execute — only fills in the ? values → much faster

prepareStatement() is a non-static method of Connection interface. It sends SQL to DB for pre-compilation at the time of object creation — not at execution time. The compiled plan is reused on every executeUpdate()/executeQuery() call.

📘 4. setXxx() Methods — Setting Parameter Values

👉 After creating PreparedStatement, we must set values for each ? placeholder using setXxx() methods.

👉 Index starts from 1 (not 0 — unlike Java arrays).

👉 setXxx() is a non-static (instance) method of PreparedStatement.

🔹 Syntax
ps.setInt(int parameterIndex, int value); ps.setString(int parameterIndex, String value); ps.setDouble(int parameterIndex, double value); ps.setFloat(int parameterIndex, float value); ps.setLong(int parameterIndex, long value); ps.setBoolean(int parameterIndex, boolean value); ps.setDate(int parameterIndex, Date value); ps.setNull(int parameterIndex, int sqlType);
Method Java Type SQL Type Example
setInt(index, value)intINTEGERps.setInt(1, 101)
setString(index, value)StringVARCHAR / TEXTps.setString(2, "Pravin")
setDouble(index, value)doubleDOUBLE / NUMERICps.setDouble(3, 50000.0)
setFloat(index, value)floatFLOATps.setFloat(3, 50000.0f)
setBoolean(index, value)booleanBOOLEANps.setBoolean(4, true)
setDate(index, value)java.sql.DateDATEps.setDate(5, date)
setNull(index, sqlType)nullNULLps.setNull(3, Types.INTEGER)
⚠️ Index Rule — Very Important:
Index in setXxx() corresponds to the position of ? in SQL from left to right.
Example: "insert into student values(?,?,?)"
→ 1st ? = index 1, 2nd ? = index 2, 3rd ? = index 3
→ ps.setInt(1, sid) | ps.setString(2, sname) | ps.setInt(3, sage)
setXxx() methods replace ? placeholders in PreparedStatement with actual values. Index starts from 1, corresponding to the left-to-right position of ? in the SQL string. Values are treated as pure data — never as SQL code — preventing SQL Injection.

📄 Program 1 — InsertData.java (INSERT using PreparedStatement)
🔹 What this program does

Inserts one student record into the student table in SecondDayDataBase using PreparedStatement with ? placeholders and executeUpdate().

package com.ty; import java.sql.Connection; import java.sql.DriverManager; import java.sql.PreparedStatement; import java.sql.SQLException; public class InsertData { public static void main(String[] args) throws ClassNotFoundException, SQLException { // Step 1: Load and Register Driver Class.forName("org.postgresql.Driver"); // Step 2: Create Connection Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/SecondDayDataBase", "postgres", "root"); // Step 3: Create PreparedStatement // Query with placeholders (?) PreparedStatement preparedStatement = connection.prepareStatement("insert into student values(?,?,?)"); // Step 4: Set Values // Index starts from 1 preparedStatement.setInt(1, 2); preparedStatement.setString(2, "mayuresh"); preparedStatement.setInt(3, 25); // Step 5: Execute Query // executeUpdate() is better for INSERT int rows = preparedStatement.executeUpdate(); // Step 6: Close Connection connection.close(); System.out.println("Data added, rows affected = " + rows); } }
Data added, rows affected = 1
📖 Line-by-Line Explanation
import java.sql.PreparedStatement;
Import PreparedStatement interface from java.sql. Not auto-imported — must be declared explicitly.
connection.prepareStatement("insert into student values(?,?,?)")
Non-static method of Connection. Sends SQL to DB for pre-compilation. 3 ? placeholders — one for each column (sid, sname, sage).
preparedStatement.setInt(1, 2)
Sets 1st ? → integer value 2 → sid column. Index 1 = first ? from left.
preparedStatement.setString(2, "mayuresh")
Sets 2nd ? → String "mayuresh" → sname column. Treated as data — not SQL code.
preparedStatement.setInt(3, 25)
Sets 3rd ? → integer 25 → sage column. Index 3 = third ? from left.
int rows = preparedStatement.executeUpdate()
executeUpdate() — NO argument (SQL was given at prepareStatement()). Returns int = rows affected. For INSERT = 1.
📝 Key difference from Statement:
Statement: stmt.execute("insert into student values(1,'Pravin',20)") — SQL hardcoded
PreparedStatement: ps.executeUpdate() — NO SQL argument — SQL was given at prepareStatement() time.
Also: executeUpdate() is used here (not execute()) because it returns int (rows affected) which is more meaningful for DML.
In PreparedStatement, SQL is passed to prepareStatement() not to executeUpdate(). executeUpdate() takes NO argument. It returns int — number of rows affected. For INSERT, it returns 1. setXxx() index starts from 1, mapping to left-to-right position of ? in SQL.

📄 Program 2 — UpdateData.java (UPDATE using PreparedStatement)
🔹 What this program does

Updates sname and sage of the student where sid = 1 using PreparedStatement. Demonstrates correct order of setXxx() calls matching the SQL ? positions.

package com.ty; import java.sql.Connection; import java.sql.DriverManager; import java.sql.PreparedStatement; public class UpdateData { public static void main(String[] args) throws Exception { Class.forName("org.postgresql.Driver"); Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/SecondDayDataBase", "postgres", "root"); // SQL Query PreparedStatement ps = connection.prepareStatement( "UPDATE student SET sname=?, sage=? WHERE sid=?"); // Set values // Correct order ps.setString(1, "Pravin Updated"); // sname ps.setInt(2, 26); // sage ps.setInt(3, 1); // sid // Execute int rows = ps.executeUpdate(); System.out.println("Rows updated: " + rows); connection.close(); } }
Rows updated: 1
📖 Explanation
throws Exception
Exception is parent of both ClassNotFoundException and SQLException — shortcut to handle both in one clause. Less specific but valid.
"UPDATE student SET sname=?, sage=? WHERE sid=?"
SQL with 3 placeholders. 1st ?=sname, 2nd ?=sage, 3rd ?=sid. Order of ? matters — setXxx() must match this order.
ps.setString(1, "Pravin Updated")
1st ? → sname. Sets new name. Comment "// sname" confirms which column this index maps to.
ps.setInt(2, 26)
2nd ? → sage. Sets new age value 26.
ps.setInt(3, 1)
3rd ? → sid. WHERE condition — updates only row where sid = 1.
int rows = ps.executeUpdate()
Executes UPDATE. Returns 1 if row with sid=1 exists and updated, 0 if no row matched.
📝 Important — Order of setXxx() must match order of ? in SQL:
SQL: UPDATE student SET sname=?, sage=? WHERE sid=?
Index:                          1               2                    3
Wrong index → wrong column gets updated → data corruption!
In UPDATE with PreparedStatement, the WHERE clause ? comes last in SQL, so its setXxx() index is highest. The index of each setXxx() call must exactly match the left-to-right position of its ? in the SQL string.
📄 Program 3 — DeleteData.java (DELETE using PreparedStatement)
🔹 What this program does

Deletes the student record where sid = 2 using PreparedStatement. Simplest PreparedStatement — only one ? placeholder for the WHERE condition.

package com.ty; import java.sql.Connection; import java.sql.DriverManager; import java.sql.PreparedStatement; public class DeleteData { public static void main(String[] args) throws Exception { Class.forName("org.postgresql.Driver"); Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/SecondDayDataBase", "postgres", "root"); // SQL Query PreparedStatement ps = connection.prepareStatement( "DELETE FROM student WHERE sid=?"); // Set value ps.setInt(1, 2); // Execute int rows = ps.executeUpdate(); System.out.println("Rows deleted: " + rows); connection.close(); } }
Rows deleted: 1
📖 Explanation
"DELETE FROM student WHERE sid=?"
One ? placeholder — for the sid value in WHERE clause. No ? in DELETE for the row data — only condition needs parameter.
ps.setInt(1, 2)
Only one ? (index 1) — sets sid = 2. Deletes the row where sid = 2.
int rows = ps.executeUpdate()
Returns 1 if sid=2 existed and deleted, returns 0 if no row matched — no exception thrown.
📝 Safety of PreparedStatement DELETE:
With Statement: stmt.execute("DELETE FROM student WHERE sid=" + userInput) → If userInput = "1 OR 1=1" → deletes ALL rows!
With PreparedStatement: ps.setInt(1, userInput) → treated as pure int data → safe!
DELETE with PreparedStatement uses one ? for the WHERE condition. ps.setInt(1, 2) safely binds sid=2 as a parameter value — not SQL code. executeUpdate() returns 0 if no row matched — does not throw exception for "no rows deleted".

📄 Program 4 — FetchDataPrepared.java (SELECT + ResultSet using PreparedStatement)
🔹 What this program does

Fetches and displays student record where sid = 1 using PreparedStatement + executeQuery() + ResultSet. Also shows proper resource closing order: rs → ps → connection.

package com.ty; import java.sql.Connection; import java.sql.DriverManager; import java.sql.PreparedStatement; import java.sql.ResultSet; public class FetchDataPrepared { public static void main(String[] args) throws Exception { // Step 1: Load Driver Class.forName("org.postgresql.Driver"); // Step 2: Create Connection Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/SecondDayDataBase", "postgres", "root"); // Step 3: Create PreparedStatement PreparedStatement ps = connection.prepareStatement( "SELECT * FROM student WHERE sid=?"); // Step 4: Set value ps.setInt(1, 1); // Step 5: Execute Query ResultSet rs = ps.executeQuery(); // Step 6: Process Result while (rs.next()) { int id = rs.getInt("sid"); String name = rs.getString("sname"); int age = rs.getInt("sage"); System.out.println(id + " " + name + " " + age); } // Step 7: Close resources rs.close(); ps.close(); connection.close(); } }
1 Pravin Updated 26
📖 Line-by-Line Explanation
import java.sql.ResultSet;
Extra import — ResultSet needed for SELECT. Not imported in INSERT/UPDATE/DELETE programs.
ps.prepareStatement("SELECT * FROM student WHERE sid=?")
? placeholder for sid in WHERE clause. SQL pre-compiled with filter condition.
ps.setInt(1, 1)
Sets 1st ? = 1. Fetches only student where sid = 1.
ResultSet rs = ps.executeQuery()
executeQuery() — NO argument (SQL already in ps). Returns ResultSet with matching rows. Used for SELECT only.
rs.next()
Moves cursor to next row. Returns true if row exists. Cursor starts BEFORE first row.
rs.getInt("sid"), rs.getString("sname"), rs.getInt("sage")
Column name-based getters (better than index). "sid", "sname", "sage" match exact column names in DB table.
rs.close(); ps.close(); connection.close();
Correct closing order: ResultSet first → PreparedStatement second → Connection last. Reverse of creation order.
📝 Column name vs Column index — Comparison:
By index (Program 3 — Fetch_Data): rs.getInt(1) → fragile — breaks if column order changes in DB
By name (this program): rs.getInt("sid") → robust — works regardless of column order
👉 Column name method is preferred in real projects.
⚠️ Resource Closing — FetchDataPrepared is BEST PRACTICE:
Programs 1, 2, 3 — only close connection.close() (Statement/PS not closed explicitly)
Program 4 — closes ALL: rs.close() → ps.close() → connection.close()
Always close in reverse order of creation for complete resource cleanup.
executeQuery() in PreparedStatement takes NO argument — SQL was given at prepareStatement(). It returns ResultSet. Column name-based getters (rs.getInt("sid")) are preferred over index-based as they are more readable and robust to schema changes.

  • Index maps to left-to-right position of ? in SQL
  • SQL is passed to prepareStatement() — not to executeUpdate()
  • executeUpdate() / executeQuery() take NO argument
  • prepareStatement() = non-static method of Connection
  • PreparedStatement extends Statement interface
  • All in java.sql package
  • SQL pre-compiled once at prepareStatement()
  • Only ? values change on each execution — not SQL structure
  • Prevents SQL Injection — user input is data, not SQL code
  • executeUpdate() → DML → returns int (rows affected)

PreparedStatement pre-compiles SQL at creation time, reuses the plan on execution, treats all user input as data preventing SQL Injection, and is faster for repeated queries. It extends Statement. setXxx() index starts at 1. executeUpdate()/executeQuery() take no SQL argument.
