📘 1. What is a Connection Pool?

✅ Definition: A Connection Pool is a cache of pre-created database connections that are reused by applications instead of creating a new connection every time a DB operation is needed.

👉 Instead of opening and closing a connection on every request (expensive!), a pool of connections is created at startup and handed out to requests — then returned back to the pool after use.

Without Connection Pool ❌
  1. Request comes in
  2. New Connection created (slow!)
  3. DB operation done
  4. Connection closed (wasted!)
  5. Next request → repeat from step 1

👉 1000 requests = 1000 new connections opened and closed = very slow

With Connection Pool ✅
  1. App starts → 5 connections created at once
  2. Request 1 → gets conn from pool
  3. DB operation done
  4. Connection returned to pool (not closed)
  5. Next request → reuses same connection

👉 1000 requests = only 5 connections → much faster

🔹 Real-Life Analogy

Think of a taxi stand 🚕:

  • Pool = Taxi stand with 5 taxis ready
  • getConnection() = Taking a taxi from stand
  • recieveConnection() = Returning taxi back to stand
  • If all taxis busy → create new taxi (extra connection)
  • If stand full → close extra taxi (close extra connection)

A Connection Pool is a cache of pre-created, reusable database connections. Instead of creating a new connection per request (costly), the pool hands out existing connections and takes them back after use. This improves performance significantly in multi-request / multi-threaded applications.
📘 2. Why Connection Pool?
⚡ Performance

Creating a DB connection is expensive — involves network handshake, authentication, memory allocation. Pooling avoids this overhead on every request.

♻️ Reusability

Connections are reused instead of destroyed. Same 5 connections serve thousands of requests over time.

🔒 Resource Control

Pool limits max connections to DB. Prevents DB server from being overwhelmed. Extra connections closed when pool is full.

Connection Pooling improves performance by reusing pre-created connections, avoids repeated creation overhead, controls resource usage by capping max connections, and is essential in real-world applications where many users query the DB simultaneously.
📘 3. Key Concepts Used in this Program
🔹 Static Variables

All fields (driverPath, url, user, password, connect, pool_size) are static — they belong to the class, not any object. Shared across all usages.

🔹 Static Block

A static { } block runs once automatically when the class is first loaded by JVM — before main() or any constructor. Used here to:

  • Load the JDBC driver
  • Create 5 connections and fill the pool

👉 Pool is ready before anyone calls getConnection().

🔹 ArrayList<Connection>

ArrayList<Connection> stores the pool of connections.

  • add(conn) → add connection to pool
  • remove(0) → remove first connection from pool (give to requester)
  • isEmpty() → check if pool has any connections
  • size() → how many connections currently in pool
🔹 pool_size = 5

Maximum connections maintained in pool. If pool has < 5 → return connection to pool. If pool has = 5 already → close the extra connection.

The pool uses ArrayList<Connection> as the container. static variables ensure one shared pool. static block initializes the pool once at class load. pool_size controls max connections in pool — excess connections are physically closed to prevent resource waste.
Connection Pool Notes | Page 2 — ConnectionPool.java (Core Pool Class)
📄 ConnectionPool.java — Complete Pool Implementation
🔹 What this class does

This is the core pool class. It creates 5 connections at startup (via static block), provides getConnection() to lend a connection, and recieveConnection() to take it back. All methods and fields are static — no object creation needed.

package jdbc6thday; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.util.ArrayList; public class ConnectionPool { // Static fields — class-level, shared across all callers private static String driverPath = "org.postgresql.Driver"; private static String url = "jdbc:postgresql://localhost:5433/jdbc6thday"; private static String user = "postgres"; private static String password = "root"; private static ArrayList<Connection> connect = new ArrayList<Connection>(); private static int pool_size = 5; // Static block — runs ONCE when class is first loaded by JVM static { try { Class.forName(driverPath); for (int i = 0; i < pool_size; i++) { connect.add(createConnection()); } } catch (ClassNotFoundException e) { e.printStackTrace(); } catch (SQLException e) { e.printStackTrace(); } } // Private helper — creates one fresh DB connection private static Connection createConnection() throws SQLException { Connection connection = null; connection = DriverManager.getConnection(url, user, password); return connection; } // Public — give a connection from pool (or create new if pool empty) public static Connection getConnection() throws SQLException { if (!connect.isEmpty()) { return connect.remove(0); } else { return createConnection(); } } // Public — return connection back to pool (or close if pool is full) public static void recieveConnection(Connection c) throws SQLException { if (connect.size() < pool_size) { connect.add(c); } else { c.close(); } } }
📖 Field-by-Field Explanation
private static String driverPath
FQCN of PostgreSQL driver. private = only used inside this class. static = shared at class level, no object needed.
private static String url
JDBC connection URL for jdbc6thday database on port 5433.
private static ArrayList<Connection> connect
The actual pool — ArrayList storing live Connection objects. Private — only this class manages it directly.
private static int pool_size = 5
Maximum number of connections in pool. Controls both initial creation (loop) and return logic (size check).
📖 Method-by-Method Explanation
static { Class.forName(); for loop → add(createConnection()) }
Static initializer block. Runs once at class load. Loads driver. Creates 5 connections using createConnection() and adds to pool ArrayList.
private static Connection createConnection()
Helper method — creates one fresh DB connection using DriverManager.getConnection(). Private — not called by outside classes directly.
public static Connection getConnection()
If pool not empty → remove(0) returns first connection from list and removes it from pool. If pool empty → create new connection on-demand (emergency).
public static void recieveConnection(Connection c)
Return connection back. If pool has less than pool_size → add it back (reuse). If pool already full (size == 5) → close the connection permanently (discard extra).
📝 getConnection() Logic:
connect.remove(0) → removes and returns the connection at index 0 (first connection). ArrayList shifts remaining connections. This removes it from the pool so another caller can't get the same connection simultaneously.

📝 recieveConnection() Logic:
connect.size() < pool_size → if pool has space → add back for reuse
else c.close() → pool is full → physically close this connection to free DB resources
getConnection() uses remove(0) to atomically take the first connection out of the pool — removing it so no other caller gets it. recieveConnection() returns it back if pool has space, or closes it if pool is full. The static block pre-fills the pool at class load time.
Connection Pool Notes | Page 3 — InsertData.java (Batch) & deletedata.java
📄 InsertData.java — INSERT using Batch + PreparedStatement + Connection Pool
🔹 What this program does

Gets a connection from the pool, uses PreparedStatement with Batch to insert 3 student records in a single DB trip, then returns the connection back to pool using recieveConnection().

package jdbc6thday; import java.sql.Connection; import java.sql.PreparedStatement; import java.sql.SQLException; public class InsertData { public static void main(String[] args) throws SQLException { Connection c = ConnectionPool.getConnection(); // Statement s = c.createStatement(); ← commented out // s.execute("Insert into student values(101,'abc',35)"); ← old way PreparedStatement p = c.prepareStatement("insert into student values (?,?,?)"); p.setInt(1, 102); p.setString(2, "Ram"); p.setInt(3, 20); p.addBatch(); p.setInt(1, 103); p.setString(2, "Ram"); p.setInt(3, 20); p.addBatch(); p.setInt(1, 105); p.setString(2, "Ram"); p.setInt(3, 20); p.addBatch(); p.executeBatch(); ConnectionPool.recieveConnection(c); System.out.println("Data inserted....."); } }
Data inserted.....
📖 Line-by-Line Explanation
Connection c = ConnectionPool.getConnection()
Gets a pre-existing connection from the pool. No new connection created — reused from pool. Static call — no object of ConnectionPool needed.
// Statement commented out
Old approach shown (commented) — Statement with execute(). New approach uses PreparedStatement with Batch for efficiency.
c.prepareStatement("insert into student values (?,?,?)")
PreparedStatement created from pool connection c. SQL pre-compiled once. 3 ? for sid, sname, sage.
p.setInt / p.setString — then p.addBatch()
Set values for each row, then addBatch() queues the INSERT. Repeated 3 times for 3 different rows. Not sent to DB yet.
p.executeBatch()
Sends ALL 3 queued INSERT statements to DB in ONE network trip. Much faster than 3 separate execute() calls.
ConnectionPool.recieveConnection(c)
Returns connection c back to pool for reuse. MUST be called after every DB operation — otherwise connection is lost from pool permanently.
📝 Batch Insert — 3 rows, 1 DB trip:
Row 1: sid=102, sname="Ram", sage=20 → addBatch()
Row 2: sid=103, sname="Ram", sage=20 → addBatch()
Row 3: sid=105, sname="Ram", sage=20 → addBatch()
executeBatch() → sends all 3 at once → returns int[] = {1, 1, 1}
Batch insert with PreparedStatement: set values → addBatch() → repeat for each row → executeBatch() sends all in one DB trip. ConnectionPool.getConnection() gets a pooled connection; recieveConnection() must be called after use to return it — otherwise pool shrinks permanently.
📄 deletedata.java — DELETE using Statement + Connection Pool
🔹 What this program does

Gets a connection from pool, deletes student where sname='Ram' using Statement, returns connection back to pool.

package jdbc6thday; import java.sql.Connection; import java.sql.SQLException; import java.sql.Statement; public class deletedata { public static void main(String[] args) throws SQLException { Connection c = ConnectionPool.getConnection(); Statement s = c.createStatement(); s.execute("delete from student where sname='Ram'"); ConnectionPool.recieveConnection(c); System.out.println("delete....."); } }
delete.....
📖 Explanation
ConnectionPool.getConnection()
Borrows a connection from pool. Pool now has 4 connections (one taken out).
c.createStatement()
Creates Statement on the pooled connection. Statement used for simple DELETE — no parameters needed.
s.execute("delete from student where sname='Ram'")
Deletes ALL rows where sname='Ram'. Returns false (DML — no ResultSet). Multiple rows may be deleted if multiple students named Ram exist.
ConnectionPool.recieveConnection(c)
Returns connection back to pool. Pool goes back to 5. Critical — if forgotten, pool shrinks by 1 each run.
In Connection Pool pattern, every getConnection() must be paired with a recieveConnection() call — similar to a lock-unlock pattern. Forgetting recieveConnection() causes pool depletion over time — connections leak out and pool eventually runs dry.
Connection Pool Notes | Page 4 — fetchdata.java & updateData.java
📄 fetchdata.java — SELECT using executeQuery() + ResultSet + Connection Pool
🔹 What this program does

Gets a connection from pool, executes SELECT query for student with sid=101, iterates ResultSet using index-based getters, then returns connection to pool.

package jdbc6thday; import java.sql.Connection; import java.sql.ResultSet; import java.sql.SQLException; import java.sql.Statement; public class fetchdata { public static void main(String[] args) throws SQLException { Connection c = ConnectionPool.getConnection(); Statement s = c.createStatement(); ResultSet r = s.executeQuery("select * from student where sid=101"); while (r.next()) { System.out.println(r.getInt(1) + "=Id"); System.out.println(r.getString(2) + "=Name"); } ConnectionPool.recieveConnection(c); } }
101=Id abc=Name
📖 Explanation
import java.sql.ResultSet
Extra import needed for SELECT — ResultSet holds the query result. Not needed in INSERT/UPDATE/DELETE programs.
ResultSet r = s.executeQuery("select * from student where sid=101")
executeQuery() — for SELECT only. Returns ResultSet r containing matching rows. Cursor starts before first row.
while (r.next())
Moves cursor to next row. Returns true if row exists. For sid=101 — only one row exists, so loop runs once.
r.getInt(1) / r.getString(2)
Index-based column access. Column 1 = sid (int), Column 2 = sname (String). Index starts at 1.
ConnectionPool.recieveConnection(c)
Returns connection to pool after all operations done. Note: ResultSet and Statement not explicitly closed here — good practice to close them before returning connection.
In Connection Pool pattern, for SELECT: get connection from pool → create statement → executeQuery() → process ResultSet → return connection to pool. Closing ResultSet and Statement before recieveConnection() is best practice to avoid resource leaks on the DB server side.

1
Class Loaded by JVM → static block runs → Class.forName() loads driver → loop creates 5 connections → pool ArrayList has 5 connections
2
Client calls getConnection() → pool not empty → remove(0) returns Conn1 → pool now has 4 connections
3
Client uses Connection → creates Statement/PreparedStatement → executes SQL → gets result
4

5
If pool empty & new request → getConnection() → creates new connection on-demand → not from pool
6
If pool full & connection returned → recieveConnection() → pool size = 5 already → c.close() discards extra

🗂️ Quick Revision — Key Rules
ConnectionPool Class Rules:
  • All fields and methods are static
  • Pool container: ArrayList<Connection>
  • Pool size: pool_size = 5
  • Static block runs ONCE at class load
  • getConnection() → remove(0) if not empty
  • getConnection() → createConnection() if empty
  • recieveConnection() → add(c) if size < pool_size
  • recieveConnection() → c.close() if pool full
Pattern Used in All Programs:
// 1. Get from pool Connection c = ConnectionPool.getConnection(); // 2. Do DB operation Statement s = c.createStatement(); s.execute(sql); // 3. ALWAYS return to pool ConnectionPool.recieveConnection(c);
Important Notes:
  • Always call recieveConnection() after use
  • Forgetting → pool depletes over time
  • This is a custom pool — real projects use HikariCP, C3P0, DBCP
  • Real pools handle threading, timeouts, validation
Connection Pool pattern: getConnection() borrows a connection; recieveConnection() returns it. static block initializes pool at class load. This custom pool uses ArrayList. In production, HikariCP or Apache DBCP are used — they add thread-safety, connection validation, timeout handling, and monitoring.
