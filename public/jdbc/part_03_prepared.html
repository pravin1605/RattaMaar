📄 Program 1 — InsertDataIntoTable.java (INSERT using Class.forName)
🔹 What this program does

This program demonstrates how to insert multiple rows into an employee table in PostgreSQL using JDBC. It uses Class.forName() to load the driver and statement.execute() to run INSERT queries.

package jdbcfirstdayproject; import java.sql.Connection; import java.sql.DriverManager; import java.sql.Statement; import java.sql.SQLException; public class InsertDataIntoTable { public static void main(String[] args) throws ClassNotFoundException, SQLException { // Step 1: Load and Register the Driver // Class is a predefined class in java.lang package // forName() is a static method used to load the driver class into memory Class.forName("org.postgresql.Driver"); // Step 2: Create Connection // DriverManager is a class that manages database drivers // getConnection() is a static factory method that returns Connection object Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/FirstDayDataBase", "postgres", "root" ); // Step 3: Create Statement // Connection is an interface // createStatement() is a non-static method of Connection // It returns a Statement object used to execute SQL queries Statement statement = connection.createStatement(); // Step 4: Execute Query (INSERT) // execute() is a non-static method present in Statement interface // It sends SQL query to database statement.execute("insert into employee values(101,'Pravin',50000)"); statement.execute("insert into employee values(102,'Mayuresh',40000)"); statement.execute("insert into employee values(103,'Vednat',50)"); // Step 5: Close Connection // Closes the database connection and releases resources connection.close(); System.out.println("Successfully data added"); } }
Successfully data added
📖 Short Explanation — Key Points
throws ClassNotFoundException, SQLException
Propagates both checked exceptions. ClassNotFoundException from Class.forName(), SQLException from getConnection() and execute().
Class.forName("org.postgresql.Driver")
Loads driver class into JVM. Internal static block calls DriverManager.registerDriver() automatically.
DriverManager.getConnection(url, user, pwd)
Static factory method. Picks registered PostgreSQL driver, establishes live DB session, returns Connection object.
connection.createStatement()
Non-static method of Connection interface. Creates Statement object to send SQL queries.
statement.execute("insert into...")
Non-static method of Statement. Sends INSERT SQL to DB. Returns boolean — false here (no ResultSet for INSERT).
connection.close()
Ends DB session. Releases all resources. Prevents memory leaks and connection pool exhaustion.
📝 Important: execute() is used here for INSERT — it works but returns false (boolean) since no ResultSet. More appropriate method for INSERT is executeUpdate() which returns int (rows affected). Both are correct.
Class.forName() loads the driver into JVM and its static block auto-registers it. execute() is a non-static method of Statement that sends any SQL to DB and returns boolean — false for DML operations like INSERT.

📄 Program 2 — UpdateData.java (UPDATE using Driver object registration)
🔹 What this program does

This program demonstrates how to update an existing row in the employee table. It uses the alternative driver registration method — creating a Driver object manually and registering it with DriverManager.registerDriver() instead of Class.forName().

package jdbcfirstdayproject; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.sql.Statement; import org.postgresql.Driver; public class UpdateData { public static void main(String[] args) throws SQLException { // Step 1: Load and Register the Driver // Creating object of PostgreSQL Driver // registerDriver() registers driver with DriverManager Driver d = new Driver(); DriverManager.registerDriver(d); // Step 2: Create Connection // Establish connection with PostgreSQL database Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/FirstDayDataBase", "postgres", "root"); // Step 3: Create Statement // createStatement() is non-static method of Connection interface // Returns Statement object to execute SQL queries Statement statement = connection.createStatement(); // Step 4: Execute Update Query // execute() method is used to run SQL query // Here we are updating salary of employee whose id = 101 statement.execute("update employee set salary=10 where id=101"); // Step 5: Close Connection // Close DB connection and release resources connection.close(); System.out.println("Successfully data updated"); } }
Successfully data updated
📖 Short Explanation — Key Points
import org.postgresql.Driver;
We import the actual PostgreSQL Driver class explicitly — needed because we create its object manually.
throws SQLException (only)
No ClassNotFoundException here — because we're NOT using Class.forName(). Driver object is created directly so no dynamic class loading.
Driver d = new Driver();
Creates object of PostgreSQL Driver class directly. This is explicit manual instantiation of the driver.
DriverManager.registerDriver(d);
Static method of DriverManager. Manually registers the driver object with DriverManager so it can be used for connections.
"update employee set salary=10 where id=101"
SQL UPDATE query — changes salary column to 10 for the row where id = 101.
🔑 Key Difference from Program 1 — Two Ways to Register Driver:
Way 1 (Program 1): Class.forName("org.postgresql.Driver") → Dynamic loading, auto-registers via static block. Throws ClassNotFoundException.
Way 2 (Program 2): Driver d = new Driver(); DriverManager.registerDriver(d); → Manual object creation + registration. Only throws SQLException.
👉 Both achieve the same result — driver gets registered with DriverManager.
📝 SQL UPDATE Breakdown: update employee set salary=10 where id=101
update employee → target table | set salary=10 → column to change and new value | where id=101 → condition — only row with id=101 is updated. Without WHERE clause — ALL rows would be updated!
In UpdateData.java, the driver is registered manually using Driver object and DriverManager.registerDriver(). This is an alternative to Class.forName(). Since no dynamic class loading, only SQLException is declared in throws clause — not ClassNotFoundException.

📄 Program 3 — DeleteData.java (DELETE + boolean return of execute())
🔹 What this program does

Deletes a record from employee table where id = 101. Also demonstrates that execute() returns a boolean — and that value is captured and printed.

package jdbcfirstdayproject; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.sql.Statement; public class DeleteData { public static void main(String[] args) throws ClassNotFoundException, SQLException { // Step 1: Load and Register Driver // Loads PostgreSQL driver into memory and registers it Class.forName("org.postgresql.Driver"); // Step 2: Create Connection // Establish connection with database Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/FirstDayDataBase", "postgres", "root"); // Step 3: Create Statement // Used to execute SQL queries Statement statement = connection.createStatement(); // Step 4: Execute Delete Query // Deletes record where id = 101 // execute() returns false because no ResultSet is returned boolean res = statement.execute("delete from employee where id = 101"); // Step 5: Close Connection // Releases database resources connection.close(); System.out.println("Successfully data deleted = " + res); } }
Successfully data deleted = false
📖 Short Explanation — Key Points
boolean res = statement.execute("delete...")
execute() returns boolean. For DELETE (DML) → returns false because no ResultSet is produced. Result is captured in variable res.
"delete from employee where id = 101"
SQL DELETE query — removes the row from employee table where id = 101. WHERE clause is mandatory otherwise ALL rows get deleted.
"Successfully data deleted = " + res
Prints the boolean result — output will be: Successfully data deleted = false
execute() returns false for DML operations (INSERT/UPDATE/DELETE) because they do not produce a ResultSet. It returns true only when a SELECT query is executed and a ResultSet is available.
📄 Program 4 — Fetch_Data.java (SELECT + ResultSet + executeQuery())
🔹 What this program does

Fetches and displays employee data where id = 102. Uses executeQuery() which returns a ResultSet. Iterates using rs.next() and reads column values using index-based getters.

package jdbcfirstdayproject; import java.sql.Connection; import java.sql.DriverManager; import java.sql.ResultSet; import java.sql.SQLException; import java.sql.Statement; public class Fetch_Data { public static void main(String[] args) throws ClassNotFoundException, SQLException { // Step 1: Load and Register Driver // Loads PostgreSQL driver class into memory Class.forName("org.postgresql.Driver"); // Step 2: Create Connection // Establish connection with database Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/FirstDayDataBase", "postgres", "root"); // Step 3: Create Statement // Used to execute SQL queries Statement statement = connection.createStatement(); // Step 4: Execute SELECT Query // executeQuery() is used for SELECT and returns ResultSet ResultSet rs = statement.executeQuery("select * from employee where id = 102"); // ResultSet is an interface that holds data in tabular form // Cursor initially points before first row while (rs.next()) { // Moves cursor to next row // Fetch data column-wise System.out.println(rs.getInt(1) + " = Id"); System.out.println(rs.getString(2) + " = Name"); System.out.println(rs.getDouble(3) + " = Salary"); System.out.println("================================="); } // Step 5: Close Connection connection.close(); System.out.println("Successfully data displayed"); } }
102 = Id Mayuresh = Name 40000.0 = Salary ================================= Successfully data displayed
📖 Short Explanation — Key Points
import java.sql.ResultSet;
Extra import needed — ResultSet interface holds SELECT query results. Not needed in INSERT/UPDATE/DELETE programs.
ResultSet rs = statement.executeQuery(...)
executeQuery() — used ONLY for SELECT. Returns ResultSet (tabular data). Cannot be used for INSERT/UPDATE/DELETE.
rs.next()
Moves cursor to next row. Returns true if row exists, false when no more rows. Cursor starts BEFORE first row.
rs.getInt(1), rs.getString(2), rs.getDouble(3)
Column index-based getters (index starts at 1). getInt(1)=id, getString(2)=name, getDouble(3)=salary.
📝 Two ways to read ResultSet columns:
By index: rs.getInt(1) — column position (starts at 1)
By name: rs.getInt("id") — column name (more readable, preferred in real projects)
executeQuery() is used exclusively for SELECT statements and returns a ResultSet. ResultSet cursor initially points before first row — rs.next() moves it forward row by row, returning true as long as rows exist.

📘 Hierarchy of Statement in JDBC

👉 All come under java.sql package

Statement (Interface) ↑ ├── PreparedStatement (Interface) │ ↑ │ └── CallableStatement (Interface)
🔹 Explanation
Statement Base Interface
  • Base interface for all statement types
  • Executes static/hardcoded SQL
  • No parameters
  • No pre-compilation
  • Simple but less secure
PreparedStatement Extends Statement
  • Extends Statement interface
  • Executes parameterized SQL using ?
  • Pre-compiled → faster on repeat
  • Prevents SQL Injection
  • Used in real projects
CallableStatement Extends PreparedStatement
  • Extends PreparedStatement
  • Calls stored procedures in DB
  • Supports IN / OUT parameters
  • Pre-compiled
  • Used in enterprise logic

Statement hierarchy: Statement → PreparedStatement → CallableStatement. All are interfaces in java.sql. PreparedStatement extends Statement and adds pre-compilation + parameterized queries. CallableStatement extends PreparedStatement and adds support for stored procedures with IN/OUT parameters.

📘 JDBC Execute Methods (Complete List)
🔹 1. executeQuery()

✅ Definition: Executes SELECT query and returns data as ResultSet.

✅ Syntax:

// Statement ResultSet rs = stmt.executeQuery(String sql); // PreparedStatement ResultSet rs = ps.executeQuery(); // CallableStatement ResultSet rs = cs.executeQuery();

✅ Arguments:

InterfaceArgument
StatementString sql
PreparedStatement❌ No argument
CallableStatement❌ No argument

✅ Return: 👉 ResultSet

📝 Extra: Only for SELECT. Throws SQLException if used with INSERT/UPDATE/DELETE. ResultSet cursor starts before first row — use rs.next() to iterate.
🔹 2. executeUpdate()

✅ Definition: Executes INSERT, UPDATE, DELETE, DDL queries and returns affected rows.

✅ Syntax:

int rows = stmt.executeUpdate(String sql); int rows = ps.executeUpdate(); int rows = cs.executeUpdate();

✅ Return: 👉 int (rows affected)

📝 Extra: For DDL (CREATE, DROP) — returns 0. For DML — returns actual rows affected. More appropriate than execute() for INSERT/UPDATE/DELETE as it gives row count.
🔹 3. execute()

✅ Definition: Executes any SQL query and returns boolean.

✅ Syntax:

boolean result = stmt.execute(String sql); boolean result = ps.execute(); boolean result = cs.execute();

✅ Return: 👉 boolean

  • true → ResultSet available (SELECT)
  • false → update count (DML)
📝 Extra: Most generic method — works for all SQL. Used in our 4 programs for INSERT/UPDATE/DELETE. Returns false for all DML because no ResultSet is produced.
🔹 4. addBatch() ⭐

✅ Definition: Adds multiple SQL queries to a batch to execute later.

✅ Syntax:

🔸 Statement:

stmt.addBatch("INSERT INTO student VALUES(1,'A',20)"); stmt.addBatch("INSERT INTO student VALUES(2,'B',22)");

🔸 PreparedStatement:

ps.setInt(1, 1); ps.setString(2, "A"); ps.setInt(3, 20); ps.addBatch(); ps.setInt(1, 2); ps.setString(2, "B"); ps.setInt(3, 22); ps.addBatch();

🔸 CallableStatement:

cs.addBatch();

✅ Argument:

InterfaceArgument
StatementString sql
PreparedStatement❌ No argument
CallableStatement❌ No argument
📝 Extra: addBatch() does NOT execute the query immediately — it only adds to the batch queue. Actual execution happens when executeBatch() is called. Used for bulk operations — much faster than individual execute() calls.
Statement Codes | Page 6 — executeBatch(), clearBatch() & Complete Execute Method Summary
📘 JDBC Execute Methods — Continued
🔹 5. executeBatch() ⭐

✅ Definition: Executes all queries added in batch and returns array of results.

✅ Syntax:

int[] result = stmt.executeBatch(); int[] result = ps.executeBatch(); int[] result = cs.executeBatch();

✅ Return: 👉 int[] (array of update counts)

📝 Extra — How addBatch() + executeBatch() work together:
// Step 1: Add queries to batch stmt.addBatch("INSERT INTO student VALUES(1,'A',20)"); stmt.addBatch("INSERT INTO student VALUES(2,'B',22)"); stmt.addBatch("INSERT INTO student VALUES(3,'C',21)"); // Step 2: Execute all at once int[] result = stmt.executeBatch(); // result = [1, 1, 1] — each 1 means 1 row inserted per query
Why use batch? Instead of 1000 separate execute() calls (1000 trips to DB), batch sends all in one trip → much faster → reduces network overhead.
🔹 6. clearBatch()

✅ Definition: Clears all queries from batch.

✅ Syntax:

stmt.clearBatch(); ps.clearBatch(); cs.clearBatch();

✅ Return: 👉 void

📝 Extra: Used to cancel/empty all previously added batch queries without executing them. Useful when you want to reset the batch in case of errors or conditional logic before calling executeBatch().
addBatch() adds SQL queries to a batch queue without executing. executeBatch() sends all queued queries to DB in one trip and returns int[] (update count per query). clearBatch() empties the queue. Batch processing is significantly faster than individual execute() calls for bulk operations.

true → first result is a ResultSet (SELECT was run)
false → first result is an update count (DML/DDL was run)
