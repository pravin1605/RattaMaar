📘 1. What is DDL in SQL?

✅ Definition: DDL stands for Data Definition Language. It is a category of SQL commands used to define, create, modify, or delete database structures (not data).

🔹 DDL Commands:
CommandPurpose
CREATECreate database / table / index
ALTERModify existing table structure
DROPDelete database / table permanently
TRUNCATERemove all rows from table
RENAMERename a table or column
🔹 Key Properties of DDL:
  • Auto-commit — DDL statements are auto-committed in most databases. Cannot rollback.
  • No ResultSet — DDL does not return rows of data
  • execute() returns false — because no ResultSet is produced
  • Affects structure — not data inside tables
🔹 In JDBC:
  • DDL is executed using Statement.execute(sql)
  • Returns boolean → always false for DDL
  • No executeUpdate() for CREATE DATABASE
DDL (Data Definition Language) includes CREATE, ALTER, DROP, TRUNCATE. In JDBC, DDL queries are executed via Statement.execute(). It returns false because DDL produces no ResultSet. DDL is auto-committed — changes cannot be rolled back.
📘 2. Exception Handling in JDBC — try-catch-finally vs try-with-resources

👉 JDBC operations can throw checked exceptions. There are two ways to handle them properly in JDBC programs.

🔹 Way 1 — try-catch-finally Programs 1 & 2
try { }
Main JDBC code
(connection, statement, execute)
catch (ClassNotFoundException e) { }
Driver JAR missing
catch (SQLException e) { }
DB error (wrong SQL, no DB, etc.)
finally { }
ALWAYS runs — close connection here
Check: if (connection != null)
🔹 Way 2 — try-with-resources Program 3
try (Connection c = DriverManager.getConnection(...)) { // JDBC code here // c auto-closed after this block } catch (SQLException e) { e.printStackTrace(); } // No finally needed! // Connection auto-closed by JVM

👉 AutoCloseable — Connection implements AutoCloseable interface → JVM auto-calls close() when try block ends — even if exception occurs.

✔ Cleaner code ✔ Less boilerplate ✔ No null check needed

⚠️ Why connection declared outside try in Programs 1 & 2:
Connection connection = null; is declared OUTSIDE try block so it is accessible in the finally block. If declared inside try → finally cannot see it → cannot close it → resource leak!
Rule: Any variable needed in finally must be declared outside try.
try-catch-finally: connection declared outside try, closed in finally with null check. try-with-resources (Java 7+): resource declared in try() → auto-closed — Connection implements AutoCloseable. try-with-resources is preferred as it eliminates finally block boilerplate and prevents resource leaks automatically.
📘 3. Connecting to PostgreSQL Server WITHOUT a Database Name
🔹 Normal connection (with DB name):
"jdbc:postgresql://localhost:5433/mydb" ↑ database name

👉 Connects to a specific database. Used for DML/DQL operations.

🔹 Connection WITHOUT DB name (for CREATE DATABASE):
"jdbc:postgresql://localhost:5433/" ↑ slash with no DB name

👉 Connects to PostgreSQL server itself — not any specific DB. Required for CREATE DATABASE.

⚠️ Why no DB name for CREATE DATABASE?
You cannot create a database while already connected to that same database (it doesn't exist yet!). Connect to the server root first → create the database → then connect to the new database.
To execute CREATE DATABASE in JDBC, connect to the PostgreSQL server without specifying a database name: "jdbc:postgresql://localhost:5433/". You cannot connect to a database that doesn't exist yet — connect to server root first, create the DB, then reconnect with the DB name.
DDL Notes | Page 2 — Program 1: CreateDAtabse.java
📄 Program 1 — CreateDAtabse.java (CREATE DATABASE using try-catch-finally)
🔹 What this program does

Creates a new PostgreSQL database named jdbcconnection5thday. Connects to PostgreSQL server root (no DB name in URL). Uses try-catch-finally for proper exception handling. Connection is declared outside try block and closed in finally.

package jdbcFithyDay; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.sql.Statement; public class CreateDAtabse { public static void main(String[] args) { // Declare connection reference Connection connection = null; try { // Step 1: Load and Register Driver // Loads PostgreSQL driver into memory Class.forName("org.postgresql.Driver"); // Step 2: Create Connection // Note: No database name at end → connecting to PostgreSQL server connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/", "postgres", "root"); // Step 3: Create Statement // Used to execute SQL query Statement statement = connection.createStatement(); // Step 4: Create Database Query String query = "CREATE DATABASE jdbcconnection5thday"; // Execute query // execute() returns false because DDL does not return ResultSet boolean res = statement.execute(query); } catch (ClassNotFoundException e) { // Driver class not found e.printStackTrace(); } catch (SQLException e) { // SQL error (DB already exists / permission issue / syntax error) e.printStackTrace(); } finally { // Step 5: Close Connection (Important) try { if (connection != null) { connection.close(); // free resources } } catch (SQLException e) { e.printStackTrace(); } } System.out.println("Database Created Successfully"); } }
Database Created Successfully
📖 Line-by-Line Explanation
public static void main(String[] args)
No throws clause — exceptions are handled internally using try-catch-finally. Not propagated to JVM.
Connection connection = null;
Declared OUTSIDE try block. If declared inside → finally block cannot access it → cannot close → resource leak. null prevents NullPointerException if connection never established.
try { ... }
Contains all JDBC code that may throw exceptions. If exception occurs → jumps to matching catch block.
"jdbc:postgresql://localhost:5433/"
URL ends with / and NO database name. Connects to PostgreSQL server root — required for CREATE DATABASE because the target DB doesn't exist yet.
String query = "CREATE DATABASE jdbcconnection5thday"
DDL query stored in a String variable for readability. Same as passing directly to execute().
boolean res = statement.execute(query)
execute() returns false for DDL — no ResultSet produced. res = false. Value not printed/used here.
catch (ClassNotFoundException e)
Catches exception from Class.forName() — thrown when PostgreSQL JAR is not in classpath.
catch (SQLException e)
Catches DB errors: DB already exists, wrong URL, server not running, permission denied. e.printStackTrace() prints full error trace.
finally { if (connection != null) connection.close(); }
finally ALWAYS runs — even if exception occurs. Null check prevents NPE if connection failed. Inner try-catch handles SQLException from close().
System.out.println("Database Created Successfully")
Prints OUTSIDE try-catch — runs always (even if exception occurred). Better placement would be inside try after execute().
📝 Why two separate catch blocks?
ClassNotFoundException → from Class.forName() — driver not found
SQLException → from getConnection(), createStatement(), execute() — DB errors
Separate catches allow different handling logic for different error types. Could also write catch (Exception e) as shortcut — but less specific.
In try-catch-finally pattern: Connection is declared null outside try so finally can access it. finally always executes — even on exception — making it the right place to close connections. The null check prevents NullPointerException if connection was never established.

📄 Program 2 — CreateTable.java (CREATE TABLE using try-catch-finally)
🔹 What this program does

Creates an emp table with 3 columns inside the jdbcconnection5thday database that was created by Program 1. Uses same try-catch-finally pattern. Connects to the specific database (not server root) because DB now exists.

package jdbcFithyDay; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.sql.Statement; public class CreateTable { public static void main(String[] args) { // Declare connection reference Connection connection = null; try { // Step 1: Load and Register Driver // Loads PostgreSQL driver into JVM Class.forName("org.postgresql.Driver"); // Step 2: Create Connection // Connect to already created database "jdbcconnection5thday" connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/jdbcconnection5thday", "postgres", "root"); // Step 3: Create Statement // Statement is used to execute SQL queries Statement statement = connection.createStatement(); // Step 4: SQL Query to Create Table // Creating table "emp" with 3 columns // eid → primary key // ename → varchar (string) // esal → double precision (salary) String query = "CREATE TABLE emp(eid INT primary key, ename varchar(45), esal DOUBLE PRECISION)"; // Execute query // execute() returns false because DDL does not return ResultSet boolean result = statement.execute(query); } catch (ClassNotFoundException e) { // Driver class not found e.printStackTrace(); } catch (SQLException e) { // SQL error (table already exists / syntax issue) e.printStackTrace(); } finally { // Step 5: Close Connection // Always close connection to free resources try { if (connection != null) { connection.close(); } } catch (SQLException e) { e.printStackTrace(); } } System.out.println("Table Created Successfully"); } }
Table Created Successfully

"CREATE TABLE emp(eid INT primary key, ename varchar(45), esal DOUBLE PRECISION)"
Full CREATE TABLE DDL. Creates emp table with 3 columns. Entire SQL stored in a String variable for readability.

Column 3 → employee salary. Data type: DOUBLE PRECISION (64-bit floating point). Used for decimal salary values.

DDL Notes | Page 4 — Program 3: insertData.java (try-with-resources)
📄 Program 3 — insertData.java (INSERT using try-with-resources)
🔹 What this program does

Inserts 3 employee records into the emp table created by Program 2. Demonstrates try-with-resources — a modern Java 7+ approach where the Connection is automatically closed when the try block ends. No finally block needed.

package jdbcFithyDay; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.sql.Statement; public class insertData { public static void main(String[] args) throws ClassNotFoundException { Class.forName("org.postgresql.Driver"); try(Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/jdbcconnection5thday", "postgres", "root")) { Statement statement = connection.createStatement(); statement.execute("insert into emp values(101,'Pravin',50000)"); statement.execute("insert into emp values(102,'Mayuresh',40000)"); statement.execute("insert into emp values(103,'Vednat',50)"); } catch(SQLException e) { e.printStackTrace(); } } }
📖 Line-by-Line Explanation
throws ClassNotFoundException
Class.forName() is called OUTSIDE try-with-resources. So ClassNotFoundException is propagated via throws. Only SQLException is caught inside.
Class.forName(...) outside try block
Driver loading done outside the try-with-resources block. Can also be placed inside — both are valid. ClassNotFoundException propagated here via throws.
try(Connection connection = DriverManager.getConnection(...))
try-with-resources syntax — resource declared in (). Connection auto-closed when try block exits — success or exception. No finally needed. Connection implements AutoCloseable.
{ Statement statement = connection.createStatement(); }
try block body — statement created inside. Uses the auto-managed connection. All JDBC operations here.
statement.execute("insert into emp values(101,'Pravin',50000)")
DML INSERT using Statement. Values hardcoded. execute() used — returns false (DML but boolean return is not captured here).
catch(SQLException e) { e.printStackTrace(); }
Catches SQL errors (duplicate key, wrong table, wrong column count). printStackTrace() prints error details to console.
📝 What is AutoCloseable?
AutoCloseable is an interface in java.lang with one method: close().
Connection extends AutoCloseable → JVM automatically calls connection.close() at end of try block.
Any object that implements AutoCloseable can be used in try-with-resources.
Order of closing (when multiple resources): last declared → first closed.

try-with-resources (Java 7+) auto-closes any AutoCloseable resource when the try block ends — even if an exception occurs. Connection implements AutoCloseable. No finally block or null check needed. This prevents resource leaks more reliably than manual close() in finally.

🗂️ Quick Revision — Key Rules
DDL Rules:
  • DDL = CREATE, ALTER, DROP, TRUNCATE
  • execute() returns false for DDL always
  • DDL is auto-committed — cannot rollback
  • CREATE DATABASE → URL without DB name
  • CREATE TABLE → URL with DB name
Exception Handling Rules:
  • ClassNotFoundException → Class.forName() → driver missing
  • SQLException → all DB operations
  • IOException → file operations (db.properties)
  • finally → ALWAYS runs (success or exception)
  • Connection null outside try → prevents NPE in finally
try-with-resources Rules:
  • Syntax: try(ResourceType r = new ...)
  • Resource must implement AutoCloseable
  • Connection implements AutoCloseable ✅
  • PreparedStatement implements AutoCloseable ✅
  • ResultSet implements AutoCloseable ✅
  • JVM calls close() in reverse order of declaration
  • Multiple resources: try(Conn c = ...; Stmt s = ...)
PostgreSQL Data Types used:
  • INT → integer (eid)
  • VARCHAR(n) → variable string max n chars (ename)
  • DOUBLE PRECISION → 64-bit decimal (esal)
