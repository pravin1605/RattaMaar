📘 1. What is a Stored Procedure?

✅ Definition: A Stored Procedure is a pre-written set of SQL statements stored inside the database, which can be executed whenever needed.

🔹 Simple Words

👉 It is like a function inside the database.

👉 You write SQL logic once → store it in DB → call it by name from Java/Python/etc. whenever needed.

Real-Life Analogy

Think of a saved recipe 📖 in a cookbook:

  • You write the recipe once
  • Any chef (Java, Python, PHP) can follow it
  • Recipe is stored in one place
  • Everyone calls the same recipe by name

👉 Recipe = Stored Procedure | Chef = Application

How it works in DB
SQL logic written in DB
↓
Stored with a name (e.g. insertdata)
↓
Java calls: {call insertdata(?,?,?)}
↓
DB executes the stored SQL
A Stored Procedure is a pre-compiled, named block of SQL statements stored inside the database. It is like a function in a programming language — written once, stored in DB, and called by name from any application using CallableStatement in JDBC.
📘 2. Why We Use Stored Procedure?
🔹 1. Code Reusability ♻️

👉 Write once → use many times

  • Insert logic written once
  • Used from Java, Python, etc.
🔹 2. Performance ⚡

👉 Stored procedure is:

  • Precompiled
  • Optimized by database

✔ Faster than normal SQL

👉 DB compiles procedure once when created — not on every call. Just executes cached plan.

🔹 3. Security 🔐

👉 Users don't access tables directly

👉 Only call procedure

✔ More secure

👉 You give user permission to call procedure — not to directly SELECT/INSERT/DELETE on table. Table structure is hidden.

🔹 4. Centralized Logic 🧠

👉 Business logic stored in DB

👉 Easy to maintain

👉 Change logic in one place (DB) — all applications automatically get the updated logic without redeploying code.

Stored Procedures are used for: Code Reusability (write once, call many times), Performance (pre-compiled and optimized), Security (hide table structure, expose only procedure), and Centralized Logic (business logic in DB — one change affects all clients).

📘 4. What is CallableStatement?

👉 CallableStatement is an interface in java.sql package used to call stored procedures stored in the database from Java.

👉 It extends PreparedStatement — so it has all features of PreparedStatement plus ability to call stored procedures.

👉 It supports IN, OUT, and INOUT parameters.

🔹 How to Create CallableStatement
CallableStatement cs = connection.prepareCall("{call procedurename(?,?,?)}");
📖 Syntax Breakdown
CallableStatement
Interface in java.sql. Extends PreparedStatement. Used specifically for calling stored procedures.
connection.prepareCall()
Non-static (instance) method of Connection interface. Creates and returns a CallableStatement object.
{call procedurename(?,?,?)}
JDBC escape syntax to call a stored procedure. Curly braces {} are mandatory. "call" is keyword. ? are placeholders for procedure parameters.
? placeholders
Same as PreparedStatement — index starts from 1. Set values using setXxx() methods before execution.
⚠️ JDBC Escape Syntax — Very Important:
{call procedurename()} — procedure with no parameters
{call procedurename(?,?,?)} — procedure with 3 IN parameters
{? = call procedurename(?)} — procedure with OUT/return value
The { } curly braces are mandatory — they tell JDBC driver this is a stored procedure call.
CallableStatement is an interface in java.sql that extends PreparedStatement. It is used to call stored procedures from Java using JDBC escape syntax: {call procedurename(?)}. It supports IN, OUT, and INOUT parameters. prepareCall() is the method of Connection used to create it.

📘 6. Parameter Types in CallableStatement
Parameter Type Direction How to Set Example
IN Java → DB (input) setXxx(index, value) Passing id, name, salary to procedure
OUT DB → Java (output) registerOutParameter(index, Types.xxx) then getXxx(index) Getting result/status back from procedure
INOUT Both directions Both setXxx() and registerOutParameter() Send value, procedure modifies and returns it
📝 Programs in these notes use IN parameters only — values are passed FROM Java TO stored procedure. OUT parameters are used when procedure needs to return a value back to Java.
CallableStatement supports three parameter modes: IN (Java sends value to DB), OUT (DB sends value back to Java — needs registerOutParameter()), and INOUT (bidirectional). In our programs, only IN parameters are used — set using setInt(), setString(), setDouble().

🗄️ PostgreSQL Stored Procedure — insertdata (INSERT Logic)
🔹 Procedure stored inside PostgreSQL Database
BEGIN INSERT INTO emp(eid, ename, sal) VALUES (id, name, esal); END
📖 Procedure Breakdown
BEGIN
Starts the procedure body block. All SQL logic goes between BEGIN and END.
INSERT INTO emp(eid, ename, sal)
SQL INSERT into emp table — targeting specific columns: eid, ename, sal.
VALUES (id, name, esal)
id, name, esal are the IN parameters of the procedure — passed from Java via CallableStatement setXxx() methods.
END
Ends the procedure body block.
📝 Full PostgreSQL Procedure Syntax (Complete Form):
CREATE OR REPLACE PROCEDURE insertdata(id INT, name VARCHAR, esal DOUBLE PRECISION) LANGUAGE plpgsql AS $$ BEGIN INSERT INTO emp(eid, ename, sal) VALUES (id, name, esal); END; $$;
CREATE OR REPLACE → creates new or replaces existing procedure | LANGUAGE plpgsql → procedural SQL language | $$ → dollar-quoting for procedure body
A PostgreSQL stored procedure uses CREATE OR REPLACE PROCEDURE. Parameters defined in signature (id, name, esal) are IN parameters. BEGIN...END block contains the SQL logic. Java calls it via CallableStatement using JDBC escape syntax {call insertdata(?,?,?)}.
📄 Program 1 — InsertData.java (CallableStatement + Driver object registration)
🔹 What this program does

Calls the insertdata stored procedure in PostgreSQL to insert one employee record into emp table. Uses Driver object registration (not Class.forName). Uses connection.prepareCall() to create CallableStatement.

package jdbcFourthDay; import java.sql.CallableStatement; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import org.postgresql.Driver; public class InsertData { public static void main(String[] args) throws SQLException { // Step 1: Create PostgreSQL Driver object Driver d = new Driver(); // Step 2: Register driver with DriverManager DriverManager.registerDriver(d); // Step 3: Establish connection with database Connection connection = DriverManager.getConnection( "jdbc:postgresql://localhost:5433/FourthDayDatabse", "postgres", "root"); // Step 4: Create CallableStatement to call stored procedure // "insertdata" is procedure name with 3 parameters CallableStatement s = connection.prepareCall("{call insertdata(?,?,?)}"); // Step 5: Set input values for procedure parameters s.setInt(1, 101); // 1st parameter → id s.setString(2, "Pravin"); // 2nd parameter → name s.setDouble(3, 34550); // 3rd parameter → salary // Step 6: Execute stored procedure s.execute(); // Step 7: Close connection (good practice) connection.close(); // Step 8: Confirmation message System.out.println("Data Insert"); } }
Data Insert
📖 Line-by-Line Explanation
import java.sql.CallableStatement;
Must explicitly import CallableStatement interface from java.sql. Not auto-imported.
import org.postgresql.Driver;
Import PostgreSQL Driver class — needed because we create its object manually (new Driver()).
throws SQLException (only)
No ClassNotFoundException — Driver object created directly, no Class.forName() dynamic loading used.
Driver d = new Driver(); DriverManager.registerDriver(d);
Alternative driver registration — manual object creation + explicit registration. Same result as Class.forName().
connection.prepareCall("{call insertdata(?,?,?)}")
Non-static method of Connection. Creates CallableStatement. JDBC escape syntax with 3 ? for 3 IN parameters of insertdata procedure.
s.setInt(1, 101) | s.setString(2, "Pravin") | s.setDouble(3, 34550)
Sets IN parameters: index 1=id, index 2=name, index 3=salary. Maps to procedure parameters in order.
s.execute()
Calls the stored procedure in DB. execute() is preferred for stored procedures — it handles both result sets and update counts.
prepareCall() is a non-static method of Connection that creates a CallableStatement. The JDBC escape syntax {call procedurename(?,?,?)} is mandatory. setXxx() sets IN parameters. execute() is preferred over executeUpdate() for stored procedures as procedures can return result sets or update counts.

📘 8. What is db.properties File? (New Concept)

👉 A db.properties file is an external configuration file that stores database connection details (URL, username, password, driver class) as key=value pairs.

👉 Instead of hardcoding DB credentials in Java code, we externalize them into a .properties file.

🔹 Sample db.properties file content
driverclass=org.postgresql.Driver url=jdbc:postgresql://localhost:5433/FourthDayDatabse user=postgres password=root
🔹 Why use db.properties?
  • No hardcoded credentials in source code
  • Change DB URL/password → only update .properties file — no recompile
  • Secure — .properties file can be excluded from version control (git)
  • Professional practice used in real projects
  • Different environments (dev/test/prod) → different .properties files
🔹 How to read db.properties in Java
// 1. Open the file FileInputStream fis = new FileInputStream("db.properties"); // 2. Create Properties object Properties p = new Properties(); // 3. Load file data into Properties p.load(fis); // 4. Read values by key String driver = p.getProperty("driverclass"); String url = p.getProperty("url");
📝 Classes used for db.properties:
FileInputStream (java.io) → opens the file as byte stream
Properties (java.util) → stores key-value pairs; extends Hashtable
p.load(fis) → reads key=value pairs from file into Properties object
p.getProperty("key") → returns String value for given key
Extra import needed: java.io.FileInputStream, java.io.IOException, java.util.Properties
db.properties is an external configuration file storing DB credentials as key=value pairs. FileInputStream reads it; Properties.load() parses it. DriverManager.getConnection(url, p) accepts a Properties object directly — reading user and password from it — avoiding hardcoded credentials in Java source code.
🗄️ PostgreSQL Stored Procedure — updatedata (UPDATE Logic)
BEGIN UPDATE emp SET sal=esal WHERE eid=id; END;
📖 Procedure Breakdown
BEGIN
Start of procedure body block.
UPDATE emp SET sal=esal WHERE eid=id;
Updates salary (sal) to esal value WHERE employee id (eid) matches id. esal and id are IN parameters from Java.
END;
End of procedure body block. Semicolon after END is required in PostgreSQL.
📝 Full PostgreSQL UPDATE Procedure:
CREATE OR REPLACE PROCEDURE updatedata(id INT, esal DOUBLE PRECISION) LANGUAGE plpgsql AS $$ BEGIN UPDATE emp SET sal=esal WHERE eid=id; END; $$;
2 parameters: id (to find row) + esal (new salary value). Called from Java as: {call updatedata(?,?)}
📄 Program 2 — updateData.java (CallableStatement + db.properties)
🔹 What this program does

Calls updatedata stored procedure to update employee salary. Uses db.properties file to load DB configuration — no hardcoded credentials in Java code. Demonstrates DriverManager.getConnection(url, Properties) overload.

package jdbcFourthDay; import java.io.FileInputStream; import java.io.IOException; import java.sql.CallableStatement; import java.sql.Connection; import java.sql.DriverManager; import java.sql.SQLException; import java.util.Properties; public class updateData { public static void main(String[] args) throws ClassNotFoundException, IOException, SQLException { // Step 1: Load properties file (db configuration) FileInputStream fis = new FileInputStream("db.properties"); // Step 2: Create Properties object Properties p = new Properties(); // Step 3: Load data from file into Properties p.load(fis); // Step 4: Load driver class dynamically from properties file Class.forName(p.getProperty("driverclass")); // Step 5: Create connection using URL + properties (username, password inside file) Connection c = DriverManager.getConnection(p.getProperty("url"), p); // Step 6: Prepare callable statement to call stored procedure CallableStatement cs = c.prepareCall("{call updatedata(?, ?)}"); // Step 7: Set input parameters // Step 8: Execute procedure cs.execute(); // good for procedure // Step 9: Close connection c.close(); // Step 10: Print message System.out.println("Data Updated Successfully"); } }
Data Updated Successfully

throws ClassNotFoundException, IOException, SQLException
Three checked exceptions: ClassNotFoundException (Class.forName), IOException (FileInputStream file not found), SQLException (DB operations).
new FileInputStream("db.properties")
Opens db.properties file from project root as byte stream. Throws IOException if file not found.
new Properties()
Creates Properties object — stores key-value pairs. Part of java.util package. Extends Hashtable.
p.load(fis)
Reads all key=value lines from db.properties file and stores them in Properties object p.
Class.forName(p.getProperty("driverclass"))
Loads driver dynamically. p.getProperty("driverclass") returns "org.postgresql.Driver" from file. No hardcoded string in Java.
DriverManager.getConnection(p.getProperty("url"), p)
Overloaded getConnection(url, Properties). URL from file; user and password also read from Properties p automatically.
c.prepareCall("{call updatedata(?, ?)}")
Creates CallableStatement. updatedata procedure has 2 IN parameters: id and esal.
Step 7 — Set input parameters (empty in notes)

cs.execute() // good for procedure
Calls the stored procedure. Comment confirms execute() is appropriate for stored procedures.

🗂️ Quick Revision — Key Rules for CallableStatement + Stored Procedure
CallableStatement Rules:
  • Created by connection.prepareCall()
  • JDBC escape syntax: {call name(?,?)}
  • Curly braces { } are mandatory
  • Index starts from 1 for setXxx()
  • execute() preferred for stored procedures
  • Extends PreparedStatement → all PS methods available
  • OUT params: registerOutParameter(index, Types.xxx)
db.properties Rules:
  • External file — not in Java code
  • Format: key=value
  • Read using: FileInputStream + Properties.load()
  • Access value: p.getProperty("key")
  • getConnection accepts Properties object directly
  • Must throws IOException for FileInputStream
  • Stored Procedure rules:
  • Created with CREATE OR REPLACE PROCEDURE
  • Body between BEGIN...END
  • Parameters are IN by default
  • Language: plpgsql
CallableStatement.prepareCall("{call procedurename(?,?)}") creates a callable statement. Curly braces are mandatory JDBC escape syntax. execute() is preferred for procedures. db.properties externalizes DB credentials — FileInputStream reads it, Properties.load() parses it, and getConnection(url, p) uses it directly.
