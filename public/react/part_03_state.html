What is State?

📘 Definition

State is a plain JavaScript object used by React to store information about a component. It represents the current data of a component. Whenever state changes, React automatically updates the UI.

⚡ Simple Definition

State is data that can change over time and causes the component to re-render when updated.

The Problem Without State

❌ Without State — UI doesn't update
// count changes but UI stays same
let count = 0;

function increment() {
  count++;   // React doesn't know!
}

Even if count = 3, browser still shows 0 ❌

✅ With State — UI updates automatically
this.setState({
  count: this.state.count + 1
});
// React detects → re-renders → UI updates ✅

React detects the change → re-renders component → UI updates ✅

How State Solves the Problem

State Changes
↓
React Detects Change
↓
Component Re-renders
↓
UI Updates Automatically ✅
2

Important Points About State

📦 Plain JavaScript Object

State is just a regular JS object with key-value pairs.

this.state = {
  name: "Pravin",
  age: 21
};
🔄 Stores Dynamic Data

Counter values, login status, form data, user info, theme mode — anything that changes.

this.state = {
  isLoggedIn: false
};
🔒 Internal to Component

State belongs only to the component where it is created. Other components cannot access it directly.

🏛️ Available in Class Components

Before Hooks, state was used inside Class Components. Functional components now use useState().

class Demo extends Component {}
🚫 Never Modify State Directly
// ❌ Wrong — React won't know
this.state.count = 10;

// ✅ Correct — triggers re-render
this.setState({ count: 10 });
⚡ Causes Re-render

Every time setState() is called, React automatically re-renders the component and updates the browser UI.

🚫
Never do this: this.state.count = 10;
React has no way to detect this change → UI will NOT update.
Always use: this.setState({ count: 10 }); → React detects → re-renders → UI updates.
3

Constructor and State

In Class Components, state is initialized inside the constructor.

🔧 Why Constructor?

The constructor executes first when a component is created. It is used to initialize state, bind methods, and perform initial setup.

Syntax

constructor() {
  super();    // must call super() first

  this.state = {
    count: 0
  };
}
💡 Why super()? — super() calls the parent class constructor (React.Component). Without it, this cannot be used inside the constructor and React will throw an error.

State Lifecycle

1. Component Created
↓
2. Constructor Runs
↓
3. State Initialized
↓
4. Component Rendered (render() called)
↓
5. User Action (button click etc.)
↓
6. setState() Called
↓
7. Component Re-rendered
↓
8. UI Updated ✅

Practical Examples

Example 1 — Counter Application

  Counter.jsx 
import React, { Component } from 'react';

class Counter extends Component {

  constructor() {
    super();
    this.state = {
      count: 0
    };
  }

  increment = () => {         // Arrow function — no binding needed
    this.setState({
      count: this.state.count + 1
    });
  }

  render() {
    return (
      <>
        <h1>Count : {this.state.count}</h1>
        <button onClick={this.increment}>
          Increment
        </button>
      </>
    );
  }
}

export default Counter;
▶ Output
Initially → Count : 0
After 1 click → Count : 1
After 2 clicks → Count : 2
After 3 clicks → Count : 3
🔍 How it works step by step
Button Clicked
→
increment() called
→
setState({ count: count+1 })
→
React re-renders
→
New count shown ✅

Example 2 — Login Status

  Login.jsx 
import React, { Component } from 'react';

class Login extends Component {

  constructor() {
    super();
    this.state = {
      isLoggedIn: false
    };
  }

  login = () => {
    this.setState({
      isLoggedIn: true
    });
  }

  render() {
    return (
      <>
        <h1>
          {this.state.isLoggedIn
            ? "Welcome User"        // true → show this
            : "Please Login"}       // false → show this
        </h1>
        <button onClick={this.login}>Login</button>
      </>
    );
  }
}

export default Login;
▶ Before Login Click
Please Login
▶ After Login Click
Welcome User
💡 This uses a Ternary Operator inside JSX: condition ? "value if true" : "value if false". The UI changes based on state — this is Conditional Rendering.

State vs Props

FeatureStateProps
Who manages it? Managed inside the component Passed from parent component
Can it change? ✅ Mutable (can change) ❌ Immutable (read-only)
How to update? setState() Cannot be modified by child
Type of data Internal / local data External data from parent
Re-render? Yes — on every setState() Yes — when parent sends new props

Real-Life Analogy — Mobile Phone 📱

🔵 Props — Fixed Phone Details

Received from the company. Fixed, cannot change.

Brand = Samsung
Model = S24
Color = Black

These details don't change — just like Props.

🟠 State — Changing Condition

Current status that keeps changing over time.

Battery = 80%
Battery = 50%
Battery = 20%

Battery keeps changing — just like State.

🎯 Interview Q&A
Q: What is State in React?
A: State is a built-in React object used to store and manage dynamic data within a component. Whenever state changes using setState(), React automatically re-renders the component and updates the UI.
Q: Why is State used?
A: State is used to store dynamic information such as user input, counter values, login status, API data, and other data that changes during the lifetime of a component.
Q: Why use setState() instead of directly updating state?
A: setState() informs React that state has changed. React then re-renders the component. Directly modifying state (this.state.x = y) does NOT trigger re-rendering — so the UI may never update.
Q: What is the difference between State and Props?
A: State is internal, mutable data managed by the component itself. Props are external, read-only data passed from a parent component. Both trigger re-renders when changed.
Q: Why is super() needed in the constructor?
A: super() calls the parent class (React.Component) constructor. Without it, this is not available inside the constructor, causing a runtime error.
