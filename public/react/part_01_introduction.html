Introduction to React

📘 Definition

React is an Open-Source JavaScript Library used for building dynamic and interactive user interfaces by creating reusable components and efficiently updating the UI using the Virtual DOM.

Why React is Used?

  • ✓ To create fast and interactive web applications
  • ✓ To build Single Page Applications (SPA)
  • ✓ To create reusable UI components
  • ✓ To manage application state efficiently
  • ✓ To improve performance using Virtual DOM
  • ✓ To simplify complex UI development
2

Features of React

🧩 Component-Based Architecture

Applications are built using small, independent, reusable components — Header, Navbar, Footer, Login — that can be reused throughout the app.

function Header() {
  return <h1>Welcome to React</h1>;
}
⚡ Virtual DOM

React uses a Virtual DOM to improve performance. Instead of updating the entire webpage, React updates only the changed elements.

📝 Declarative Syntax

Developers describe what should appear; React handles updates automatically — easier to read and debug than manual DOM manipulation.

function App() {
  return <h1>Hello React</h1>;
}
🔁 Unidirectional Data Flow

Data flows in one direction: Parent → Child. Makes apps easier to understand and debug.

function Child(props) {
  return <h2>{props.name}</h2>;
}
function Parent() {
  return <Child name="Pravin" />;
}
🔣 JSX

JSX allows writing HTML-like code inside JavaScript, making React code easier to understand and write.

const element = <h1>Hello React</h1>;

Single Page Application (SPA)

📘 Definition

A Single Page Application loads only one HTML page and updates content dynamically without reloading the entire webpage.

📱 Real-Life Example — Instagram: When you like a post, the entire page does NOT reload — only the like count changes. This is React SPA behaviour.

Virtual DOM

What is DOM?

DOM = Document Object Model. It represents the structure of an HTML page as objects.

<body>
  <h1>Hello</h1>
</body>

DOM Tree:
Body
 └── H1
       Hello
📘 What is Virtual DOM?

Virtual DOM is a lightweight copy of the Real DOM maintained by React in memory. React first updates the Virtual DOM and then updates only the changed parts in the Real DOM.

Why Virtual DOM?

Updating Real DOM directly is expensive and slower. Virtual DOM makes updates faster.

❌ Without Virtual DOM

Suppose 20,000 elements exist. Even if only 1 button changes, all 20,000 elements are checked and re-rendered.

✅ With Virtual DOM

React compares old and new Virtual DOM trees. Only the changed element is updated — massive performance gain!

6

Reconciliation

📘 Definition

Reconciliation is the process of comparing the Old Virtual DOM with the New Virtual DOM and updating only the changed elements in the Real DOM using the Diffing Algorithm.

Working of Reconciliation

Step 1 — State or Props change
↓
Step 2 — React creates a New Virtual DOM
↓
Step 3 — React compares Old VDOM vs New VDOM (Diffing Algorithm)
↓
Step 4 — React finds the changed elements
↓
Step 5 — Only changed elements updated in Real DOM ✅
🔍 Diffing Algorithm: React uses a special algorithm to find differences between two Virtual DOM trees efficiently — this is what makes React fast!

createRoot()

📘 Definition

createRoot() is a React method used to create a root container where React components will be rendered. It acts as a bridge between index.html and main.jsx.

Syntax

import ReactDOM from "react-dom/client";

const root = ReactDOM.createRoot(
  document.getElementById("root")
);

Full Example

index.html

<div id="root"></div>

main.jsx

import ReactDOM from "react-dom/client";
import App from "./App";

const root = ReactDOM.createRoot(
  document.getElementById("root")
);
root.render(<App />);

createElement()

React.createElement() is a React method used to create React elements programmatically. Before JSX, React apps were written using this method.

Syntax

React.createElement(
  type,      // HTML tag or component
  props,     // attributes / null
  children   // content inside the element
)
🔧 createElement() (Before JSX)
React.createElement(
  "h1",
  null,
  "Hello React"
)
✅ Equivalent JSX (After JSX)
<h1>Hello React</h1>
💡 JSX replaced createElement() because JSX is easier to read, easier to write, looks similar to HTML, and reduces code complexity.

JSX (JavaScript XML)

📘 Definition

JSX (JavaScript XML) is a syntax extension for JavaScript that allows writing HTML-like code inside JavaScript, making React applications easier to build and understand.

const element = <h1>Welcome to React</h1>;
🔍 Behind the Scene: JSX is automatically converted into React.createElement() calls by Babel before running in the browser.

Rules of JSX

Rule 1 — Return Single Parent Element
❌ Wrong
return (
  <h1>Hello</h1>
  <p>Welcome</p>
)
✅ Correct
return (
  <div>
    <h1>Hello</h1>
    <p>Welcome</p>
  </div>
)
Rule 2 — Close Every Tag
<input />  ✅
<input>   ❌
Rule 3 — Use camelCase
onClick   ✅
onclick   ❌
Rule 4 — className not class
className="box"  ✅
class="box"       ❌
Rule 5 — htmlFor not for
htmlFor="name"  ✅
for="name"       ❌

JSX Expressions — Writing JS inside JSX using {}

Any valid JavaScript expression written inside { } in JSX is called a JSX Expression.

// Example 1: Variable
function App() {
  let name = "Pravin";
  return <h1>Hello {name}</h1>;   // Output: Hello Pravin
}

// Example 2: Arithmetic
function App() {
  return <h1>{10 + 20}</h1>;         // Output: 30
}

// Example 3: Function Call
function App() {
  function add(a, b) { return a + b; }
  return <h1>{add(10, 20)}</h1>;     // Output: 30
}
🎯 Interview Q&A
Q: What is JSX?
A: JSX (JavaScript XML) is a syntax extension for JavaScript that allows writing HTML-like code inside JavaScript. It gets compiled into React.createElement() by Babel.
Q: Is JSX mandatory in React?
A: No. JSX is not mandatory but it is strongly recommended because it makes code readable and maintainable. Without JSX, you have to write React.createElement() manually.
Q: What is Virtual DOM and how does it improve performance?
A: Virtual DOM is a lightweight in-memory copy of the Real DOM. React updates the Virtual DOM first, then uses the Diffing Algorithm to find changes and updates only those in the Real DOM — avoiding unnecessary full-page re-renders.
Q: Difference between Real DOM and Virtual DOM?
A: Real DOM updates the full tree (slow, expensive). Virtual DOM only updates changed nodes (fast, efficient).
