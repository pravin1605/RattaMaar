What is Lifecycle?

A Lifecycle is the sequence of phases a React component goes through from its creation to its removal from the DOM. React provides special Lifecycle Methods to run code at each stage.

Mounting Phase

🟢 Mounting

Mounting is the process of creating a component and inserting it into the DOM for the first time. Happens once when the user first visits the page/route.

Execution Order

1. constructor()
↓
2. getDerivedStateFromProps()
↓
3. render()
↓
4. componentDidMount()
1

constructor(props)

The first method called when the component object is created. Used to initialize state and bind methods.

Initialize State Bind Methods Initial Setup
Syntax
constructor(props) {
  super(props);   // Must call super() first!
  this.state = {
    count: 0      // Initialize state here
  };
}
Rule: Always call super(props) as the first line inside constructor. Without it, this.props will be undefined.
2

static getDerivedStateFromProps()

Called before every render. Syncs state with incoming props. Rarely used in real-world projects.

Example
static getDerivedStateFromProps(props, state) {
  // Return updated state based on props, or null for no change
  return { username: props.username };
}
Note: This is a static method — it cannot access this. Rarely used. Usually you can derive the value directly inside render instead.
3

render()

The only required method in a class component. Returns JSX that describes what to display on screen.

Syntax
render() {
  return (
    <h1>Hello React</h1>
  );
}
Important: Every class component MUST have render(). Without it → No UI, No Output. Also runs again during every update.
4

componentDidMount()

Executed immediately after the component is inserted into the DOM. The most commonly used lifecycle method. Component is fully visible and ready.

⭐ API Calls Database Calls Event Listeners Timers
Real-World API Example
componentDidMount() {
  // Component is ready in DOM — safe to fetch data!
  fetch("https://api.example.com/users")
    .then(res => res.json())
    .then(data => this.setState({ users: data }));
}
Why here? Because the component is already displayed and ready to receive and show data. Calling API in constructor or render is risky since DOM isn't ready yet.

Updating Phase

🔵 Updating

Updating occurs whenever State changes OR Props change. React re-renders the component with fresh data.

Execution Order

1. getDerivedStateFromProps()
↓
2. shouldComponentUpdate()
↓
3. render()
↓
4. getSnapshotBeforeUpdate()
↓
5. componentDidUpdate()
1

shouldComponentUpdate()

Decides whether React should re-render the component or skip it. Returns true (update) or false (skip).

⚡ Performance Optimization Skip Expensive Renders Conditional Updates
Real Example — Stop after count > 5
shouldComponentUpdate(nextProps, nextState) {
  if (nextState.count > 5) {
    return false;   // Stop re-rendering when count exceeds 5
  }
  return true;     // Otherwise allow update
}
Result: Counter will show 1, 2, 3, 4, 5 — then stop updating even if button is clicked.
2

getSnapshotBeforeUpdate()

Runs just before DOM updates. Captures information from the DOM before it changes. The returned value is passed to componentDidUpdate.

Scroll Position Chat Applications Previous Screen State
Syntax
getSnapshotBeforeUpdate(prevProps, prevState) {
  // Capture DOM info before update happens
  return prevState.count;   // passed to componentDidUpdate
}
3

componentDidUpdate()

Executed immediately after the component re-renders. Use for side effects that depend on the updated DOM or props.

API Calls on Change State Monitoring Side Effects
Real-World Example — Fetch when ID changes
componentDidUpdate(prevProps) {
  // Only fetch if ID actually changed — avoid infinite loop!
  if (prevProps.id !== this.props.id) {
    fetch(`/api/user/${this.props.id}`)
      .then(res => res.json())
      .then(data => this.setState({ user: data }));
  }
}
⚠️ Avoid Infinite Loop: Always compare prevProps or prevState before calling setState() inside componentDidUpdate, or you'll trigger an infinite re-render loop!

1

componentWillUnmount()

Runs just before the component is removed. Use it to clean up everything the component created — timers, listeners, subscriptions, etc.

❌ Without cleanup you get:
Memory Leaks  ·  Running timers on dead components  ·  Unnecessary API calls  ·  Orphaned event listeners
🧹 Clear Timers Cancel API Requests Remove Event Listeners Close WebSockets

Timer — Setup & Cleanup

componentDidMount — Setup Timer
componentDidMount() {
  this.timer = setInterval(
    () => console.log("Running"),
    1000
  );
}
componentWillUnmount — Clear Timer
componentWillUnmount() {
  // Stop the timer when component dies
  clearInterval(this.timer);
}

Event Listener — Setup & Cleanup

componentDidMount — Add Listener
componentDidMount() {
  window.addEventListener(
    "resize",
    this.handleResize
  );
}
componentWillUnmount — Remove Listener
componentWillUnmount() {
  window.removeEventListener(
    "resize",
    this.handleResize
  );
}

Lifecycle Methods vs Hooks

Modern React uses Functional Components + Hooks instead of Class Component lifecycle methods. Here's the mapping:

Class Component Method Functional Component Hook
constructor() useState()
componentDidMount() useEffect(() => {}, [])
componentDidUpdate() useEffect(() => {}, [dependency])
componentWillUnmount() useEffect cleanup function
shouldComponentUpdate() React.memo() / useMemo()
Trend: Modern React apps prefer Functional Components + Hooks. But Class Component lifecycle is still heavily tested in interviews and found in older codebases.

Interview Questions 🎯

What is React Component Lifecycle?
The series of phases a React component passes through — Mounting (creation), Updating (state/props change), and Unmounting (removal). React provides lifecycle methods to run code at each specific stage.
What are the three phases of React lifecycle?
1. Mounting — Component is created and added to DOM
2. Updating — Component re-renders due to state/props change
3. Unmounting — Component is removed from DOM
Where should API calls be made?
In componentDidMount() — because the component is fully inserted into the DOM and ready to display data. Never in constructor() or render().
What is componentWillUnmount() used for?
Cleanup — clearing timers (clearInterval), removing event listeners (removeEventListener), cancelling API requests, closing WebSocket connections. Without cleanup → memory leaks.
What is shouldComponentUpdate()?
A method that controls whether a component should re-render. Returns true to allow re-render or false to skip it. Used for performance optimization to prevent expensive unnecessary renders.
What is the order of mounting lifecycle methods?
constructor() → getDerivedStateFromProps() → render() → componentDidMount()
