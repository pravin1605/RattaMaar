What are Props?

📘 Definition

Props (Properties) are used to share data from one component to another. Props allow a Parent Component to pass data to a Child Component. They are read-only inputs that help make components reusable.

The Problem Without Props

❌ Without Props — Hardcoded, Duplicate Code
// Data is hardcoded inside
function Student() {
  return <h1>Pravin</h1>;
}
// Need separate components for each student!
// Student1 → Pravin
// Student2 → Rahul   (duplicate code)
// Student3 → Amit    (duplicate code)
✅ With Props — One Component, Multiple Uses
// One component, different data
<Student name="Pravin" />
<Student name="Rahul"  />
<Student name="Amit"   />
// No duplication! Reusable ✅
💡 Props = Properties. Think of props like function arguments — you pass different values each time and get different output from the same component.
2

Key Points About Props

🏷️ Props = Attributes

Props are special attributes used to pass data between components.

<Student
  name="Pravin"
  age={21}
/>
➡️ One-Way Data Flow

Data always flows Parent → Child only. Never child to parent via props.

Parent Component
↓
Child Component
🔒 Read-Only (Immutable)

Props cannot be modified inside the Child Component.

// ❌ Wrong — throws error
props.name = "Rahul";

// ✅ Correct — only read
<h1>{props.name}</h1>
📦 Internally an Object

React stores all props inside a single object internally.

// You write:
<Student name="Pravin" age={21}/>

// React stores as:
props = { name: "Pravin", age: 21 }
♻️ Makes Components Reusable

Same component, different data, different output — without writing duplicate code.

<Student name="Pravin"/>
<Student name="Rahul"/>
<Student name="Amit"/>
🧩 Access via props Object

The child receives all passed attributes inside a props parameter.

function Child(props) {
  return <h1>{props.name}</h1>;
}
3

How Props are Passed — Parent to Child

Props are passed inside the opening tag of the component, like HTML attributes.

👨 Parent Component (App.jsx)

function App() {
  return (
    <Student
      name="Pravin"
      age={21}
    />
  );
}

👶 Child Component (Student.jsx)

function Student(props) {
  return (
    <>
      <h1>{props.name}</h1>
      <h2>{props.age}</h2>
    </>
  );
}
▶ Output
Pravin
21

Types of Props (Data Types)

Props can hold any JavaScript data type as a value.

🔤 String
<Student
  name="Pravin"
/>
🔢 Number
<Student
  age={21}
/>
✅ Boolean
<Student
  isLogin={true}
/>
📋 Array
<Student
  hobbies={["Cricket", "Coding"]}
/>
📦 Object
<Student
  address={{
    city: "Mumbai",
    state: "MH"
  }}
/>
⚙️ Function
<Student
  showData={display}
/>
// pass callback fn
💡 Syntax Rule: Strings use name="value" (no curly braces). All other types (numbers, booleans, arrays, objects, functions) must use age={value} (curly braces).

Props Drilling

📘 Definition

Props Drilling is the process of passing data through multiple nested components even when intermediate components do not need that data.

Why is Props Drilling a Problem?

Suppose Component D needs data from App. Data must travel through every component in between — even though A, B, and C don't need it.

❌ Props Drilling Problem
App
has data
↓ name
A
doesn't need it
↓ name
B
doesn't need it
↓ name
C
doesn't need it
↓ name
D
actually needs data
❌ Code — Passing Through All
// App.jsx
<A name="Pravin"/>

// A.jsx — just passes it on
<B name={props.name}/>

// B.jsx — just passes it on
<C name={props.name}/>

// C.jsx — just passes it on
<D name={props.name}/>

// D.jsx — finally uses it
<h1>{props.name}</h1>
⚠️
Props Drilling makes code:
  • ❌ Complex — too many prop passes for simple data
  • ❌ Hard to Maintain — renaming a prop requires changes everywhere
  • ❌ Difficult to Debug — hard to track where data comes from

Solution — Context API

❌ Props Drilling — Data Passes Through All
App
↓
A
↓
B → C → D
✅ Context API — Direct Access
Context Provider
↓
Any Component

D gets data directly — no middle-men!

🔧 Solutions for Props Drilling

1. Context API — Built into React. Best for most cases.
2. Redux — Popular state management library for large apps.
3. Zustand — Lightweight and simple state management.
4. Recoil / Jotai — Modern atom-based state managers.

🎯 Interview Q&A
Q: What are Props in React?
A: Props (Properties) are used to pass data from a parent component to a child component. Props are read-only and help make components reusable by allowing different data to be passed each time the component is used.
Q: Why are Props immutable?
A: Props are controlled by the parent component. Child components should only display or use the data — not modify it. This ensures predictable, one-directional data flow.
Q: What is Props Drilling?
A: Props Drilling is the process of passing data through multiple nested components even when intermediate components do not require that data — only the deeply nested component needs it.
Q: How can we avoid Props Drilling?
A: Props Drilling can be avoided using Context API (built-in), Redux, Zustand, or other state management libraries that allow global data access without passing through each component.
Q: What is the difference between Props and State?
A: Props are external, read-only data passed from a parent. State is internal, mutable data managed by the component itself. Both trigger re-renders when changed.
