What is Context API?

📘 Definition

Context API is a built-in React mechanism used to share data between components without passing props through every intermediate component. It helps avoid the problem of Props Drilling.

⚡ Simple Definition

Context API allows sharing data globally — any component in the tree can directly access the shared data without needing props passed through every level.

The Problem Context API Solves

❌ Without Context — Props Drilling

Data must pass through EVERY component — even those that don't need it.

✅ With Context API — Direct Access

Any component accesses data directly from the Context Provider.

↓

No prop drilling — clean and simple!

3

3 Steps to Use Context API

1
Create Context
createContext()

Create a context object — a central store for your shared data.

2
Provide Data
<Context.Provider>

Wrap components with Provider to make data available to all children.

3
Consume Data
useContext()

Use the useContext Hook inside any child component to read data directly.

Complete Flow

Step 1 — createContext() — Creates the context storage
↓
Step 2 — <Context.Provider value={data}> — Broadcasts the data
↓
value travels through the Provider tree
↓
Step 3 — useContext() — Any component reads the data directly ✅
4

Step-by-Step Syntax

1
Create Context — createContext()
import { createContext } from "react";

const UserContext = createContext();
// Creates a central storage object for shared data
💡 Why createContext()?

React needs a central place to store shared data. createContext() creates that storage — like setting up a WiFi hotspot.

2
Provide Data — Context.Provider
import { createContext } from "react";

export const UserContext = createContext();   // export so child can import

function App() {
  const name = "Pravin";

  return (
    <UserContext.Provider value={name}>   // broadcast data to all children
      <Home />
    </UserContext.Provider>
  );
}
💡 Why Provider?

Provider makes data available to all child components. The value prop is what gets shared — wrap your whole app or a section of it.

3
Consume Data — useContext()
import { useContext } from "react";
import { UserContext } from "./App";    // import the context object

function Home() {
  const data = useContext(UserContext);   // directly access data — no props!

  return <h1>{data}</h1>;
}
💡 Why useContext()?

useContext() directly accesses data from the Context — no props needed. Import the context, call the hook, done!

5

Practical Example — Complete App

App.jsx — Create & Provide

  App.jsx 
import React, { createContext } from 'react';
import Home from './Home';

// Step 1: Create
export const UserContext = createContext();

function App() {
  const name = "Pravin";

  return (
    // Step 2: Provide
    <UserContext.Provider value={name}>
      <Home />
    </UserContext.Provider>
  );
}
export default App;

Home.jsx — Consume

  Home.jsx 
import React, { useContext } from 'react';
import { UserContext } from './App';

function Home() {
  // Step 3: Consume
  const user = useContext(UserContext);

  return (
    <h1>Welcome {user}</h1>
  );
}
export default Home;
▶ Output
Welcome Pravin

Sharing Multiple Values — Object in Context

Provide Object

const user = {
  name: "Pravin",
  age:  21,
  city: "Mumbai"
};

<UserContext.Provider value={user}>
  <Home />
</UserContext.Provider>

Consume Object

const data = useContext(UserContext);

<h1>{data.name}</h1>   // Pravin
<h2>{data.age}</h2>    // 21
<h2>{data.city}</h2>   // Mumbai

Real Project Pattern — Language Context

// App.jsx — create and provide language globally
export const languageContext = createContext();

<languageContext.Provider value={language}>
  <Child />
</languageContext.Provider>

// Any child component — consume directly
const data = useContext(languageContext);
💡 In real projects, Context usually holds objects with theme, user auth, language, etc. This pattern is used everywhere in production React apps.

Advantages & Disadvantages

✅ Advantages
🚫 Avoids Props Drilling

No need to pass props through every intermediate component manually.

🧹 Cleaner Code

Less prop passing = fewer lines of code = easier to read and maintain.

🌐 Global Data Sharing

Perfect for theme, user info, language settings, and authentication.

🎨 Theme
👤 User
🌍 Lang
🔐 Auth
⚡ Easy to Use

Only 3 things: createContext(), Provider, useContext().

❌ Disadvantages
🔄 Re-rendering Issue

When context value changes, all components using that context re-render — may affect performance in large apps.

📦 Not Ideal for Large State

For very large apps, Redux / Zustand / Recoil are preferred over Context API.

🐛 Difficult to Debug

When many contexts exist, tracking which context holds which data can become confusing.

🔗 Reduces Reusability

Components that depend on specific Context Providers are harder to reuse outside that tree.

🎯 Interview Q&A
Q: What is Context API in React?
A: Context API is a React feature that allows data to be shared globally among components without passing props manually through every intermediate component. It solves the Props Drilling problem.
Q: Why is Context API used?
A: Context API is used to avoid Props Drilling and make shared data — like user info, theme, language, authentication — directly available to any component that needs it.
Q: What are the 3 steps to use Context API?
A: (1) Create Context using createContext(). (2) Provide data using <Context.Provider value={data}>. (3) Consume data using the useContext() Hook inside any child component.
Q: What is the difference between Props and Context API?
A: Props pass data manually from parent to child — causes Props Drilling. Context API provides global access — any component can consume it directly without intermediate components needing to pass it down.
Q: What are the disadvantages of Context API?
A: (1) Re-rendering — all consumers re-render when context changes. (2) Not ideal for very large state management — Redux/Zustand are better. (3) Harder to debug with many contexts. (4) Reduces component reusability.
