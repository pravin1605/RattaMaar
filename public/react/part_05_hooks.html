What are Hooks?

📘 Definition

Hooks are built-in functions provided by React that allow Function Components to use React features such as State, Context, Lifecycle methods, and more. Hooks were introduced in React 16.8.

⚡ Simple Definition

Hooks are special React functions that allow Function Components to access features that were previously available only in Class Components.

Why Were Hooks Introduced?

❌ Before Hooks — Class Components Required
// Needed for state, lifecycle, context...
class Counter extends Component {
  state = {
    count: 0
  }
  // render(), constructor, bind()...
}

More boilerplate · Hard to read · Hard to reuse logic

✅ After Hooks — Function Component is Enough
function Counter() {
  const [count, setCount] = useState(0);
  // Done! Clean and simple
}

Cleaner · Simpler · Reusable · Easy to maintain

Important Features of Hooks

🔧 Built into React

No installation needed. Hooks come with React — just import what you need.

⚛️ Function Components Only

Hooks work only inside Function Components — not in Class Components.

💾 State Management

Allow state to be created and managed using useState() in Function Components.

🔄 Lifecycle Functionality

Replace componentDidMount, componentDidUpdate etc. using useEffect().

♻️ Make Code Reusable

Custom Hooks allow sharing logic across multiple components without duplication.

📉 Reduce Class Usage

Hooks eliminate the need for Class Components in modern React development.

Rules of Hooks

📌 Rule 1 — Only Inside Function Components
✅ Correct
function App() {
  const [count, setCount] = useState(0);
}
❌ Wrong — Outside Component
function demo() {}

// ❌ called outside any component
const [count, setCount] = useState(0);
📌 Rule 2 — Hook Names Must Start With "use"
useState()
useEffect()
useContext()
useRef()
useMemo()

React identifies Hooks by the use prefix. Custom hooks you write must also start with use.

📌 Rule 3 — Cannot Use Inside Loops
❌ Wrong — Hook Inside Loop
for (let i = 0; i < 5; i++) {
  useState();  // ❌ Not allowed
}

Hooks must be called the same number of times on every render. Loops break this guarantee.

📌 Rule 4 — Cannot Use Inside Conditions
❌ Wrong — Hook Inside if Block
if (true) {
  useState();  // ❌ Not allowed
}

Conditional Hooks cause React to lose track of hook order between renders — always call unconditionally.

📌 Rule 5 — Call at Top Level of Component
✅ Correct — Top Level
function App() {
  // ✅ Hooks at top — always called
  const [count, setCount] = useState(0);

  return <h1>Hello</h1>;
}
💡 Always declare Hooks before any return statement and outside loops/conditions to ensure consistent hook order every render.

useState Hook — Deep Dive

📘 Definition

useState is a React Hook that allows Function Components to create and manage state variables. It is used to store and update data that changes over time.

Syntax

const [state, setState] = useState(initialValue);

Syntax Breakdown

count
State Variable
Holds the current state value.
count = 0 initially
setCount
Setter Function
Function to update the state.
setCount(5) sets count to 5
useState()
Hook Call
React Hook that creates the state.
Returns [value, setter]
0
Initial Value
Value assigned when component first loads.
useState(0) → starts at 0

How useState Solves the UI Update Problem

setCount() called (state changes)
↓
React detects the change
↓
Component re-renders
↓
UI updates automatically ✅

Practical Examples

Example 1 — Counter Application

  Counter.jsx 
import React, { useState } from 'react';

function Counter() {

  const [count, setCount] = useState(0);    // Initial value = 0

  return (
    <>
      <h1>{count}</h1>

      <button
        onClick={() => setCount(count + 1)}   // update state on click
      >
        Increment
      </button>
    </>
  );
}

export default Counter;
▶ Output
Initially → 0
After 1 click → 1
After 2 clicks → 2
After 3 clicks → 3
🔍 Line-by-Line Understanding
LineWhat it does
useState(0)Creates state variable count starting at 0
countCurrent value shown in <h1>
setCount(count + 1)On click → updates count → React re-renders → new value shown
() =>Arrow function wraps the call so it only runs on click (not immediately)

Example 2 — Toggle Button (Online / Offline)

  Toggle.jsx 
import React, { useState } from 'react';

function Toggle() {

  const [status, setStatus] = useState(false);  // starts as false (Offline)

  return (
    <>
      <h1>
        {status ? "Online" : "Offline"}   // Conditional Rendering
      </h1>

      <button
        onClick={() => setStatus(!status)}   // flip true↔false
      >
        Toggle
      </button>
    </>
  );
}

export default Toggle;
▶ Initially (status = false)
Offline
▶ After Toggle Click (status = true)
Online
💡 !status flips the boolean — true becomes false and vice versa. This is a common pattern for toggle switches, dark mode, show/hide panels etc.

Types of Values Stored in useState

useState can store any JavaScript data type as its initial value.

🔤 String
const [name, setName] =
  useState("Pravin");
🔢 Number
const [age, setAge] =
  useState(21);
✅ Boolean
const [isLogin, setIsLogin] =
  useState(false);
📋 Array
const [students, setStudents] =
  useState(["Ram", "Sham"]);
📦 Object
const [user, setUser] =
  useState({
    name: "Pravin",
    age: 21
  });
🚫 null / undefined
const [data, setData] =
  useState(null);
// common for API data

🎯 Interview Q&A
Q: What are Hooks in React?
A: Hooks are built-in React functions that allow Function Components to use state, lifecycle features, context, and other React functionalities without using Class Components. Introduced in React 16.8.
Q: Why were Hooks introduced?
A: Hooks were introduced to make Function Components more powerful and to reduce the complexity and boilerplate of Class Components — making code cleaner, simpler, and more reusable.
Q: What is useState?
A: useState is a React Hook that allows Function Components to create and manage state variables. Syntax: const [state, setState] = useState(initialValue);
Q: What happens when state changes using useState?
A: When the setter function (e.g., setCount) is called, React detects the change, re-renders the component, and automatically updates the UI with the new value.
Q: What are the rules of Hooks?
A: (1) Only inside Function Components. (2) Names must start with "use". (3) Cannot use inside loops. (4) Cannot use inside conditions. (5) Must be called at the top level of the component.
Q: Can useState store objects or arrays?
A: Yes. useState can store any JavaScript value — string, number, boolean, array, object, or null. For objects/arrays, always create a new copy when updating to trigger re-render properly.
