Why CSS in React?

React builds the UI structure — CSS makes it look beautiful and professional. Together they create complete, polished web applications.

❌ Without CSS

Plain text, no layout, no colors, no spacing. Just raw content dumped on screen.

✅ With CSS

Beautiful UI, professional layout, colors, animations, responsive design.

4 Types of CSS in React

1 · Inline CSS
Styles applied directly on the JSX element using style={{}}
2 · Internal CSS
Style stored in a JS object variable inside the component
3 · External CSS
Separate .css file imported into the component
4 · CSS Modules
Scoped .module.css file — no class name conflicts!
1

Inline CSS

Inline

Inline CSS is applied directly on a JSX element using the style attribute with a JavaScript object.

Inline CSS applies styles directly to a JSX element using the style attribute and a JavaScript object — not a CSS string.

Why Double Curly Braces {{ }} ?

{
Outer brace
JavaScript Expression
in JSX
+
{color:"red"}
Inner brace
JavaScript Object
containing styles
=
{{color:"red"}}
Double braces
Object inside
JSX expression

Syntax

Inline CSS
<h1 style={{ color: "red" }}>Hello</h1>

Example — Multiple Properties

App.jsx
function App() {
  return (
    <h1 style={{
      color: "blue",
      backgroundColor: "yellow",   // camelCase! not background-color
      padding: "10px"
    }}>
      React CSS
    </h1>
  );
}
React CSS  — Blue text, Yellow background
camelCase Rule: CSS properties with hyphens become camelCase in JSX. background-color → backgroundColor, font-size → fontSize, border-radius → borderRadius

✅ Advantages

  • Simple and quick
  • Dynamic / conditional styling
  • No separate file needed

❌ Disadvantages

  • Hard to manage in large projects
  • Not reusable across components
  • Poor readability with many props
2

Internal CSS

Internal

Internal CSS stores styles in a JavaScript object variable inside the component and applies it via the style prop — cleaner than inline, still inside the file.

Internal CSS stores styles inside the component as a JS object variable and applies them to elements through the style attribute.

Example

App.jsx
function App() {
  // Style stored as a JS object — reusable within this component
  const headingStyle = {
    color: "white",
    backgroundColor: "green",
    padding: "10px",
    borderRadius: "6px"
  };

  return (
    <h1 style={headingStyle}>   // Single braces — passing a variable
      Internal CSS
    </h1>
  );
}
Internal CSS  — White text, Green background

✅ Advantages

  • Styles reusable within component
  • Cleaner than inline CSS
  • Easy to maintain

❌ Disadvantages

  • Not suitable for large projects
  • Styling logic mixed with JSX
3

External CSS

External

The most commonly used approach — styles live in a separate .css file and are imported into the component. Clean separation of concerns.

External CSS stores styles in a separate .css file which is imported into the React component and applied via the className attribute.

Step-by-Step

1

Create the CSS file — write your styles using normal CSS syntax.

2

Import it in your component file using import "./App.css"

3

Apply the class using className="heading" (NOT class)

App.css
.heading {
  color: white;
  background-color: blue;
  padding: 10px;
  border-radius: 6px;
}
App.jsx
import "./App.css";   // Step 2: import the CSS file

function App() {
  return (
    <h1 className="heading">   // className, not class!
      External CSS
    </h1>
  );
}
External CSS  — White text, Blue background
Why className and not class?
Because class is a reserved keyword in JavaScript (used for ES6 classes). React uses className to avoid the conflict. In the final HTML output it becomes class automatically.

✅ Advantages

  • Most popular approach
  • Easy maintenance
  • Reusable across components
  • Good project structure

❌ Disadvantages

  • CSS class conflicts possible
  • Styles are global in scope
4

CSS Modules

CSS Modules

CSS Modules solve the global scope conflict problem of External CSS. Each class name becomes unique and scoped to the component that imports it.

CSS Modules are CSS files whose styles are scoped locally to a specific component — preventing naming conflicts between different components.

The Problem CSS Modules Solve

File1.css
.heading {
  color: red;
}
⚔️
CONFLICT!
File2.css
.heading {
  color: blue;
}

Both files define .heading — one will overwrite the other. CSS Modules fix this by making each class unique automatically.

Step-by-Step

1

Create the module file — name it ComponentName.module.css

2

Import it as an object: import styles from "./App.module.css"

3

Use classes via the object: className={styles.heading}

App.module.css
.heading {
  color: white;
  background-color: red;
  padding: 10px;
  border-radius: 6px;
}
/* React converts this to: .App_heading__xK2p9 (unique hash!) */
App.jsx
import styles from "./App.module.css";  // imported as object

function App() {
  return (
    <h1 className={styles.heading}>  // access via styles.classname
      CSS Module
    </h1>
  );
}
CSS Module  — White text, Red background, Scoped! ✅
💡 How scoping works: React automatically transforms .heading into a unique class like App_heading__xK2p9 — so even if another file has .heading, they'll never conflict!

✅ Advantages

  • No CSS class conflicts ever
  • Component-specific styling
  • Better maintainability
  • Perfect for large projects

❌ Disadvantages

  • Slightly more syntax to write
  • Small learning curve

When to Use Which?

🎨 Inline CSS

Small Dynamic Styles

When style depends on state, props, or user action. Example: changing button color on click.

🔧 Internal CSS

Single Component Only

When styles belong only to one component and don't need to be shared anywhere else.

📁 External CSS

Medium Projects

Best for most everyday React projects where styles are shared across a few components.

🏗️ CSS Modules

Large Enterprise Apps

When many developers work on the same codebase and class name conflicts must be avoided.

Decision Flow

Small dynamic style → Inline CSS
↓
Single component styles → Internal CSS
↓
Medium project → External CSS
↓
Large / Enterprise app → CSS Modules ⭐

Interview Questions 🎯

What are the different types of CSS in React?
React supports 4 methods: (1) Inline CSS using style={{}}, (2) Internal CSS using a JS style object, (3) External CSS by importing a .css file, and (4) CSS Modules using a .module.css file.
Why is className used instead of class in React?
Because class is a reserved keyword in JavaScript (used for ES6 classes). React uses className to avoid conflicts. It gets converted to the class attribute in the final HTML.
What are CSS Modules?
CSS Modules are locally scoped CSS files that prevent class name conflicts. React automatically generates unique class names like Component_class__hash so styles never leak between components.
Which CSS type is best for large projects?
CSS Modules — because they provide component-level scoping, prevent global CSS conflicts, and are easy to maintain as the project grows.
Why does inline CSS use double curly braces?
The outer brace is a JSX expression container, the inner brace is the JavaScript object containing style properties. So style={{color:"red"}} = JSX expression containing a style object.
