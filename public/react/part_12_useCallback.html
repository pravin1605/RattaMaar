What is useCallback?

useCallback is a built-in React Hook used to memoize (cache) a function and prevent it from being unnecessarily recreated on every component re-render.

useCallback is a React Hook that returns a memoized version of a function and only recreates it when its dependencies change.
Key idea: In JavaScript, every time a function is declared, it creates a new object in memory. useCallback prevents this from happening on every render by caching and reusing the same function reference.
2

The Problem — Why We Need It

Every time a React component re-renders, all functions inside it are recreated as new objects, even if their logic didn't change at all.

Without useCallback — Problem 
function App() {
  // This function is RE-CREATED on every render! ⚠️
  const handleClick = () => {
    console.log("Clicked");
  };
}

What Actually Happens on Each Render

Render 1 → handleClick created
↓
Render 2 → NEW handleClick created
↓
Render 3 → NEW handleClick created
↓
Child receives new function → Child re-renders ❌

The Real Pain Point — Parent → Child

❌ Without useCallback
Count Changes
↓
Parent Re-renders
↓
showMessage Recreated
↓
Child Re-renders ❌

Even though child data didn't change at all!

✅ With useCallback
Count Changes
↓
Parent Re-renders
↓
Function SAME (cached)
↓
Child Skips Re-render ✅

Used together with React.memo.

Syntax & Import

Import

Import 
import { useCallback } from "react";

Full Syntax

Syntax 
const memoizedFunction = useCallback(
  () => {
    // your function logic here
  },
  [dependencies]   // recreate only when these change
);

How the Flow Works

Component Renders
↓
Dependency Changed?
↓
YES → Create New Function
─ OR ─
NO → Reuse Existing (Cached) Function
Empty dependency array []: The function is created only once — on the first render — and reused forever after.

Examples

Example 1

Normal Function — The Problem

App.jsx — Without useCallback 
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  // ⚠️ Recreated on EVERY render
  const showMessage = () => {
    console.log("Hello");
  };

  return (
    <>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </>
  );
}
⚠️ Problem: Every time count changes → showMessage is recreated as a brand new function object in memory.
Example 2

Using useCallback — The Fix

App.jsx — With useCallback 
import { useState, useCallback } from "react";

function App() {
  const [count, setCount] = useState(0);

  // ✅ Cached — not recreated unless dependencies change
  const showMessage = useCallback(() => {
    console.log("Hello");
  }, []);  // Empty [] = create once only

  return (
    <>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </>
  );
}
showMessage is NOT recreated on count change ✅
Same function reference reused across renders
Example 3

Real Scenario — Parent Passing Function to Child

Child.jsx 
function Child({ showMessage }) {
  console.log("Child Rendered");   // Watch how often this runs!

  return (
    <button onClick={showMessage}>
      Click Me
    </button>
  );
}

export default Child;
App.jsx — Optimized Parent 
import { useState, useCallback } from "react";
import Child from "./Child";

function App() {
  const [count, setCount] = useState(0);

  // ✅ Same function reference every render (unless deps change)
  const showMessage = useCallback(() => {
    console.log("Hello from Parent");
  }, []);

  return (
    <>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>

      <Child showMessage={showMessage} />
    </>
  );
}
💡 Best Practice: Pair useCallback with React.memo on the Child component. Without React.memo, the child will still re-render even with the same function reference.

useCallback with Dependency

When your function uses a value from state or props, you must add it to the dependency array so the function gets the latest value.

With Dependency — count 
const showData = useCallback(() => {
  console.log(count);   // uses count → must be in deps
}, [count]);             // recreate when count changes
Count Changes
Dependency Changed
↓
Function Recreated
↓
Gets fresh count value
Count Doesn't Change
Dependency Same
↓
Existing Function Reused ✅
↓
No unnecessary re-render
⚠️ Stale Closure Bug: If you use count inside the function but forget to add it to the dependency array, the function will always see the old value of count from when it was first created. Always add used values to deps!

useMemo vs useCallback

These two hooks look similar but serve different purposes. A common interview topic!

useMemo — Stores a VALUE
const result = useMemo(() => {
  return count * count;
}, [count]);

// Returns: 25 (a number)
// → A VALUE, not a function
useCallback — Stores a FUNCTION
const handleClick = useCallback(
  () => { /* logic */ },
  []
);

// Returns: () => {...}
// → A FUNCTION, not a value

ReturnsA computed valueA memoized function
MemoizesResult of a calculationThe function itself
Used forExpensive calculationsFunctions passed to children

🧠 Easy Memory Trick:
useMemo → Memoize a VALUE
useCallback → Memoize a FUNCTION

Pros, Cons & When to Use

✅ Advantages

  • Prevents unnecessary function recreation
  • Improves performance in large trees
  • Works perfectly with React.memo
  • Reduces child component re-renders

❌ Disadvantages

  • Uses extra memory to cache function
  • Not needed for simple components
  • Overuse can actually reduce performance

✅ When Should You Use useCallback?

Use it when:

• Passing a function as a prop to a child component
• The child is wrapped with React.memo
• You have expensive component trees that re-render often
• You specifically need to optimize performance
Don't use it everywhere! Adding useCallback to every function is premature optimization and wastes memory. Profile first, optimize second.

Interview Questions 🎯

What is useCallback?
useCallback is a React Hook that memoizes a function and only recreates it when its dependencies change — preventing unnecessary re-creation on every render.
Why is useCallback used?
It prevents unnecessary function recreation on each render, which improves performance — especially when passing functions to child components.
What does useCallback return?
It returns a memoized function — the same function reference until the dependency array changes.
Difference between useMemo and useCallback?
useMemo returns a memoized value (result of a computation).
useCallback returns a memoized function.
Simple rule: useMemo = store value | useCallback = store function.
Does useCallback improve performance?
Yes — especially when passing functions to child components wrapped with React.memo. It prevents child re-renders when parent state changes but the function logic didn't.
What is the interview keyword for useCallback?
"Prevent Unnecessary Function Recreation" — Say this in every interview answer about useCallback!
