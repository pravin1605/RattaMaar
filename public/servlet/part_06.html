6. web.xml & @WebServlet
Part A — web.xml (Deployment Descriptor)
What is web.xml?
📌 Definition

web.xml is the Deployment Descriptor of a Java web application. It is a configuration file that tells the Servlet Container (Tomcat):

  • Which servlet classes exist in the application
  • What URL should invoke which servlet
  • Other application-level settings (welcome files, error pages, filters, etc.)

Think of it as the "instruction manual / phone directory" for Tomcat.

Why is web.xml Needed?
❌ Without web.xml
  • Tomcat doesn't know PageA.java is a servlet
  • No URL to access it from browser
  • Server doesn't know when to run it
✅ With web.xml
  • You tell server: "This is a servlet, its name is pagea"
  • You tell server: "When user visits /pagea, run it"
  • Server knows exactly what to do
XML Tags in web.xml — Explained
TagMeaningWhat It Does
<servlet> "Register this servlet" Tells the server: "This servlet exists in my app"
<servlet-name> "Give it a nickname" Creates a unique name / ID for your servlet (used to link the two blocks)
<servlet-class> "Where is the code?" Fully qualified class name of the servlet e.g. com.ty.PageA
<servlet-mapping> "Connect name to URL" Tells server: "When someone visits this URL, run this servlet"
<url-pattern> "This is the URL" The URL path users type in browser (e.g. /pagea)
web.xml Structure
web.xml
<web-app> <!-- STEP 1: REGISTER THE SERVLET --> <servlet> <servlet-name>pagea</servlet-name> <!-- Nickname/ID --> <servlet-class>com.ty.PageA</servlet-class> <!-- Actual Java class --> </servlet> <!-- STEP 2: CONNECT NAME TO URL --> <servlet-mapping> <servlet-name>pagea</servlet-name> <!-- Same nickname (must match!) --> <url-pattern>/pagea</url-pattern> <!-- URL user types in browser --> </servlet-mapping> </web-app>
⚠️ Key Rule

<servlet-name> must be exactly the same in both <servlet> and <servlet-mapping> blocks. This is how Tomcat connects the class name to the URL. It acts like a handshake between the two sections.

How web.xml Works — Step by Step
1
User types URL in browser → http://localhost:8080/myapp/pagea
2
Tomcat receives the request → opens and reads web.xml
3
Tomcat looks for <url-pattern>/pagea</url-pattern> → found!
4
Tomcat reads the servlet-name → pagea
5
Tomcat finds the class → <servlet-class>com.ty.PageA</servlet-class>
6
Tomcat loads & runs com.ty.PageA → servlet processes request → response sent

Multiple Servlets in web.xml — Real Example

In real applications, multiple servlets are registered in a single web.xml file.

web.xml — Online Shopping App
<web-app> <!-- Login Servlet --> <servlet> <servlet-name>login</servlet-name> <servlet-class>com.shop.LoginServlet</servlet-class> </servlet> <servlet-mapping> <servlet-name>login</servlet-name> <url-pattern>/login</url-pattern> </servlet-mapping> <!-- Product Servlet --> <servlet> <servlet-name>products</servlet-name> <servlet-class>com.shop.ProductServlet</servlet-class> </servlet> <servlet-mapping> <servlet-name>products</servlet-name> <url-pattern>/products</url-pattern> </servlet-mapping> </web-app>
User Types URLServlet That RunsWhat Happens
/loginLoginServletChecks username/password against database
/productsProductServletFetches and displays all products
Extra — One Servlet Mapped to Multiple URLs

A single servlet can be mapped to more than one URL:

<!-- Same servlet handles both URLs --> <servlet-mapping> <servlet-name>pagea</servlet-name> <url-pattern>/pagea</url-pattern> </servlet-mapping> <servlet-mapping> <servlet-name>pagea</servlet-name> <url-pattern>/view/pagea</url-pattern> </servlet-mapping>

Both /pagea and /view/pagea will run the same com.ty.PageA servlet class.

Part B — @WebServlet Annotation (Modern Approach)
What is @WebServlet?
📌 Definition

@WebServlet is an annotation introduced in Servlet 3.0 (2009) that replaces web.xml configuration for URL mapping.

It is written directly on the servlet class — configuration and code are in the same file.

Requires: Tomcat 7+ or any Servlet 3.0+ container.

Problem with web.xml
ProblemWhy It's Bad
Large XML filesOne big web.xml with 50+ servlets becomes huge and unmanageable
Hard to readToo many tags — hard to find what you need
Separation of concernsJava code in one file, config in another — hard to track
Error-proneA typo like <servlet-nam> instead of <servlet-name> breaks the app
Too much typingNeed 6–7 lines of XML just for one servlet
Hard to maintainRename a class → must update both Java file AND web.xml
@WebServlet — Syntax
PageA.java — using @WebServlet
// 1 line replaces entire web.xml entry @WebServlet("/pagea") public class PageA extends HttpServlet { public void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException { // Your business logic here response.getWriter().print("<h1>Hello from PageA!</h1>"); } }
How @WebServlet Works
PartWhat It Means
@WebServlet"This class is a servlet" — marks the class for Tomcat
("/pagea")"When user visits /pagea, run this servlet" — URL mapping
extends HttpServletThe actual Java servlet code
📘 What Tomcat Does Automatically
  1. Scans all classes for @WebServlet annotation at startup
  2. Reads the URL pattern from the annotation
  3. Creates internal mapping (no web.xml needed)
  4. Invokes the correct servlet when URL is accessed
Side by Side — web.xml vs @WebServlet
OLD — web.xml (6-7 lines per servlet)
<servlet> <servlet-name>pagea</servlet-name> <servlet-class> com.ty.PageA </servlet-class> </servlet> <servlet-mapping> <servlet-name>pagea</servlet-name> <url-pattern>/pagea</url-pattern> </servlet-mapping> // For 2 servlets = 14-16 lines
NEW — @WebServlet (1 line per servlet)
@WebServlet("/pagea") public class PageA extends HttpServlet { } @WebServlet("/login") public class LoginServlet extends HttpServlet { } // For 2 servlets = 2 lines
Extra — Multiple URL Patterns with @WebServlet

A single servlet can handle multiple URLs using array syntax:

// Servlet handles both /pagea and /view/pagea @WebServlet(urlPatterns = {"/pagea", "/view/pagea"}) public class PageA extends HttpServlet { }

When to Use Which?
Use web.xml When
  • Enterprise apps with complex configuration
  • All mappings need to be in one central file
  • Team prefers XML-based configuration
  • Very old legacy systems (pre-Servlet 3.0)
  • Environment-specific configs without recompiling
Use @WebServlet When
  • Simple or medium-sized web apps
  • Want cleaner, readable code
  • Modern projects (Tomcat 7+, Servlet 3.0+)
  • Faster development required
  • Most new real-world projects use this
⭐ Modern Standard

Most new Java web projects use @WebServlet instead of web.xml. However, both approaches produce the same result — Tomcat handles them identically at runtime. You can even use both together in the same project if needed.

🎯 Interview Q&A
Q1. What is web.xml in a Servlet application?
web.xml (Deployment Descriptor) is an XML configuration file that registers servlet classes with the container and maps URLs to servlets. It tells Tomcat: "This class exists, and this URL should invoke it."
Q2. What is the role of <servlet-name> in web.xml?
<servlet-name> is a unique ID (nickname) used to link the <servlet> block (which declares the class) with the <servlet-mapping> block (which declares the URL). Both blocks must use the exact same name — it acts as the bridge between them.
Q3. What is @WebServlet annotation?
@WebServlet is an annotation introduced in Servlet 3.0 that maps a URL directly to a servlet class, replacing the need for web.xml configuration. Example: @WebServlet("/login") written on the servlet class tells Tomcat to invoke it when /login is accessed.
Q4. What is the difference between web.xml and @WebServlet?
web.xml — separate XML file, 6–7 lines per servlet, error-prone, legacy approach. @WebServlet — annotation in the Java class itself, 1 line per servlet, cleaner, modern approach. Both achieve the same URL-to-servlet mapping.
Q5. Which Servlet version introduced @WebServlet?
Servlet 3.0, released in 2009. Requires Tomcat 7 or higher.
Q6. Can we use both web.xml and @WebServlet together?
Yes. Both can coexist in the same project. However, care must be taken to avoid duplicate URL mappings, which would cause conflicts.
Q7. What happens if <servlet-name> doesn't match in web.xml?
The mapping will fail. Tomcat will not be able to connect the servlet class to the URL. The <servlet-name> in <servlet> and <servlet-mapping> must be identical.
Q8. Why was @WebServlet introduced?
To solve the problems of web.xml — large XML files, code-configuration separation, error-prone tags, and high maintenance cost. Annotations keep configuration with the code, making it cleaner, faster, and easier to maintain.
