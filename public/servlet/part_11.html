Why RequestDispatcher is Needed?

Suppose one servlet processes a request, but after processing it wants another resource to continue the work.

Instead of sending a new request from the browser, the same request can be transferred internally on the server.

📌 Definition

RequestDispatcher is an interface that provides the facility of dispatching (forwarding) a request from one resource to another resource.

The resource may be: HTML, JSP, or another Servlet.

It can also include the content of another resource in the current response.

Methods of RequestDispatcher Interface
Method 1 — forward()

Syntax:

public void forward(ServletRequest req, ServletResponse res)

Purpose: Forwards the request from one servlet to another resource.

First Servlet Response: ❌ Not Displayed

Second Resource Response: ✅ Displayed

Browser only sees output of the second resource.

Method 2 — include()

Syntax:

public void include(ServletRequest req, ServletResponse res)

Purpose: Includes another resource's output inside the current response.

First Servlet Response: ✅ Displayed

Second Resource Response: ✅ Displayed

Both outputs are visible in browser.

How to Get RequestDispatcher Object?
❌ Wrong — Cannot use new
new RequestDispatcher(); // ERROR — It's an interface!
✅ Correct — Use getRequestDispatcher()
RequestDispatcher rd = request.getRequestDispatcher("welcome"); // "welcome" can be Servlet/HTML/JSP

⭐ Critical — forward() Discards First Response

Even if LoginServlet writes:

pw.print("Login Successful");

before calling rd.forward()...

The browser will ONLY display: "Welcome User"

Why? forward() clears the output buffer of LoginServlet and gives full control to WelcomeServlet.

🎯 Interview Q&A
Q1. Why do we use RequestDispatcher?
RequestDispatcher is used to transfer a request from one resource to another resource (forward) or include the content of another resource in the current response (include) — all on the server side without a new browser request.
Q2. How do you get the RequestDispatcher object?
RequestDispatcher rd = request.getRequestDispatcher("resource"); — obtained from the HttpServletRequest object. Cannot use new RequestDispatcher() because it is an interface.
Q3. What is the difference between forward() and include()?
forward() — Transfers control completely. First servlet output is discarded. Only second resource response shown. include() — Includes second resource content. Both outputs visible. Control returns to calling servlet.
Q4. Which method is used after successful login?
rd.forward(request, response) — because after successful authentication, control should move completely to the next resource (e.g., WelcomeServlet or Dashboard).
Q5. Which method is used for validation error messages?
rd.include(request, response) — because we want to show the error message AND the same login page again together in one response.
Q6. What happens to LoginServlet output if forward() is called?
It is completely discarded. Even if pw.print("Login Successful") was written before rd.forward(), the browser will not see it. Only WelcomeServlet's output ("Welcome User") is shown.
Q7. Can RequestDispatcher forward to an HTML page or JSP?
Yes. request.getRequestDispatcher("page.html") — forwards to HTML. request.getRequestDispatcher("page.jsp") — forwards to JSP. It works with Servlet, HTML, and JSP.
