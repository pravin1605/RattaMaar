Default Behavior — Lazy Loading
📌 What is Lazy Loading?

By default, Tomcat follows Lazy Loading — the Servlet object is NOT created when the server starts. It is created only when the first request arrives for that servlet.

Server Starts
Servlet objects NOT created yet
↓ (time passes...)
First Request Arrives → /pagea
↓
Tomcat NOW creates: new PageA()
↓
init() → service() → Response
First user experiences delay!
Problem with Lazy Loading

In critical applications, some servlets must be ready before any user arrives:

Bank Application

DB Connection Servlet must be ready before first transaction

Hospital System

Authentication Servlet must be ready before first login

E-Commerce

Configuration Servlet must be ready before first purchase

With lazy loading, the first user waits while the servlet loads. This is unacceptable for critical applications.

Solution — load-on-startup (Eager Loading)
📌 Definition

<load-on-startup> is an element in web.xml that tells the web container to load and initialize a servlet during server startup instead of waiting for the first request.

This is called Eager Loading — servlet is created eagerly at startup, not lazily on demand.

Lazy Loading vs Eager Loading (load-on-startup)
❌ Lazy Loading (Default)
  • Servlet created on first request
  • First user experiences delay
  • No <load-on-startup> in web.xml
  • Saves memory at startup
  • Fine for low-priority servlets
✅ Eager Loading (load-on-startup)
  • Servlet created when server starts
  • First user gets instant response
  • <load-on-startup>n</load-on-startup> in web.xml
  • Uses memory at startup
  • Used for critical / high-priority servlets
Syntax — load-on-startup
web.xml
<servlet> <servlet-name>pagea</servlet-name> <servlet-class>com.ty.PageA</servlet-class> <load-on-startup>1</load-on-startup> <!-- Priority rank --> </servlet>
⚠️ Important Rules for load-on-startup Value
  • Positive value (1, 2, 3...) → Servlet loaded at startup in ascending order
  • Smaller number = Higher priority → loaded first
  • Negative value or absent → Treated as lazy loading (default behavior)
  • Same value → Tomcat decides the order (implementation-specific)

Best Practice — Constructor vs init()
📌 Why is Constructor used in this project?

The constructor is used only for demonstration — to observe when Tomcat creates the object. In real projects, initialization logic should NOT be placed in the constructor.

❌ Not Recommended — Constructor
public class PageA extends HttpServlet { // Only for learning/demo public PageA() { System.out.println( "im from pag a"); } }

Constructor may run before servlet infrastructure is ready. Cannot throw ServletException. Not the correct lifecycle point for initialization.

✅ Recommended — init() method
public class PageA extends HttpServlet { // Correct lifecycle method @Override public void init() throws ServletException { System.out.println( "Servlet Initialized"); // DB connect, config load etc. } }

init() is the proper servlet lifecycle method for initialization. Can throw ServletException. Has access to ServletConfig.

🎯 Interview Q&A
Q1. What is load-on-startup in Servlet?
load-on-startup is an element in web.xml that tells the servlet container to load and initialize a servlet during server startup instead of waiting for the first client request. It enables eager loading of servlets.
Q2. What is the difference between Lazy Loading and Eager Loading?
Lazy Loading (default) — servlet created only when first request arrives. First user experiences delay. No load-on-startup in web.xml. Eager Loading — servlet created at server startup. All users get instant response. Configured using load-on-startup.
Q3. Which servlet loads first if values are 1, 2, and 3?
The servlet with value 1 loads first, then 2, then 3. Smaller positive value = higher priority = loads earlier. Tomcat sorts by ascending order and loads accordingly.
Q4. What happens if load-on-startup value is negative?
A negative value (or absent element) means the servlet is not loaded at startup. Tomcat treats it as lazy loading — the servlet is created only when a request arrives for it.
Q5. Why do we use load-on-startup?
To improve response time for critical servlets by initializing them at server startup. Important servlets like Database Connection, Authentication, and Configuration loaders should be ready before any user request arrives.
Q6. What is the difference between Servlet Constructor and init()?
Constructor — Java language feature, called by JVM when new is executed. Cannot throw ServletException, has no access to ServletConfig. init() — Servlet lifecycle method, called by Container after object creation. Can throw ServletException, has access to ServletConfig. Always use init() for servlet initialization logic.
Q7. What is the output if PageB has rank 1, PageC has rank 2, PageA has rank 3?
Console output at startup: im from page b → im from pag c → im from pag a. This output appears even without any user request because load-on-startup creates objects at server startup.
Q8. Can two servlets have the same load-on-startup value?
Yes, it is allowed. But if two servlets have the same value, the order of loading between them is implementation-specific — Tomcat decides. To ensure a fixed order, always use unique values.
Q9. Can load-on-startup be used with @WebServlet annotation?
Yes. In @WebServlet, use: @WebServlet(urlPatterns="/pagea", loadOnStartup=1). This achieves the same result as <load-on-startup>1</load-on-startup> in web.xml — without needing the XML file.
🧠 Memory Trick — load-on-startup

"Load Early, Serve Fast"

Lazy = Late creation (on request) | Eager = Early creation (at startup)

Rank rule: Think of it as a queue number — token 1 gets served first, token 3 waits.
