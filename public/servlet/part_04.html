4. Servlet Container & Life Cycle
What is a Servlet Container?
📌 Definition

Servlet Container (also called Web Container) is a Java program inside a web server that:

  • Manages Servlets — your Java servlet classes
  • Controls entire life cycle — when to create, run, and destroy
  • Handles requests & responses — receives from browser, sends back

Think of it as: "The Manager that runs and controls all your servlets."

Popular Servlet Containers
Apache Tomcat
Most Popular — used in most Java web projects
Jetty
Lightweight container — used for embedded servers
GlassFish
Full Java EE container — supports more specifications
Why is Servlet Container Needed?

Servlets have no main() method. They cannot run on their own like a regular Java program.

⚠️ Key Point

Servlets cannot run without a Container. Container provides the runtime environment, handles HTTP, creates threads, and calls lifecycle methods automatically.

⭐ Most Important Points
  • init() and destroy() are called only ONCE in the entire servlet lifetime
  • service(), doGet(), doPost() are called multiple times — once per request
  • service() acts like the main() method of a servlet — it handles all incoming requests
  • Container does NOT create new object for each request — same object is reused
  • Container creates a new thread for each request (multithreading)

Detailed Life Cycle — Each Step
Step 1 — Load Class

When the first request arrives for a servlet, the container checks if the servlet class is already loaded in JVM.

  • If NOT loaded → Container loads .class file into JVM memory
  • Called only once per servlet
  • No method involved — done internally by the Container's ClassLoader
Step 2 — Create Object

After class is loaded, Container creates one instance of the servlet class.

  • Equivalent to: LoginServlet obj = new LoginServlet();
  • Called only once — same object is reused for all future requests
  • No method involved — done automatically by Container
Step 3 — init() Method
📌 init()

Called by Container once after object creation. Used to initialize resources that the servlet will use throughout its lifetime.

When triggered: After object is created, before first request is served.

Purpose: Load config data, connect to database, initialize variables.

Step 4 — service() Method ⭐ Most Important
📌 service()

Called by Container for every single request. This is the main working method of Servlet — like main() in regular Java programs.

What it does: Checks whether the request is GET or POST and internally calls doGet() or doPost() accordingly.

doGet() — called for HTTP GET requests (e.g., opening a page, clicking a link)

doPost() — called for HTTP POST requests (e.g., submitting a login form)

Step 5 — destroy() Method
📌 destroy()

Called by Container once when the server is shutting down, application is undeployed, or the servlet is reloaded.

Purpose: Close DB connections, release resources, save important data, free memory.

After destroy(): Object is eligible for garbage collection and removed from memory.

🎯 Interview Q&A
Q1. What is a Servlet Container?
A Servlet Container (Web Container) is a runtime environment inside a web server (like Tomcat) that manages the complete lifecycle of servlets — loading, creating, initializing, executing, and destroying them.
Q2. What are the steps of the Servlet Life Cycle?
1. Load Class → 2. Create Object → 3. init() (once) → 4. service() / doGet() / doPost() (multiple times) → 5. destroy() (once)
Q3. How many times is init() called?
init() is called only once — after the servlet object is created, before the first request is processed.
Q4. What is the role of service()?
service() is called for every HTTP request. It acts like the main() method of the servlet. It checks whether the incoming request is GET or POST and delegates to doGet() or doPost() accordingly.
Q5. When is destroy() called?
destroy() is called once when the server shuts down, the application is undeployed, or the servlet is reloaded. Used to close DB connections and release resources.
Q6. Does Container create a new servlet object for each request?
No. Container creates only one servlet object. For each request, it creates a new thread (not a new object). This is why servlets are multithreaded and must handle thread safety.
Q7. What is the difference between init() and doGet()?
init() — called once for initialization (DB connect, config load). doGet() — called multiple times for each GET request to handle business logic.
Q8. Who calls the lifecycle methods — programmer or container?
The Servlet Container calls all lifecycle methods (init(), service(), destroy()) automatically. The programmer only overrides them to write business logic — never calls them manually.
