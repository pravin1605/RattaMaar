1. Servlet
What is Servlet?

A Servlet is a Java technology used to create dynamic web applications.

A Servlet is simply a Java class that runs inside a Web Server (Tomcat) and processes client requests and generates responses.

📌 Definition

Servlet is a server-side Java component used to receive requests from clients, process them, and send responses back to the client.

Why Servlet is Needed?

Before Servlets, web pages were mostly static HTML pages.

Static pages cannot:

  • Process user input
  • Validate login credentials
  • Store data in database
  • Generate dynamic content
📘 Example

Suppose a user enters: Username: Pravin   Password: 1234

HTML alone cannot verify this information.

Servlet receives the data → processes it → checks the database → sends response.

∴ Servlets are required for dynamic web applications.

Real-Life Example

When you login to Gmail, Facebook, Instagram, or Amazon — your request is sent to a server.

A Servlet (or similar server-side technology) processes Username + Password and returns:

✅ Login Successful
❌ Invalid Credentials

🎯 Interview Q&A
Q1. What is Servlet?
Servlet is a server-side Java technology used to develop dynamic web applications. It runs inside a web container, receives requests from clients, processes them, and sends responses back to the client.
Q2. Where does Servlet run?
Servlet runs inside a Web Container (e.g. Apache Tomcat), not directly in JVM like a standalone Java program.
Q3. What is the difference between Static and Dynamic web page?
Static: Fixed HTML, cannot process data. Dynamic: Generated at runtime by Servlet based on user input or database data.
Q4. Why are Servlets preferred over CGI?
Servlets are faster (run inside JVM), platform independent, secure, and can handle multiple requests efficiently using threads instead of separate processes.
Q5. What is a Web Container?
Web Container (like Tomcat) is the runtime environment that manages the lifecycle of Servlets — creating, initializing, calling service methods, and destroying them.
