Way 1 — Implementing Servlet Interface
📌 What is Servlet Interface?

Java needed a common set of rules that every servlet must follow. Therefore Java created the Servlet Interface.

This interface defines 5 methods that every servlet must implement:

  • init() — initialize servlet
  • service() — handle requests
  • destroy() — cleanup
  • getServletConfig() — get config
  • getServletInfo() — get info string
✅ Advantage
  • Complete control over servlet behavior
  • Good for understanding internal working
❌ Disadvantage
  • Must implement all 5 methods — even unused ones
  • Lots of unnecessary boilerplate code
📍 Where Used?

Rarely used in real projects. Mainly used to understand the internal working of servlets.

Way 2 — Extending GenericServlet
📌 What is GenericServlet?

GenericServlet is an abstract class that already implements the Servlet Interface.

It provides ready-made implementations for: init(), destroy(), getServletConfig(), getServletInfo()

You only need to override: service()

Why was GenericServlet introduced? Developers complained: "Why should we write all 5 methods when we only need service()?" → Java introduced GenericServlet to solve this.

✅ Advantage
  • Less coding — only override service()
  • Protocol independent — can handle any protocol
❌ Disadvantage
  • Cannot distinguish GET, POST, PUT, DELETE
  • Everything goes through single service() method
  • Developer must manually check request type
📍 Where Used?

Used when protocol independence is required. Mostly for learning. Rarely used in modern web applications.

Project Structure — GenericServlet Example
src/main/java/ └── com/ty/servlet/ └── RegistrationForm.java src/main/webapp/ ├── Registration.html └── WEB-INF/ └── web.xml
Registration.html — Why Needed?

HTML page collects data from the user and sends it to the servlet via form submission.

Registration.html
<form action="register"> Name : <input type="text" name="name"> Age : <input type="text" name="age"> Email : <input type="email" name="email"> <input type="submit" value="Register"> </form>
RegistrationForm.java — Why Needed?

Receives the request sent by HTML form and processes the data.

RegistrationForm.java
public class RegistrationForm extends GenericServlet { @Override public void service(ServletRequest req, ServletResponse res) throws ServletException, IOException { String name = req.getParameter("name"); String age = req.getParameter("age"); String email = req.getParameter("email"); System.out.println(name); // prints to server console System.out.println(age); System.out.println(email); } }
web.xml — Why Needed?

Tomcat does not know which URL should execute which servlet. web.xml creates the URL-to-Servlet mapping.

web.xml
<web-app> <servlet> <servlet-name>register</servlet-name> <servlet-class>com.ty.servlet.RegistrationForm</servlet-class> </servlet> <servlet-mapping> <servlet-name>register</servlet-name> <url-pattern>/register</url-pattern> </servlet-mapping> </web-app>

Way 3 — Extending HttpServlet (Most Used ⭐)
📌 What is HttpServlet?

HttpServlet is an abstract class that extends GenericServlet and provides HTTP-specific methods.

Why introduced? GenericServlet handles all requests through one service() method. But web applications mainly use HTTP — developers wanted GET, POST, PUT, DELETE to be handled separately.

HTTP Methods Supported
MethodPurposeReal-World Use
doGet()Handle HTTP GET requestFetch data, open page, search
doPost()Handle HTTP POST requestLogin form, register form, submit data
doPut()Handle HTTP PUT requestUpdate existing record
doDelete()Handle HTTP DELETE requestDelete a record
✅ Advantage
  • Very powerful — separate methods for each request type
  • Least coding effort
  • Cleanly separates GET and POST logic
  • Used in all real-world projects
❌ Disadvantage
  • Works only with HTTP protocol
  • Not protocol-independent
📍 Where Used?

Most commonly used servlet type. Used in: Banking Applications, E-Commerce, Hospital Management, College Portals, Employee Management — almost every real-world servlet application.

⭐ Extra — @WebServlet Annotation (Modern Alternative to web.xml)

Instead of writing URL mapping in web.xml, modern Servlet 3.0+ projects use the @WebServlet annotation directly on the servlet class:

@WebServlet("/student")

This maps /student URL directly to the servlet without any web.xml entry. Both approaches produce the same result.

🎯 Interview Q&A
Q1. What are the 3 ways to create a Servlet?
1. Implementing Servlet Interface — must override all 5 methods. 2. Extending GenericServlet — override only service(). 3. Extending HttpServlet — override doGet()/doPost(). HttpServlet is the most used in real projects.
Q2. Why is GenericServlet preferred over Servlet Interface?
GenericServlet already implements all methods of the Servlet Interface except service(). Therefore developers only need to override service(), reducing coding effort significantly.
Q3. Why is HttpServlet preferred over GenericServlet?
HttpServlet provides HTTP-specific methods such as doGet(), doPost(), doPut(), and doDelete(), making it easier to handle different types of HTTP requests separately without manually checking request type inside service().
Q4. What is the role of web.xml in a Servlet application?
web.xml (Deployment Descriptor) maps URLs to Servlet classes. Without it (or @WebServlet), Tomcat would not know which servlet to invoke for a given URL.
Q5. What is the difference between GenericServlet and HttpServlet?
GenericServlet — protocol-independent, overrides service(), cannot separately handle GET/POST. HttpServlet — HTTP-specific, provides doGet()/doPost() etc., used in all HTTP web applications.
Q6. What is the alternative to web.xml for URL mapping?
@WebServlet("/url-pattern") annotation introduced in Servlet 3.0. It maps the URL directly on the servlet class, eliminating the need for web.xml entries.
Q7. Can you directly implement Servlet Interface in real projects?
Technically yes, but it is not recommended. You must implement all 5 methods even if unused. GenericServlet and HttpServlet reduce this burden significantly. Servlet Interface is mainly used for understanding internals.
Q8. What does form action="register" do in HTML?
It tells the browser to send the form data to the URL /register when the form is submitted. Tomcat matches this URL in web.xml (or @WebServlet) and invokes the corresponding servlet.
