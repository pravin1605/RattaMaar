10. RequestDispatcher
What is RequestDispatcher?
📌 Definition

RequestDispatcher is an interface provided by the Servlet API that is used to:

  • Forward a request from one resource to another resource
  • Include the content of another resource in the current response

The resource can be: HTML Page, JSP Page, or another Servlet.

Why RequestDispatcher is Needed?
📘 Problem Without RequestDispatcher

Suppose a Login Servlet verifies a user. After successful verification, we want to show a Welcome Page.

Without RequestDispatcher, the browser would have to send a new request — which is slow and exposes URLs.

With RequestDispatcher, the same request is transferred internally from Login Servlet → Welcome Servlet — faster, secure, no extra browser trip.

Real-World Use 1

Login → Forward to Dashboard Servlet on success

Real-World Use 2

Include header/footer JSP in every page response

Real-World Use 3

Include error message + show login page again on failure

RequestDispatcher Interface — 2 Methods
Method 1 — forward()

Syntax: rd.forward(request, response);

  • Transfers complete control to another resource
  • First servlet's response is discarded
  • Only the second resource's response is shown
  • URL in browser does NOT change (server-side)
  • Used after successful processing
Method 2 — include()

Syntax: rd.include(request, response);

  • Includes another resource's content into current response
  • First servlet's response is retained
  • Both outputs are visible in browser
  • Control returns back to the calling servlet
  • Used for error messages, headers, footers
How to Create RequestDispatcher Object?
⚠️ Important — Why We Can't Use new?

RequestDispatcher is an Interface. Interfaces cannot be instantiated directly.

new RequestDispatcher() → ❌ NOT Allowed

Therefore, we use request.getRequestDispatcher("resource") which returns an implementation object provided by the Container.

// Syntax — Getting RequestDispatcher object RequestDispatcher rd = request.getRequestDispatcher("url-of-resource"); // Examples RequestDispatcher rd = request.getRequestDispatcher("welcome"); // → Servlet RequestDispatcher rd = request.getRequestDispatcher("login.html"); // → HTML RequestDispatcher rd = request.getRequestDispatcher("result.jsp"); // → JSP // Then use forward or include rd.forward(request, response); // Transfer control completely rd.include(request, response); // Include content + return back

Example 1 — Login Validation (forward + include)
login.html — Purpose: Collect Username & Password
login.html
<form action="login"> Username : <input type="text" name="username"> Password : <input type="password" name="password"> <input type="submit" value="Login"> </form>
LoginPage.java — Validates Credentials + Uses forward() and include()
LoginPage.java
@WebServlet("/login") public class LoginPage extends HttpServlet { protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException { String user = request.getParameter("username"); String pass = request.getParameter("password"); PrintWriter pw = response.getWriter(); if(pass.equals("123")) { // ✅ SUCCESS → FORWARD to WelcomeServlet RequestDispatcher rd = request.getRequestDispatcher("welcome"); rd.forward(request, response); // Note: pw.print() before forward() is DISCARDED } else { // ❌ FAILURE → show error + INCLUDE login.html again pw.print("<h3>Invalid Password</h3>"); RequestDispatcher rd = request.getRequestDispatcher("login.html"); rd.include(request, response); // Both "Invalid Password" + login form shown together } } }
WelcomeServlet.java — Receives Forwarded Request
WelcomeServlet.java
@WebServlet("/welcome") public class WelcomeServlet extends HttpServlet { protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException { PrintWriter pw = response.getWriter(); pw.print("<h1>Welcome User!</h1>"); } }

⭐ Most Important Point — forward() Discards First Servlet Response

Even if you write pw.print("Login Success") in LoginPage servlet BEFORE calling rd.forward(), the output "Login Success" will be discarded.

The browser will only see WelcomeServlet's response — "Welcome User!"

Why? Because forward() transfers control completely. The first servlet's output buffer is cleared.

  • Session expired message + login form
  • Advertisement panel in sidebar

🎯 Interview Q&A
Q1. What is RequestDispatcher?
RequestDispatcher is an interface in the Servlet API used to forward a request to another resource (servlet, JSP, HTML) or include the content of another resource in the current response — all on the server side without a new browser request.
Q2. How do you get a RequestDispatcher object?
RequestDispatcher rd = request.getRequestDispatcher("resource-url"); — It is obtained from the HttpServletRequest object. We cannot use new RequestDispatcher() because it is an interface.
Q3. What is the difference between forward() and include()?
forward() — transfers complete control to another resource. First servlet's response is discarded. Only second resource output shown. include() — includes second resource's output into current response. Both outputs visible. Control returns to calling servlet.
Q4. Which method is used after successful login?
rd.forward(request, response) — because after successful authentication we want to move completely to the next page (e.g., Welcome Servlet or Dashboard) and discard the login page response.
Q5. Which method is used for error messages?
rd.include(request, response) — because we want to display the error message AND also show the original page (e.g., login form) again. Both are visible together in the browser.
Q6. Does forward() change the URL in the browser?
No. forward() happens on the server side. The browser URL remains the same (e.g., still shows /login). Only the displayed content changes to the forwarded resource's output.
Q7. What happens if you write output before calling forward()?
Any output written before rd.forward() is discarded. The browser only receives the response from the forwarded resource (e.g., WelcomeServlet). The first servlet's buffer is cleared on forward.
Q8. What is the difference between RequestDispatcher and sendRedirect()?
RequestDispatcher.forward() — server-side, same request/response, URL doesn't change, faster. sendRedirect() — client-side, browser sends a new request, URL changes, slightly slower. forward() can share request attributes; sendRedirect() cannot.
🧠 Memory Trick — forward vs include

forward() = Fully moves (like handing a letter to someone else — you keep nothing)

include() = Includes and returns (like photocopying a document and giving it back)

Success → forward() | Error / Header / Footer → include()
