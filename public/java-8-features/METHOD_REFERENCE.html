📘 Definition
🔹 What is a Method Reference?

A Method Reference is a shorthand syntax for a Lambda Expression that simply refers to an existing method. Instead of writing the implementation again using a Lambda Expression, we can directly refer to an already existing method. Method References were introduced in Java 8 along with Lambda Expressions.

🔹 Simple definition (for interviews)

Method Reference is a compact way of referring to an existing method using the :: operator.

📘 Why Method Reference?
🔹 Using a Lambda Expression

Lambda is simply calling an already existing method — this is repetitive.

Demo d = () -> Reference.m1();
🔹 Using a Method Reference

We can directly refer to the method instead — shorter, cleaner.

Demo d = Reference::m1;
🔹 Purpose — why use Method Reference
1
Improves readability — code becomes easier to understand
2
Improves conciseness — less code is written
3
Avoids repetition — no need to rewrite the same implementation
4
Supports Functional Programming — works with Functional Interfaces and Lambda Expressions
📘 Syntax
🔹 Static Method Reference
ClassName::staticMethodName

Example:

Math::max
🔹 Instance Method Reference
objectReference::instanceMethodName

Example:

obj::display

🔹 1 — Reference to a static method

🔹 2 — Reference to an instance method of a particular object
objectReference::instanceMethodName
METHOD REFERENCE | Page 2 — Type 1: Reference to a Static Method
✅ Type 1 — Reference to a Static Method
🔹 Example 1 — static method reference (wish)
// Functional Interface public interface Demo { void wish(); } // Implementation class class Reference { public static void m1() { System.out.println("hello world"); } } public static void main(String[] args) { Demo d = Reference::m1; d.wish(); }
Output: hello world
🔍 Explanation

The method m1() is already available. Instead of writing the full Lambda, we directly refer to it with Reference::m1. When d.wish() is executed, Java internally calls Reference.m1().

🔹 Example 2 — static method reference using Math::max
public interface Calci { int findMax(int x, int y); } public static void main(String[] args) { Calci c = Math::max; System.out.println(c.findMax(10, 20)); }
Output: 20
🔍 Explanation

Math::max refers to Math.max(int, int). When c.findMax(10, 20) is executed, internally Math.max(10, 20) is executed, giving output 20.

METHOD REFERENCE | Page 3 — Type 2: Instance Method of a Particular Object
✅ Type 2 — Reference to an Instance Method of a Particular Object
🔹 Definition

If we refer to a non-static method using an object reference, it is called an Instance Method Reference.

🔹 Example 1 — instance method reference
// Reference class public class Reference { public void test() { System.out.println("we are getting more testing requirements"); } } // Functional Interface public interface Demo { void m1(); public static void main(String[] args) { Reference r = new Reference(); Demo d = r::test; // using object reference d.m1(); Demo d2 = new Reference()::test; // using inline object d2.m1(); } }
Output: we are getting more testing requirements we are getting more testing requirements
🔍 Explanation

r::test means r.test(). Similarly, new Reference()::test means new Reference().test(). Both forms are valid.

🔹 Example 2 — System.out::println
public interface Remo { void display(String x); } public class Demo1 { public void m1(String s) { System.out.println(s); } public static void main(String[] args) { Remo r = System.out::println; r.display("hello" + " every one " + 20 + 30); } }
Output: hello every one 2030
🔍 Explanation

System.out::println refers to System.out.println(). Therefore r.display(...) internally becomes System.out.println(...).

METHOD REFERENCE | Page 4 — Important Notes & Return Type Rules
📘 Important Notes
🔹 Note 1 — compiler converts to Lambda

Method References are converted into Lambda Expressions by the compiler internally.

Reference::m1 // internally behaves like: () -> Reference.m1()
🔹 Note 2 — parameter list must match

The parameter list of the Functional Interface method must match the parameter list of the referred method.

🔹 Note 3 — return type compatibility

Return type compatibility rules must be followed between the Functional Interface method and the referred method.

⚠️ Return Type Rules
❌ Rule 1 — compile time error case

If the Functional Interface method returns a value, the referred method must also return the same compatible type. Mismatch causes a Compile Time Error.

public interface Demo2 { int m1(); // returns int } class Ref { public static void fun() { // returns void — MISMATCH System.out.println("having fun"); } } // Demo2 d = Ref::fun; → COMPILE TIME ERROR
Functional Interface method returns int but fun() returns void — mismatch → Compile Time Error.
✔️ Rule 2 — void method accepts any return type

If the Functional Interface method returns void, the referred method may return any datatype. The returned value will simply be ignored by Java.

public interface Demo2 { void m1(); // returns void } class Ref { public static int fun() { // returns int — ALLOWED System.out.println("having fun"); return 10; // 10 is ignored } } Demo2 d = Ref::fun; // valid d.m1();
Output: having fun
void m1() does not expect any return value. Even though fun() returns 10, Java ignores it. Program executes successfully.
