Multithreading in Java01 · Multitasking

🧩 Multitasking

🧩 What is Multitasking?
The process of performing more than one task parallelly is called Multitasking. It is of 2 types.
★ Most Important — everything in this file is really "thread-based multitasking inside one program"
🖥️ 1 — Process based (OS level)
The process of executing more than one task where each task is independent of each other and each task belongs to a different program.
Examples:
Task 1: Browsing on Google
Task 2: Watching a YouTube video
Task 3: Using Excel
Task 4: Typing something on Word
🧵 2 — Thread based (Program level)
The process of executing multiple tasks parallelly, where each task is an independent unit of execution within the same program, is called thread-based multitasking or multithreading.
Example — Chat app running at same time:
Task 1: Receiving messages
Task 2: Sending messages
Task 3: Showing typing indicator
Task 4: Auto-saving chat history
🧠 Memory trick: "Process = different apps sharing the CPU. Thread = different jobs sharing one app." One program, many hands.

🚀 Advantages of Multithreading

1️⃣ CPU utilisation
Better utilisation of CPU resources — idle cycles (e.g. while one task waits on I/O) get used by another thread instead of sitting empty.
2️⃣ Performance
Faster execution — hence performance will be improved, since independent parts of a task run at the same time instead of one after another.
⚠️ Extra theory: multithreading speeds things up only when tasks are genuinely independent. Threads that constantly fight over the same shared data can end up slower than a single thread, once synchronization overhead is added.
💬 Interview Line: "Multitasking has two flavours — process-based at the OS level and thread-based inside one program; multithreading is the thread-based kind, and it exists mainly to squeeze more performance out of one program without opening a second process."
Multithreading in Java02 · Thread basics

🧵 What is a Thread?

📖 Definition — 3 ways to say it
1It is a flow of execution
2It is a small unit of a program
3It is a lightweight process
A thread is called a lightweight subprocess because it runs independently (like a process) but uses less memory.
☕ Thread as an object in Java
In Java, a thread is actually an object which is used to perform a task. 
// Example: 1000 lines of code split between 2 threads
Thread 1 → executes first 500 lines
Thread 2 → executes second 500 lines
// Both run parallelly
🧠 Memory trick: "Process = heavyweight house. Thread = lightweight room inside it." Rooms share the house's furniture (memory); they don't need a separate one each.

🏁 Default Thread / Main Thread

🏁 What is the Main Thread?
1When a Java program starts, the JVM automatically creates a thread.
2This thread is known as the main thread.
3The JVM uses this main thread to invoke the main(String[] args) method of your class.
★ Most Important — every Java program, even single-threaded ones, is already multithreaded to some degree (main + GC + JIT threads).

🏷️ Thread Properties — id, name, priority

🏷️ Every thread has an id, name, priority
PropertyDetails
idRandomly assigned by JVM automatically
nameProgrammer can set it, or JVM gives a default name like Thread-0, Thread-1, etc.
priorityRange is 1 to 10. Default is 5. Thread scheduler requests OS to execute based on priority, but OS makes the final decision depending on available cores.
Priority constants: MIN_PRIORITY = 1, NORM_PRIORITY = 5, MAX_PRIORITY = 10
💬 Interview Line: "A thread is a lightweight flow of execution inside a process; the JVM always starts one for you — the main thread — and every thread carries an id, a name and a priority whether you set them or not."
Multithreading in Java03 · Creating threads

🛠️ Creation of Thread — 2 ways

🧬 Way 1 — Extending Thread class
1Create a class that extends Thread
2Override the run() method — write task inside it
3Create an object of your class
4Call start() to begin execution
🔌 Way 2 — Implementing Runnable
1Create a class that implements Runnable
2Override the run() method
3Create an object of that class
4Pass the object to Thread constructor
5Call start() on the Thread object
🧠 Memory trick: "Extend when you ARE a thread's job. Implement when you HAVE a job a thread can carry." Prefer HAVE — it keeps your inheritance slot free.

🔌 Runnable Interface

🔌 About Runnable
1It is a Functional Interface present in java.lang package.
2It contains one abstract method: public void run();
⚠️ Because it's a functional interface, it can be implemented with a lambda: Runnable r = () -> System.out.println("hi"); — modern code rarely writes a full Runnable class by hand.

🧵 Thread class

🧵 About Thread class
1Present in java.lang package.
2It implements the Runnable interface.
3It provides an empty implementation for run() method.
🏗️ Constructors of Thread class
Thread(Runnable target)
Thread(Runnable target, String name)
Thread(String name)
💬 Interview Line: "Thread itself implements Runnable — that's why you can pass a Runnable straight into a Thread constructor; the two approaches to creating a thread are just two ways of filling in run()."
Multithreading in Java04 · Methods & scheduler

📋 Thread class — all methods

📋 Method reference
MethodDeclarationPurpose
start()public void start()Starts a new thread of execution. Internally calls run() in a separate thread. Heart of multithreading.
run()public void run()Contains the task to be executed. If called directly (not via start()), it runs in the main thread — no new thread is created.
join()public final void join() throws InterruptedExceptionWaits for the thread to finish. If t1.join() is called, the current thread waits until t1 completes.
getName()public final String getName()Returns name of the thread. Default names: Thread-0, Thread-1, etc.
setName()public final void setName(String name)Used to set or change the name of the thread.
getId()public long getId()Returns the unique ID of the thread. Assigned automatically by JVM.
getPriority()public final int getPriority()Returns the priority of the thread (default is 5).
setPriority()public final void setPriority(int priority)Sets priority between 1 to 10. 1=MIN, 5=NORM, 10=MAX.
isAlive()public final boolean isAlive()Returns true if the thread has been started and has not yet finished.
sleep() (static)public static void sleep(long millis) throws InterruptedExceptionPauses the current thread for specified milliseconds. Thread.sleep(1000) sleeps for 1 second.
currentThread() (static)public static Thread currentThread()Returns the currently executing thread object. Used to get name, id, or status of the running thread.
🧠 Memory trick: group them as "Identity" (getName/setName/getId), "Behaviour" (start/run/join/sleep) and "Rank" (getPriority/setPriority). Interviewers usually ask one from each group.
⚙️ What start() does internally
1Registers the thread with the Thread Scheduler
2After that, invokes run() internally in a new thread
Without calling start() there is no chance of starting a new thread — that's why it's the heart of multithreading. Declaration: public synchronized void start(); Calling it twice on the same object throws IllegalThreadStateException.
🗓️ Thread Scheduler
The part of the JVM responsible for deciding, when multiple threads are waiting, in which order they should execute.
Algorithm differs JVM to JVM, so exact output can never be guaranteed. Common OS algorithms: Round RobinFCFSPriority Scheduling. Scheduler requests — the OS decides, based on core availability.
💬 Interview Line: "start() does two things — registers the thread with the scheduler, then internally invokes run() on a new call stack; if you skip start() and call run() yourself, you just made a normal method call on the main thread."
Multithreading in Java05 · Thread Life Cycle

🔄 Thread Life Cycle

🔄 Five states, flowchart
NEWnew CustomThread()
↓
RUNNABLEct.start() called
↓
RUNNINGThread Scheduler allocates a core
↕
WAITINGsleep() or join() → back to Runnable when done
↓
DEADrun() method completes execution
📖 Five states, explained
StateWhen it happens
NewWhen we create a thread object — CustomThread ct = new CustomThread();
RunnableWhen we call start() method — ct.start();
RunningWhen thread scheduler allocates a processor (core) to the thread
Waitingsleep() or join() is called. Goes back to Runnable once waiting is over.
DeadAfter run() method is completely executed
★ Most Important — "Runnable" ≠ "Running". Runnable only means eligible/waiting for a core; Running means it actually has one right now.
⚠️ Extra theory: a thread that calls sleep() or blocks on join()/I-O moves out of Running into Waiting (or Timed Waiting) — it does not go back to New. Once Dead, a thread object can never be restarted, even via a fresh start() call.
🧠 Memory trick: "N-R-R-W-D" — Newborn Runs Really Wonderfully, Dies. Five letters, five states, in order.
💬 Interview Line: "A thread moves New → Runnable → Running → (optionally Waiting, then back to Runnable) → Dead; the scheduler controls the Runnable-to-Running hop, and nothing controls the Dead state — once run() finishes, that's final."
Multithreading in Java06 · Program 1–2

💻 Program 1 — Main thread details using currentThread()

▶️ Accessing main thread properties
currentThread()getId()getName()getPriority() 
public class _01CurrentThread {
  public static void main(String[] args) {
    System.out.println("main started");
    Thread t = Thread.currentThread();
    System.out.println(t.threadId());
    System.out.println(t.getName());
    System.out.println(t.getPriority());
    System.out.println("main ended");
  }
}
Output:
main started
1 // JVM-assigned thread id (may vary)
main // default name of main thread
5 // default priority is 5
main ended

Explanation: Thread.currentThread() returns the currently running thread object. Here it is the main thread. We can access its id, name, and priority using the methods.
🧠 Extra theory: threadId() replaces the deprecated getId() from Java 19 onward — both still appear in codebases, so recognise either in an interview.

💻 Program 2 — Custom thread by extending Thread class

▶️ Creating a custom thread — extending Thread
extends Threadrun()start() 
public class _02CustomThread extends Thread {
  public void run() {
    System.out.println(threadId());
    System.out.println(getName());
    System.out.println(getPriority());
    System.out.println(isAlive());
  }
  public static void main(String[] args) {
    _02CustomThread ct = new _02CustomThread();
    ct.start();
  }
}
Output:
21 // JVM-assigned id (may vary)
Thread-0 // default name given by JVM
5 // default priority
true // isAlive() = true since thread is currently running

Explanation: Class extends Thread and overrides run(). ct.start() registers with scheduler and calls run() in a new separate thread.
💬 Interview Line: "isAlive() returning true here just confirms the new thread has actually started and hasn't finished run() yet — it's the cheapest way to check a thread's state without touching the lifecycle enum."

Multithreading in Java08 · Program 5–6

💻 Program 5 — join() method

▶️ join() — wait for thread to complete before main continues
join()start() 
public class joinmethod {
  public static void main(String[] args) throws InterruptedException {
    System.out.println("main Start");
    Mythread mt = new Mythread();
    mt.start();
    mt.join();   // main waits here until mt finishes
    for (int i = 0; i < 10; i++) {
      System.out.println("main executing");
    }
    System.out.println("main end");
  }
}
class Mythread extends Thread {
  public void run() {
    for (int i = 0; i < 10; i++)
      System.out.println("MYThread execute");
  }
}
Output (guaranteed order):
main Start
MYThread execute (×10)
main executing (×10)
main end

Explanation: Without join(), main and Mythread would run in mixed order. With mt.join(), the main thread pauses and waits until Mythread finishes completely. Only then does main continue. join() throws InterruptedException so it must be handled.
★ Most Important — join() is the one method in this whole set that turns unpredictable order into guaranteed order.

💻 Program 6 — sleep() method

▶️ sleep() — pause thread for a given time
sleep() 
public class sleepmethod {
  public static void main(String[] args) throws InterruptedException {
    System.out.println("main start");
    for (int i = 0; i < 100; i++) {
      System.out.println("main thread");
      Thread.sleep(2000); // pause for 2 seconds after each print
    }
    System.out.println("main end");
  }
}
Output:
main start
main thread // waits 2 seconds
main thread // waits 2 seconds
... (continues 100 times with 2 second gap each)
main end

Explanation: Thread.sleep(2000) pauses the current thread for 2000 milliseconds (2 seconds). During sleep, the thread moves to Waiting state. After the sleep duration, it goes back to Runnable state. It is a static method and throws InterruptedException.
🧠 Memory trick: "join() waits for a THREAD. sleep() waits for TIME." One depends on another thread finishing, the other depends only on the clock.
💬 Interview Line: "join() and sleep() both put a thread into Waiting, but join() has a target — another thread — while sleep() just waits out a duration; that's the cleanest way to tell them apart under pressure."
Multithreading in Java09 · Program 7–8

💻 Program 7 — Square and Cube using parallel threads + join()

▶️ Parallel computation — square and cube simultaneously
extends Threadstart()join() 
class square extends Thread {
  int num, sqaure;
  public square(int num) { this.num = num; }
  public void run() { sqaure = num * num; }
}
class cube extends Thread {
  int num, cube;
  public cube(int num) { this.num = num; }
  public void run() { cube = num * num * num; }
}
public class sqaure_cube_parallel {
  public static void main(String[] args) throws InterruptedException {
    System.out.println("main start");
    for (int i = 1; i < 10; i++) {
      square sq = new square(i);
      cube cu = new cube(i);
      sq.start();
      cu.start();
      sq.join();  // wait for both to finish
      cu.join();
      System.out.println("square=" + sq.sqaure + " Cube=" + cu.cube);
    }
  }
}
Output:
main start
square=1 Cube=1
square=4 Cube=8
square=9 Cube=27
square=16 Cube=64
square=25 Cube=125
square=36 Cube=216
square=49 Cube=343
square=64 Cube=512
square=81 Cube=729

Explanation: For each number, both square and cube threads start parallelly. sq.join() and cu.join() make main wait until both complete. Then the result is printed. This demonstrates true parallel computation — both calculations happen at the same time, not one after the other.
🧠 Extra theory: two new thread objects get created on every loop iteration here — fine for a demo, but in real systems this pattern is replaced by a reusable thread pool (ExecutorService) to avoid the cost of constant thread creation.

💻 Program 8 — Thread priority demo

▶️ Setting and observing thread priorities
setPriority()getPriority()setName()getName() 
class myThread extends Thread {
  public void run() {
    for (int i = 0; i <= 10; i++) {
      System.out.println("name = " + getName());
    }
  }
}
public class priority {
  public static void main(String[] args) {
    myThread m1 = new myThread();
    myThread m2 = new myThread();
    myThread m3 = new myThread();
    m1.setName("Pravin");
    m2.setName("mayuresh");
    m3.setName("saskshi");
    m1.setPriority(1);   // MIN_PRIORITY
    m2.setPriority(5);   // NORM_PRIORITY
    m3.setPriority(10);  // MAX_PRIORITY
    m1.start();
    m2.start();
    m3.start();
    System.out.println("main end");
  }
}
Output (order may vary — not guaranteed):
name = saskshi // priority 10 — likely executes more
name = mayuresh
name = Pravin // priority 1 — least preferred
... (mixed, repeated 11 times each)
main end

Explanation: setName() assigns custom names. setPriority() sets priority. m3 (saskshi) has the highest priority (10) so the thread scheduler prefers it, but the OS makes the final decision. Output order is not guaranteed. setPriority() is a request, not a command.
💬 Interview Line: "Priority is a hint, not a guarantee — on most modern OS schedulers, higher priority just means the thread is favoured more often, it doesn't mean it always runs first."

💻 Program 9 — Thread by implementing Runnable interface

▶️ Runnable interface implementation
implements RunnableThread(Runnable, name)start() 
class ExRunnable implements Runnable {
  public void run() {
    for (int i = 0; i < 10; i++) {
      System.out.println(Thread.currentThread().getName());
    }
  }
}
public class Driver {
  public static void main(String[] args) {
    Runnable r = new ExRunnable();
    Thread t1 = new Thread(r, "MyThread"); // pass runnable + name
    t1.start();
    for (int i = 0; i < 10; i++) {
      System.out.println(Thread.currentThread().getName());
    }
  }
}
Output (order may vary):
MyThread // custom thread printing its name
main // main thread printing its name
... (mixed 10 times each)

Explanation: ExRunnable implements Runnable. The object is passed to Thread constructor with the name "MyThread". t1.start() starts the custom thread while main loop runs simultaneously.

⚖️ Extending Thread vs Implementing Runnable

⚖️ Side-by-side comparison
FeatureExtending ThreadImplementing Runnable
InheritanceUses up the single inheritance slotFree to extend another class
FlexibilityLess flexibleMore flexible — preferred approach
Object creationMyThread t = new MyThread(); t.start();Thread t = new Thread(new MyRunnable()); t.start();
Code reuseClass tightly coupled to ThreadTask logic separated from Thread
RecommendedSimple casesAlways preferred in professional code
★ Most Important — in real projects, prefer Runnable (or Callable with ExecutorService); "extends Thread" is mostly a teaching device.
🧠 Memory trick: "IS-A vs HAS-A." extends Thread → your class IS a thread. implements Runnable → your class HAS a task. Favour HAS-A for reusable, testable code.
💬 Interview Line: "I'd implement Runnable over extending Thread almost every time — it keeps my class free to extend something else, and it separates 'what the task does' from 'how it's run', which matters once you move to thread pools."
Multithreading in Java11 · Key rules & recap

🔑 Key Rules and Important Notes

🚫 IllegalThreadStateException
Calling start() more than once on the same thread object throws IllegalThreadStateException. One thread object can start only once.
🔀 run() vs start()
If you call run() directly instead of start(), it executes in the main thread — no new thread is created. Always use start() to create a new thread.
🎲 Output not guaranteed
In multithreading there is no guarantee of exact output order. Thread scheduler + OS decide execution order based on priority and core availability.
🙋 setPriority() is a request
setPriority() is just a request — not a command. The JVM listens but the OS decides which thread runs.
🏆 Key rule to always remember
start() is the heart of multithreading. It registers with scheduler and invokes run() in a new thread. Never call run() directly. Use join() when you need to wait for a thread to finish before continuing. Use sleep() to pause a thread. Priority is a hint — the OS makes the final call. Thread output order is never guaranteed.
★ Most Important — of everything in this file, this one card is the exam-ready summary.
