What is an API?

API — Application Programming Interface

API stands for Application Programming Interface. It is a set of rules, methods, or tools that allows one software (or code) to communicate with another software.

What is Stream API?

Stream API — definition

1
It is a set of classes and interfaces.
2
These built-in interfaces and classes are present in the java.util.stream package.
3
Introduced in Java 8.
4
Allows a developer to process collections (like List or Set) in a functional approach — using filters, mappings, sorting, and more — without using loops.
What is a Stream in Java?

Stream is a built-in interface

Present in java.util.stream package.

Not a data structure

Stream is not a data structure but it takes a data structure as input to perform operations.

Provides methods

A Stream is an object that provides several methods to perform operations on a collection object — like filtering, mapping, sorting, etc.

What is a Stream Pipeline?

Definition

A stream pipeline is a sequence of operations (steps) performed on a stream of data. It has 3 stages:

Source
→
Intermediate Operations
→
Terminal Operation

Stream initialization example

ArrayList<Integer> al = new ArrayList<>();
al.add(10);
al.add(21);

// creates the stream object and returns the address
Stream<Integer> s = al.stream();
System.out.println(s);
Types of Stream Operations

Intermediate Operations

These methods return a Stream and are used to build the pipeline. They are lazy — they execute only when a terminal operation is called.

filter() map() sorted() distinct() limit()

Terminal Operations

Terminal operations terminate the pipeline and trigger the actual processing of the stream. Once called, the stream is consumed.

forEach() reduce() max() min() count() toList() toArray()

Optional Class

What is Optional?

Optional is a wrapper class used to represent the presence or absence of a value, mainly to avoid NullPointerException , especially in Stream API terminal operations. When we work with streams, some operations like finding max / min or searching for an element may not produce a result. Returning null may lead to NullPointerException . Optional handles this safely.

Programs — filter() Method
Uses: filter() forEach() — filter is Intermediate, forEach is terminal
Print only even numbers from a list filter()forEach() 
List<Integer> list = Arrays.asList(10, 15, 20, 25, 30);
list.stream()
    .filter(n -> n % 2 == 0)
    .forEach(n -> System.out.println(n));
Output10 20 30
Explanation: filter(n -> n%2==0) keeps only elements where remainder is 0 (even). 15 and 25 are odd so they are removed. forEach() prints each remaining element.
Print numbers greater than 20 filter()forEach() 
List<Integer> list = Arrays.asList(10, 25, 18, 40, 5);
list.stream()
    .filter(n -> n > 20)
    .forEach(System.out::println);
Output25 40
filter(n -> n>20) keeps only 25 and 40. 10, 18, 5 are removed. System.out::println is a Method Reference used in place of a Lambda.
Print only strings starting with 'A' filter()forEach() 
List<String> list = Arrays.asList("Apple", "Banana", "Avocado", "Mango");
list.stream()
    .filter(s -> s.startsWith("A"))
    .forEach(System.out::println);
OutputApple Avocado
Explanation: startsWith("A") checks each string. Only "Apple" and "Avocado" pass the filter. "Banana" and "Mango" are removed.
Print numbers divisible by both 3 and 5 filter()forEach() 
List<Integer> list = Arrays.asList(10, 15, 30, 22, 45, 7);
list.stream()
    .filter(n -> n % 3 == 0 && n % 5 == 0)
    .forEach(System.out::println);
Output15 30 45
Explanation: && applies both conditions together. 15 (3×5), 30 (3×10=✓, 5×6=✓), 45 (3×15=✓, 5×9=✓) pass. 10 (not div by 3), 22, 7 fail.

Programs — sorted() Method
Uses: sorted() forEach() — sort is intermediate, forEach is terminal
Sort numbers in ascending order sorted()forEach() 
List<Integer> list = Arrays.asList(40, 10, 30, 20);
list.stream()
    .sorted()
    .forEach(n -> System.out.println(n));
Output10 20 30 40
Explanation: sorted() with no argument sorts in natural (ascending) order. Original list is NOT modified.
Sort numbers in descending order sorted(comparator)forEach() 
List<Integer> list = Arrays.asList(40, 10, 30, 20);
list.stream()
    .sorted((a, b) -> b - a)
    .forEach(System.out::println);
Output40 30 20 10
Explanation: (a, b) -> b - a is a custom comparator. When b-a is positive, b comes first — this reverses the natural order giving descending sort.
Sort strings in alphabetical order sorted()forEach() 
List<String> list = Arrays.asList("Banana", "Apple", "Mango", "Cherry");
list.stream()
    .sorted()
    .forEach(System.out::println);
OutputApple Banana Cherry Mango
Explanation: sorted() on Strings uses alphabetical (lexicographic) order by default.
Sort strings based on length sorted(comparator)forEach() 
List<String> list = Arrays.asList("Java", "Spring", "API", "Microservices");
list.stream()
    .sorted((s1, s2) -> s1.length() - s2.length())
    .forEach(System.out::println);
OutputAPI Java Spring Microservices
Explanation: Custom comparator s1.length() - s2.length() sorts by string length in ascending order — shortest first.

Programs — Terminal Operations
Find the sum of all elements — reduce() reduce() 
List<Integer> list = Arrays.asList(10, 20, 30);
int sum = list.stream()
              .reduce(0, (a, b) -> a + b);
System.out.println("Sum = " + sum);
OutputSum = 60
Explanation: reduce(0, (a,b)->a+b) — identity value is 0 (starting point). Then adds each element: 0+10=10, 10+20=30, 30+30=60.
Find product of all elements — reduce() reduce() 
List<Integer> list = Arrays.asList(2, 3, 4);
int product = list.stream()
                  .reduce(1, (a, b) -> a * b);
System.out.println("Product = " + product);
OutputProduct = 24
Explanation: Identity is 1 (for multiplication). 1×2=2, 2×3=6, 6×4=24.
Find maximum element without identity — Optional reduce() 
List<Integer> list = Arrays.asList(10, 50, 30, 70);
Optional<Integer> max = list.stream()
                            .reduce((a, b) -> a > b ? a : b);
System.out.println(max.orElse(0));
Output50
Explanation: Without identity, reduce returns Optional. (a,b)->a>b?a:b keeps the larger of two. orElse(0) returns 0 if stream is empty.
Find maximum and minimum element — max() / min() max()min()get() 
List<Integer> list = Arrays.asList(10, 40, 25, 5);

int max = list.stream()
              .max(Integer::compareTo)
              .get();

int min = list.stream()
              .min(Integer::compareTo)
              .get();

System.out.println("Max = " + max);
System.out.println("Min = " + min);
OutputMax = 40 Min = 5
Explanation: max(Integer::compareTo) returns an Optional — get() extracts the value. Similarly for min. Integer::compareTo is a Method Reference used as a comparator.
Count how many elements are greater than 10 — count() filter()count() 
List<Integer> list = Arrays.asList(5, 15, 20, 8, 25);
long count = list.stream()
                 .filter(n -> n > 10)
                 .count();
System.out.println("Count = " + count);
OutputCount = 3
Explanation: filter(n>10) keeps 15, 20, 25. count() returns the number of remaining elements — 3. Return type is long .
Store even numbers in a new list and array — toList() / toArray() filter()toList()toArray() 
List<Integer> list = Arrays.asList(10, 15, 20, 25, 30);

List<Integer> evenList = list.stream()
    .filter(n -> n % 2 == 0)

Explanation: toList() (Java 16+) collects filtered stream into a List. toArray() collects into an Object array. Both store only even numbers — 10, 20, 30.
How Stream Processing Works Internally
#RuleExplanation
1Terminal operation starts the work.Until a terminal method is called, no data is processed. The terminal operation begins traversing the source collection.
2Elements are taken one by oneThe stream does not take all elements at once. Each element is picked individually during traversal.
3Intermediate operations are lazyFor each element, intermediate operations like filter() and map() are applied only when an element is needed.
4Original collection is not changedStream operations never modify the source collection. The original list remains exactly the same.
5No intermediate storage by defaultFiltered or mapped elements are not stored anywhere — they are processed and then discarded.
6Data is stored only when requiredIf the terminal operation is collect() / toList(), a new collection is created. Only then are the transformed elements stored.

Important note on intermediate operations

1
In each and every intermediate operation, a new Stream object is created.
2
These new streams are not separate pipelines — they are chained together.
3
All intermediate operations are lazy and will be executed only when a terminal operation is called.
Why Use Stream API?
1

Makes code shorter and readable

2

No need for explicit for loops

3

Supports functional programming

4

Can process data in parallel (faster)

5

Keeps original data unchanged

Key rule to always remember

Stream operations are lazy — nothing executes until a terminal operation is called. Intermediate operations ( filter , map , sorted , distinct , limit ) return a Stream. Terminal operations ( forEach , reduce , count , max , min , toList , toArray ) end the pipeline and trigger execution. The original collection is never modified.
