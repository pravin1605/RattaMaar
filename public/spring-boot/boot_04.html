1. What is JpaRepository?

One of the most important Spring Data JPA interview questions. First understand the problem JpaRepository solves.

Suppose your project has a Resident table:

idnameflatmobile
1RahulA1019876543210
2AmitA1029988776655

Your Spring Boot app needs to: Create resident, Read resident, Update resident, Delete resident, Search resident. Normally you'd write database-related code yourself — but Spring Data JPA gives us JpaRepository.

What is JpaRepository?

A Spring Data JPA interface that provides predefined methods for performing common database operations.

public interface ResidentRepository
        extends JpaRepository<Resident, Long> {}

Resident → Entity class. Long → Type of primary key.

JpaRepository<Resident, Long> means:
"This repository is used to perform database operations on the Resident entity, whose primary key is of type Long."

Why do we use JpaRepository?

Because we don't need to manually write basic CRUD operations. CRUD = Create, Read, Update, Delete.

residentRepository.save(resident);
residentRepository.findById(id);
residentRepository.findAll();
residentRepository.deleteById(id);

Without JpaRepository

Open database connection ↓ Create SQL query ↓ Execute query ↓ Handle result ↓ Close connection
INSERT INTO residents(name, flat, mobile)
VALUES('Rahul', 'A101', '9876543210');

You would need to manage a lot of database-related code.

With JpaRepository

residentRepository.save(resident);

Spring Data JPA and Hibernate handle the underlying persistence work.

Java Object ↓ Repository ↓ JPA ↓ Hibernate ↓ SQL ↓ Database

2. Important: JPA vs Hibernate vs JpaRepository

A very common interview confusion.

JPA

JPA = Java Persistence API. A specification/standard for object-relational persistence. It defines concepts and APIs for mapping Java objects to database tables.

Hibernate

Hibernate is a popular implementation of JPA.

JPA ↓ Rules / Specification Hibernate ↓ Implementation of those rules

Spring Data JPA

Spring Data JPA provides an abstraction that makes working with JPA repositories easier.

Spring Data JPA ↓ JPA ↓ Hibernate ↓ Database

JpaRepository

An interface provided by Spring Data JPA.

JpaRepository ↓ Spring Data JPA ↓ JPA ↓ Hibernate ↓ Database

This distinction is very useful in interviews.

Example from Your Project

@Entity
@Table(name = "residents")
public class Resident {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
    private String flatNumber;
    private String mobile;
}
public interface ResidentRepository
        extends JpaRepository<Resident, Long> {
}

That's enough for basic CRUD operations — you don't have to implement the interface yourself.

3. What Methods Does JpaRepository Give Us?

save()

Used to save an entity.

residentRepository.save(resident);

It can be used for creating and, depending on entity state/ID, updating entities.

findById()

Find a record by primary key. Usually returns Optional<Resident>.

residentRepository.findById(101L);

So we commonly write:

Resident resident =
    residentRepository.findById(101L)
        .orElseThrow(() ->
            new ResidentNotFoundException(
                "Resident not found"
            )
        );

findAll()

Get all records.

List<Resident> residents =
        residentRepository.findAll();

deleteById()

Delete by primary key.

residentRepository.deleteById(101L);

existsById()

Check whether a record exists.

boolean exists =
        residentRepository.existsById(101L);

count()

Get the number of records.

long total =
        residentRepository.count();

4. Custom Query Methods

One of the powerful features of Spring Data JPA is that you can create methods based on the method name — Spring Data derives the query automatically.

Optional<Resident> findByEmail(String email);

List<Resident> findByBuilding(String building);

List<Resident> findByResidentType(String residentType);

List<Resident> findByBuildingAndFlatNumber(
        String building,
        String flatNumber);

Instead of manually writing SQL for many simple queries, Spring Data can generate the query based on the method name.

📚 Library Analogy
Without JpaRepository: You need a book → Go to storage → Find shelf → Search manually → Bring book.

With a repository: You: "Give me book ID 101." Library System: "Here it is."

Similarly: residentRepository.findById(101L); — you tell the repository what you need, and the framework handles much of the underlying database interaction.
Interview Answer — JpaRepository
"JpaRepository is an interface provided by Spring Data JPA that provides predefined methods for performing database operations on JPA entities. It supports common CRUD operations such as save, findById, findAll and deleteById, and it also provides features like pagination, sorting and query-method derivation. We don't have to implement these basic methods manually." Then: "For example, in my SocietyHub project, I can create ResidentRepository extends JpaRepository<Resident, Long>. Here Resident is the entity and Long is its primary-key type. I can then use methods such as save(), findById(), findAll() and deleteById() to interact with the resident data."

5. What is JSON?

JSON stands for JavaScript Object Notation. It is a lightweight text-based format commonly used to exchange data between applications, especially between frontend and backend.

Why Do We Need JSON?

Suppose your React frontend wants resident information from Spring Boot. The backend has a Java object Resident resident, but React doesn't directly receive a Java object — the backend needs to send the data in a commonly understood format. JSON is one of the most common formats.

Java Object ↓ JSON ↓ React

Example

Resident resident = new Resident();
resident.setName("Rahul");
resident.setFlatNumber("A-101");
resident.setMobile("9876543210");

The API can return:

{
  "name": "Rahul",
  "flatNumber": "A-101",
  "mobile": "9876543210"
}

The frontend can easily understand this structure.

6. JSON Structure & Data Types

JSON mainly consists of key-value pairs.

{
  "name": "Rahul",
  "age": 22,
  "city": "Mumbai"
}

"name" → key, "Rahul" → value. Same pattern for age/22 and city/"Mumbai".

JSON Data Types

TypeExample
String{ "name": "Rahul" }
Number{ "age": 22 }
Boolean{ "active": true }
Array{ "skills": ["Java", "Spring Boot", "SQL"] }
Object{ "address": { "city": "Mumbai", "pincode": "400001" } }
Null{ "middleName": null }

7. JSON in Your Spring Boot Project

Suppose React wants to create a resident. React sends:

POST /api/residents
{
  "name": "Rahul",
  "flatNumber": "A-101",
  "mobile": "9876543210"
}

Spring Boot controller:

@PostMapping
public Resident createResident(
        @RequestBody ResidentRequest request) {
    return residentService.createResident(request);
}
JSON ↓ @RequestBody ↓ ResidentRequest Java object

Spring Boot converts the JSON request into a Java object. This process is commonly associated with deserialization.

What Happens in the Response?

return residentResponse;

The frontend might receive:

{
  "id": 101,
  "name": "Rahul",
  "flatNumber": "A-101",
  "mobile": "9876543210"
}

Spring Boot converts the Java object into JSON. This process is commonly called serialization.

Request: JSON → Java Object → Deserialization Response: Java Object → JSON → Serialization
🌐 Common Language Analogy
React Developer ↔ JSON ↔ Spring Boot Developer.
React understands JavaScript objects. Spring Boot works with Java objects. JSON acts as a common data representation.

React says: { "name": "Rahul", "flat": "A-101" } — Spring Boot receives the information and converts it into a Java object.

JSON vs Java Object

Java ObjectJSON
Exists inside the Java application (application memory)Text-based data representation used for communication

8. JSON vs XML

Sometimes an interviewer may ask: "Why JSON instead of XML?" Both can be used for data exchange.

JSON:

{
  "name": "Rahul",
  "age": 22
}

XML:

<student>
    <name>Rahul</name>
    <age>22</age>
</student>

JSON is often preferred for modern REST APIs because it is:

  • Lightweight
  • Easy to read
  • Easy to parse
  • Convenient for JavaScript/React applications
  • Less verbose than XML for many common API payloads
⚠️ Don't say
"JSON is always better than XML."
Instead say
"JSON is commonly preferred for modern REST APIs because it is lightweight and convenient for frontend applications, although XML is still used in many systems."

10. ⭐ Interview Answers to Memorize

JpaRepository
"JpaRepository is a Spring Data JPA interface that provides predefined database operations for JPA entities. It provides methods such as save(), findById(), findAll(), deleteById(), and existsById(), so we don't have to write basic CRUD operations manually. For example, in my project, ResidentRepository extends JpaRepository<Resident, Long> allows me to perform database operations on the Resident entity."
JSON
"JSON stands for JavaScript Object Notation. It is a lightweight, text-based format commonly used for exchanging data between frontend and backend applications. In my Spring Boot project, the frontend sends JSON in the request body, Spring converts it into Java objects using @RequestBody, and the backend returns Java objects that are converted into JSON responses."

⭐ Two Diagrams You Should Remember

JpaRepository

Controller ↓ Service ↓ Repository ↓ JpaRepository ↓ JPA ↓ Hibernate ↓ Database

JSON

React │ │ JSON Request ▼ Spring Boot │ │ @RequestBody ▼ Java Object │ ▼ Business Logic │ ▼ Database Database ↑ Java Object ↑ Spring Boot │ │ JSON Response ▼ React

The key thing to understand: JpaRepository is about database persistence, while JSON is about representing/exchanging data between applications.

11. Interview Q&A Bank Added

Q: What's the difference between CrudRepository, PagingAndSortingRepository, and JpaRepository?
CrudRepository provides basic CRUD methods. PagingAndSortingRepository extends it, adding pagination and sorting. JpaRepository extends PagingAndSortingRepository and adds JPA-specific features like batch operations (saveAll, flush) — it's the most feature-complete of the three.
Q: How does Spring Data JPA generate queries from method names?
It parses the method name against a defined keyword grammar (findBy, And, Or, OrderBy, etc.) and matches property names on the entity to build a JPQL query automatically at startup — no manual SQL/JPQL needed for simple queries.
Q: What does save() do if the entity already has an ID?
Depending on the ID generation strategy and whether Hibernate considers the entity "new" or "detached," save() may perform an INSERT or a merge/UPDATE — this is a common source of confusion and bugs.
Q: Why does findById() return Optional instead of the entity directly?
To force the caller to explicitly handle the "not found" case (via orElseThrow, orElse, isPresent, etc.) rather than risking a NullPointerException.
Q: What is the default content type for @RequestBody / @ResponseBody in Spring Boot?
application/json — Spring Boot auto-configures a Jackson-based HttpMessageConverter by default when spring-boot-starter-web is on the classpath.
Q: What is the difference between serialization and deserialization?
Serialization converts a Java object into a transferable format (like JSON) for a response. Deserialization converts an incoming format (like JSON) back into a Java object, typically for a request body.

12. Memory Tricks Added

🧠 JPA/Hibernate/Spring Data JPA stack
"Spring Data JPA simplifies JPA, JPA is the rulebook, Hibernate follows the rulebook." Remember top-down: Spring Data JPA → JPA → Hibernate → Database.
🧠 Serialization direction
"S for Sending → Serialize. Coming iN → Deserialize (turning iNto a Java object)."
🧠 JpaRepository<Entity, IdType>
Read the generic types like a sentence: "Repository of <Entity>, keyed by <IdType>."
🧠 JSON vs XML pick
"JSON = JS's Own Notation" — light, native to JavaScript, so a natural fit for a React frontend talking to any backend.

13. Common Bugs / Gotchas Added

⚠️ Calling .get() on Optional without checking
residentRepository.findById(id).get() throws NoSuchElementException if absent, with a poor error message. Always use orElseThrow() with a meaningful custom exception instead.
⚠️ Forgetting the entity needs @Id
JpaRepository requires the entity class to have a field annotated @Id — without it, Spring Boot fails at startup with a mapping exception, not a runtime error.
⚠️ Sending the Entity directly instead of a DTO
Returning the JPA @Entity directly from a controller (instead of a Response DTO) can leak internal fields, cause lazy-loading serialization errors, or expose more data than intended in the JSON response.
⚠️ Mismatched JSON field names and Java field names
If the incoming JSON key doesn't match the Java field name (and no @JsonProperty is used), Jackson silently leaves that field null instead of throwing an error — a common source of "why is this always null" bugs.
⚠️ Overusing derived query method names
Very long method names like findByBuildingAndFlatNumberAndResidentTypeAndMobile become hard to read and maintain — beyond 2-3 conditions, a @Query with JPQL/native SQL is often clearer.
