Events in JavaScript

A web page becomes interactive because of events. Whenever a user performs an action — clicking, typing, scrolling, submitting — the browser detects it and JavaScript can respond. Events are the backbone of every interactive web application.

What is an event

"An event is an action or occurrence generated by the user or browser that can be detected and handled by JavaScript."

Easy definition

"An event is anything that happens on a webpage." — click, type, scroll, resize, submit.

Real-life analogy

Doorbell rings (event) → you open the door (event handling). Button clicked (event) → JS function runs (event handling).

Event flow

User action → Event occurs → Browser detects it → JavaScript executes the handler function.

Event handling — responding to events

What is Event Handling?

Event Handling is the process of writing code that runs when a specific event occurs. You attach a function (called an event handler or listener) to an element so it executes when that event fires.

"Event Handling is the mechanism of executing JavaScript code when a specific event occurs."

Basic example

<button onclick="show()">Click Me</button>
function show() {
  alert("Button Clicked");
}

Output — on click

Browser alert popup: "Button Clicked"

3 ways to add events — know all three for interviews

Way 1

Inline Event not recommended

Event written directly inside the HTML tag as an attribute. Mixes HTML and JS — considered bad practice.

  • HTML and JS are mixed — hard to maintain.
  • Only one handler per event allowed.
  • Avoid in real projects.

HTML

<button onclick="show()">Click</button>

JavaScript

function show() {
  alert("Hello");
}

Output — on click

Alert: "Hello"
Way 2

DOM Property acceptable

Assign a function to the element's event property in JS. Separates HTML and JS but still only allows one handler at a time.

  • HTML and JS are separated — better than inline.
  • Only ONE handler per event — assigning again overwrites the previous.
  • Uses element.onclick, element.onchange, etc.

HTML

<button id="btn">Click</button>

JavaScript

let btn = document.getElementById("btn");
btn.onclick = function() {
  alert("Hello");
};

Output — on click

Alert: "Hello"
Way 3

addEventListener() ✓ recommended

The modern, most powerful way. Attaches an event listener to an element. Allows multiple handlers on the same event — nothing gets overwritten.

  • Multiple listeners can be added to the same element for the same event.
  • Can be removed using removeEventListener().
  • Cleaner, more flexible, and better for large applications.
  • Syntax: element.addEventListener("eventName", callback).

HTML

<button id="btn">Click</button>

JavaScript

let btn = document.getElementById("btn");
btn.addEventListener("click", () => {
  alert("Hello");
});

Output — on click

Alert: "Hello"

Mouse events — triggered by mouse actions

Mouse Events 5 events

Mouse events fire when the user interacts with elements using the mouse — clicking, hovering, moving.

click

Fires when element is clicked once.

btn.addEventListener("click", () => { console.log("Clicked"); });
Clicked

dblclick

Fires when element is double-clicked.

btn.addEventListener("dblclick", () => { console.log("Double Clicked"); });
Double Clicked

mouseover

Fires when mouse pointer enters the element.

btn.addEventListener("mouseover", () => { console.log("Mouse Over"); });
Mouse Over

mouseout

Fires when mouse pointer leaves the element.

btn.addEventListener("mouseout", () => { console.log("Mouse Out"); });
Mouse Out

mousemove

Fires every time the mouse moves anywhere on the page.

document.addEventListener("mousemove",()=>{ console.log("Moving"); });
Moving ← fires continuously on every move

Keyboard events — triggered by key actions

Keyboard Events 3 events

Keyboard events fire when the user presses or releases keys. Useful for live search, shortcuts, game controls, and form validation.

keydown

Fires the moment a key is pressed down. Fires before the character appears.

document.addEventListener("keydown",(e)=>{ console.log("Key Pressed:", e.key); });
Key Pressed: a ← fires immediately on press

keyup

Fires when a key is released. Fires after the character appears.

document.addEventListener("keyup",(e)=>{ console.log("Key Released:", e.key); });
Key Released: a ← fires when finger lifts

keypress

Fires when a printable character key is pressed. Does not fire for Shift, Ctrl, Alt, Arrow keys.

document.addEventListener("keypress",(e)=>{ console.log("Typing:", e.key); });
Typing: a ← only for character keys
  • Order: keydown → keypress → keyup. All three fire in this sequence for printable keys.
  • keydown detects ALL keys including Shift, Ctrl, Arrow keys — most useful.
  • keypress is deprecated in modern browsers — prefer keydown.
  • Use event.key to get which key was pressed, event.code for physical key location.

Form events — triggered by form interactions

Form Events 4 events

Form events fire when users interact with input fields and forms — submitting, changing values, focusing in and out.

submit

Fires when a form is submitted. Use event.preventDefault() to stop default page reload.

<form id="myForm"> <button>Submit</button> </form> document.getElementById("myForm") .addEventListener("submit",(e)=>{ e.preventDefault(); console.log("Form Submitted"); });
Form Submitted ← page does NOT reload

change

Fires when input value changes and the element loses focus. Good for dropdowns and checkboxes.

input.addEventListener("change",(e)=>{ console.log("Value:", e.target.value); });
Value: newText ← fires after blur

focus

Fires when an input element receives focus (clicked or tabbed into).

input.addEventListener("focus",()=>{ console.log("Focused"); });
Focused ← cursor enters the field

blur

Fires when an input element loses focus (clicked away or tabbed out). Opposite of focus.

input.addEventListener("blur",()=>{ console.log("Focus Lost"); });
Focus Lost ← cursor leaves the field
  • Always use event.preventDefault() on submit to prevent the default browser form reload.
  • focus and blur are opposites — in and out of a field.
  • input event (not listed above) fires on every keystroke — more real-time than change.

Window events — triggered by browser actions

Window Events 3 events

Window events fire for browser-level actions like the page loading, the window being resized, or the user scrolling.

load

Fires when the entire page (HTML, images, CSS) has fully loaded.

window.addEventListener("load",()=>{ console.log("Page Loaded"); });
Page Loaded ← after everything finishes loading

resize

Fires every time the browser window size changes.

window.addEventListener("resize",()=>{ console.log("Width:", window.innerWidth); });
Width: 1024 ← fires on every resize

scroll

Fires every time the user scrolls up or down the page.

window.addEventListener("scroll",()=>{ console.log("Y:", window.scrollY); });
Y: 250 ← fires continuously on scroll

Clipboard events — triggered by copy, cut, paste

Clipboard Events 3 events

Clipboard events fire when the user copies, cuts, or pastes content. Useful for restricting copy-paste on forms or tracking user behavior.

copy

Fires when the user copies selected content.

document.addEventListener("copy",()=>{ console.log("Copied"); });
Copied

cut

Fires when the user cuts selected content.

document.addEventListener("cut",()=>{ console.log("Cut"); });
Cut

paste

Fires when the user pastes content into the page.

document.addEventListener("paste",()=>{ console.log("Pasted"); });
Pasted

Event object — the information JS gives you automatically

The Event Object

Every time an event fires, JavaScript automatically creates an Event Object and passes it to your handler function. It contains useful details about what happened — which element was clicked, which key was pressed, where the mouse is, etc.

  • Automatically created by JS — you don't need to do anything special.
  • Conventionally named event or e in the callback.
  • event.preventDefault() stops the default browser behavior (e.g. stop form submit from reloading page).
  • event.stopPropagation() stops the event from bubbling up to parent elements.

Example — accessing event object

btn.addEventListener("click", (event) => {
  console.log(event);
  console.log(event.type);
  console.log(event.target);
});

Output

PointerEvent { type: "click", target: button, ... } click <button id="btn">Click</button>

Example — mouse position

document.addEventListener("mousemove",(e)=>{
  console.log("X:", e.clientX, "Y:", e.clientY);
});

Output — updates as mouse moves

X: 320 Y: 150 X: 321 Y: 152 X: 325 Y: 160 ← updates in real time

Example — key pressed

document.addEventListener("keydown",(e)=>{
  console.log("Key:", e.key);
  console.log("Code:", e.code);
});

Output

Key: a Code: KeyA

⭐ Golden rules — say these in an interview

  • Always use addEventListener() — it allows multiple handlers and can be removed. onclick only allows one and overwrites.
  • Always use event.preventDefault() on form submit to prevent the default page reload behavior.
  • keydown fires for ALL keys including Shift, Ctrl, Arrow. keypress only fires for printable characters and is deprecated — prefer keydown.
  • focus and blur are opposites — focus fires when cursor enters an input, blur fires when it leaves.
  • event.target = element that triggered the event. event.currentTarget = element the listener is attached to (may be different when using event delegation).
  • Event bubbling — events bubble up from child to parent. A click on a button also fires on its parent div and document. Use event.stopPropagation() to stop this.
