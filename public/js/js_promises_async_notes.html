Promises in JavaScript

A Promise is an object that represents the eventual completion or failure of an asynchronous operation. It is a guarantee that a result will be available — now, later, or never. Used for API calls, DB operations, file handling, and network requests.

Easy definition

"A Promise is a guarantee that a result will be available now, later, or never."

Real-life analogy

Ordering food online — it is either delivered (resolved) or cancelled (rejected). While waiting, it is pending.

Syntax

let p = new Promise((resolve, reject) => {
  // async task
});

Why needed

Async tasks don't give results immediately. Promises let us say "do this task and call me when it's done."

Promise states — every promise goes through these

3 states of a Promise

⏳

Pending

Initial state — neither done nor failed. Neither resolve() nor reject() called yet.

✅

Fulfilled

Operation completed successfully. resolve() was called. .then() runs.

❌

Rejected

Operation failed. reject() was called. .catch() runs.

State examples

// PENDING — neither called
let p = new Promise((resolve, reject) => {
  console.log("Running...");
});
// State: Pending

// FULFILLED
let p = new Promise((resolve, reject) => {
  resolve("Payment Successful");
});
// State: Fulfilled

// REJECTED
let p = new Promise((resolve, reject) => {
  reject("Payment Failed");
});
// State: Rejected

Handling a promise — .then() .catch() .finally()

.then()

.then(callback) on success

Executes when the Promise is resolved successfully. The resolved value is passed as the argument to the callback.

".then() executes code when a Promise is resolved successfully."
  • Only runs when resolve() is called.
  • Can be chained — return a value from .then() and the next .then() receives it.
  • Memory tip: "then = IF all goes well, THEN do this."

Example

let p = new Promise((resolve, reject) => {
  resolve("Data Received");
});

p.then((data) => {
  console.log(data);
});

Output

Data Received
.catch()

.catch(callback) on failure

Executes when the Promise is rejected or when a runtime error occurs. Think of it as the safety net.

".catch() handles rejected Promises and runtime errors."
  • Only runs when reject() is called or an error is thrown.
  • Placed at the end of a chain to catch any error from any step.
  • Memory tip: "catch = safety net — catches whatever falls (errors)."

Example

let p = new Promise((resolve, reject) => {
  reject("Server Error");
});

p.catch((error) => {
  console.log(error);
});

Output

Server Error
.finally()

.finally(callback) always runs

Executes regardless of whether the Promise was resolved or rejected. Perfect for cleanup tasks like hiding loaders.

".finally() always executes after a Promise settles, whether success or failure."
  • Runs after .then() or .catch() — always last.
  • Does not receive any value — no argument passed.
  • Use for: hide loading spinner, close DB connection, cleanup.
  • Memory tip: "finally = no matter what happens, this ALWAYS runs."

Example — success

let p = new Promise((resolve, reject) => {
  resolve("Success");
});

p.then((data) => {
  console.log(data);
}).finally(() => {
  console.log("Completed");
});

Output

Success Completed
Complete

then + catch + finally together

The full promise pattern — handle success, handle failure, and always run cleanup. This is the correct way to write a complete Promise.

Example

let p = new Promise((resolve, reject) => {
  let login = true;
  if (login) {
    resolve("Login Successful");
  } else {
    reject("Login Failed");
  }
});

p.then((msg) => {
  console.log(msg);
}).catch((err) => {
  console.log(err);
}).finally(() => {
  console.log("Process Finished");
});

Output (login = true)

Login Successful Process Finished

Promise chaining — solving callback hell

What is Promise Chaining?

Connecting multiple .then() calls so the return value of one step becomes the input of the next. Avoids deeply nested "callback hell" code.

  • Each .then() receives the return value of the previous one.
  • Makes multi-step async operations readable top-to-bottom.
  • One .catch() at the end catches errors from any step.
  • Memory tip: "chaining = assembly line — each station passes the product to the next."

Example 1 — numbers

Promise.resolve(5)
.then((num) => {
  console.log(num);   // 5
  return num * 2;
})
.then((num) => {
  console.log(num);   // 10
  return num * 2;
})
.then((num) => {
  console.log(num);   // 20
});

Output

5 10 20

Example 2 — real life salary

new Promise((resolve) => {
  resolve(1000);
})
.then((salary) => {
  console.log("Salary :", salary);
  return salary + 5000;
})
.then((salary) => {
  console.log("Bonus Added :", salary);
  return salary + 2000;
})
.then((salary) => {
  console.log("Final Salary :", salary);
});

Output

Salary : 1000 Bonus Added : 6000 Final Salary : 8000

Advanced promise methods — working with multiple promises

01

Promise.all([ ])

Runs all promises simultaneously. Resolves only when ALL succeed. If even one fails, the whole thing fails immediately.

"Promise.all() resolves when all promises fulfill, or rejects immediately if any one fails."
  • All must succeed — one failure = total failure.
  • Returns array of all results in the same order.
  • Use when every result is required — e.g. load user + orders + settings together.
🧠 Everyone must pass — or all fail

Example

let p1 = Promise.resolve("HTML");
let p2 = Promise.resolve("CSS");
let p3 = Promise.resolve("JavaScript");

Promise.all([p1, p2, p3])
.then((result) => {
  console.log(result);
});

Output

["HTML", "CSS", "JavaScript"]
02

Promise.any([ ])

Returns the first successfully resolved promise. Ignores rejections unless ALL promises fail.

"Promise.any() returns the first fulfilled promise and ignores rejected ones."
  • Only needs one success — others are ignored.
  • Fails only if ALL promises are rejected.
  • Use when any one result is enough — e.g. try multiple servers, use whichever responds.
🧠 Any one passing is enough

Example

let p1 = Promise.reject("Error 1");
let p2 = Promise.resolve("Success");
let p3 = Promise.resolve("Java");

Promise.any([p1, p2, p3])
.then((result) => {
  console.log(result);
});

Output

Success
03

Promise.race([ ])

Returns the result of the first promise that settles — whether resolved or rejected. Fastest one wins.

"Promise.race() returns the result of the first promise that completes, success or failure."
  • First to finish wins — resolved OR rejected.
  • All others are ignored after the first settles.
  • Use for timeout patterns — if API takes too long, reject first.
🏁 Fastest wins the race

Example

let p1 = new Promise((resolve) => {
  setTimeout(() => resolve("HTML"), 3000);
});
let p2 = new Promise((resolve) => {
  setTimeout(() => resolve("CSS"), 1000);
});

Promise.race([p1, p2])
.then((result) => {
  console.log(result);
});

Output — CSS finishes first

CSS
04

Promise.allSettled([ ])

Waits for ALL promises to finish — success or failure — and returns every result. Never rejects because of one failure.

"Promise.allSettled() returns all results after every promise has settled, regardless of success or failure."
  • Never fails — always waits for every promise.
  • Returns objects with status: "fulfilled" or status: "rejected".
  • Use when you need to know the outcome of every promise, even failures.
📋 Show everyone's result — pass or fail

Example

let p1 = Promise.resolve("HTML");
let p2 = Promise.reject("Error");
let p3 = Promise.resolve("JavaScript");

Promise.allSettled([p1, p2, p3])
.then((result) => {
  console.log(result);
});

Output

[ { status: "fulfilled", value: "HTML" }, { status: "rejected", reason: "Error" }, { status: "fulfilled", value: "JavaScript" } ]

fetch() — getting data from a server

fetch(url) returns a Promise

A built-in JS method to send HTTP requests and receive data from APIs. Replaced the old XMLHttpRequest (XHR). Because API calls take time, fetch() returns a Promise.

  • Returns a Promise — must use .then() or await.
  • First .then() receives the raw Response object — call .json() on it to parse data.
  • Always add .catch() to handle network errors.
  • Memory tip: "fetch = call the waiter — waiter goes to kitchen (server) and brings back food (data)."

Example — using .then() chain

fetch("https://jsonplaceholder.typicode.com/users")
.then((response) => {
  return response.json();    // parse raw response
})
.then((data) => {
  console.log(data);         // actual data
})
.catch((error) => {
  console.log(error);        // handle error
});

async / await — ES8 (2017) — promises made easy

async

async function ES8 — 2017

The async keyword before a function makes it automatically return a Promise. Even if you return a plain value, it gets wrapped in a resolved Promise.

"The async keyword declares an asynchronous function that always returns a Promise."
  • Any function with async = returns a Promise, always.
  • Allows use of await inside the function.
  • Memory tip: "async = this function will deal with Promises."

Example

async function demo() {
  return "Hello";
}

demo().then((data) => {
  console.log(data);
});

Output

Hello
await

await keyword only inside async

Pauses the execution of an async function until the Promise resolves. Makes async code read like normal synchronous code — no more .then() chains.

"await pauses an async function until a Promise resolves before continuing execution."
  • Can ONLY be used inside an async function.
  • Pauses only that function — not the whole program.
  • Memory tip: "await = hold on, wait for the Promise to finish, THEN continue."

Example

function getData() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve("Data Received");
    }, 3000);
  });
}

async function display() {
  let result = await getData();
  console.log(result);
}

display();

Output — after 3 seconds

Data Received
fetch + async/await

Fetching API data with async/await — the modern way

Combining fetch() with async/await makes API calls look clean and readable. Use try/catch instead of .catch() for error handling.

  • Wrap in try { } — success code goes here.
  • Wrap in catch(error) { } — error handling goes here.
  • Much cleaner than chaining multiple .then() calls.

Example

async function getUsers() {
  try {
    let response = await fetch(
      "https://jsonplaceholder.typicode.com/users"
    );
    let data = await response.json();
    console.log(data);
  } catch (error) {
    console.log(error);
  }
}

getUsers();

⭐ Golden rules — say these in an interview

  • A Promise has exactly 3 states — pending, fulfilled, rejected. Once settled it cannot change state again.
  • async/await is built on top of Promises — it is just cleaner syntax, not a replacement.
  • await can ONLY be used inside an async function — using it outside throws a SyntaxError.
  • Promise.all() fails fast — the moment one rejects, the whole thing rejects. Use allSettled() when you need all results regardless.
  • fetch() only rejects on network failure — a 404 or 500 response is still a resolved promise. Always check response.ok.
  • Promise chaining solves callback hell — keeps code flat and readable instead of deeply nested.
