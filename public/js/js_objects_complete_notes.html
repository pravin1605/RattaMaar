JavaScript Objects — Complete Study Notes

Objects in JavaScript

An object is a block of memory that stores data as key-value pairs. Every real-world thing can be modelled as an object — a student has a name, age, hobbies, and address. Objects have two things: properties (data/characteristics) and methods (functions attached to the object).

Way 1 — literal

let obj = {
  key: value,
  key: value
};

Way 2 — constructor

let obj = new Object();
obj.name = "Pravin";
obj.age  = 22;

Access values

obj.name       // dot notation
obj["name"]    // bracket notation

Key traits

Can store any data type — strings, numbers, arrays, nested objects, and even functions as values.

A real object — what it can hold

Object with all data types inside

An object can hold strings, numbers, booleans, arrays, nested objects, and methods — all at the same time.

Example

let student = {
  name     : "Pratham",          // string
  age      : 22,                 // number
  isMarried: false,              // boolean
  hobbies  : ["cricket","football","coding"],  // array
  address  : {                   // nested object
    city   : "Pune",
    state  : "Maharashtra",
    country: "India"
  },
  isWorking: function() {        // method
    return "Yes, I am working";
  }
};

Accessing nested values

console.log(student.name);             // Pratham
console.log(student.hobbies[0]);       // cricket
console.log(student.address.city);     // Pune
console.log(student.isWorking());      // Yes, I am working
console.log(student["address"]["state"]); // Maharashtra

Output

Pratham cricket Pune Yes, I am working Maharashtra

Dot notation vs Bracket notation

Dot notation — obj.key

  • Simple and readable
  • Key must be a valid identifier
  • Cannot use variables as keys
  • Example: student.name

Bracket notation — obj["key"]

  • More flexible
  • Can use variables as keys
  • Works with special characters in keys
  • Example: student["name"]

Accessing object values in a template literal

You can embed object values directly inside a template literal using ${}. This is the cleanest way to build dynamic strings from object data.

Example

let emp = {
  id      : 11,
  name    : "ram",
  hobbies : ["sleeping","eating"],
  address : { city:"Pune", state:"Maharashtra", country:"India" },
  isWorking: function(){ return "Yes, I am working"; }
};

let info = `Employee ID: ${emp["id"]}
Name: ${emp["name"]}
City: ${emp["address"]["city"]}, ${emp["address"]["state"]}
Hobbies: ${emp["hobbies"][0]} and ${emp["hobbies"][1]}
Status: ${emp["isWorking"]()}`;

console.log(info);

Output

Employee ID: 11 Name: ram City: Pune, Maharashtra Hobbies: sleeping and eating Status: Yes, I am working

Object methods

01

Object.keys(obj)

Returns an array of all the property keys (names) of the object. Think of it as reading all the labels on the filing cabinet drawers.

  • Returns an array of strings.
  • Only returns own properties — not inherited ones.
  • Memory tip: "keys = give me all the drawer labels."

Example

console.log(Object.keys(student));

Output

["name", "age", "isMarried", "hobbies", "address", "isWorking"]
02

Object.values(obj)

Returns an array of all the property values of the object. Like opening all the drawers and listing what's inside.

  • Returns an array of values (any type).
  • Order matches the order keys were added.
  • Memory tip: "values = give me the contents of every drawer."

Example

console.log(Object.values(student));

Output

["Pratham", 22, false, ["cricket",...], {city:...}, function]
03

Object.entries(obj)

Returns an array of [key, value] pairs. Each item in the array is itself an array of two elements — the key and its value together.

  • Returns array of arrays: [["name","Pratham"], ["age",22], ...].
  • Perfect for looping: use with forEach or for...of.
  • Memory tip: "entries = give me label + contents together for each drawer."

Example

console.log(Object.entries(student));

Output

[["name","Pratham"],["age",22],["isMarried",false],...]
04

Object.assign(target, source)

Copies all properties from a source object into a target object. Used to clone or merge objects.

  • Returns the target object after copying.
  • Use {} as target to create a fresh copy — avoids modifying original.
  • Shallow copy only — nested objects are still shared by reference.
  • Memory tip: "assign = photocopy one object into another."

Example

let student2 = { name:"Pravin", age:22 };
let student3  = Object.assign({}, student2);
console.log(student3);

Output

{ name: "Pravin", age: 22 }
05

hasOwnProperty(key)

Checks whether the object has the specified property as its own (not inherited). Returns true or false.

  • Returns a boolean.
  • Checks only own properties — NOT inherited prototype properties.
  • Safer than using in operator which checks inherited too.
  • Memory tip: "hasOwnProperty = is this drawer MINE, not borrowed?"

Example

console.log(student.hasOwnProperty("name"));
console.log(student.hasOwnProperty("salary"));

Output

true false

Protecting objects — seal vs freeze

Seal vs Freeze — what is allowed?

Normal object

  • ✓ Add new properties
  • ✓ Delete properties
  • ✓ Modify properties
  • No protection at all

Object.seal()

  • ✗ Cannot add new properties
  • ✗ Cannot delete properties
  • ✓ Can still modify values
  • Like a sealed envelope — can edit inside, but can't add or tear pages

Object.freeze()

  • ✗ Cannot add new properties
  • ✗ Cannot delete properties
  • ✗ Cannot modify values
  • Like ice — completely solid, nothing changes
06

Object.seal(obj)

Seals the object — you can still modify existing values but you cannot add new properties or delete existing ones.

  • Add → silently ignored (no error in non-strict mode).
  • Delete → silently ignored.
  • Modify → still works normally.
  • Memory tip: "seal = sealed envelope — edit what's inside, can't add or remove pages."

Example

Object.seal(student);

student.salary = 50000;    // add — IGNORED
delete student.name;       // delete — IGNORED
student.name = "Pravin";   // modify — WORKS

console.log(student.name);
console.log(Object.isSealed(student));

Output

Pravin true
07

Object.freeze(obj)

Freezes the object — you can do nothing to it. No adding, no deleting, no modifying. It becomes completely read-only.

  • Add → silently ignored.
  • Delete → silently ignored.
  • Modify → silently ignored.
  • Freeze is stronger than seal — seal + no modify = freeze.
  • Memory tip: "freeze = ice block — completely solid, zero changes allowed."

Example

Object.freeze(student);

student.salary = 50000;    // add — IGNORED
delete student.name;       // delete — IGNORED
student.name = "Pravin";   // modify — IGNORED

console.log(student.name);
console.log(Object.isFrozen(student));

Output

Pratham true
08

Object.isSealed(obj)

Checks whether an object is sealed. Returns true if sealed, false if not.

  • Returns a boolean.
  • A frozen object is also considered sealed — isSealed returns true for frozen objects too.

Example

console.log(Object.isSealed(student));   // sealed
console.log(Object.isSealed(student2));  // normal

Output

true false
09

Object.isFrozen(obj)

Checks whether an object is frozen. Returns true if frozen, false if not.

  • Returns a boolean.
  • A sealed object is NOT necessarily frozen — they are different levels of protection.

Example

console.log(Object.isFrozen(student));   // frozen
console.log(Object.isFrozen(student2));  // normal

Output

true false

Golden rules of objects — say these in an interview

  • Objects store data as key-value pairs — keys are always strings (or symbols), values can be anything.
  • Objects are reference types — when you copy an object with =, both variables point to the same object in memory. Use Object.assign() or spread {...obj} to make an independent copy.
  • seal = can modify, cannot add/delete. freeze = cannot do anything. Freeze is stronger than seal.
  • A frozen object is also sealed — Object.isSealed(frozenObj) returns true. But a sealed object is NOT frozen.
  • Object.assign() is a shallow copy — nested objects inside are still shared by reference, not truly duplicated.
  • Use hasOwnProperty() over the in operator when you want to check only the object's own keys — in also checks the prototype chain.
