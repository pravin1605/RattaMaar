Hoisting in JavaScript

01What is Hoisting?
Definition
Hoisting is the process in JavaScript where variables and functions can be accessed before their declaration. This happens because JavaScript internally moves declarations to the top of their scope during the memory creation phase — before any code actually runs.
How JavaScript executes code — two phases
Phase 1 — Memory creation phase
JavaScript scans all the code first and allocates memory for all variables and functions before any line runs. This is where hoisting happens.
Phase 2 — Execution phase
JavaScript runs the code line by line. By this point, all declarations are already known.
Hoisting behaviour for each keyword
var
Fully hoisted
Declaration hoisted. Value set to undefined until assignment.
function
Fully hoisted
Entire function definition hoisted. Can be called before declaration.
let / const
Partially hoisted
Hoisted but stuck in Temporal Dead Zone — cannot be accessed early.
02Hoisting with var
How it works
Variables declared using var are hoisted to the top of their scope. Only the declaration is hoisted — NOT the initialization. So the variable exists before the line runs, but its value is undefined until the assignment line is reached.
Declaration is hoisted ✅  ·  Initialization is NOT hoisted ❌
The variable exists but holds undefined until the value is actually assigned.
Example — accessing var before declaration
console.log(a); // accessed before declaration var a = 10;
Output
undefined
Internal working — what JavaScript actually does
JavaScript internally rearranges the code like this during the memory creation phase:
Code you write
console.log(a); var a = 10;
What JS does internally
var a; // hoisted console.log(a); // undefined a = 10; // assigned later
Why output is undefined — step by step
1 JS scans code → finds var a → allocates memory → sets value to undefined
2 Execution starts → console.log(a) runs → a is undefined at this point
3 a = 10 runs → now a is assigned the value 10
After declaration — works normally
var a = 10; console.log(a); // accessed after declaration
Output
10
03Hoisting with function declaration
How it works
Function declarations are completely hoisted — the entire function body is moved to the top during the memory creation phase. This means a function can be called before its declaration and it will work perfectly.
Entire function definition is hoisted ✅
The function can be called anywhere in the code — even before the line where it is written.
Example — calling function before declaration
greet(); // called before declaration function greet() { console.log("Hello"); }
Output
Hello
Internal working — what JavaScript does
Code you write
greet(); function greet() { console.log("Hello"); }
What JS does internally
// entire function hoisted function greet() { console.log("Hello"); } greet(); // now called
Why function declaration works — but function expression does not
Function declaration ✅
greet(); // works! function greet() { console.log("Hello"); }
Output
Hello
Function expression ❌
greet(); // error! var greet = function() { console.log("Hello"); };
Error
TypeError: greet is not a function
With a function expression, only the var greet part is hoisted (as undefined) — the function body is not. So calling it early causes a TypeError.
04Hoisting with let and const
How it works
let and const are also hoisted — but they are placed into the Temporal Dead Zone (TDZ) and cannot be accessed before their declaration line is reached. Trying to access them early throws a ReferenceError.
Temporal Dead Zone (TDZ)
The Temporal Dead Zone is the period between the start of the block and the line where the variable is declared. During this time, the variable exists in memory but is completely inaccessible. Any attempt to read it throws a ReferenceError.
Example — accessing let before declaration
console.log(b); // accessed before declaration let b = 20;
Error
ReferenceError: Cannot access 'b' before initialization
Example — accessing const before declaration
console.log(c); // accessed before declaration const c = 100;
Error
ReferenceError: Cannot access 'c' before initialization
After declaration — works normally
let b = 20; console.log(b); // accessed after declaration const c = 100; console.log(c); // accessed after declaration
Output
20 100
Visualising the Temporal Dead Zone
TDZ starts here
Block begins — let/const are hoisted into memory but completely inaccessible. Accessing them here throws ReferenceError.
TDZ zone — danger area
Any console.log or access here will throw: ReferenceError: Cannot access before initialization
TDZ ends here — safe zone
The declaration line is reached → variable is initialized → now accessible safely.
05Hoisting — full comparison
Type Hoisted? Initial value Access before declaration
var Yes — fully undefined Allowed — returns undefined
function declaration Yes — fully Full function Allowed — works perfectly
let Yes — partial TDZ (no value) Not allowed — ReferenceError
const Yes — partial TDZ (no value) Not allowed — ReferenceError
function expression Partial (var only) undefined Not allowed — TypeError
Interview Answer — What is Hoisting?
Hoisting is a JavaScript mechanism where variable and function declarations are moved to the top of their scope during the memory creation phase before code execution. var is fully hoisted with value undefined, function declarations are fully hoisted with their complete body, and let and const are hoisted but remain in the Temporal Dead Zone and cannot be accessed before their declaration line.
Memory Trick — var = hoisted as undefined  ·  function declaration = fully hoisted  ·  let / const = hoisted but in TDZ → ReferenceError if accessed early
