Asynchronous JavaScript — Complete Study Notes

Asynchronous JavaScript

JavaScript is single-threaded — it can only do one thing at a time. By default it runs code line by line (synchronous). But some tasks take time — API calls, file reading, timers. Async JS lets these run in the background while the rest of the code keeps moving.

Synchronous

Code runs line by line. Next line waits for the current one to finish. Like a queue — one person at a time.

Asynchronous

Long tasks run in the background. Other code keeps executing. Like ordering food and watching TV while it cooks.

Why needed

API calls, DB operations, file reading, timers, user events — all take time and would freeze the app if waited on.

Interview line

"Async JS allows long-running operations to run independently without blocking the main thread."

Time functions in JavaScript

What are time functions?

Time functions are built-in JavaScript functions used to execute code after a delay or repeatedly at a fixed interval. There are 4 time functions — 2 pairs that work together.

One-time execution

setTimeout() — run once after a delay
clearTimeout() — cancel it before it runs

Repeated execution

setInterval() — run repeatedly at fixed gap
clearInterval() — stop it

01

setTimeout(fn, ms) runs once

Executes a callback function once after a specified delay in milliseconds. After that it stops — it does not repeat.

"setTimeout() is a built-in timer function that executes a callback once after a specified delay."
  • 1000 ms = 1 second. So 3000 ms = 3 seconds.
  • Does not block other code — JS keeps running while waiting.
  • Returns a timer ID that can be used to cancel it with clearTimeout().
  • Memory tip: "setTimeout = set an alarm — rings once and that's it."

Syntax

setTimeout(function, timeInMilliseconds);

Use cases

Delay execution
Show notification
Loading screen
Future message

Example

setTimeout(() => {
  console.log("Welcome");
}, 3000);

Output — after 3 seconds

Welcome
02

clearTimeout(id) cancels setTimeout

Cancels a timeout before it fires. You must pass the timer ID returned by setTimeout(). If called before the delay ends, the callback never runs.

"clearTimeout() stops or cancels a timeout created by setTimeout() before it executes."
  • Must store the return value of setTimeout() to cancel it.
  • If called after the timeout already fired — it has no effect.
  • Memory tip: "clearTimeout = cancel the alarm before it rings."

Use cases

User cancels action
Timer no longer needed
Prevent delayed run

Example

let timer = setTimeout(() => {
  console.log("Hello");
}, 5000);

clearTimeout(timer); // cancelled before 5s

Output

// Nothing prints — timer was cancelled
03

setInterval(fn, ms) repeats forever

Executes a callback function repeatedly at a fixed time interval. It keeps running until you stop it with clearInterval().

"setInterval() repeatedly executes a callback function at specified time intervals until stopped."
  • Runs indefinitely — you MUST call clearInterval() to stop it.
  • Returns a timer ID used to stop it.
  • Memory tip: "setInterval = set a repeating alarm — rings every N seconds forever."

Syntax

setInterval(function, timeInMilliseconds);

Use cases

Digital clock
Countdown timer
Auto refresh
Live score
Notifications

Example

setInterval(() => {
  console.log("Hello");
}, 2000);

Output — every 2 seconds

Hello Hello Hello ... (keeps going)
04

clearInterval(id) stops setInterval

Stops the repeated execution started by setInterval(). Pass the timer ID to tell JS which interval to stop.

"clearInterval() stops an interval that was started using setInterval()."
  • Must store the return value of setInterval() to stop it.
  • Commonly called inside the interval itself once a condition is met (e.g. countdown = 0).
  • Memory tip: "clearInterval = hit snooze forever — make the repeating alarm stop."

Use cases

Countdown hits 0
User stops timer
Task completed
Stop auto-refresh

Example — count to 5 then stop

let count = 0;

let timer = setInterval(() => {
  count++;
  console.log(count);

  if (count === 5) {
    clearInterval(timer);
  }
}, 1000);

Output — one per second, then stops

1 2 3 4 5 // Stops here

Golden rules — say these in an interview

  • JavaScript is single-threaded — it has one call stack and executes one thing at a time.
  • Async JS does NOT make JS multi-threaded — it uses the event loop to handle tasks in the background via Web APIs.
  • Time in setTimeout and setInterval is in milliseconds — 1000ms = 1 second.
  • Always store the return value of setTimeout / setInterval if you may need to cancel it later.
  • setTimeout(fn, 0) does not run immediately — it still goes to the task queue and runs after the current code finishes.
  • A frozen setInterval that is never cleared causes a memory leak — always clear it when done.
