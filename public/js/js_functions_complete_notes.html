Functions in JavaScript

A function is a reusable, self-contained block of code designed to perform a specific task. It runs only when explicitly called, allowing you to write logic once and reuse it as many times as needed — keeping code clean, readable, and maintainable.

Syntax

function name(params) {
  // code
  return value;
}

Why we need it

Avoid repetition (DRY principle), break big problems into smaller pieces, and make code easier to test and debug.

Key uses

Reusable logic · Event handling · Async operations · Callbacks · Modular code structure

Introduced

Functions have been part of JavaScript since ES1 (1997). Arrow functions were added in ES6 (2015).

01 — Named Function

Named Function ES1 Hoisting ✓

A function defined with the function keyword and a meaningful name. The name makes it self-documenting and easy to identify in stack traces and debuggers.

Key points

  • Has a name visible in error stack traces — very helpful for debugging.
  • Can call itself recursively using its own name.
  • Hoisting applies — JavaScript moves the entire definition to the top before execution.
  • Preferred for standalone, reusable utility functions.

Syntax

function functionName(params) { return value; }

Example

function greet() {
  console.log("Hello Mayuresh");
}
greet();

Output

Hello Mayuresh
02 — Function Declaration

Function Declaration ES1 Hoisting ✓

The standard way to define a function using the function keyword. The entire function — name and body — is hoisted to the top of its scope, so it can be called before the line where it is written.

Key points

  • Fully hoisted — both the name and body are moved to the top of the scope during compilation.
  • Calling it before its definition in the file works without errors.
  • Introduced in ES1 (1997) — the original function syntax.
  • Best choice when you need a clearly named, globally available function.
  • Interview tip: "Hoisting is possible because the JS engine processes function declarations in the compilation phase, before any code runs."

Syntax

function add(a, b) { return a + b; }

Example

console.log(add(5, 3));  // called BEFORE declaration — still works!

function add(a, b) {
  return a + b;
}

Output

8
03 — Anonymous Function

Anonymous Function ES1 Hoisting ✗

A function with no name. It cannot exist on its own — it must be assigned to a variable or passed as an argument. Because it has no name, it shows as anonymous in stack traces.

Key points

  • No hoisting — cannot be used before assignment.
  • Shows as "anonymous" in error stack traces, making debugging harder.
  • Commonly used as a one-time callback or immediately invoked function (IIFE).
  • Must be stored in a variable to be called later.
  • Why introduced: to allow functions to be treated as values — passed around like data.

Syntax

const name = function() { /* code */ };

Example

const sayHi = function() {
  console.log("Hello from anonymous function");
};
sayHi();

Output

Hello from anonymous function
04 — Function Expression

Function Expression ES1 Hoisting ✗

A function assigned to a variable. JavaScript treats it as a variable assignment, not a function declaration, so the function is only available from the line it is defined onwards.

Key points

  • No hoisting — the variable is hoisted but its value (the function) is not.
  • Calling it before its assignment throws: TypeError: multiply is not a function.
  • Works with var, let, and const — but const is recommended to prevent reassignment.
  • Can be named or anonymous — naming helps in recursion and debugging.
  • Why introduced: enables functions as first-class values — stored, passed, and returned.

Syntax

const name = function(params) { return value; };

Example

const multiply = function(a, b) {
  return a * b;
};
console.log(multiply(4, 3));

Output

12
05 — Arrow Function

Arrow Function ES6 — 2015 Hoisting ✗

A shorter syntax for writing functions, introduced in ES6. Designed to simplify callback-heavy code and to fix the common this binding problem in regular functions.

Key points

  • No hoisting — treated as a variable assignment.
  • Does not have its own this — inherits this from the surrounding (lexical) scope. This was the primary reason for its introduction.
  • No arguments object — use rest parameters (...args) instead.
  • Cannot be used as a constructor — new ArrowFn() throws a TypeError.
  • Single-expression body: curly braces and return can be omitted.
  • Single parameter: parentheses around it can be omitted.
  • Why introduced (ES6): to solve this confusion inside callbacks (e.g. inside setTimeout, map, event listeners).

Syntax

const name = (params) => expression; // or with body: const name = (params) => { return value; };

Example

const subtract = (a, b) => a - b;
console.log(subtract(10, 4));

Output

6
06 — Higher Order Function

Higher Order Function ES1 Depends on type used

A function that takes another function as an argument, returns a function, or both. It is a concept from functional programming that makes code more abstract and composable.

Key points

  • Hoisting depends on how the function itself is declared (declaration = yes, expression = no).
  • Built-in JS HOFs: map(), filter(), reduce(), forEach(), sort().
  • Enables functional programming patterns — clean, reusable transformations on data.
  • The function it receives is called a callback function.
  • Why important: powers asynchronous JavaScript (event listeners, Promises, async/await internally).

Syntax

function higherOrder(a, callbackFn) { return callbackFn(a); }

Example

function add(a, b) {
  return a + b;
}
function num() {
  return 8;          // callback function
}
console.log(add(num(), num()));

Output

16
07 — Callback Function

Callback Function ES1 Depends on type used

A function passed as an argument to another function, to be executed later — either immediately (synchronous) or after an event or async operation (asynchronous).

Key points

  • Not a special syntax — any function becomes a callback when passed as an argument.
  • Synchronous callbacks run immediately (e.g. inside map, filter).
  • Asynchronous callbacks run later (e.g. inside setTimeout, fetch, event listeners).
  • Nesting too many callbacks creates "callback hell" — Promises and async/await were introduced to solve this.
  • You can pass a named function, anonymous function, or arrow function as a callback.
  • Why important: the entire JS event system (browser events, Node.js I/O) is built on callbacks.

Syntax

outerFunction(arg, callbackFn);

Example

function add(a, b) {
  return a + b(4, 5);   // b is called as a function
}
console.log(add(5, (x, y) => x * y));
// (x,y) => x*y  is the callback

Output

25

Rules of the return keyword

  • Stops the execution of a function immediately and sends a value back to the caller.
  • Any code written after return is unreachable and will never execute.
  • Without return, the function returns undefined by default.
  • Only one value can be returned — wrap multiple values in an array or object.
  • return should always be the last meaningful line inside a block.
